# M-Box门店验证计划

目标：在购买正式云资源和接入真实支付前，证明系统能够稳定提升服务响应、主动服务、出品追踪和投诉闭环。验证结论以审计记录和量化指标为准，不以“感觉好用”代替。

## 验证边界

- 现有POS和支付终端仍是资金事实来源；系统只使用模拟支付或物理POS人工报送。云端验证环境仅在`MBOX_PILOT_PAYMENT_SIMULATION_ENABLED=true`时允许非结算模拟支付，生产环境拒绝该开关。
- 使用员工测试编号和顾客测试编号，不录入身份证、人脸、支付密钥、完整手机号等敏感信息。
- 摄像头、人脸识别、真实微信通知和真实退款不进入本轮验证。
- 当前验证环境运行在独立Google Cloud项目；PC、平板和手机通过HTTPS访问，不开放数据库公网端口。
- 每日自动备份PostgreSQL到独立对象存储，关店后仍需导出问题、审计记录和当晚指标。

## 第0阶段：设备与数据准备

1. 准备至少两台员工平板和两部测试手机，并保留一台门店PC用于值班经理总览。
2. 从门店PC打开云端验证地址，使用门店验证口令选择当前员工；测试设备不保存共享口令截图。
3. 录入本轮使用的区域、桌台、员工、主责、候补、领班、经理、商品、档口和SLA草稿。
4. 只启用本轮要验证的服务类型；确认加水、协助点单、买单、投诉和生日服务话术。
5. 逐台打开员工端和顾客桌码样例，验证页面、接单、到桌、员工完成后任务自动消失。

## 第1阶段：桌面场景演练

用2至4名员工、5张测试桌完成以下场景，每个场景至少重复3次：

| 场景 | 预期结果 |
|---|---|
| 客人入桌未点单 | 员工标记后按配置时间生成协助点单任务；下单后停止提醒 |
| 客人呼叫加水/冰块柠檬 | 客户立即收到“已收到”；主责接单并完成，到桌和完成均有审计 |
| 主责忙碌或不响应 | 超时后按候补、领班、经理顺序升级，不出现无人负责 |
| 商品提交 | 订单保留价格快照并进入正确档口KDS |
| 出品超过目标时间 | 任务升级到对应岗位，送达前不能标记服务闭环 |
| 赠送和折扣 | 权限内直接执行，越权必须进入审批，不能绕过审计 |
| 投诉 | 高优先级通知领班/经理，记录处理、补偿和顾客确认 |
| 生日服务 | 显示动作卡、话术和可赠权益，不依赖员工自由发挥 |
| 员工设备断网后恢复 | 只重放允许的服务动作；订单、支付、库存等写入保持禁止 |
| 重复点击和刷新 | 不产生重复任务、重复订单、重复赠送或重复库存扣减 |

## 第2阶段：高峰模拟

1. 使用20至50张模拟桌，连续产生呼叫、未点单、订单、KDS超时和投诉事件。
2. 安排一名主责暂停或离岗，验证候补接管和领班升级。
3. 同时让多台设备接单，确认同一任务只有一个有效负责人和一致状态。
4. 模拟Wi-Fi中断后恢复，核对离线动作、冲突和审计记录。
5. 每轮结束检查未关闭任务、重复记录、库存差异和无法解释的状态。

## 第3阶段：真实营业影子运行

- 连续运行3至7个营业夜；员工照常使用原POS收款，同时使用M-Box完成服务任务和出品跟踪。
- 第一晚只覆盖一个区域，稳定后扩大到全店；不在同一晚同时修改大量SLA和人员责任。
- 每桌结束后抽查服务任务、KDS、赠送、投诉、完成人和处理结果记录。
- 值班经理使用`templates/pilot-night-record.md`完成当晚记录，所有失败必须有负责人和截止时间。

## 验收指标

| 指标 | 通过门槛 |
|---|---|
| 顾客呼叫系统确认 | 5秒内达到99% |
| 员工接单 | 60秒内达到95% |
| 员工到桌 | 3分钟内达到90% |
| 主责无响应后的候补接管 | 触发后30秒内达到95% |
| 未点单提醒按配置产生 | 达到95%，且下单后误提醒为0 |
| KDS超时任务产生 | 达到95%，漏报为0个严重超时 |
| 投诉经理确认 | 2分钟内达到100%，未关闭投诉为0 |
| 任务状态可追溯 | 100%具有桌台、人员、时间和动作审计 |
| 重复任务/订单/权益/库存扣减 | 0 |
| 员工使用覆盖 | 当班员工完成系统动作比例达到90% |

## 停止条件

出现跨桌数据、重复资金记录、无法恢复的数据丢失、权限绕过或审计缺失时立即停止扩大验证，保存状态和操作时间，不通过人工修改数据掩盖问题。

## 进入正式生产迁移的门槛

同时满足以下条件才开始正式云部署：

1. 连续3个营业夜无P0/P1故障。
2. 至少完成50桌次、100个服务任务和20个候补升级事件。
3. 上述验收指标全部达标，未达标项已有修复并复测。
4. 店长确认SOP和人员责任链可执行，财务确认模拟账务逻辑无不可解释差异。
5. 正式支付、微信、域名、国内云账号和门店主数据资料已经具备负责人和计划日期。

通过后再部署国内云生产环境、PostgreSQL高可用数据库、HTTPS域名和监控，并进行真实支付小额PoC；验证环境数据不直接作为正式生产数据导入。
