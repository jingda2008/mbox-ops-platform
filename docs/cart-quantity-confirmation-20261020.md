# 顾客多份商品数量确认

更新时间：2026-10-20 21:16 CST

## 行为

同一商品以productId识别，在本次待提交购物车内累计数量大于1，就在最终提交前弹出一张完整、可滚动的清单。例如啤酒×3、薯条×2；其他仅1份商品不在此提醒中出现。同名但不同商品ID不合并，不计入既有订单，不拆算套餐内部商品。

“是，确认提交”直接继续原提交/支付流程；只有真实业务响应才能判定成功，不跳过支付或渠道确认。“否，返回购物车”不发起下单、不修改数量、不删除商品，返回可编辑购物车。无需重复数量提醒的购物车保持原确认流程。

微信与支付宝在最终确认后、下单请求前检查；H5顾客端使用同一数量规则，员工上单不增加此提醒。原历史重复订单确认、未知结果恢复、幂等键和购物车版本保护保留。确认期间改桌、购物车版本/代次、备注/优惠或冻结状态发生变化，原确认不能创建订单。隐藏/离开小程序页面会取消未完成的数量确认。

- 新增小程序真实页面逻辑专项22项，通过：同商品分行合并、同名不同ID、取消后保留、单份不提示、再次提交重新提示、双击不重复、版本/代次/备注/冻结/桌位/隐藏变化、60项完整清单、失败不显示成功、未知结果原请求保留。
- 小程序整体回归610项全部通过，包含新增22项；微信静态检查通过。
- 支付宝静态检查和平台13项通过；在保留既有平台差异的同时，对新提示框模板和样式增加双端一致性断言，并刷新精确文件哈希。
- 支付宝官方SDK1.x编译器23页编译通过，worker 1,218,085字节；这是命令编译，不是IDE2.x或真机验收。
- 网页定向17项通过；浏览器7项通过，包括真实隔离数据库的取消、并发改数量、商品逐份备注、实际提交、丢失响应后的原请求恢复及版本冲突。支付为测试环境，未产生线上订单或资金。
