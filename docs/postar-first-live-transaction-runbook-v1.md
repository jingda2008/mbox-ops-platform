适用范围：首笔真实小额微信支付、回调、主动查单、对账和退款验收。本文不包含密钥、付款码、手机号或客户隐私。

## 1. 当前不可跳过的前置条件

1. 星驿确认机构 `FWH000030224` 与商户 `60000001067349` 已开通微信支付和对应测试/生产通道。
2. 取得与该环境一致的星驿RSA公钥；只存入服务器秘密配置，不进GitHub。
3. 星驿后台确认回调地址：`https://pay.shmbox.com/api/payments/providers/postar/callback`。
4. `pay.shmbox.com` DNS、TLS和反向代理验证通过，证书与私钥仅在服务器。
5. 明确联调环境。`validation` 只能使用 `test/uat`；真实生产付款必须走 `production` 候选和全部生产配置门禁，不能在验证环境偷开生产支付。
6. 陈方宇或其明确授权人在场，确认付款人、金额、时间窗口和退款处理人。

## 2. 建议首笔交易

- 商品：“其他/补差额”1份，单价1元。
- 桌号：专用测试桌，不与员工实操混用。
- 路径：先验证“员工协助点单 -> 客人扫二维码”；JSAPI需额外的微信AppID和openid绑定，不作为首笔必选。
- 禁止：不用真实客人订单，不在高峰期执行，不用重复点击验证幂等。

## 3. 验收步骤

1. 冻结提交SHA和镜像摘要，确认线上运行版本一致。
2. 使用真实服务器配置执行只读预检；DNS/TLS/回调检查失败时不进行数据库操作。
3. 打开测试桌，提交1元订单，记录内部 `orderId/paymentId`。
4. 发起一次二维码支付，校对桌号、商品和金额，付款人确认后付款。
5. 验证验签回调将同一 `paymentId` 置为成功；订单、桌码、员工和收银界面状态一致。
6. 重放同一回调，支付、对账和业务事件不得增加第二笔。
7. 在不重新收款的情况下点“核对是否到账”，主动查单应返回同一渠道交易号且不重复入账。
8. 核对星驿渠道流水、M-BOX对账记录和审计事件金额全部为1元。
9. 由申请人发起全1元退款，由另一名有权人审批和执行；退款回调/查单成功后再显示已退。
10. 完成日对账：收款1元、退款1元、净额0元，不存在未知支付或未完成退款。

## 4. 停止条件

任一情况立即停止，不发起第二笔收款：金额/商户/单号不一致，回调验签失败，支付状态未知，渠道扣款但系统未入账，系统入账但渠道无流水，对账出现差异，或日志出现密钥/付款码/完整手机号。
