# M-BOX 1.0.0-rc.66 现场履约质量与岗位简化

## 升级目标

- 让调酒师、厨房和服务员在高峰期只处理自己当前必须执行的动作。
- 减少制作与配送点击次数，同时保留可追溯、可解释的真实审计证据。
- 消除跨岗位信息噪音，按异常、截止时间、主责和候补关系排序。
- 统一库存个人授权、预约/临客分离和打印失败数字兜底。
- 用独立质量监督智能体复审差异，禁止把本地测试冒充部署或商业完成。

## 核心改动

- 制作岗位从待制作直接点击“制作完成”；系统记录自动接单标记，不能伪装为员工此前点击过开始制作。
- 配送岗位从待取货直接点击“已送达”；服务端同一事务内写入系统推定取货、员工确认送达、KDS、服务任务、订单和审计状态。
- 制作与配送仍是不同岗位的不同动作；旧“完成并送达”公共接口明确拒绝，避免制作人伪造配送。
- 调酒师只看主吧台酒水，厨房只看对应后厨工位，服务员只看已完成待送商品；经理保留监督视图。
- 队列按异常/超时、本人配送、可候补配送、本人制作分组，同组按最早截止时间排序。
- 打印排队或失败时明确显示电子出品单继续有效，打印失败进入AI值班经理风险。
- 后台可分别授予个人入库、盘点、补做和存酒能力，API与页面同步生效；直接授权不再扩大为全部库存管理权，角色继承权限仍遵守岗位政策。
- 预约台分为待到店、已到店待安排和已入座/历史；现场临客走直接开台，不进入预约列表和指标。
- 新增独立质量门禁和专项TC，所有未执行、外部阻塞和现场项目单独列明。

## 本地验证结果

- 全量Vitest：141个测试文件、1103项通过。
- 客户与预约：45项聚焦测试、10项跨端Playwright通过。
- 移动端烟雾：3项通过。
- 支付、退单和退款模拟：15个测试文件、162项通过。
- 构建和lint通过，生产依赖高危审计为0。
- 300个客户旅程、60并发、900请求，错误率0，HTTP P95 28.13ms。
- 岗位页面验证：冷言志只见主吧台制作任务；Tom只见待送商品和一个“已送达”按钮。
- 真实Fastify任务接口验证KDS为`delivered`，原子任务事件和原子审计各1条，并记录请求ID、有效岗位、工位和执行阶段。
- 独立质量监督第二轮驳回6项、第三轮驳回1项；所有问题修正后第四轮复审批准本地候选版本整理。

## 发布边界

- 当前是本地候选版本，尚未提交、合并、打标签或部署阿里云。
- 独立质量监督智能体已批准本地候选代码；此结论不等于已部署、现场验收或商业完成。
- 真实打印机断纸、离线、恢复、补打和分流仍需实机验收。
- 星驿/微信真实支付、退款、物理POS和日结仍为外部阻塞；162项模拟测试不能替代渠道流水。
- 门店弱网、真实员工账号和连续营业高峰仍需现场执行。
- 部署后必须补充提交SHA、镜像摘要、数据库备份、切流、30分钟观察和回滚证据。
