# M-BOX 1.0.0-rc.48 顾客酒水菜单与桌次状态修复

## 本版完成

1. “全部酒水”同时识别菜单分类和酒水类型；历史或导入商品暂时缺少细分类时，不再整页消失。
2. 名称和标签明确的旧商品会自动归入鸡尾酒、啤酒、葡萄酒、起泡酒、洋酒或无酒精分类。
3. 后台新增客人可见酒水时必须选择酒水类型；服务端再次校验，避免错误配置发布后才由客人发现。
4. 桌次令牌过期、翻台失效、未开台或交接冻结时，不再展示可以点击却没有数据的菜单，只显示明确的重新扫码状态。
5. 顾客页面和菜单工作区限制在手机视口内，避免微信内置浏览器切换分类后出现横向空白。

## 数据迁移

- 本版不新增数据库迁移。
- 已有商品数据不被批量改写；前端兼容读取，后续管理员保存商品时由服务端按确定规则归类。
- 客人不可见的套餐组成商品允许保持未分类，不会错误出现在对客菜单。

## 发布验证

- 132个测试文件、978项单元和集成测试通过。
- 32条浏览器端到端流程全部通过，覆盖跨客户端流转、预约、打印、顾客点单、岗位权限和移动端布局。
- 顾客销售路径覆盖正常推荐、酒水分类、初始过期桌次、已打开菜单随后失效、服务入口和快速推荐。
- 微信Android模拟环境宽度430px，点击酒水前后页面宽度一致，无横向溢出，显示46个可见酒水商品。
- 生产构建成功，生产依赖审计0项漏洞。
- 浏览器测试端口支持按支线配置，多工作区并行时不会因固定端口互相中断。

## 发布边界

本版修复客户点单的P0展示故障，但仍是门店验证版本。真实微信/星驿支付、退款、打印机、KDS设备和门店岗位验收仍按商业化清单执行，不因本次修复自动视为完成。
