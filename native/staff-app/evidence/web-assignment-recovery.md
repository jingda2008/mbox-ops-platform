# 网页责任桌原请求恢复

更新时间：2026-09-27 19:13 CST。本批在原生 App 配套 guarded 责任接口上补齐网页恢复。未部署、未生产写入，未提交或发布安装包。

## 问题和实现

本地保存的主线 origin/main（1a9c5851，rc.242 合并）以及当前开发树的原网页责任安排都使用通用 command：重试生成新键，结束责任还重新计算结束时间。此前未改网页业务代码的说明属于上一批记录，本批针对这一缺口修改网页恢复逻辑，不重构原网页布局。

- 服务器 options 新增可忽略的 currentEmployeeId，与 guarded 能力一起启用；旧客户端不需要新参数，旧路由/正文/状态码仍保留。旧服务器没有能力字段时，网页保持原流程，不强制使用不存在的新接口。
- 增强协议提交前将原员工、路径、键、完整正文、结束时间及确认状态保存在 sessionStorage；保存失败不发送。每个浏览器页签仅允许一笔未决责任操作，重复点击共用请求，未知时禁止改桌台、人员、时间或换键重提。
- 刷新页面、重新登录同一员工后，可从“恢复原责任操作”继续；不同员工不能重放。已经结束、从当前责任列表消失的记录仍能恢复原回执。
- 成功回执逐桌验证原桌台集合、人员/岗位/类型/原因、时间和创建员工；结束责任绑定原记录与原结束时间。错回执保留原请求，不宣称成功。
- 服务器成功但确认保存失败时仍按原键查询/重放；已确认但列表读取或存储清理失败时，只补读列表，不再次发送操作。提交前发起的旧读取晚返回也不能清掉新的确认记录。
- 只有 guarded 明确事务未提交的冲突或请求格式拒绝可以释放原记录。普通409、撤权、超时、回退后404等都保留，不降级到旧接口重新执行原请求。
- 保留原操作布局，新增仅异常时出现的提示与恢复按钮；新提交按钮在未决期间禁用。恢复按钮适配360px窄屏、点击高度至少44px、不截断文字。

## 仍有边界

1. WEB-20260927-01 的本地代码及上述浏览器验证完成，正式整合、部署、真实岗位现场验收仍开放。当前开发树基于旧 rc.240；发布必须整合最新生产主线，不能整树覆盖线上。
2. 必须先上线兼容后台再启用网页增强。旧服务器回退期间，已保存的新协议请求仍保留原路径；不能为继续操作而改走旧接口或删除未知请求。
3. 本恢复日志是同源单页签 sessionStorage，覆盖页面刷新及页签内重新登录。关闭页签、浏览器清理存储、换浏览器/设备或部署前已发生且未保存原键的旧请求，不在自动恢复保证内，仍需主管依据服务器记录核对。
4. 本批没有新数据库迁移。前批日常支付涉及的251/252迁移、真实资金/券/打印及原生真机验收继续独立跟踪，不因网页恢复通过而关闭。
5. 会员、库存、未来责任排班、拆并桌和完整出品异常等未完成项保持原台账状态，本批不宣称全功能或营业验收完成。
