# M-BOX 版本管理规则

## 唯一版本链

正式验证版本必须遵循：

`功能分支 -> Pull Request -> CI通过 -> 合并main -> 创建版本标签 -> 标签CI通过 -> GitHub预发布 -> 不可变镜像 -> 候选验证 -> 切换流量`

禁止直接从未合并功能分支发布。云端`/api/ready`返回的`releaseSha`和`releaseImageDigest`必须与发布清单一致。

## 版本编号

- 验证版本使用`1.0.0-rc.N`。
- Git标签必须为`v1.0.0-rc.N`。
- `package.json`、`package-lock.json`、`CHANGELOG.md`和`docs/release-1.0.0-rc.N.md`必须一致。
- 数据库迁移只允许新增连续编号文件，禁止修改已经发布迁移。

## 发布门禁

1. PR CI全部通过。
2. 功能分支已经合并`main`。
3. 版本标签准确指向`main`合并提交。
4. 标签CI完成测试、浏览器流程、数据库验证和容器构建。
5. 部署前创建数据库备份。
6. 候选容器验证通过后才切换入口。
7. 保留上一个应用容器、镜像、环境文件和恢复说明。
8. 发布后记录外网健康检查、5xx、致命错误和真实岗位登录结果。

## 回滚原则

- 应用故障优先切回旧容器，不删除新版本产生的经营事实。
- 数据库迁移保持向前兼容；只有数据损坏且经负责人批准时才执行备份恢复。
- 支付、退款和库存事实不得通过覆盖数据库伪造回滚。

## GitHub限制

当前私有仓库套餐无法启用强制分支保护，因此以PR、CI、版本标签门禁和发布操作纪律代替。升级GitHub套餐后，应立即启用`main`分支保护、禁止直接推送、要求CI通过和至少一名审核人批准。
