# M-BOX 1.0.0-rc.78 审计整改候选

## 本版目的

基于2026-08-13两份只读审计报告，统一规范化运行与发布合同，恢复安全和可观测能力，并补齐服务端订单风控、推荐贡献分、预约失败收敛与收银售后工作面。

## 业务修正

- 同桌多人仍可扫码、分别选择并查看本桌已点；跨设备重复相同篮子由服务端要求确认。
- 客户和整桌限频由服务端事务执行，默认分别为每分钟5单和20单，可通过部署配置调整。
- 推荐排序使用服务端脱敏贡献分，不向客户暴露商品成本。
- 无效预约和续签失败不再持续轮询；申请回执保留，客户可以手动刷新或联系门店。
- 待确认预约不显示到店保留倒计时；只有已确认预约到达约定时间后启动10分钟保留。
- 收银与退款页面可按桌号、订单、支付或退款编号查询，显示原商品和剩余可退额。
- 退款继续执行异人审批；线上退款不允许员工手工标记成功，现金和POS必须登记独立凭证。
- 客户订单只有服务端确认成功后才清空购物车；失败时按当前桌次保留，翻台后新客不会继承上一桌商品。
- 退款网络结果不确定时复用同一请求内容和幂等键，避免重复退款；人工退款结果增加明确二次确认。

## 技术修正

- 默认开发、构建、启动、Docker镜像和阿里云发布统一为规范化运行时。
- 增加validation与production部署档，生产档对支付、库存和worker失败关闭。
- 恢复安全响应头、私有指标接口、数据库连接池指标和选择性SLS采集。
- readiness收敛为一次数据库访问，避免数据库延迟被串行放大。
- AI中继容器增加健康检查。
- 门店配置和商品目录改为单一数据库事务发布，失败时整体回滚。
- 发布证据、运行提交和镜像摘要建立强一致校验；回滚先恢复并验证旧容器，再切回流量。

## 明确未完成

- 星驿/微信真实支付、退款、回调、查单、撤销和日终对账。
- 实体POS、打印机、耳机、摄像头、微信小程序和公众号现场联调。
- 现金退款、POS退款和13个真实岗位员工的现场验收。
- 防重和限频目前是部署级配置，尚未进入店长后台动态配置页。
- 213条经营基线仍有196条未执行、17条阻塞；加上质量补充门禁后共有245项尚未达到商业发布条件。

## 放行边界

本版通过自动化、PostgreSQL、浏览器、性能和部署后核对后，只作为阿里云开发验证版本。不得据此宣称真实资金链或完整商业验收完成。
