# M-BOX 1.0.0-rc.60 推荐与收银售后升级

## 收银与售后

- 员工协助点单可明确选择“立即付款”或“挂单消费”。
- 立即付款继续创建桌边支付入口；挂单消费直接进入出品，但保留桌账应收，未收清前不能结台。
- 退款申请必须选择订单和应收处理结果，并继续执行人工审批、申请人与审批人分离、额度校验和渠道确认。
- 对“保留订单与出品、退款后恢复待收”的售后场景，系统只恢复原退款商品和金额，并把新收款单关联到原退款。
- 同一退款不能并发创建多笔有效重收单；失败或过期后可以重新发起。
- 重收成功前不能结台，重收成功后桌账恢复平衡。

## 快速选择问题

快速选择的答案已经进入推荐评分，但三款对比区域随后按低、中、高价格重新挑选商品，覆盖了评分第一名。不同答案因此可能继续显示相同的主推和相同的三款商品。

## 修复

- 合格候选仍先经过启用、客户可见、人数、可售状态、成本毛利和履约校验。
- 快速选择与开台同行场景继续改变规则评分。
- 三款对比区域必须把评分最高的合格组合显示为“人气优选”。
- 在主推商品价格以下存在合格商品时，优先保留不同酒型的轻量比较款。
- 只有后台明确配置的升级商品才能标记为“更完整”；其他商品只作为酒型或预算替代。
- 候选不足时保持原有安全降级，不凭空生成商品或营销优惠。

## 当前门店商品复算

- 2位、轻松一点、清爽好入口、听完这一场：主推“双人啤酒现场”。
- 2位、来点仪式感、慢慢喝有层次、今晚不赶时间：主推“双人开瓶主场”。
- 2位、今晚要嗨、酒感明显一点、多待一会：主推“双人开瓶主场”，两侧比较商品随评分变化。

这些结果来自当前门店已发布商品的价格、成本和推荐标签，不改写商品资料。

## 数据与发布边界

- 本版本没有数据库结构迁移。
- 不修改已有订单、支付、退款、库存、预约和桌次。
- 不自动执行退款；退款和重新收款均保留人工确认、权限和审计边界。
- 不自动修改后台商品标签；后续标签调整仍通过商品配置发布。
- 发布到阿里云验证环境，异常时按不可变镜像回滚至`v1.0.0-rc.59`。
