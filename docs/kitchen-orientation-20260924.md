# 后厨横竖屏适配

更新时间：2026-09-24 21:26 CST。本地候选，未提交、合并或部署；保留此前SYS-379/380修复。

问题：此前以760px宽度为主要分界。768px宽的竖屏平板仍进入横向双栏，窄屏则把两个620px面板上下堆放，主操作需要长距离滚动。

处理：
- 横屏保留左待制作、右制作中，两个工序同时显示。
- 竖屏（包括768宽平板）及窄屏使用待制作/制作中切换，当前工序全宽显示；搜索独立一行，底部主按钮留在可视面板底部，内部队列/详情独立滚动。
- 切换按钮已显示工序和份数，不再重复显示竖屏面板标题。
- 两个面板一直挂载，只切换显示；旋转、切换和搜索不清空批次、份数或待核操作。开做成功后进入制作中。
- 修正刚开做时客户端时钟采样早于开始时间所致的短暂“-1分钟”显示，仅将显示下限限制为0，不改变计时事实或业务数据。
- 后厨与吧台共用制作组件，因此同样的方向适配也适用于酒水制作屏。未改动取餐业务、权限、幂等或数据库。

验证：
- 3项真实隔离浏览器业务用例，竖屏768×1024、600×960、390×844开做2份，修改本次完成为1份，切换工序与搜索，旋转为1024×552横屏再转回。选择仍为1份，最终只备齐1份，另1份仍制作中，没有伪造送达。
- 3项已有三屏布局回归通过，覆盖1024宽×480/552/600/768高，长备注、异常提示、按钮命中与全屏。
- 本轮合计6项浏览器通过；187项相关单测、前端类型及正式构建通过。
- 按钮至少44px，测试确认可见且可命中，无水平页面溢出。实际Android设备旋转与软键盘仍需以后发布后实机验证。
