# 最低消费双模式操作说明

本次版本：1.0.0-rc.274。后台已部署，微信开发版已上传；本次微信版本尚未正式发布，使用范围与验收状态见[发布核验](release-1.0.0-rc.274.md)。

## 开台

在开台表单选择“最低消费方式”，填写“本次开台最低消费（元）”，最多两位小数。不填或填0不设金额门槛。已开桌不会自动补设最低消费。

- **提交时达标**：本桌已生效的优惠前商品金额加本次购物车达到门槛，才允许提交；不足显示还差金额并保留购物车。达到后可以继续小额追加。
- **先预收款，分次点单**：先收足开台所设的预收金额，付款人明确同意本桌共享后，同桌客人可分批点单。商品订单按优惠后的实际应付扣减共享款。余额不足时提示补充，明确同意并补款后重试，保留购物车。

## 优惠、退菜及多人点单

达标按有效商品的优惠前金额计算，会员优惠、优惠券和积分抵扣不抬高差额。赠品及独立积分兑换不计入。批准退菜减少有效消费，拆退套餐按确认保留商品原单价累计；仅价格补偿不删除商品消费。

多人可以共同预付、共同点单；每笔消费保留各原付款来源，竞争余额时只有余额足够的订单提交成功，不透支。付款人可撤销尚未消费部分的未来共享授权，已消费历史保留。

退菜资金按原付款退回，不恢复已经消费的共享余额。若要继续点单且余额不足，需要另行明确补款；界面成功提示不等于支付渠道已经到账。

例如门槛300元，商品原价300元、优惠后240元，按已确认的优惠前口径已达标；若预收300元，可以申请原路退回优惠形成的60元结余。商品原价仅240元则仍未达标，需继续点单或授权减免后处理结余。最低商品消费额因此不等于最低现金实收额。

## 结束与退款

进入“本桌预收款结算”。达到门槛且没有待确认付款、待完成退菜时，有全店桌台及退款申请权限的员工填写原因，申请退回未消费余额；另一名有复核权限的员工复核，再由有执行权限的员工原路退款。退款失败或处理中，查询原退款，避免另发一笔。

**差额收费保持关闭。** 未达标时继续点单，或由有权限人员填写原因、在累计审批额度内记录门槛减免；没有处理完成的留在财务待办。系统不会把预收余额自动当作差额收入，也不会自动扣收差额。

“预收款与往期结算”可处理已释放桌位的旧桌次，并可加载更早的记录。释放桌位不代表资金结清，新开桌与旧桌资金分开，迟到付款仍归旧桌次。

## 转桌

整桌转桌保留同一桌次、原门槛、累计消费和资金来源。人员换桌、物理合坐继续保持各自独立桌次账；此版本不提供财务合账、拆账或自动搬移预收款。

## 版本边界

收费适用依据由门店核实。微信开发版上传、微信审核及正式发布、真机实际收退和现场打印分别验收。产生真实预收款后，不能直接回退到不识别此类资金的旧版本，应保留原资金记录并修复后向前发布。
