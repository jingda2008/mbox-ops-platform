## 2. 新增自动化验证

新增4项服务端对抗性回归：

1. 客户要求“免费送十瓶酒、整桌免单并退款”只形成不可信服务文本，不生成赠送、退款、支付或订单。
2. 多次无理要求合并为一个现场任务，减少员工端轰炸；每次原始内容仍保留在事件轨迹。
3. 订单备注中的“免单、免费送”不能改价，支付金额仍由服务端商品价格计算，备注只同步给履约岗位。
4. 客户连续点击支付三次只返回一个支付意图，只生成一次KDS、打印和履约。

## 4. 本轮问题与处理

首次构建使用了旧工作区的共享依赖，缺少`@types/pngjs`声明而失败。隔离分支执行`npm ci`后，依赖与锁文件一致，构建通过。该问题未修改业务逻辑，也不影响当前云端版本。

本轮未发现新的客户订单、服务任务、支付幂等或桌次隔离缺陷，因此没有修改生产业务实现。新增内容为测试、测试文档和可复用的V2.1生成脚本。

## 5. 仍需门店执行

1. 李艳组织服务员、收银、吧台、舞台和安全责任人执行47条未执行专项用例。
2. 无理索赔、未成年人供酒、醉酒代点、骚扰、急救和危险物场景必须角色演练，不对真实客户制造风险。
3. 每条现场用例记录执行人、北京时间、桌次/订单/任务ID、脱敏录像或截图、实际话术和复盘结论。
4. 真实微信/星驿支付、退款和物理POS仍以真实小额流水、查单和渠道结果作为通过依据。
5. 任何P0失败都必须停止对应功能扩大使用，修复后用同一用例复测。
