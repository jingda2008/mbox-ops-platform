# M-BOX 店长 AI 自然语言命令验收基线

文档版本：`1.0.0-rc.43`  
测试角色：李艳（店长，`store` 数据范围）  
测试时区：`Asia/Shanghai`，营业日 06:00 切换  
目标：验证店长命令能否被正确识别、追问、授权、执行、派发、闭环和审计，禁止“AI说完成但业务状态未变化”。

## 1. 判定规则

1. `识别通过`：桌台、员工、人数、服务类型、时间和备注全部正确，未猜测缺失信息。
2. `执行通过`：必须返回服务端证据，并在真实桌台、任务或排班状态中查到同一对象。
3. `定时通过`：到点前不可见，到点后只向正确员工派发一次。
4. `人工流程通过`：只打开对应工作台，不得自动退款、收现金、审批、转桌、结台、关账或发布配置。
5. `拒绝通过`：无权限、对象不存在、状态冲突、信息不足或参数非法时，明确说明具体原因，业务状态不变。
6. `审计通过`：记录执行人、工具、对象、时间、请求哈希和结果证据；不保存 PIN、口令、密钥或完整原始敏感命令。
7. 自动化状态以当次 CI 结果为准；门店噪声、真机麦克风、耳机和真实员工响应仍需现场执行。

## 2. 当前能力边界

| 类型 | 当前能力 | 验收口径 |
|---|---|---|
| 服务端直接执行 | 开台、创建服务任务、定时指派、接单、到桌、完成 | 确认后执行，必须返回真实状态证据 |
| 人工高风险流程 | 退款、POS报送、现金确认、关账、库存审批、权益/折扣审批、结台、转桌 | AI只导航和解释，不得改变业务结果 |
| 模型辅助领域 | 预约、订单取消、出品、库存写入、演出排班、员工权限和配置 | 可回答或带到工作台；没有服务端工具时不得声称完成 |

## 14. 发布门禁与证据

- P0 自动化必须全部通过；任何一次假完成、越权、重复执行或高风险自动操作立即停止发布。
- P1 自动化必须全部通过；真实噪声、耳机和真机项可标记“门店待执行”，但必须指定人员和日期。
- 识别测试至少覆盖：桌号/桌名、英文名/中文读音、阿拉伯数字/中文数字、立即/分钟/半小时/小时。
- 执行测试必须同时保存：AI计划、确认人、执行ID、业务对象ID、状态前后值和审计事件。
- 当前重点命令 `1分钟后让Tom给卡座A上两杯柠檬冰水` 需在每版发布前完成端到端回归。
