# M-BOX 复杂SOP第二阶段 1.0.0-rc.17

## 本次范围

`rc.17`完成第二阶段的第一批可运营能力。所有规则继续使用配置草稿、发布版本、执行快照、幂等键和审计记录，不另建脱离现场任务系统的提醒模块。

## 新增触发事件

- 开始制作、制作完成、送达桌台，可筛选吧台或厨房工作站。
- 客户投诉、生日需求、客户选择心情。
- 原有开台、订单提交、支付成功、服务需求继续兼容。

## 新增判断条件

- 桌次消费金额达到指定值。
- 当前桌次未完成任务达到指定数量。
- 主服务员达到岗位并发任务上限。
- 仍有出品未制作完成或仍未送达。
- 条件在执行开始和每个步骤到期前都会重新判断，条件已失效时自动停止，避免过期提醒。

## 派单和升级

- 每一步可以选择执行岗位，也可以优先指定一名或多名员工。
- 指定员工仍必须具备所选岗位，员工离线、暂停或满负荷时交给现有候补调度。
- 每一步可以覆盖全店服务SLA，分别设置预警、候补接管、经理接管时间。
- 经理接管岗位可配置，不再固定只能使用一个岗位。
- 派单岗位、指定员工、SLA和经理岗位写入任务快照，后续配置变更不会改写进行中的任务。

## 完成验证

- 默认由当前责任员工按接单、到桌、完成流程闭环。
- 可要求必须由指定岗位完成，例如投诉只能由值班经理完成。
- 不符合验证岗位的完成动作会留下阻塞执行记录，不能被系统误判为SOP成功。

## 兼容和安全

- `rc.16`及更早的SOP规则不需要重新录入，新字段均有兼容默认值。
- 出品事件直接读取KDS时间戳，不使用前端倒计时作为业务事实。
- 每个触发事件和步骤只执行一次，转桌后继续跟随原桌次。
- 发布前校验工作站、岗位、员工、服务类型和时间先后关系。

## 后续第二批

- 耳机播报、企业微信、服务号和客户小程序消息动作适配器。
- 摄像头抽帧请求、扫码验证和经理独立复核节点。
- 条件分支、并行步骤、失败补偿和人工审批节点。
- 客户会员标签条件需要先完成桌次与会员身份的可靠绑定。

外部通道未取得真实设备或生产参数前，只能进入待联调或失败状态，禁止返回虚假的“发送成功”或“识别成功”。
