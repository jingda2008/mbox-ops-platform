# M-BOX 复杂 SOP 引擎 1.0.0-rc.16

## 目标

把“开台后15分钟提醒、30分钟复查”从写死计时器升级为版本化经营规则。店长或管理员可在后台配置，发布后由系统自动判断并创建真实服务任务；员工继续使用原任务页面接单、到桌、完成，不增加新的学习路径。

## 已支持能力

| 维度 | 当前能力 |
| --- | --- |
| 触发事件 | 桌台开台、订单提交、支付成功、产生服务需求 |
| 适用范围 | 全店、指定区域、指定桌台 |
| 触发筛选 | 指定服务类型、指定商品品类 |
| 判断条件 | 尚未点单、尚未付款、最低客人数 |
| 多步骤时间 | 从触发事件计时；或等待前一步完成后再计时 |
| 执行动作 | 创建服务任务，指定服务剧本和接单岗位 |
| 自动停止 | 桌次结束、已经点单、已经付款 |
| 派单与兜底 | 复用主责、候补、负载、在线状态、经理接管和 SLA 升级 |
| 状态一致性 | 步骤只执行一次；配置快照可追溯；转桌后跟随同一桌次 |
| 配置治理 | 草稿保存、发布生效、版本历史、回滚、成功或失败提示 |

## 后台操作

入口：`配置` → `复杂SOP规则`。

1. 点击“新增SOP”，填写名称、触发事件和适用区域。
2. 选择条件与停止条件。例如“开台触发、仍未点单、下单后停止”。
3. 配置一个或多个步骤。每步指定等待时间、服务任务、执行岗位和现场指令。
4. 先保存草稿，检查执行预览后再发布。
5. 发布会立即评估当前仍在营业的桌次；已经超过等待时间且条件成立的步骤会马上派单。

## 推荐首批规则

| 规则 | 触发与条件 | 步骤 | 停止条件 |
| --- | --- | --- | --- |
| 入座未点单关怀 | 开台；仍未点单 | 10分钟主动了解需求；前一步完成15分钟后复查 | 下单、结桌 |
| 酒水到桌节奏关怀 | 酒水品类订单提交 | 10分钟确认冰块/柠檬；20分钟关注续杯 | 结桌 |
| 买单后送客 | 支付成功 | 立即提醒核对存酒/随身物品；5分钟后确认送客 | 结桌 |
| 生日服务协同 | 生日服务需求 | 立即通知服务与舞台岗位；前一步完成后确认音乐和礼物 | 结桌 |

## 自动化验收

- 多步骤必须等待前一步真实完成，重复调度不产生重复任务。
- 点单或付款满足停止条件后，未执行步骤自动取消。
- 订单品类筛选只命中对应商品，派单岗位使用规则配置。
- 客人转桌后，后续步骤派到新桌并保留原桌次审计链。
- 旧版本数据自动补齐空 SOP 配置和运行记录，不需要清库。
- 无效区域、桌台、服务类型或岗位引用在保存阶段直接拒绝。

## 后续扩展边界

当前动作类型只允许创建受控服务任务，避免规则直接扣库存、赠送权益、收费或向客户发送未经确认的信息。下一阶段可在同一版本化协议上增加人工审批动作、客户通知、摄像头抽帧请求、权益建议和外部耳机推送；涉及资金、库存和客户权益的动作必须继续经过权限、审批、幂等和审计层。
