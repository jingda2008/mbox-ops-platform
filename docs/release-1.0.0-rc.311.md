# 1.0.0-rc.311 开桌与整桌票排桌并发修复

接待开桌、收银开桌和换桌与门票后台排桌按相同顺序取得门店容量锁和桌锁。遇到已售票需要保留的最后一桌，员工端显示桌位冲突并允许改选。沿用 schema 363，本版无数据库迁移。

现场核对请使用[整桌票验收记录](member-table-tickets-acceptance-20261123.md)。开售由员工按真实场次配置并发布。首场试售前需核对顾客使用的微信版本、真实收退款、逐票积分和同场接待。补丁专项的复现、回归和营业负载数据见[数据库审计](rc310-database-upgrade-audit-20261123.md#开桌排票与普通预订并发复验)。
