# 合并付款实施边界（开发中）

当前仅完成稳定分摊计算及三个测试，尚未提供可用的合付入口。

选定实现方向：一个真实支付尝试指向同桌次收款批次；批次含原订单和不可变分摊，不建立虚假订单，不把一次渠道付款伪装为多次渠道交易。支付记录、查单退避、回调验签、渠道交易唯一性和资金总账继续复用。

实施必须同时覆盖：

1. 支付新增批次目标；批次订单在同一事务按稳定顺序锁定，逐单检查原权限、剩余应收和退款重收授权。
2. 订单付款读取使用分摊事实；资金总账仍只记录一次真实付款。实际晚到多收保留在相关订单核对金额，不扩大销售额。
3. 原退款请求选择原商品，退款明确归属批次内某一原订单；同时约束原付款余额和该订单分摊余额。
4. 逐单履约、积分、推荐归因、优惠和超额退款不得因一个支付ID关联多订单而遗漏或重复。现有积分表单payment_id唯一限制需专门检查，不能盲目复用。
5. 服务端正常支付入口、渠道上下文、回调/主动查询、后台恢复、打印、收银/桌台/顾客订单、历史/日汇总全部读取同一分摊。
6. 新入口只有上述交易与权限回归全部通过才可开放，不以金额相加或仅现金路径冒充完整合付。

此文档是实施记录，不是完成或发布证明。
