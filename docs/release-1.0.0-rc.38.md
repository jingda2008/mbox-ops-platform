# M-BOX 1.0.0-rc.38 AI能力中心、语音识别与店长下钻

## 目标

解决酒吧高噪声环境中桌号、员工姓名、英文名、菜单商品和连续命令容易识别错误的问题。语音仍然只负责输入和理解，所有权限、确认、审计与业务执行继续复用统一 AI 可执行能力中心。

## 本轮升级

- Google Speech-to-Text 改用简体中文明确支持的增强版 `command_and_search` 短指令模型。
- 云端最多返回 8 个转写候选，由门店动态词典二次排序。
- 相近候选无法可靠区分时不自动猜测，员工点击正确语句后再进入确认流程。
- 浏览器原生识别会累积多段最终结果，不再只保留最后一句。
- 云端启用时，PC、安卓和微信网页统一优先使用增强识别；不可录音时仍保留原生识别或文字输入。
- 云端识别异常时，有本机识别能力的设备会在下一次点击时自动降级，不阻断员工操作。
- 动态热词上限从 180 条提升到 Google V1 单次请求允许的 5000 条，并受 10 万字节编码预算保护。
- AI 可执行能力中心统一登记服务端执行与人工审计工作流；退款继续要求人工核对、审批和留痕。
- “退单”会先确认是否已付款；折扣审批和会员权益审批进入各自正确工作台。
- 店长可从首页、巡场任务和出品数字直接进入对应 SLA、预约与 KDS 待办。

## 动态词典范围

- 全部门店桌号、桌名、区域及字母数字常见读法。
- 全部员工姓名、英文名中文读法、岗位和当班选项。
- 全部菜单商品、SKU、规格、分类、标签、酒水和菜品名称。
- 全部服务类型、工作站、歌手、当天歌单及页面可执行控件。
- 开台、转桌、点单、出品、预约、点歌、库存、赠送、收款、退款申请、延时任务和人员指派等常用运营表达。
- AI 可执行能力中心中管理员配置并启用的自然语言别名。

后台新增或修改以上资料后，下次进入语音模式自动使用最新词典，不需要重新发布前端代码。

## 风险控制

- 低置信度且未命中门店词典的内容不会自动进入执行。
- 多个桌号或人名得分接近时必须人工选择。
- 退款、现金确认、关账和审批等高风险能力仍只能进入人工审计工作流。
- 音频仅用于本次临时转写，不写入经营状态；PIN、Token、付款码和客户隐私备注不进入语音词典。
