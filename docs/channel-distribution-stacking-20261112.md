# 渠道优惠叠加开关与客组总上限

最后更新：`2026-11-12 23:37 CST`。本地候选迁移306—313；未部署、上传、修改生产或操作真实资金。

## 配置与操作

- 推广批次新增“允许同客组渠道优惠叠加”，默认关闭；遗漏字段的旧请求也按关闭处理。
- 开启后显示“本次客组总优惠上限（元，可留空）”。填写值必须为0.01元至1000万元；内部使用整数分。留空不加客组金额封顶，仍受每券上限、客组次数和商品金额约束。
- 关闭时本次连续客组只能绑定一张有效渠道券，即使L设置大于1也不能叠加。未兑现原券可按原撤销流程换券；已使用不能撤销换取额度。仅领取多张不等于能够同时使用。
- 同一客组的多券须来自同一推荐人、同一活动，且原客组与新券都允许叠加。每券封顶、L和本次客组总上限同时生效；跨批次取更严规则，不能提高已锁定的客组上限，撤销未用券也不放宽已锁定的上限。
- 后台配置、员工核验页、顾客预览/本人券包、推广图显示对应规则。员工当前桌信息展示客组实际锁定开关、总上限和已占用优惠。
- 这次开关针对渠道券之间的叠加，不开放与会员券、会员卡价、积分价格混用。

## 金额与异常处理

- 总优惠包含金额券、百分比减免，以及赠品按正常售价形成的减免；赠品档案成本只用于活动成本承诺，不当作顾客优惠金额。
- 例：两张八五折券，总上限40元。先消费100元，合计减30元；转桌再消费100元，最多再减10元。两单实付70元、90元。退款20元后净收140元、10%佣金14元，已用40元额度不恢复。
- 赠品正常售价10元，剩余总优惠只有5元时不能拆成半份赠品或额外收款；整个赠品操作回滚，原券与预留库存保留。可以由员工按原异常流程取得顾客同意后替换，或核对原消费。先赠送10元后，15元总上限仅剩5元给其他优惠。
- 转桌、拆桌、续台均沿用原客组。两个拆分桌并发下单只能共同消费剩余额度；旧报价须重新核对，不能超额。
- 只有未付款、未出品、未扣库的整单撤销，才释放该单优惠占用，重复释放无效。付款/出品后的退款不恢复已兑现额度。
- 新券总上限低于或等于本组已用金额时拒绝新绑定；已有原绑定回执仍能读取，不按新请求再扣次数。

## 实现

- `channelRuleSchema` 增加默认false的 `allowStacking` 和默认null的 `visitDiscountCapMinor`，关闭叠加却传金额上限会被拒绝。
- 新迁移313将开关与上限锁在 `channel_visits`，数据库触发器禁止已锁定策略放宽。新批次规则仍为不可变快照。
- 实际报价与最终价格授权共用客组剩余额度，金额优惠与赠品两条出品路径都检查；报价摘要含客组额度，另一桌/赠品占用后旧报价失效。
- 按全部历史绑定的优惠累计占用计算，防止顾客离桌、换券或更换商品绕过已用金额；复用原未付未出品撤单释放账。
- 迁移不重写旧批次快照。已有多张有效绑定的历史客组保留已绑定承诺（迁移标记可叠加、无新增总封顶），新的绑定仍核验新券开关；已有单券客组默认不叠加。新建临时库迁移链已验证，真实历史数据回填需未来获授权发布前只读核对，不声称已在生产验收。
