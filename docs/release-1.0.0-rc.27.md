# M-Box 1.0.0-rc.27 验证发布说明

## 本次修复

- 员工端快照轮询改为单飞请求：上一轮尚未完成时不再叠加下一轮，网络或数据库变慢时不会形成请求堆积。
- PostgreSQL写入成功后直接复用已提交状态，避免写操作结束后立刻再次读取整份经营数据。
- 经营状态内存缓存校验窗口调整为可配置项`MBOX_STATE_READ_CACHE_MS`，验证环境设为3秒。
- 工作台使用按岗位可见内容生成的稳定ETag；员工心跳只更新租约时间时返回304，不再触发全店下载和渲染约150KB快照。
- ETag采用递归键排序后的规范哈希，避免PostgreSQL JSONB重排对象键造成虚假变化。

## 性能验证

- 候选修订中，无变化工作台请求返回304、响应体0字节。
- 员工心跳成功写入后，下一次工作台请求仍返回304、响应体0字节；真正的员工在线变化和经营数据变化仍会更新。
- 同一设备的并发快照请求上限为1；失败后可以自动恢复下一轮轮询。
- 本地300人次负载测试共900个HTTP请求、1200项检查，失败率0%，HTTP p95为57.87毫秒。
- Google Cloud验证环境仍使用`db-f1-micro`且上海访问存在公网链路延迟；需要持久化的写操作仍可能约1至3秒，本版本不通过提前宣告成功绕过业务提交。

## 验证结果

- 小程序静态检查：56个文件通过。
- Vitest：109个测试文件、776项测试全部通过。
- Playwright：12项跨客户端、岗位权限、iPhone 14 Pro Max布局、客户情绪即时反馈和安全响应测试全部通过。
- Cloud Run修订：`mbox-ops-validation-rc27-fastread3`，承载100%验证流量；`mbox-ops-validation-rc26-instant`保留0%流量用于回退。
- 候选修订切流前5xx为0，心跳后304与0字节响应已在云端真实PostgreSQL环境验证。
- 213条经营TC基线仍为147条通过、50条未执行、16条阻塞；本版本仍是验证发布，不改变商业生产门禁。
