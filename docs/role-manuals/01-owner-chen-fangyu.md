# 陈方宇：老板系统与工作说明书

## 岗位目标

老板负责经营结果、重大风险和最终授权，不替代店长处理每一个普通服务任务。首页重点看营业桌台、SLA风险、待审批、未结桌账和异常趋势。

## 可使用功能

| 页面 | 主要用途 | 什么时候使用 |
|---|---|---|
| 现场 | 看全店桌台、服务风险、转桌和未点单情况 | 高峰巡视、重大投诉、跨区失衡 |
| 任务 | 查看升级、投诉和无人接单任务 | 出现红色风险或店长请求接管 |
| 预约 | 查看预约、定金、迟到、取消和入座 | 大客户、包场、争议预约 |
| 订单/KDS | 查看订单、出品超时、赠送折扣审批 | 大额赠送、异常补做、全店出品拥堵 |
| 库存/存酒 | 看库存、盘点、调整、存酒风险 | 日结差异、重大损耗、盘点审批 |
| 收银/支付 | 看收款、退款、待对账和日结 | 大额退款、重复扣款、账实不符 |
| 会员权益 | 审批权益、活动召回和通知结果 | 高价值客户关怀、批量活动 |
| 演出/点歌 | 查看排班、点歌和退款 | 重大演出调整、点歌争议 |
| 布局 | 看桌台、开台、换桌和低消 | 特殊接待、容量冲突 |
| 主数据/配置 | 查看和批准人员、权限、商品、规则版本 | 低频治理，不在营业高峰随意修改 |

## 每日工作

开店前：确认店长、运营负责人、收银和系统管理员已完成检查；只处理需要最终决定的缺口。  
营业中：关注P0/P1、重大投诉、大额授权和异常损耗，不代替一线员工清任务。  
关店后：查看支付、退款、POS、库存、权益和投诉差异；决定通过、限期整改或停止扩大验证。

## 重大风险处理案例

案例：客人说微信已扣款，但系统仍显示处理中。

1. 不让收银员再次收款，也不手工改成成功。
2. 三沐保留桌号、金额、时间、支付意图和客人支付截图。
3. 李艳组织查单；乌鸦保留请求ID和日志。
4. 渠道确认成功才补齐回执；确认失败后才能重新支付。
5. 如存在重复扣款，立即按P0处理并保留全部证据。

## 禁止事项

- 不用老板权限替员工绕过正常审批。
- 不直接修改数据库或让技术删除异常记录。
- 不在没有支付事实时批准关台。
- 不把日常门迎、制作、取送变成老板固定工作。
