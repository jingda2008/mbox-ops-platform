# M-BOX 1.0.0-rc.68 性能、反馈与质量证据升级

## 目标

本候选重点修复高峰时每次操作都读取或写回整店聚合数据造成的长尾延迟，并把运行指标、TC真实覆盖度和独立质量复审纳入发布门禁。它不改变支付审批、库存事实或责任权限。

## P1整改

- 员工心跳写入独立租约表，不再改写整店revision；登录、退出和真实在线状态变化仍保留审计。
- 心跳权限校验使用轻量员工目录与租约，不再为每次心跳读取并克隆约7MB整店状态。
- 进程启动一次性载入租约，避免逐员工连接数据库。
- 中国时间转换复用格式化器，消除工作区投影中的重复高成本对象创建。
- 预约接口复用已鉴权状态，避免同一请求重复读取聚合数据。
- 同一匿名客人、同一桌次的会话轮询只持久化一次到访事件；并发请求合并，数据库幂等约束继续兜底。
- 重复点击已完成任务返回权威终态，不因旧页面或网络重试退回原状态。
- 员工首屏先展示工作区，非关键初始心跳延后执行；关键按钮保留即时反馈和失败恢复。

## 可观测性与指标

- 增加低基数规范化路由请求计数和延迟直方图，不把业务ID或令牌写入标签。
- 就绪探针公开数据库延迟、连接池总数/空闲/等待和变更队列状态。
- 增加历史日志分析工具，输出每条规范化路由的样本量、P50、P95、P99、最大值、状态码和关键错误信号。
- 指标目标和样本门槛见`docs/runtime-quality-standards.md`；样本不足不得判定通过。

## TC质量管理

- 保留213条经营基线和原始通过条件。
- 将“验收状态”和“工程覆盖度”分开，明确外部依赖、代码支持待现场验证、部分实现和真实能力缺口。
- 当前登记有207条经营验收阻断和23条质量补充阻断，共230条未通过商业发布门禁；验证版本上线不能替代真实支付、打印、弱网、应急和连续营业验收。

## 数据库

- 新增迁移`023_staff_presence_leases.sql`，按租户和门店隔离员工在线租约并强制RLS。
- 不迁移旧测试业务数据；部署候选前必须执行迁移并验证表、策略和索引。

## 发布边界

- 当前文档描述候选目标，不等于已部署或已通过复审。
- 只有全量检查、浏览器与压力测试、独立质量复审、不可变镜像候选验证、切流后指标和回滚证据全部通过，才允许替换`rc.67`验证环境。
- 商业生产还需真实支付退款、物理打印、弱网和连续至少3个真实营业晚班达到SLA。

## 验证结果

- 当前本地`npm run check`通过：147个测试文件、1158项测试，以及lint、TC一致性、TypeScript、生产构建和确定性种子校验均通过；移动端关键浏览器冒烟3/3通过。
- 最新不可变CI为PR #62运行`31332057352`：质量、数据库、浏览器业务流程和七个独立性能阶段均完成；员工/客户页面双帧P95为386.1/372.0ms并通过，但性能资源门禁失败，发布结论仍为`DENY`。
- 员工启动两个实例事件循环P99为103.3/102.0ms；KDS完成为146.1/143.5ms，一个实例写队列等待P95为125.4ms、写服务P95为591.0ms。各实例连接池获取P95仍低于0.1ms，不支持通过扩大连接池解决。
- 当前本地候选使用数据库事务级共享/独占门和`updated_at`共同约束全实例750ms安静窗口，配置15秒后允许强制执行，并在聚合克隆后让出事件循环。15秒是强制阈值，不是已经证明的端到端延迟上限；实际延迟还包含最长2秒调度tick、数据库等待和提交时间。2次/秒KDS完成300/300、客户端P95 231.5ms，队列等待P95约0.02ms，事件循环P99最高96.0ms；后台调度仍执行5次。
- 同一候选员工启动API旅程120/120、P95 98.2ms；30个新浏览器上下文双帧P95 94.8ms，事件循环P99最高27.6ms。以上本地结果须由下一提交CI复现，不能提前改变CAP状态。
- 同一候选的5次/秒KDS容量探针300/300成功，客户端P95 171.9ms、队列等待P95约0.01ms、事件循环P99最高83.5ms；该轮没有到期调度写，只能作为`CAP-018`候选证据，不能替代`CAP-019`。
- 压测启动器现在会在测量结束前再次核对源码指纹；运行中代码或测试工具变化会保留诊断数据但拒绝作为发布证据。通用TC登记分别记录执行状态和制品状态，避免`artifact_missing`被误写成未测试。
- 5次/秒KDS容量探针、三轮完整重复、多营业日增长、真实设备/微信弱网、星驿真实支付退款、物理打印和连续3个营业晚班仍未通过。
- 质量总账已在失败CI中正确生成并尝试上传，但GitHub Actions制品额度耗尽，运行与质量制品均未归档；`CAP-013`继续失败，需授权清理旧制品或配置替代不可变存储。
