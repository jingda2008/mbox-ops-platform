# M-BOX 多维系统审计 1.0.0-rc.77

审计日期：2026-08-13  
时区：Asia/Shanghai  
审计对象：规范化开发验证系统

## 判定口径

- **通过**：当前候选有可重复的自动化或只读运行证据。
- **待现场验收**：代码具备能力，但必须由真实岗位、设备和门店网络验证。
- **能力缺口**：业务要求尚未形成完整可操作闭环。
- **外部阻塞**：需要支付机构、物理POS、打印机或其他硬件。

## 本轮修复证据

1. 过滤后无出品任务时显示明确空状态，并增加组件用例覆盖全为`false`的条件子节点。
2. 320像素视口的推荐商品增加44像素直接加购入口，自动验证其不被底部结算栏遮挡。
3. 单一搜索结果改为完整内容宽度，避免半屏空白。
4. 搜索清除、数量步进器、购物车关闭按钮扩大到44像素。
5. 顾客、预约、员工现场和员工后台补齐一级标题或可访问标题。
6. 修正顾客辅助文字、预约步骤与偏好说明、员工辅助文字的严重颜色对比度问题。
7. 修正独立临时数据库压测结束时强行结台导致的事务失败误报；共享测试环境仍保留会话清理，整库销毁的隔离测试不再执行无意义结台。

## 性能证据

2026-08-13在全新临时数据库完成40版迁移和门店初始化后，以真实HTTP持续执行每类60秒、5 RPS负载：

| 场景 | 错误率 | P95 | P99 | 最终积压 |
|---|---:|---:|---:|---:|
| 开台 | 0 | 21.03ms | 23.84ms | 0 |
| 下单 | 0 | 42.49ms | 44.38ms | 0 |
| KDS开始与完成 | 0 | 37.18ms | 39.05ms | 0 |
| 服务任务全流程 | 0 | 18.04ms | 19.69ms | 0 |

- 连接池获取等待P95为0.05ms、P99为0.10ms，获取失败0，结束等待客户端0。
- 数据库事务P95为15.46ms、P99为20.62ms，事务失败0；查询失败0。
- KDS重复领取0、状态不一致0，幂等未知冲突0。
- 员工真实浏览器启动30次P95为76.4ms，顾客会话启动30次P95为48.4ms，均无失败。
- 以上是开发机隔离环境证据，不能替代300人、门店网络和低端手机的真实晚高峰验收。

## 不能被本轮测试替代的事项

1. 真实微信/星驿支付、退款、撤销、对账和物理POS异常演练。
2. 两台真实打印机分流、断纸、离线、补打及纸单与电子KDS一致性。
3. 真实BOM、期初库存、盘点、损耗、批次采购价和闭店成本核对。
4. 12名员工及老板在真实手机、平板、收银PC和门店网络执行岗位TC。
5. 连续至少3个真实营业晚班的服务SLA、出品时效、人员负荷和300人峰值。
6. 企业微信、公众号、小程序、短信或微信通知的真实送达与失败补偿。

## 发布判断

**允许验证环境部署，不允许商业生产发布。** 任何报告不得把“代码测试通过”“模拟支付待确认”或“界面存在入口”改写为真实经营闭环已完成。
