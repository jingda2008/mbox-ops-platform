# M-BOX第四阶段设备中台 1.0.0-rc.21

## 阶段目标

在真实硬件到店前完成可测试的设备接入骨架，让摄像头、耳机、打印机、扫码器和边缘计算节点以后只需增加适配器，不改订单、SOP、AI值班经理、权限和审计主流程。本阶段是模拟联调版本，不代表任何真实设备已经接通。

## 已完成

- 统一设备主数据：设备类型、适配器、启停状态、区域、桌台、档口、能力和Secret逻辑引用均可配置。
- 统一健康模型：心跳正常、降级、离线、未配置和禁用状态；预警时间和离线时间可配置。
- 统一命令模型：摄像头关键窗口抽帧、耳机试播、打印测试、扫码测试和边缘节点健康检查。
- 关键事件证据窗口：默认取事件前后各30秒，可配置5至60秒；证据保留时间可配置。
- 故障降级：设备不可用时保留核心业务任务，并强制发送系统内通知；可选企业微信通道。
- 权限隔离：老板、运营负责人和系统管理员可管理；店长、技术岗位可查看和联调；无权限岗位不能修改设备配置。
- AI值班经理联动：设备异常、命令失败和未配置进入风险简报，不由模型直接修改业务状态。
- 全量审计与幂等：配置、心跳、模拟状态和命令均记录操作者、时间、原因和幂等键。

## 模拟器边界

- 模拟器不会访问真实摄像头、打印机、耳机或扫码器。
- 模拟命令必须显示“模拟”，模拟抽帧固定`verified=false`，不能被标记为真实视觉验证。
- 真实设备缺失时命令状态为`unconfigured`，系统保留任务并降级通知，不能伪报成功。
- 连接配置只保存Secret Manager逻辑名称或通道名称，运行状态禁止写入口令、令牌和设备密码。

## 真实硬件到店后的接入顺序

1. 摄像头：确认现有NVR品牌、ONVIF/RTSP能力、通道号、时间同步和桌台视角，优先从NVR取流。
2. 耳机：用Android网关或厂商SDK实现员工定向播报、确认回执和离线重试。
3. 打印：用门店局域网打印桥接酒水与小吃档口，验证断纸、离线、重复打印和补打审计。
4. 扫码：验证USB/Bluetooth HID扫码器和Android扫码输入，绑定商品条码与批次入库。
5. 边缘节点：部署事件缓存、抽帧和视觉推理适配器；断网时只缓存最小必要证据，恢复后受控补传。

## 验收结果

- 自动化：103个测试文件、749条测试通过后方可发布本候选版。
- 视觉：430x932和1440x1000视口无横向溢出，设备状态和配置页面可操作，浏览器控制台无错误。
- 经营门禁：213条TC仍以执行登记为准；未执行、阻塞、真实支付和真实硬件项目不会因本阶段开发自动通过。

## 发布结论

`1.0.0-rc.21`只允许用于云端验证和门店影子运行。真实硬件到店后继续完成设备回执、局域网断网、时间同步、隐私告知、数据留存和现场故障演练，才能申请把对应TC改为通过。
