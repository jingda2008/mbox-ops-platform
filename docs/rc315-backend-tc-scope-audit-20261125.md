## 门店交接

1. **值班经理、接待**。确定停写起止时间与交班人，清点在途购票、补款、退款。资金演练须等发布负责人核实员工使用的版本、商户、回调和验收入口，避免用旧版交易充当新版凭证。核实本场桌区、公示和可退时段，挑两张允许全额退款的员工票。指定桌号草稿可在后台核对，实际演练用允许售卖的票档。
2. **员工购票、接待排桌**。用两部员工手机分别验证新会员拒绝后再授权、已有会员直接购买。每张500元票单独入550分，原票可找回；接待可联系购票会员，安排一张与预约时段相符的真实桌，核对同一桌位只有一次占用。留脱敏票号、会员尾号、桌号/预约号和支付流水。
3. **收银、独立复核人**。个人原因用尚未核销入场的一张票，550分在获准餐单抵完。按条款及授权核定分摊（例如顾客500元、门店50元），取得顾客确认，在原餐单收齐，复核人应自动收到唯一待办。原路退票500元。门店原因用另一张票，用完550分后核定由门店承担550元，顾客补0元；复核后原路退500元。两案留顾客确认或承担依据、补款凭证（若有）、唯一复核待办和微信退款成功回执。
4. **财务**。按两个案号核对商户账单、原餐单、各票积分批次和营业日报。余分为零时不得再扣其他批次。补款积分按原餐单锁定版本计算。例如原合格实付为零、补款500元，旧比例得50分，每20元积1分的版本得25分。门店承担金额不作为顾客实付。若已收补款后改判门店承担，再留原补款退回凭证。开新比例时再审批生效日。记录经办人和独立复核人，按实际营业日交接。[门店操作及留证表](table-ticket-store-release-drill-20261124.md)

## 全系统商业门禁

`npm run release:quality-gate` 仍拒绝商业放行。原表是确定性计划表，既不消费本次逐项差异判断，也不凭发布包自动修改现场验收。原要求还包括连续3个真实营业晚班、现场应急与恢复及负责人签收。门店若已有合格凭证，可按原责任人提供索引；历史专项是否适用由原流程审定。两个真机案例验证本次票务资金交接，不能单独替代整店商业放行。上述四项覆盖本次变更需要门店配合的工作。运维负责环境、备份、切换、回退边界和上线后核验。
