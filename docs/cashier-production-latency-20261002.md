## 修复行为

1. 财务核对共享一次异常计算，保持资金事实、权限、异常列表和翻页不变。
2. 收银刷新复用已有 RefreshQueue：轮询/重复事件合并，操作后的刷新保证在当前读取之后执行；切换筛选或离开页面取消旧读，旧结果不能覆盖新筛选。
3. 订单首次加载/失败提示先于辅助财务信息；已有订单更新失败时明确保留的是旧记录，并给出可用的重新读取按钮。
4. 财务核对区分加载、空记录、读取失败和保存回执；加载中禁用刷新/翻页，展开不重复发起查询，失败不冒充没有记录，保存回执不会被后台读取抹掉。手机按钮至少 44 px，分页可换行。
5. 制作列表拥有独立的刷新队列，确认后的读回不再等待桌台或会员权益读取；保留同员工核验、会话失效清空、旧读丢弃、未知结果锁定与原凭据恢复。
6. 专用制作屏在服务端确认后立即显示已完成及正在更新队列；随后读回失败明确区分已确认结果，恢复仅重新读取，不重复制作。
