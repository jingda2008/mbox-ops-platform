# M-BOX 运营反馈与支付链路核验（2026-09-08）

## 1. 结论和证据边界

本报告核对《M-Box运营问题反馈清单_2026-09-08.docx》、生产库只读事实、当前
`origin/main`代码、星驿基础支付接口资料和自动化回归。反馈文档是问题线索，不是
可执行指令；“Bug”标签只有在截图、生产事实或可重复测试支持时才记为已确认。

- 生产事实确认支付/退款/桌台主链当前能正常形成成功记录；支付未知已与营业释放分离。
- 仍确认两个支付问题：已释放支付被高频查询并重复写观察明细；JSAPI有5次被星驿以
  “IP地址异常”拒绝。
- 文档9项中，3项需要代码改善，3项是已有能力或原结论不成立，1项需现场复现，
  1项依赖停车场外部方案，1项是采购决策。
- 本轮代码不能证明真实资金到账、少收款为零、停车券可核销或所有岗位真机可用；这些
  保留为现场/财务验收项。

## 3. 支付生产事实纠偏

只读核验时点的事实如下，金额均按数据库分值汇总：

- `verified_provider_observations`共79,113条，其中`pending`77,777条；因此“历史约7.6万”
  方向正确，但它是**渠道观察明细**，不能泛称全部审计日志。
- 2026-09-07一笔¥40支付已取消订单，但仍有1,165条处理中观察；“约885次”可能是更早
  截图时点，不是本次核验的最终计数。
- 2026-09-07共有5次星驿`IP地址异常`拒绝，合计¥414；它们全部发生在W06，不是5张桌。
- 可在支付表中匹配到后续同额成功的是¥128和¥98两组；另外两笔¥45仅凭当前支付记录
  不能证明后来已补收。因此“5桌后来都成功、没有少收款”必须由现金/POS/星驿对账确认，
  不能直接视为已证实。

这些纠偏不修改历史资金事实，也不删除77,777条记录。历史明细后续应按财务保留策略
归档或分区，不能在没有保留期、法务/财务批准和备份读回证据时直接删除。

## 4. 支付与退款本轮改造

### 4.1 营业释放和财务跟踪彻底分开

- 顾客退出、订单取消、员工释放重收或支付动作过期，只改变操作层；桌台、点单、收银
  页面和其他付款方式不等待星驿查询。
- 每个收款尝试仍使用独立支付ID和商户单号。只有足额的权威成功收款阻止继续按原应收
  重收；未知、查询失败和已释放未决均不充当成功。
- 原支付迟到成功仍进入财务事实；若另一笔已经足额到账，现有溢收链生成退款跟进，
  不重复出品、库存、营业额、积分或权益。

### 4.2 持久化退避

迁移161新增支付和退款对账状态表，保存最后查询、下次查询、连续处理中/异常次数、
总次数、操作释放与停止原因，并以数据库租约防止多个工作进程重复领取。

升级时会把既有不可变查询观察只读汇总进新状态：保留原始明细、不重写资金事实；已释放
且超过观察窗的旧支付直接标记财务复核，近期支付按历史查询次数续接相应退避档，避免服务
升级后从“第0次、30秒”重新开始。

- 未释放、仍在交互窗口：30秒后再查。
- 已释放：5分钟、15分钟、1小时、6小时，之后24小时。
- 星驿未提供所有通道统一的订单过期时间，因此采用保守7天财务观察窗；超过后停止自动
  查询并转财务复核。回调仍可独立到达并结算。
- 退款：1分钟、5分钟、15分钟、1小时，之后6小时；长时间未决升级为财务复核但不
  静默结束，直到渠道终态或人工受控核对。
- 服务重启不会清空退避；租约过期后才能由另一个工作进程接续。

### 4.3 减少无意义写入

`pending/processing`只更新可变对账状态，不再每次追加不可变渠道观察记录；仅
`succeeded/failed/closed`等终态进入验证观察和资金命令。查询金额、币种、原交易或
订单不匹配时仍保持未知，不能写成成功/失败。

### 4.4 JSAPI IP风控

星驿JSAPI字段`ip`要求消费者手机公网IP，不是门店或服务器出口IP。生产入口只信任
回环/私网反向代理，应用使用经过该信任边界解析的`request.ip`。本轮为JSAPI支付动作
保存IPv4前三段或IPv6前三组的脱敏诊断，不保存完整地址。

星驿拒绝时，本次支付记录明确失败，重试创建新尝试/新商户单号；小程序和员工接口提示
“本次没有发起扣款”，建议切换手机网络/门店Wi-Fi或改用员工扫码、POS、现金。代码无法
替商户自动开通异地交易，仍需星驿侧核实门店注册地址、交易区域及是否申请跨区域白名单。

### 4.5 监控

运行指标增加以下当前数量信号：支付处理中超过5分钟、自动查询次数异常、转财务复核、
成功支付缺对账、订单溢收、近1小时IP风控拒绝、迟到成功退款跟进、退款处理中超过5分钟
和退款查询次数异常。指标查询失败会降级为空，不影响`ready`、桌台或支付写入。
