本批为本地候选，未部署生产，未生成真实订单、收款、退款或库存流水。原生平台仍无 A（门店验收完成）项。网页页面本轮未改，既有网页接口保持原路由、方法、请求和回执合同。工作树原有网页及其他业务改动另有历史证据，不能归为本批新增。

## 已实现

1. **前台服务提醒**：两端紧凑服务角标，按员工隔离、任务/桌次/优先级去重；直达原任务，查看不等于完成，撤权/切员工清理。沿用45秒前台刷新；不是APNs/FCM后台推送，也没有声称锁屏能收到。
2. **库存与扫码收货**：物料搜索、低库存、在库/占用/可用数量；相机或手输条码，读取绑定包装量；按员工保存采购草稿。提交时再次核对条码物料与包装量，变更拒绝建单。先建立待验收单，服务端换算数量后再独立确认实物入库。允许零采购成本，但不修改支付金额必须大于零的规则。
3. **商品快速管理**：跨全部销售状态搜索、分页，售罄/恢复、上下架、客人菜单可见性、排序、标准售价及原因。独立价格权限；版本摘要含原更新时间与价格行，锁定原商品后拒绝覆盖其他员工的修改。沿既有后台价格历史，旧订单报价不变。套餐组成/分类维护未迁移。
4. **盘点与报损**：多物料实点草稿按员工保存，记录原数量和数据库观察时间；盘点建单及提交在一个事务完成，另一人审核/驳回。提交前及审核时检查原基准后的库存移动，整件小数、同物料重复、自审及并发变更拒绝。观察基准超过4小时要求重盘；即使刷新列表也不重写草稿基准。报损类型、原因、数量、申请与审核，沿后台既有合理损耗额度决定直接记账或进入待审。
5. **轻量经营概览**：读取原经营报表，按营业日/周/月/季/年查询；分别显示收款、退款、净收款、商品成本、损耗、经营费用及已记录经营利润。保留暂估、未对账、券未结算、缺失成本及后台口径说明，不将未知成本视为0。

库存新命令使用 `/api/native/inventory/...`，商品修改使用 `/api/native/catalog/products/:id`。原网页写入保留原接口。原生命令复用持久化原回执协议，24小时传输缓存删除后仍恢复原结果，重放重新授权并按当前成本权限裁剪回执；已知事务回滚返回明确未提交状态。原生库存路由只开放已交付的查询、收货、盘点与报损操作，不为旧配方/存酒/维护接口自动开放原生别名。没有新增数据库迁移。

客户端复用原待处理请求恢复，库存原回执先落盘再记完成；刷新失败保留原请求。新的管理弹窗在身份/权限变化时关闭。iOS采用原品牌按钮样式，Android补同层级立体按钮、安全区及键盘避让，选择物料返回录入区。
