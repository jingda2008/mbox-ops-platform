# 陈方宇会员查询报表

用户要求在陈方宇账号增加查询功能：会员数量、加入时间、手机号、消费情况和时间（金额、次数）、性别、兴趣卡及类别。

新增 `/staff/member-report`，独立权限 `member.report.view`。仅查询，不包含会员修改、发卡、退款或营销操作。原所有角色权限保持；发布后使用 `scripts/grant-member-report.mjs` 默认预览，核对指定生产账号后通过 `MBOX_APPLY_MEMBER_REPORT=true` 执行幂等、审计授权；配置读回必须包含新权限和入口。

会员数按合并后的账号去重，入会时间取该身份族最早时间；会员号和状态优先使用合并后主账号。入会日期筛选按门店时区与营业日切点（生产 Asia/Shanghai 06:00）。总数包括暂停/关闭会员，列表明确显示状态，删除客户不展示。

金额为该会员名下点单及活动报名的成功收款，扣除截至查询时成功退款（人民币）。分批合并付款使用订单分摊事实，原始支付流水不重复；同桌多次加单计一消费次、每次活动报名计一消费次，全额退款后不计次数。另列有效订单数。消费明细显示所属营业日、首次/末次付款时间和末次退款时间、实收/退款/净额。点单营业日来自订单，活动来自首次成功付款。活动费用和点单金额合计。

未成功付款、模拟付款、明确标记测试/验收的订单与活动排除。未关联会员的员工代点、零现金兑换不计入；订单创建人不一定是付款人，消费次数不是真实到店人数或签到次数。不使用会员缓存累计金额代替权威支付退款事实。

手机号仅从当前有效、未撤销的已核验联系方式读取，支持当前与历史加密封装及完整手机号匹配。解密失败显示暂无法读取，不暴露密文、哈希或密钥；接口和错误响应均 private,no-store，不在浏览器持久化数据。新权限不会因原 OWNER 角色自动授予其他员工。

当前无已采集性别数据，显示未填写，不从姓名推测；本次不新增性别录入。兴趣卡和联名卡分别显示项目名称/类别/状态/有效期，有效兴趣卡筛选只包含 active 且在有效期的持卡，保留冻结/退出/撤销历史。

验证：隔离数据库覆盖身份合并、营业日边界、电话当前与历史加密、权限拒绝、分页、退款/次数、测试支付和兴趣卡状态；手机浏览器验证登录、筛选、明细、刷新及失败恢复。生产只读统计查询123ms，395名会员、393个有效手机号记录，未输出个人资料。具体最终验证结果在任务最终交付及后续记录列明。当前是候选，未发布、未生产授权、未真机验收。
