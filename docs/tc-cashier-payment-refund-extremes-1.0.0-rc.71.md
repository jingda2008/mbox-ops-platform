# M-BOX 收银、支付与退款极端场景验收 V1.0

执行日期：2026-08-12  
适用版本：1.0.0-rc.71 开发工作区  
范围：规范化支付、退款、再次收款、现金、实体POS、对账和并发完整性。  
原则：仅使用模拟通道和隔离PostgreSQL，不制造真实扣款或退款。

## 结论

- 新增19项真实PostgreSQL事务测试，连同规范化数据库测试共88个文件、515项全部通过。
- 修复一个P0缺陷：支付结算查询返回`has_pending`，代码错误读取`hasPending`，导致待支付判断失效和再次收款状态错误。
- 新增数据库唯一约束：同一订单最多存在一个`created`或`pending`收款意图，应用判断失效时数据库仍会阻止重复收款。
- 商品退款、总金额部分退款都必须分配到原订单商品，不能只记录一个脱离商品的金额。
- 这次结果不等于真实微信、星驿、实体POS和现金现场验收通过。

## 退款状态口径

| 状态 | 是否占用可退额度 | 是否记入退款账 | 处理原则 |
|---|---:|---:|---|
| requested | 是 | 否 | 等待有权限且非申请人的员工审批 |
| approved | 是 | 否 | 等待调用渠道或人工退款 |
| processing | 是 | 否 | 渠道未知、超时也留在这里，先查单不得重退 |
| succeeded | 是 | 是 | 终态，重复回调只重放原结果 |
| rejected/cancelled | 否 | 否 | 可更正后创建新退款单 |
| failed | 否 | 否 | 仅用于渠道已明确确认失败；新退款必须使用新单据 |

## 发布门禁

1. 所有资金测试必须使用全新数据库从001迁移到当前版本后执行。
2. 任一超退、重复收款、重复入账、回调金额不一致或账表不平，都必须阻止发布。
3. 硬件和真实支付未接通期间可部署其他功能，但支付界面必须明确处于模拟或未配置状态。
4. 真实渠道联调不得复用生产客户订单，不在代码、日志或测试报告中保存密钥、付款码和完整个人信息。
