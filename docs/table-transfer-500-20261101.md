# B1 转 A8 报 500：根因与本地修复

范围：2026-11-01 生产只读调查；本地分支 `fix/table-transfer-500-20261101` 修复和测试。用户明确禁止部署及修改现场桌台、订单，本轮未执行生产写入、转台、结台、重新开台或资金操作。

## 根因证据

北京时间 21:10:58—21:18:04，原 B1 桌次的转台接口收到 16 次 POST，全部 HTTP 500。A8 原桌次在 21:10:42 关闭，到 21:18:30 才重新开台，因此当时的失败不能解释为 A8 已占用。目标 A8 来自用户描述；接入日志未保存请求体或响应体。

生产只读核对确认：原 B1 桌次登记 `guest_count=2`；第一笔失败时有 3 个有效顾客位置记录，均在 21:04—21:05 建立，直到 21:18:14 该桌次关闭才离开。生产约束 `table_customer_movement_events_check` 要求 `moved_participant_count <= moved_guest_count`，此时条件为 `3 <= 2`，必然失败。

扫码位置记录代表关联账号，并不等同于现场实际人数。扫码入口允许关联账号数量超过人工登记人数；整桌转台会移动全部有效账号，但沿用人工登记人数。两套语义被旧约束错误绑定。

隔离 PostgreSQL、完整迁移至 schema296、受限运行账号、实际 HTTP 转台接口复现：登记 2 人、3 个账号经扫码位置函数建立关联，接口返回 HTTP 500、SQLSTATE `23514`，指向上述同名约束。新增测试修复前失败，原有 53 项测试仍通过。原线上异常响应正文未取得，根因依据是线上历史数据和约束读回，加上同条件确定性复现。

## 修复

- 新增迁移 `297_whole_table_transfer_identity_count.sql`：仅整桌转台允许关联账号数大于登记人数，仍要求非负；拆桌、合台继续要求明确移动人数覆盖选中的账号数。
- 保留登记人数、同一桌次、全部有效账号及其历史位置。订单、付款记录及主服务员不变；旧桌扫码凭证按原规则失效。
- 保留目标桌占用、区域可用、容量／加座说明、位置版本和权限检查，以及幂等和审计规则。
- 未知桌台异常写入脱敏日志：请求编号、SQLSTATE、约束名、路由模板；不记录 SQL 正文、行内容或顾客资料。客户端收到通用错误和查询编号，不再暴露数据库错误正文，也不声称未知失败已回滚。

迁移仅调整约束及 schema 元数据，不回写现场桌次、订单或历史转台事实。应用旧版本也能使用新约束；一旦新约束下存在“账号数大于人数”的真实转台记录，不应直接恢复旧约束，否则校验会失败。该项仅是未来发布时的回退边界，本轮未部署。
