# 旧聚合架构删除矩阵

该清单是删除计划，不是兼容计划。每项只有在替代仓储、契约测试和并发测试通过后才能标记完成。

| 旧能力 | 当前问题 | 替代能力 | 删除门槛 |
| --- | --- | --- | --- |
| `RuntimeRepository.mutate()` | 整店锁、深拷贝、序列化 | 领域仓储与 Unit of Work | 所有生产调用为 0 |
| `PostgresRepository.mutate()` | 全局排队、CAS、整店写入 | 行级事务命令 | 所有领域切换完成 |
| `mutationTail` | 不同桌台相互阻塞 | PostgreSQL 行锁 | 跨桌台并发测试通过 |
| `runtime_states` | 单行整店事实源 | 规范化领域表 | 新数据库不创建该表 |
| `runtime_state_versions` | 记录整店JSON版本 | 领域事件和审计 | 审计查询覆盖完成 |
| `compareAndSwapState` | 整店级冲突 | 目标行版本或条件更新 | 并发冲突测试通过 |
| `PostgresOperationalProjector` | JSON投影和双写 | SQL查询服务 | 查询契约测试通过 |
| `operational_*` | 镜像、Payload重复 | 权威表/必要SQL视图 | 读取路径不再引用 |
| KDS兼容镜像 | 状态双写可能分叉 | `kds_tasks/events` | KDS不一致为0 |
| RuntimeState后台扫描 | 全店扫描和串行写 | `SKIP LOCKED` workers | 多实例领取测试通过 |
| `BootstrapResponse extends RuntimeState` | 前端依赖整店聚合 | `StaffBootstrapView` | 五岗位契约测试通过 |
| JSON本地生产仓储 | 行为与Postgres不同 | Postgres测试容器/内存领域适配器 | 生产配置无JSON模式 |

## 当前切流阻塞项

1. 星驿真实出站建单、支付动作返回、退款执行和查询补偿尚未接入规范化worker；只完成内部意图与回调验签不能视为支付接通。
2. 真实通知、打印、耳机和SOP动作适配器缺失。候选校验要求适配器明确声明六项商业能力，缺一即阻断。
3. 有财务权限的岗位额度尚未获得经营方确认并配置；系统不会自行猜测赠送、折扣、退款和权益额度。
4. 65张桌台的最低消费（无低消也需明确为0）和可视化布局坐标尚未确认，商业就绪检查已改为阻断。
5. 真实初始库存、支付机构响应样本、打印机和消息通道仍需现场联调证据。
6. 已通过全新PostgreSQL 86个文件/476项测试、真实移动浏览器3条关键流程，以及跨越90秒员工在线租约的持续HTTP验收；修复前4分钟测试暴露的会话心跳问题后，100秒复测为零错误。最终代码冻结后仍需重跑完整4分钟验收。
7. 上述阻断项全部关闭前，不切换阿里云现有服务，不打商业发布标签，也不把规范化候选描述为已部署。
