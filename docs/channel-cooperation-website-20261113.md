# 官网合作后台与微信直达领券

本记录取代早期方案中“小程序合作店长后台”和“对外提供原订单明细”的设计。客户不用先打开小程序扫码；微信直接扫海报小程序码，或长按识别，进入该优惠领取页，点领取即可绑定本人的微信身份账户，已关联会员自动同步。主动退出账号的用户需重新登录；不会绕过退出意愿。服务员到店核验入口保留，两入口共用额度与原有客组规则。

## 管理员、店长和客户怎么操作

1. 管理员在员工网页“周边店合作”建立合作方、推荐人、优惠活动和批次，复核后开放领取；生成当天专属图，或让店长自己下载。同一批次图片重下载保持同一码与额度；有效时间、限额、优惠变化用新批次。
2. 管理员选店长，生成“官网开通／重置链接”，私下交给本人。72小时内用链接设置账号和至少12位密码，再登录官网“合作”。无需绑定会员或进入微信小程序。链接只可用一次；遗忘密码由管理员重新发链接，成功重置后退出旧登录。停用合作账号会撤销会话。
3. 店长从官网合作后台下载自己的推广图，发送给客户；管理员也可代生成和转发。网站保存“请求下载”记录，不把下载当作已经发送或客户已到店。
4. 客户微信扫码/长按识别，直达优惠页并领取。未领券到店也能出示推广图/优惠号码，由服务员核对本人并绑定本次客组；沿用领取、核销、转桌拆桌、退款及计佣规则。
5. 店长在官网看匿名推荐记录（日期、到店/接待状态、计佣净消费、佣金）和自己的结算汇总。可查看历史分页、确认汇总或提出异议。内部订单核对由酒吧有权限的员工处理。

## 对外数据边界

只返回当前登录推荐人的数据，不接收前端指定的店长/门店身份。顾客姓名、手机号、会员号、微信标识、桌号、订单编号、所点商品、支付流水、收款账户和内部成本一律不返回；页面隐藏不能代替接口限制。匿名客组编号仅用于追踪一次推荐消费，不是顾客身份。推广优惠本身的商品名称属于营销内容，可以展示；顾客实际所点商品不展示。旧小程序店长接口及页面撤除，不留旧接口绕过路径。

佣金显示沿用实付、退款、观察期及不可变账本规则。“累计佣金”“累计已付”“未付余额”分别展示；未付余额包含待核对/观察期金额，不等于立即可付款。对账单仅显示匿名客组的计佣净额与佣金变动，不展示银行账户；内部财务保留完整证据与独立复核。

## 安全与异常

- 账号独立于员工、顾客和会员；密码加盐scrypt，数据库只保存邀请/会话令牌哈希。12小时会话，Secure/HttpOnly/SameSite=Strict Cookie，登出、停用及重置失效。
- 固定官网来源与自定义请求头保护写操作；限流按真实请求IP、账号和已登录会话。登录/开通每15分钟每IP最多30次、同账号10次；已登录读取每分钟60次。
- 邀请只放URL片段，进入页面立即移除，不进入请求日志；页面禁止缓存、嵌框和搜索收录。密码及Cookie日志脱敏。
- 断网/响应丢失保留原结算请求编号；恢复只查原回执，不换编号重做。账号切换隔离未确认操作；激活响应丢失时先用刚设置的账号登录核对。
- 跨店访问、伪造分页游标、停用账号、失效链接均拒绝；图片生成前后再次核验权限。无自动拨付佣金、建真实合作账号或对外发消息。

## 开发与发布

新增迁移314：官网账号、邀请与会话，以及结算确认人的推荐人身份。复用原活动/图片缓存、核销、连续客组、计价、库存、账本、对账和命令回执；新增官网页面、独立认证、隐私白名单及官网入口代理。历史小程序店长测试迁移至真实PG/HTTP和官网浏览器测试，顾客小程序测试继续保留。

官网现行v25是阿里云独立运行站点，历史Sites源不是当前版本。发布工具只克隆当前站点、在14个主页/菜单页面的桌面导航及手机可见页脚增加“合作”，其余文件按哈希保持一致；官网`/cooperation/`页面及专用API转发至标准后台。先通过完整CI并发布后台，再核对准确SHA/schema314后切官网入口，失败恢复原入口。后台数据库按标准停写、备份、迁移与只读回查发布。

微信小程序领取页必须正式发布后，release推广码才能对普通顾客生效。后台与官网部署、微信开发版上传、平台正式发布和真机扫码均分别记录，不相互替代。所有本地模拟及测试不代表真实银行付款、现场出品或微信正式发布验收。

手机入口验证：页头与页脚均提供合作链接；基于实际14页和5份线上样式，在390/768/1440三种宽度共42次浏览器可见性与溢出检查通过。完整样式回查确认原站窄屏导航可见，页脚是额外入口。
