## 0. 产品首要原则：适合少人手营业，帮助成交与复购

用户已明确：这是人员较少的小酒吧商业应用。产品首先帮助顾客愿意买、方便买，员工更快推荐、加单、收款和解决客诉；控制和记录为这些目标服务。不能按多部门、大连锁、专职审核/仓管常驻的假设设计。

本节作为方案取舍和交互复杂度的优先解释；保留真实资金、数量、归属及用户已确认的一次退款审核规则。后台严谨性尽量自动实现，开发验收记录由开发维护，不转化成员工逐单填写的表格。

### 0.1 功能取舍

- 每项改动先说明能改善哪件事：减少点单/支付流失、方便推荐与加单、促进合理复购、减少现场操作和等待、减少误单损耗。不能仅用“更规范、更多记录、更多权限层级”作为新增功能的理由。
- 先修挡住营业的已证实问题，再做少人手高频操作和已确认销售需求；把孤立的低频管理功能排后。真实错账、错桌、重复退款等仍及时处理，因为同样损害收入与顾客信任。
- 默认沿用可用的推荐、套餐、会员、优惠和加单能力，不新增一套营销平台。新的促销政策、价格规则或推荐算法单独列建议，不因“销售优先”自动纳入本批开发。
- 营业收益同时看有效成交、净收入/可确认毛利、服务耗时和客诉退款；不能只以客单价或销售总额上升认定改动有效，也不能把缺失成本当零。比较时说明营业时段、客流和活动差异，不把促销期间变化直接归因于程序。

### 0.2 少人手操作规则

| 设计点 | 本项目要求 |
|---|---|
| 一人兼岗 | 权限可按门店授权组合，同一员工可点单、收款、处理现场、确认实物；不要求不同账号逐岗接力，不创建虚拟人员凑流程。退款申请人不自审的既定规则保留 |
| 首屏与入口 | 点单、加单、查看消费和收款优先；异常明细、技术编号、流水和审计默认收起，有需要再展开，不挤占销售操作 |
| 填写和确认 | 系统已有的桌号、订单、数量、金额、人员和时间自动带入；常见原因点选，确有补充才输入。正常操作不增加重复确认，收退款等必要确认展示商品/数量/金额即可 |
| 退款与退库 | 一个售后入口汇总商品、资金及实物进度；有退库权且实物已收到时可在同一入口完成确认。自动预留释放/未制作回补不要求再去仓库页面点一次 |
| 岗位与交班 | “责任岗位”表示实际接手能力，不要求新增专职岗位。系统自动进入现有当班待办；同一人能处理则直接处理，仅确需他人接手才移交，不要求每单选负责人或写交班报告 |
| 通知 | 正常点单/付款由系统同步，不要求各岗位逐条确认。暂停已打印商品、制作中拦截、实物回收等确需现场确认的事项才保留必要反馈；只提醒可采取行动且有变化的异常 |
| 暂时无人审核 | 停止未制作部分和其他销售继续，原退款保留待审并通知既定审核人。不得假设第二人始终在场；不自动批准、不默许自审。远程审核仅复用已有可用入口，不临时新增审批平台 |
| 顾客购买 | 推荐和套餐可跳过；不强制入会、领券、看推荐或处理历史售后才能继续合法购买。明确价格和可用优惠，先完成当前购买意图 |

### 0.3 本批功能的销售和效率验收

除原有金额及恢复测试，使用门店实际当班人数和兼岗方式走一遍正常晚间流程，不预设额外经理、收银或仓管在场。记录改动前后同场景的页面跳转、必填内容、人工确认、等待及处理时间；默认不增加正常下单、加单、收款步骤。若确需增加一步，要说明防止的具体错误和简化替代方案。

- 顾客扫码到下单、员工协助点单、同桌快速加单、付款后继续加单保持顺畅；推荐不打断支付。
- 停一瓶水后能继续处理本桌其他商品，无须跑多个页面重复录入；一次退款审核保留，自动事项不再重复确认。
- 异常提示可展开处理，待办不会挡住无关销售；权限不足有实际可找到的接手人或既定入口。
- 推荐和优惠相关改动同时验证缺货/停售、真实成交价和已确认叠加规则；售罄不误售，正常有货不因无关流程被锁住。
- 先用已有数据及少量现场观察判断是否省时、助成交；本批不默认新建复杂埋点、绩效考核或经营仪表盘。不编造提升百分比或强行增加员工录入。

## 4. 稳定性与失败恢复要求

- **限制影响范围**：暂停、锁、提交限制及重试只作用于相关商品、订单、付款或本人桌次。打印离线、通知失败或单笔售后异常不阻塞其他桌台正常营业。
- **保护金额和数量**：原成交价、优惠和分摊快照保留；已退及在途占用共同限制退款额度；已释放/已回补量共同限制后续库存处理。取消应收、实收、退款、库存成本分别留事实，不删原记录凑平账。
- **先保存可恢复事实**：一次审核批准与后续执行任务可靠关联，程序重启后可继续，不能只靠浏览器依次调用审批和执行。优先复用现有持久任务、观察与恢复机制。
- **确认成功后只恢复剩余步骤**：渠道已退款但本地应用失败，保留权威渠道观察并恢复本地处理；库存或通知失败不能再次退款。不得随意拆散账务事务以避免报错。
- **区分失败与未知**：可证明未发出的错误、渠道已确认失败、请求结果未知分别展示和处理；未知先核原操作，确认允许新尝试后才生成新的关联尝试。
- **处理成功而刷新失败**：保存成功编号和结果，提示数据待更新并恢复读取；不因读回失败重复发起业务动作。只限制必要的相关动作，不锁住整个页面。既有独立竞态候选仍按暂缓规则执行。
- **控制恢复频率**：超时、重试和退避沿现有机制，明确次数/时限/终止原因，避免新增长时间占锁、无限轮询和重复报警；不凭空制定全系统统一超时。
- **兼容旧客户端与数据**：新字段及迁移说明旧记录如何读取，缺证据显示待核而不补造。先建立服务端兼容，再逐端启用新入口；迁移在隔离库演练，不默认大规模历史回写。
- **可回退但不倒退业务事实**：回退前核对新数据与旧版本兼容性；不删除已确认收退款、库存流水或审计记录。关闭新入口后，已批准退款和已暂停商品仍需有可用的处理路径，不能留下无人恢复的中间状态。
