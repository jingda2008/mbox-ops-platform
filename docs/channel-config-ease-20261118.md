## 员工新版操作

**选推荐店长 → 复制这位店长上一批配置 → 填本次领取及使用时间、核对标题和规则 → 生成暂停批次 → 另一管理员审批 → 下载专属推广图。**

- 没有上一批时按原表单首次填写；复制只产生页面草稿，不新增券、批次、库存预留或佣金。
- 自动填入所属活动、优惠、商品范围、次数、门槛、叠加规则、佣金、观察天数及条款。四个日期留空，必须明确填写本次时间，避免沿用过期活动。
- 金额券只显示减免金额；折扣券只显示减免比例和封顶；赠品只显示商品和份数。切换类型后不提交隐藏字段，也不把20元当成20%自动带过去。九折填写10。
- 活动、员工/顾客入口、批次、推荐人启用及确认结算权限均回显实际状态；联系人同步回显。只改需要调整的项目，不必反复勾选全部开关。
- 若提示“记录已变化，请刷新核对”，先刷新看最新状态，再决定是否修改。断网结果未知时仍按原入口恢复操作，不重新生成一批。

## 前后端约束

- 新增只读模板接口 `/api/staff/channel/batch-template/:promoterId`，要求渠道管理权限，按当前租户、门店、推荐人查询最新批次；不受目录最近100批次窗口限制。不返回旧二维码、公开令牌或审批状态。
- 复制来源限定为当前选择的推荐店长。切换店长会清空原复制草稿；换账号或撤权后，迟到的模板响应不能填入新账号。
- 历史适用/计佣/赠品商品已停用或不在当前列表时，明确要求核对，不自动删掉商品缩小原范围。原活动不在当前目录时同样提示重新核对。
- 沿用原批次创建接口：服务器重新校验商品、赠品成本、归属与规则；新批次新号码、新公开令牌、暂停待审，创建人不能自批，旧批次和累计额度保持原逻辑。前端复制不携带旧赠品成本作为有效依据。
- 目录补充两入口、推荐人权限及联系人状态；缺失状态不猜成“全部关闭”，新版界面禁止在状态不完整时保存开关。
- 新版开关请求携带读取时状态，在原店级锁内锁定并比对数据库记录；不一致返回409，不覆盖。断网重试复用原永久回执，不重复开关或创建。原客户端无快照请求保持兼容，因此本项并非“所有旧客户端都强制使用新快照”的升级。
- 刷新结果按请求顺序保护，旧目录响应不能覆盖新目录。已知错误保留原恢复机制，未扩大权限，无数据库迁移。
