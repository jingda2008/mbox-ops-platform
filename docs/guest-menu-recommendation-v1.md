# M-BOX 客人菜单与推荐逻辑 V1

## 1. 页面目标

客人打开点单页后可以立即浏览，不需要先回答问题，也不需要先跳过套餐。页面通过一个稳定菜单承载单品、组合商品和推荐结果，不建立第二套结算流程。

固定顺序：

1. 演出信息：沿用现有逻辑，不因推荐功能改变。
2. 推荐工具：`帮我快速选`、`摇一摇喝什么`。
3. 一级分类：`今夜推荐`、`组合甄选`、`酒水`、`小食`、`搜索`。
4. 酒水二级分类：`全部酒水`、`鸡尾酒`、`啤酒`、`葡萄酒`、`起泡酒`、`洋酒`、`无酒精`。
5. 商品详情、购物车、订单确认和支付：组合商品与单品完全共用。

菜单页不再显示“加水”快捷入口。点歌、生日和呼叫服务员放在服务页，不抢占点单首屏。

## 2. 三种推荐的关系

三种入口共用同一个可售候选池和同一套排序规则，不各自维护商品名单。

### 今夜推荐

- 是稳定的默认陈列。
- 使用开台人数、营业时段、演出状态、库存、履约能力和后台策略排序。
- 首屏集中展示三款可售方案，清楚对比酒型、包含内容、组合价、当前单点合计和少付金额。
- 一款标记为“今晚正好”，另外两款使用真实酒型或场景标签，避免三个方案看起来完全相同。
- 三款都可直接加入购物车；其他合适商品继续正常展示，不阻断客人浏览。
- 只有后台明确配置的升级商品可以出现一次补差升级建议。

### 帮我快速选

- 是对默认排序的补充，不是独立套餐入口。
- 只问三个影响选择的问题：今晚节奏、口味感觉、停留时间。
- 问题不直接询问预算，使用“轻松一点”“今晚要嗨”“来点仪式感”等隐性需求信号。
- 客人可随时退出；退出后仍回到正常菜单。
- 完成后在原位置重排多款合适商品，不改变分类顺序和购物车。

### 摇一摇喝什么

- 是低承诺、带趣味的探索入口。
- 继承开台人数和快速选择答案。
- 只在当前排序前八名的合格商品中加权抽取，最多三次且优先不重复。
- 不得绕过库存、供应时间、人数、履约和毛利条件。
- 结果进入相同商品详情、购物车和结算。
- 反馈采用原创双段短音与轻振动：开始 `[28,45,28]`，揭晓 `[45,30,70]`。
- 支持静音；减少动态效果、无振动能力或音频受限时静默降级。

## 3. 推荐计算

### 第一层：硬过滤

以下商品不得进入推荐：

- 商品停用、客人不可见、售罄或不在供应时间。
- 人数低于最少人数或高于最多人数。
- 标价不高于成本。
- 组合商品缺少组成商品，或任一组成商品停用、售罄、过时段。
- 需要出品但现场没有可用工作站。

### 第二层：基础经营分

- 后台推荐优先级。
- 人数范围与实际人数的接近程度。
- 是否适合一轮集中准备。
- 准备时间在八分钟内加分，超过十五分钟逐步减分。
- 正毛利及毛利率贡献，但不能单独决定推荐结果。
- 组合商品的履约完整性。

### 第三层：客人意图分

- 同行场景只作为员工开台时的冷启动信号。
- 快速选择的节奏、口味和停留时间用于重排。
- 场景和答案只改变顺序，不能把其他正常酒种完全删除。
- 不使用外貌、性别、人脸或敏感属性做销售推荐。

### 第四层：价值真实性

- 组合商品的“单点合计”和“少付金额”必须由当前组成商品价格实时计算。
- 没有真实单点价差时，不显示“少付”“划算”等价格优势文案。
- 价格、库存、权限、支付和订单状态由确定性业务规则控制，AI不能直接改写。

## 4. 消费心理约束

- 先降低决策成本，再提高客单价。
- 不强迫回答、不制造跳过阻力，保持客人控制感。
- 推荐比较区固定三款，既提供比较锚点，又不扩展成难以选择的商品墙。
- 视觉上只轻度突出一款“今晚正好”，但三款的价格、内容和按钮具有同等可读性与可操作性。
- 推荐理由表达使用场景、口味和履约价值，不使用“系统判断”“规则要求”等机械文案。
- 补差升级只在客人已加入商品后出现一次，并提供明确的“保持现在这样”。
- 不连续追售，不在三分钟一次性交付流程中重复弹窗。
- 金额只在商品详情、购物车核对和结算中清楚呈现，不在折叠购物车持续制造账单压力。

## 5. 后台商品配置

每个商品可配置：

- 基础资料、分类、图片、标签、菜单顺序、供应状态和供应时间。
- 单品或组合商品、酒水类型、组成商品数量、替换商品。
- 客人可见性、出品工作站、单笔最大数量。
- 标价和有权限保护的成本。
- 推荐开关、优先级、徽标、标题、理由。
- 推荐人数范围、同行场景、节奏、口味、停留时间标签。
- 一轮集中准备、预计准备时间、最佳持有时间。
- 唯一升级商品。

保存成功或失败必须给出明确反馈；每次保存增加配置版本并写入审计记录。

## 6. 组合商品履约

- 购物车和支付只显示一个收费的组合商品父行。
- 提交订单后，系统按组成商品生成零价履约子行。
- 子行分别进入吧台、厨房、打印和库存消耗。
- 订单金额、员工业绩和支付分摊只计算父行，避免重复计算。
- 组成商品缺失、停用、售罄或无法履约时，整套组合拒绝下单并返回具体原因。

## 7. 验收重点

- 不使用推荐工具也能完成浏览、下单和支付。
- 三种推荐入口的候选商品满足同一套硬过滤。
- 快速选择完成后商品重排，分类和购物车不变。
- 摇一摇最多三次、优先不重复、可静音且不影响下单。
- 默认推荐显示三款真实可售方案并支持同屏比较，升级只来自后台明确关系且只提示一次。
- 单品和组合共用详情、购物车、确认和支付。
- 组合金额不重复，组成商品能分别进入正确出品口。
- 后台编辑并保存后不丢失任何旧字段或推荐字段。

## 9. AI接入边界与回退

正式链路固定为：

```text
确定性规则筛选
库存可售 + 人数匹配 + 正毛利 + 供应时间 + 组合可履约
        ↓
AI理解自然表达并对合格候选重新排序
        ↓
系统重新校验商品白名单、去重、三档结构和推荐理由
        ↓
展示轻松开始 / 今晚正好 / 更尽兴或真实同价酒型选择
        ↓
记录推荐曝光、答案、结果、加购、未结算离开、下单和付款
```

约束：

- AI不能创建商品、修改价格、声称虚假优惠，也不能绕过库存和供应时间。
- AI返回不存在商品、重复商品、少于所需选择，或理由中包含未经验证的价格、免费、折扣承诺时，立即回退到规则排序。
- 当前Qwen用于员工AI助理；客人菜单的模型调用尚未启用。菜单仍使用稳定规则排序，但已具备AI结果白名单校验和回退函数。
- 快速选择完成后，页面短暂显示本次推荐是否发生变化以及主推荐商品，不永久占据版面。
- 行为闭环记录`recommendation_result_updated`和`cart_abandoned`，付款完成由服务端记录；不得由客户端伪造。
- 相同输入和候选池应复用结果，避免重复模型调用；AI超时不能阻塞浏览、加购、订单或支付。
