# 1.0.0-rc.204 支付通知兼容修复

## 问题与行为

合法星驿手续费通知通过 RSA 后因缺少 ORDER_STATUS 被旧接收器误拒 401。新版按官方 NOTIFY_TYPE=01 分派手续费通知，独立持久化后返回协议确认；不将手续费当作支付/退款终态，不改写订单或收款流水。交易结果通知继续验证商户、签名、金额和原交易绑定，两个回调地址均可分派支付与退款结果；退款处理中只保存非终态观察。

官方协议：[交易手续费通知](https://www.postar.cn/xyf/doc/396878246e0)，核验日期 2026-09-16。该协议明确手续费与交易共用通知地址；NOTIFY_TYPE=01 为手续费，其余按交易结果解析。未知/不支持交易状态保留拒绝，不泛化成功响应。

schema 204 新增 provider_fee_notifications，按门店隔离、运行角色只允许查询/追加。回执允许先于交易结果到达，存必要金额、交易引用和报文规范摘要；重复并发返回同一记录，冲突拒绝。不同内容作为新证据保留，不覆盖历史。

错误分类：签名错误401、商户未绑定401、字段无效400、类型/状态不支持422。日志只保存原因、请求号、原始报文摘要与长度；不记录原文、签名、公钥、顾客身份。

## 验证和上线门槛

- 真实 RSA 测试签名覆盖手续费先到、零手续费/退款负值、扩展字段、篡改、缺失字段、支付及退款终态/处理中分流。
- PostgreSQL 测试覆盖并发幂等、冲突、无付款对象回执、租户隔离、不可改写、无支付权威及无收款副作用。
- 完整 CI、干净数据库迁移、不可变发布包、备份与 OSS 回读、候选就绪及公开页面冒烟按既有发布流程执行。
- 历史 44 次401没有完整通知正文，不能凭此次修复宣称历史全部同因或全部账务核清。上线后应检查自然通知回执及入账唯一性。

本版范围为后台支付通知处理；不包含小程序包上传、图片或推荐功能变更。商业验收历史未完成项继续开放。
