## 5. 售后统一闭环方案（开发目标，非已有功能）

员工只需要“选择商品和数量→选择原因→提交”；已付取消进入一次审核，未付挂单按权限直接处理。复杂判断由后端承担，普通员工不选择内部状态。

1. **提交前判断**：读取原订单、商品、数量、制作/送达历史、实收/退款和分摊；返回允许动作、金额及确切不可操作原因。页面显示未付款不能代替服务器事实。
2. **商品处置事实**：关联原订单项，记录涉及数量、申请人、用途、审核版本、暂停/停止/继续处理、实际已做/已送/实物回收及负责人。复用订单/KDS/退款/库存原标识；必要新增处置记录，不建立另一套资金账。
3. **及时止损**：对未制作数量原子暂停，同时阻止该数量开始制作；已做部分保留实际历史。原生产票还在手中时，电子通知和现场核实同步跟进。
4. **未付款**：取消相应有效应收，剩余品项照常；全单停止不自动关桌。现有整单cancel_unpaid_order及经理KDS取消不能直接代替此功能。
5. **已付款**：单次审核通过后，在同一数据库提交中记录可恢复的退款执行任务，再异步调用原渠道。审批已提交但程序重启必须可继续；不能只在页面串联approve、execute两个请求。
6. **拒绝/撤回**：未执行可撤回或形成新申请版本，旧审核失效；暂停商品进入明确待处理，服务人员可确认继续制作（重新校验库存）或现场解决。不是第二次资金审核，不自动无限暂停。
7. **库存**：只预留则释放；有原扣减且确认未制作可回补；未开封实物收到后确认；已消耗计成本/损耗；纯资金退款不回库。自动与人工回补必须共享剩余可返还事实，避免重复。
8. **结果恢复**：停菜、计费、资金、实物、通知分别有状态和原操作编号。钱已退而库存失败时继续恢复库存处置，不能再退一次；部分渠道成功只处理其余部分。
9. **交接收口**：每个需要处理的事项有责任岗、最近进展、原桌次和下一动作；退款成功不自动清走实物待办。无需回库/已消耗等为明确终态，实际未完成事项持续可查。

最终关闭必须同时满足适用的各项：计费已调整、所需退款终态可证实、后续履约有明确处置、库存释放/回补/不回库有事实、必要岗位通知已确认或完成现场核对。不适用项有明确原因，不能填假成功。
