# M-BOX 1.0.0-rc.77 多维审计与移动操作修正

## 本版目的

对规范化系统执行功能、岗位权限、模拟经营、支付退款、库存、性能、安全、日志、视觉和移动端适配审计，并修复能够稳定复现的问题。本版仍是阿里云开发验证版本，不改变商业生产门禁。

## 已修正

- 出品队列经过岗位过滤后没有可操作项目时，明确显示空状态，不再留下空白页面。
- 320像素窄屏在首屏推荐卡提供44像素直接加购入口，避免结算栏遮挡首个有效动作。
- 菜单搜索仅命中一个商品时使用完整内容宽度。
- 搜索清除、数量调整、购物车关闭等高频触控区达到44像素。
- 顾客点单、预约和员工工作面补齐页面标题语义，并修正严重颜色对比度问题。
- 修正独立数据库负载验收的会话清理误报，并在真实PostgreSQL下完成每类60秒、5 RPS重跑，错误率、最终积压和事务失败均为0。
- 将上述问题加入浏览器和组件回归，不依赖人工记忆。

## 审计结论

- 客户点单、预约申请、员工登录、现场桌台、协助点单、商品赠送、出品、退款领域事务、权限隔离和移动端主要流程具备自动化证据。
- 模拟支付目前能安全创建待支付订单且不冒充真实到账，但规范化界面缺少受控的模拟成功闭环。
- 真实微信/星驿支付、物理POS、打印机、耳机和摄像头尚未完成现场联调，继续保持禁用或未配置状态。
- AI执行中心目前覆盖开台和定时派水等有限能力，尚未覆盖所有岗位、所有页面动作。
- 桌台责任分配、客户权益、经营数据和库存的部分服务端能力尚未形成完整的岗位操作界面。
- 213条经营TC在当前候选中仍为0条当前候选通过、196条未执行、17条阻塞；另有38条专项P0/P1未完成。工程测试通过不能替代员工现场验收。

## 发布边界

本版只允许部署到阿里云验证环境，供员工继续操作演练。不得接入真实顾客资金，不得宣称真实支付、退款、打印、库存或整店商业验收完成。

详细证据见[多维系统审计](multidimensional-system-audit-1.0.0-rc.77.md)、[增量测试案例](tc-multidimensional-audit-1.0.0-rc.77.md)和[213条经营TC报告](tc-execution-report-1.0.0-rc.77.md)。
