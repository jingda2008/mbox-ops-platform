### 店员需要知道的入口差异

顾客用微信扫一扫或长按识别官方小程序码，进入优惠页领取。员工网页的普通二维码扫描器不能识别微信专有码，现场用推广图上的优惠号码核验、复用原券并绑定当前桌次。不能把“已经领取”当作“已经到店/已经核销/已经收款”；这些是不同状态。

## 本轮发现并修复

1. **官网合作后台日期遗漏（P1）**：接口返回 PostgreSQL 时间文本（空格、微秒、`+00`），页面原先直接 `new Date(value)`。宽松桌面浏览器及原 ISO 样例掩盖了严格解析环境失败。现统一显式时区校验/标准化，固定北京时间显示，缺失或非法日期显示“时间待核对”。新增15项合同测试（修复前失败、修复后通过）、严格解析浏览器场景和真实伙伴HTTP时间到网页格式化的联验。未声称已在真实iPhone验收。
2. **持续回归遗漏（P2）**：日期与优惠后金额的2个小程序专项脚本原未纳入常规发布回归，现加入 `release:miniprogram:test`，避免只靠手动补跑。
3. **服务端构建校验遗漏（P2）**：3份近期共享测试及其引用的菜单计价模块省略ESM文件扩展名，Vitest可运行但NodeNext类型检查失败。已补齐导入路径，并把 `typecheck:server` 加入常规 `check`；不修改计价行为。
4. **跨模块覆盖补强**：新增普通/渠道订单对照、真实赠品数量履约、实际合作HTTP时间与隐私校验。调试中出现的角色约束、缺少协助点单会话及收款/关桌权限，均是新增测试夹具不完整；补齐真实会话及最小所需权限，未降低业务校验，未把这些夹具失败计作产品漏洞。
