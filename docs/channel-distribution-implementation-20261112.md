## 1. 店长和员工怎么用

1. **管理员准备一次**：合作餐厅及推荐人→发送单次邀请由店长绑定自己的账号→填写结算主体、固定跟进员工和权限；配置全店发券、承诺份数及成本上限。财务登记脱敏账户标识及经授权保管的资料编号，由另一名财务复核；后台不代替银行账户资料保管。
2. **每日推广**：建立活动及当天专属批次，填写北京时间起止、共用额度N、每人K、连续客组L、商品、门槛、满减/折扣上限/赠品、佣金比例及观察期。另一管理员发布，活动和对应入口同时开启后才可新领。默认10%佣金、7天观察期仅为可调整规则默认值；须按合作协议确认。店长自行下载，或酒吧逐张/批量下载后人工发送；同一批次再下载不增加额度，人工发送/确认收到/反馈/下次联系分别记录。
3. **A员工入口**：顾客出示图片→员工在当前桌详情输入新版图上的优惠号码（旧版业务二维码仍支持扫码）→识别本人会员码或选择已核验的本桌顾客→预览规则→选择已有券或明确新领→一次确认完成领取及本次客组绑定。失败整笔回滚，不扣半笔额度。没有可验证顾客身份，不能绕过每人限领。
4. **B顾客入口**：微信扫一扫或长按推广图识别→直接进入对应优惠页→点击“立即领取到本人账户”→到店扫描当前桌码→明确选择使用；无需先打开小程序找入口或手输号码。主动退出登录者先登录，登录后返回同一优惠页；旧版图片和手输号码仍可用。二维码与号码共用N/K；B已领后A直接复用原券。顾客自扫不自动算物理到店，员工现场确认后后台才显示“确认到店”。
5. **点单与计价**：来源在首单前锁定到连续客组；员工代点和顾客自助都先核对渠道报价再提交。服务端以本次累计合格商品计算减免，报价2分钟有效，购物车、身份、商品或历史消费变化须重报。加单不重复发满减；渠道价与会员券/会员卡价/积分选择互斥。使用预付款时只按优惠后应付分配原款；全额优惠以明确0元结清凭证出单，不造现金支付。
6. **赠品**：领券时占用真实销售份数及配方库存。员工达标后点击原券“赠品出品”，系统生成关联原券的零元赠品订单，进入现有KDS。重复操作返回原订单；开始制作时按现有库存流程消耗一次，正常售卖不能挤占已承诺库存。下架、配方变更或供应异常不能假兑现，主管在顾客同意后替换未出品原券，原/新库存原子转换并重新核对成本容量。
7. **退款和交班**：仍从现有售后/原支付渠道退款。渠道任务从已支付、已履约、退款事实重算差额账；未结清、未履约、未知付款、退款处理中、原预约待核对等不可结算。交班查看原未决请求、未出赠品、冻结原因和同步时间；超时恢复原请求，不新建重复付款或赠品。
8. **每周结算**：财务重新核算→生成成熟且未占用账项的结算单→店长查原消费/退款明细后确认或提争议→另一财务审批→人工银行付款→登记待查付款→另一财务按真实银行回单确认成功/失败。支持部分付款和银行部分退回；不提供自动转账。旧付款状态未知时禁止再付或换账户续结；账户变更需要独立核实并重新确认。若原单已付部分，选择“更换账户，生成原单尾款续结单”，仅续结剩余金额，重新由合作人确认及独立审批；多次换账户、银行部分退回也沿同一原单累计校验，既有付款和账项占用不改。合作人已收的退款冲佣形成负余额，冲抵以后佣金，不删旧实付记录。

**图片说明（本次更新）**：新版推广图接入微信官方小程序码，固定正式版领取页 `pages/channel-coupons/index`，场景 `CH_` 加原优惠号码（新建12位，兼容8—16位）。微信扫一扫/长按识别直达对应优惠，图上仍显示备用优惠号码及完整北京时间。图片不伪装实时剩余数量，重复下载不加额度。新图片模板、AppID、路径、环境、场景、规则及PNG摘要独立归档；旧普通二维码缓存不会复用。此处为本地代码能力，真实微信识别须待新页面发布后真机验收。

## 2. 营业例外统一规则

| 情况 | 系统处理与员工动作 |
|---|---|
| 已领完、暂停新领 | 原有效券仍可用；不重发图片制造新额度 |
| 等于截止、跨午夜 | 以服务器时钟为准；截止拒绝新领取/使用，截止前已绑定本次权益可正常完成结账 |
| 取消、正常到期 | 发行历史N/K不自动退；未兑现可释放使用占位。已支付/已制作/已兑现不自动复活券 |
| 整单未付款且未制作取消 | 可释放未兑现的普通价格抵扣占用；已消费后退款不会再发一次优惠 |
| 门店排队延期 | 主管只延长原券，最长未来7天；重新检查活动及全店容量、库存，记录原因，不另发一张 |
| 赠品替换 | 仅未出品原券；明确顾客同意、份数、成本；失败原券/旧库存保持。已制作按现有售后处理，不复用同券再出品 |
| 换桌、同组加单/拆账 | 用原转桌流程，来源和L跟随同一连续客组；换付款人不重置 |
| 不同客组拼桌 | 禁止直接合并来源不明的订单；保留各自原桌次分别下单/结账。首版不提供同一桌次内混合两个推荐来源 |
| 近期关桌后重开 | 同一已验证顾客30分钟内再次绑定，需主管明确“续台”或“真实离店后新到店”；续台保留原来源及L。不是通过猜测顾客人脸识别 |
| 首单后漏扫、错来源、原预约 | 普通扫码不倒认历史消费；主管按原消费单号及凭据更正指定订单。原订单、原付款、原归属记录不改，佣金按旧负新正调整；原预约普通绑定先冻结计佣，不能直接算新渠道业绩 |
| 付款未知、争议、已审批后退款 | 重新读源交易；相关账项冻结/新增调整，旧单失效须重新核对。退款提交与佣金付款登记由同一数据库锁串行化 |
| 已付佣金后退款 | 追加负差额，展示应计/已付/负余额；银行已发生付款如实记账，不因后来的退款抹掉实际支出 |
| 暂停功能、店长离职 | 停新领不破坏原券/售后/结算；外部账号停用后拒绝查看、下载和确认，旧账保留 |
| 身份切换、网络中断 | 丢弃旧响应、清除旧报价，保留原持久化回执；必须恢复核对原操作，不借新键绕过未知结果 |
