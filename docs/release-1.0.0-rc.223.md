# 1.0.0-rc.223 恢复验证扩展属主权限修复

rc.222在隔离原生维护演练的恢复验证阶段失败，未切换生产。诊断演练35823933100确认`btree_gist`原属主缺少临时恢复库CREATE权限；原日志与清理凭据保留。独立真实PostgreSQL回归进一步确认：当临时恢复库归维护管理员所有，归档中的可信扩展属于非超级用户且无数据库CREATE时，按原属主建扩展被拒绝。

本版本只在临时恢复库的同一事务中，按需授予原扩展属主CREATE、创建扩展并收回该权限。若创建失败，事务回滚；源营业库、角色成员关系和原ACL不放宽。保留原扩展属主和最终完整证据比较。

增强恢复回归在rc.222失败，修复后通过，覆盖成功恢复、故障清理、源活动连接不受影响、原属主保留及无新增永久CREATE权限。真实RDS对9月21日schema224冻结备份的复验已通过，临时恢复库删除、营业源库未替换；恢复脚本SHA256为`6a9988a052c68ef4becb069364a7d2144f7f591d9cdd6c67587432419a3ae843`。最终CI、原生正常及向前恢复演练、实际生产结果仍分别记录。

财务、吧台、三屏业务代码和242条迁移保持rc.222。已通过的120人业务验收及首次失败记录见[完整记录](rc222-release-verification-20260923.md)。不将CI、模拟或正式包发布当作实际部署，也不覆盖rc.222不可变标签。
