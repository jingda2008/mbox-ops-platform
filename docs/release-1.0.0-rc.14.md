# M-BOX Ops Platform 1.0.0-rc.14

发布日期：2026-07-18

## AI 员工助理

- 所有员工岗位使用同一 AI 助理入口，可询问现场状态、补充信息并生成最多五步的可执行计划。
- Gemini 只负责自然语言理解和结构化建议；权限、实时状态、风险分级、确认、审批和业务写入仍由 M-BOX 系统决定。
- 对话按员工和营业日隔离，服务端只提供角色可见的桌台、任务、出品和演出状态。
- 模型结果不会直接执行。员工确认后，系统逐步操作原岗位页面；每一步重新校验，歧义、越权、状态变化或接口失败立即暂停。
- 已验证“L04 来了四位客人，开台并归属 Tom”生成五步计划并真实写入桌态、人数和销售归属。

## 稳定性与隐私

- 使用 Gemini Interactions 结构化输出并设置服务商侧不留存；异常输出自动进行一次结构修复。
- API 密钥只通过运行环境或 Secret Manager 注入，不写入代码、数据库、审计或前端包。
- 敏感控件及字段值不发送给模型；员工输入中的 PIN、口令、Token 和密钥会先脱敏。
- 相同请求编号幂等重放；不同内容复用同一请求编号时拒绝处理。
- 模型不可用时回退原确定性快捷命令，不影响点单、服务、KDS、支付和岗位页面。

## 交互修正

- 员工端统一使用“AI 助理”名称，支持自然对话、可点击澄清选项和新对话。
- 成功反馈四秒消失，完成计划五秒自动收起；错误信息保留更久供员工核对。
- 390x844 手机视口无横向溢出，对话、麦克风、文字输入和确认计划均可读可操作。
- 销售归属以在职状态为准，不再因设备在线状态变化导致 Tom 无法选择自己开台。

## 当前边界

- 当前复合计划属于浏览器顺序编排，不是数据库事务；后一步失败不会回滚已经成功的前一步。
- 支付、退款、赠送、折扣、库存调整、结台、转桌、发布和权限操作继续执行高风险确认与原审批链。
- 本版本是验证候选版本，不改变 213 条经营验收门禁；未完成的门店设备、真实支付和应急演练仍阻止商业生产发布。
