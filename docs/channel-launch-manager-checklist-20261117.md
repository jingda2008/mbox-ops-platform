# 周边店合作：启用步骤与现场验收

适用：rc298。目的：把合作店推荐的顾客、优惠、本次消费和佣金对应起来，方便服务与对账。以下是待执行清单，不代表已配置或已验收。

**先安排人员：**店长统筹；营销负责商家与优惠；服务员负责到店绑定；收银负责收退款；财务负责佣金。批次发布、退款复核、账户核实及付款核实均按系统要求由不同人员办理，不能共用账号自审。

**一、营业前配置，按顺序操作**

| 顺序／负责人 | 系统操作及完成结果 |
| --- | --- |
| 1．管理员：授权 | 员工网页→系统配置→权限管理，按下表授权并发布；员工刷新或重新登录。退款另按岗位配置申请、复核、执行权限，复核人设置足够的 **CNY 单次额度**，不得本人审批本人申请。 |
| 2．营销：登记商家 | 工作台→**周边店合作**→“1. 登记合作店和推荐店长”。填写店名、推荐店长、约定佣金结算主体和登记依据，保存。每家店选择自己的推荐店长，不能混用推广图。 |
| 3．营销：开通官网 | 选择“当前推荐店长”→“生成官网开通／重置链接”，仅交给本人设置账号密码。在“营业配置、发券审批与异常处理”→“推荐人权限及联系人”，启用推荐人、勾选“授权本人确认结算单”、指定酒吧联系人。外部店长使用官网 `/cooperation/`，不使用员工账号或小程序店长后台。 |
| 4．营销：设置总额度 | 在“营业配置、发券审批与异常处理”选择“设置全店总上限”；再到“2. 建立活动总额度”。分别填写发券数、承诺份数、优惠成本上限和依据，覆盖本次计划的小批次。这里是优惠成本控制，不是新增广告预算，不能随意填0。 |
| 5．营销：配置优惠批次 | “3. 生成每日专属推广批次”：选活动和店长，填标题、总领取数N、每人限领K、每客组限用L、领取／使用起止时间（北京时间）；选优惠类型、适用商品、使用门槛和封顶。首轮保持 **K=1、L=1、不叠加**；需要叠加时明确填写客组总优惠上限。九折选“百分比减免”并填 **10**，不是90。赠品另选商品和份数，先核对商品成本、可用库存及出品岗位。 |
| 6．营销＋另一管理人员：审批开放 | 批次填写佣金比例（本方案10%）、计佣商品、合作条款及约定观察天数。活动和批次新建后均暂停；到“活动及两入口开关”启用活动，同时开启A员工代办、B顾客自领；**由另一位有管理权限的员工**在“独立审批发布或停发批次”启用该批次。确认活动、批次、推荐人都启用且未超额。 |
| 7．财务＋复核人：收款账户 | “周边店合作财务”→“登记新版收款账户依据”，登记真实结算主体及经授权保管的账户资料编号／脱敏标识；另一员工选择“独立复核账户”。正式观察期按约定，不为赶进度随意改成0天。 |
| 8．营销＋合作店长：核图 | 管理员点“下载推广图，单独发送”；合作店长也可在官网点“下载专属推广图”。核对来源、优惠、号码、时间及适用商品；同批次反复下载不增加额度，换日期／规则需新建并审批批次。实际发送后登记“已人工发送”及下次跟进。先完成下方验收，再向客户推广。 |

| 人员 | 需要的合作权限 |
| --- | --- |
| 营销及独立发布人 | 查看周边店合作＋管理周边店合作 |
| 服务员 | 核验周边店合作优惠券＋原有桌台、点单权限；需要转桌时保留相应桌台操作权限 |
| 财务及独立复核人 | 查看周边店合作＋审核周边店合作结算；收退款权限另按职责配置 |
| 店长处理异常 | 查看周边店合作＋更正周边店合作来源与权益；只按证据处理 |

**二、现场验收：店长逐项打勾**

安排空闲时段，使用验收专用小批次、空闲桌和知情参与的本人账号，不群发推广图。真实收退款、赠品出品及佣金付款必须按实操作、按实记账；“现金已收／已退”和佣金付款登记不会自动收钱、退钱或银行转账。验收记录保留，不能伪造回单或删除账目。

| 完成 | 项目／负责人 | 实际怎么验；通过标准 |
| --- | --- | --- |
| □ | 微信领券／营销＋顾客 | 用真实手机分别试“微信扫一扫”和聊天图片“长按识别”，直接打开本张优惠并点击领取；首次按提示登录本人账号。本人券包显示正确来源、优惠及有效期，换账号看不到别人的券；重复领取不突破K。**先核对微信正式版包含领券页面，开发版上传不等于正式发布。** |
| □ | 到店绑定与核销／服务员＋收银 | 员工网页→现场→正确桌台→“周边店合作·核验绑定本桌”。输入图上优惠号码，选本桌顾客或扫描本人会员码→“查看优惠与顾客已有券”→“确认顾客与本桌并绑定”；已有券复用，不重复发券，未领券时可走员工代办。分别核对顾客自助和员工代点的原价、优惠、应付一致；完成真实收款、出品送达后检查券“已兑现”及官网到店记录。绑定不等于已核销；赠品须有真实出品记录，使用打印时核对实际出纸。 |
| □ | 转桌／服务员 | 使用系统转桌，把本次客组从验收桌A移至B；在新桌刷新绑定记录再加单。原券、推荐店、客组和累计优惠保留，次数／总上限不重置；不重新领券、不另外开台绕过限制。 |
| □ | 退款／申请人＋独立复核人＋执行人 | 找原订单／支付申请退款，另一有权限及CNY额度的员工复核，再按实际渠道执行。核对系统成功状态和顾客实际到账／现金退还；原账单、净消费及佣金同步扣减，已用优惠不自动恢复。额度不足、自审及重复操作应被拦截或恢复原结果，不重复退款。 |
| □ | 佣金结算／财务＋合作店长＋独立复核人 | 结台后“重新核对原交易”；核对计佣商品合格净实收、退款差额和约定比例。客组已结束、退款已处理且观察期届满后，按“生成成熟账项结算单→合作店长官网确认→独立审批→登记线下付款待查账→实际付款查账→独立核实付款结果”办理。应计、已付、余额及真实回单一致；未到观察期只验冻结／成熟时间，**到期再补验付款，不能提前勾选完成**。 |
| □ | 限制、断网与脱敏／店长 | 验二维码和号码共享总额度及每人／每客组限制；领取期结束不能新领，过使用期未绑定的券不能新用，已绑定权益按系统原承诺核对；断网后用“恢复原操作”核对，不能因结果未知新建退款或付款。官网只见本人推荐的匿名汇总，不出现顾客身份、桌号及点单明细。 |

**每项反馈：**操作人、时间、通过／未通过、批次／券／订单／退款／结算单号及对应截图；资金环节另留真实查账依据。失败写明现象，修复后重验。未完成的项目保持未完成；店长确认适用项目通过后才扩大推广。
