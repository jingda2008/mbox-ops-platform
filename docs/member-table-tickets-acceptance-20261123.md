# 整桌演出票开发验收记录

范围为[已确认开发方案第 8 节](会员门票与消费积分开发方案-V1.0-20261122.md)的 69 项。以下记录基于独立开发库、服务端和客户端测试。门店演出批文、现场履约与微信真实渠道结果需以门店或渠道证据验收。

## 已接入的操作

| 岗位 | 从哪里进入 | 操作及结果 |
| --- | --- | --- |
| 票务运营 | 员工后台 → 活动运营 → 对应场次 → 整桌门票 | 首次核实本场公示、真实演出、时段与退票说明。选桌区，填票名、每桌售价和每张赠分，发布。可选大分类、展示时段和独立开售／停售时间，未填即沿用默认。修改生成新版本。 |
| 购票会员 | 小程序菜单 → 选场次／桌区 → 门票详情 | 新客同意会员协议并授权本人手机号，已有会员沿用原账户。核对条款及桌数，选择是否沿用本人符合条件的预约，按原支付入口实付。每桌一票，年限从实际支付日起逐票记账。在「我的门票」查看赠分、桌号、入场码和售后。 |
| 当班接待 | 预约与到店 → 门票接待，或活动运营的待联系提醒 → 对应场次 | 一笔购票生成一个接待任务，认领、联系或现场安排，逐票选择原区域具体桌号；在购票接待单直接按「联系购票人」，复用原报名权限、审计和60秒查看时限。顾客出示票码，可分批登记到场人数。 |
| 代客点菜 | 员工点菜选会员及菜品 → 代选用分 → 顾客在本桌菜单查看 | 两端可一键填本单最多可用分并手改。本人核对代选菜品、用分和实付后，走原报价和结账。 |
| 收银与售后 | 我的门票／员工门票接待 → 原票退票 → 原收银退款 | 选定一张票后冻结对应批次；依据购票时版本核算票款。需补菜款时按原菜品、原抵扣及已付金额列示，本人确认后在原餐饮单收款并计入日常奖励。票款另循原支付退款。迟到收款未出票者可从原单申请退回实付款。 |
| 授权管理及财务 | 门票接待 → 原票冲正／核对原票、积分和菜款 | 错户更正须双人、足额审批及原票归属。逐票查看原票分摊金额、原支付号、积分批次流水、退票和补款退款凭证。 |

启用整桌票的门店，从首次发布起，新开桌的强制餐饮下限为零。历史已实收的预收款仍须逐笔结算。「一桌不设人数限购」保留，场次实际放行另核对全场核准人数。退票费率依上架时已复核的公示及个案责任人工核定，顾客与员工不能改写已售票档。

逐项核对共 69 项，本轮有 47 项本地通过、22 项部分验证。首次核对为14项本地通过、53项部分验证、2项待验证。表内保留每项的证据及未验证条件。

## 操作入口与人工核账

- 收银在「收银与售后 → 原挂桌单使用会员积分」输入原单号和会员号。点「填入本单最多可用的积分」可再手改，会员在微信点单页核对并确认。十分钟内原单金额、桌次位置、积分或授权变化时要重报。已付款和抵扣均留在原消费单。
- 错户已用时，先确认实际用分人。由购票人授权的消费在「我的门票」按菜品金额确认，再由另一位有权限员工复核；门店承担的走门店责任分支。错误会员、未确认或原批次已有变动时均会拦截。
- 接待从原票发出可承接的同价、同桌区场次和新桌号，会员在「我的门票」决定。旧场和新场都能查原票。核准容量、物理桌号或场次发生变化时提示重新核对，原安排仍可办理售后。已入座转桌后沿原桌次查新桌号；清台后结束该票的排桌和验码。不同价款或跨区变更走原退票及重新选择。
- 有逐份原参考价的挂桌套餐可用分。两份各130元的套餐用200分加60元，退其中一份时按原整单与保留菜品重算现金退款。历史多份菜只留一笔总收款、没有逐份分摊凭证，或已发生不明预收、在途退款、历史优惠叠加时，收银按原单据核实，系统不会按现价追收。此边界适用于具有这些事实的旧单；新单使用成交时保存的份次、金额和来源。

## 支付与积分交叉复核（本地 schema 360）

本轮在原案办理中途改变餐饮付款或退菜状态，核对原支付号、菜品份次、积分批次、补款和退票金额。下列收退款使用本地回执。

| 顺序 | 核对结果 |
| --- | --- |
| 购票首次明确售罄或桌数不足 | 服务端确认未建单后，会员可减少桌数继续购买。第一次发送后丢回执时，重开小程序仍用原购买凭据核对，同一笔未知请求不能改数量再次发送。 |
| 菜品已用200分，余款60元未收时申请退票 | 在途时拦住个人原因退票。若原餐单取消，200分按原来源释放一次，原案可退500元。若60元到账，原案刷新为已抵200元，可向购票会员提请确认。 |
| 发出200元补款，请求仍未确认，随后办理部分退菜 | 原单实付退30元，按份次退100分。重新核算后应补100元，原200元确认链接失效，新明细由会员确认。收银在原餐单仅收100元；原来已退的30元没有再收。 |
| 原餐桌已关，再由会员确认200元补款 | 收银从已关桌的原餐单调出会员确认记录，提交确认号与金额才可登记。无权限、金额改为199元及第二次收款均被拦截，桌次保持关闭。此入口沿用关桌后的受控线下收款。 |
| 已收200元补款后，人工核定门店承担 | 门店可单独按原票退500元。票款退成后产生200元原补款退款申请，由收银复核执行；补款退成后冲回20餐饮积分，保留原付60元对应的6分。 |
| 改由门店承担时，200元补款渠道仍在处理 | 票款可先退500元。在补款到账前没有补款退款申请；迟到的200元成功回执抵达后，只产生一笔关联该收款的退款申请，再次回调仍为一笔。原补款退款成功、付款和退款均重放后，原菜品最终保留6分和60成长值，已退票的赠分批次余额为零。 |
| 同张票重复提交退款 | 金额与门店责任相同，查回同一退款号；把500元改成450元再次提交，会提示核对原凭证。 |

历史订单缺少逐份实收凭证时仍由收银人工核账。渠道实际何时到账、收到微信回执时真机显示什么，以及现金是否交接，均以外部实测为准。

## 本地核算边界

第32项通过两组独立事务验证了多个渠道同时争用一桌。普通预约另核人数容量；候补仅排队时没有具体桌号，实际分桌与桌票共用物理桌位。已验证清台终态，前台交班、实体桌码和真实人流另由门店验收。换号与并户查回、积分暂停／恢复、过期批次、套餐子项和跨日对账已有本地专项记录。各项以原行的条件为准。
