# M-BOX rc.68 阿里云候选复测与现场验收计划

更新时间：2026-08-09

## 当前边界

- 本地代码、浏览器和数据库门禁通过不等于阿里云环境已通过；PR #62首次共享CI性能作业未通过，修订后的混合到达率模型必须在固定提交上重新验证。
- 现网仍保持`rc.67`；`rc.68`只有绑定完整提交SHA的GitHub CI成功后才允许进入候选环境。
- 当前213条经营TC在`rc.68`候选下仍有207条P0/P1未达到通过，真实支付、退款回调、物理打印、弱网和连续营业晚班不能由模拟测试替代。

## 阶段A：不可变候选

1. PR全量CI通过，下载名称包含完整提交SHA的镜像制品和质量证据总账。
2. 校验镜像压缩包、发布清单、迁移清单和质量总账的SHA256。
3. 记录完整提交SHA、CI run id、镜像摘要、执行人和下载时间。
4. 禁止在阿里云服务器重新构建代码；候选、切流和回滚必须使用同一个镜像摘要。

通过条件：代码提交、CI证据、镜像摘要三者可相互对应，工作区无未提交修改。

## 阶段B：资源与数据库前检

在切流前采集现网至少15分钟基线：

- ECS CPU、内存、磁盘使用和磁盘等待。
- 容器重启、OOM、健康检查和网络连接。
- PostgreSQL连接总数、活跃/空闲/等待、慢查询和锁等待。
- API 5xx、P95/P99、事件循环和变更队列。

数据库先做备份，再执行：

```bash
npm run db:migrate
npm run db:verify
npm run db:verify:time
npm run db:verify:operational
npm run db:verify:presence
```

通过条件：23个迁移校验一致、强制RLS通过、UTC/北京时间与早6点营业日边界通过、规范化投影和跨实例租约通过。

## 阶段C：零流量候选

1. 在独立端口启动`rc.68`候选，不替换`rc.67`。
2. 检查`/api/live`和`/api/ready`，确认版本SHA、数据库、投影、队列和时间偏差均正常。
3. 使用隔离测试门店或测试数据执行登录、开台、下单、任务、KDS、预约和客户会话。
4. 先执行与CI相同的5分钟压缩营业混合负载，再执行单桌热点突发和至少30分钟稳定性测试；三类结论不得互相替代。
5. 压测客户端使用独立资源，记录目标RPS、实际RPS和调度延迟，保存客户端、服务端、连接池、锁等待、事件循环、CPU和内存原始证据。

阿里云候选最低性能门禁：

| 指标 | 门禁 |
|---|---:|
| 业务5xx | 0 |
| 员工登录至首屏API旅程P95/P99 | 500ms / 800ms |
| 缓存启动P95/P99 | 150ms / 300ms |
| 客户会话P95/P99 | 500ms / 800ms |
| 连接池获取P95 | 50ms |
| 连接池等待/失败 | 0 / 0 |
| 事件循环P95/P99 | 硬门禁75ms / 100ms，50ms为理想值 |
| 写队列拒绝/超时 | 0 / 0 |

通过条件：关键路由P95每轮至少300个成功样本；用于正式P99容量判断时至少1000个成功样本并重复3轮。数据无重复、回退或跨实例不一致，压测机能够维持目标到达率，候选资源没有持续饱和。

## 阶段D：现场P0/P1验收

由实际岗位使用真实设备完成，并把时间、人员、订单号、照片或回执写入TC：

1. 星驿真实小额支付、回调、查单、撤销、部分退款、重复回调和日结对账。
2. 酒水与小吃两台物理打印机分流、断纸、离线、补打和恢复。
3. iPhone、Android、平板、微信内浏览器在正常网、弱网、断网重连下操作。
4. 客户呼叫、员工替补、KDS制作、取货配送、取消出品和经理接管完整流转。
5. 预约、自选座位、锁台、到店、迟到、换桌、取消和重复预约冲突。
6. 连续至少3个20:30至02:00真实营业晚班，观察300人规模下的错误率、延迟、资源和员工操作负担。

通过条件：所有P0/P1 TC有真实结果和证据，失败项形成缺陷并回归；不允许以“代码支持”代替现场通过。

## 阶段E：切流与回滚

1. 切流前再次记录数据库备份、旧容器摘要和新容器摘要。
2. 先小比例或内部流量，再切全部验证流量。
3. 切流后连续观察5xx、延迟、连接池、队列、CPU、内存和容器重启。
4. 实际执行一次回滚演练，确认旧版可恢复且数据库变化兼容。
5. 生成部署证据总账，并用`--require-deployment`校验镜像摘要、提交一致性和回滚结果。

## 立即回滚条件

- 资金、权限、库存或订单状态错误。
- 重复扣款、重复出品、任务状态回退或跨实例状态不一致。
- 持续5xx、连接池耗尽、队列拒绝、OOM或容器反复重启。
- P95/P99持续超过硬门禁，且无法在观察窗口内恢复。
- 员工无法完成开台、下单、出品、配送或收银核心流程。

## 交付证据

- GitHub CI质量总账及SHA256。
- 不可变镜像发布清单及镜像摘要。
- 数据库备份、迁移和RLS报告。
- 阿里云负载、日志、资源和运行指标报告。
- P0/P1现场TC逐条结果。
- 切流与回滚记录。

缺少任一资金、权限、数据库或回滚证据时，只能保留验证环境，不批准商业生产。
