# 护古：运营负责人系统与工作说明书

## 岗位目标

把老板的经营要求转化为当日可执行规则，监督店长完成服务、出品、收银、库存、会员和演出闭环。护古拥有全店运营查看、配置、审批、日结和异常接管权限，但账号与身份管理由乌鸦负责。

## 首页先看什么

1. SLA风险：即将超时或已经超时的服务任务。
2. 升级任务：主责和候补都没有按时处理的事项。
3. KDS拥堵：吧台或后厨是否出现集中超时。
4. 待审批：赠送、折扣、退款、库存调整和权益。
5. 未结桌账与待对账：不能拖到关店后才发现。

## 功能与场景

| 功能 | 操作原则 | 典型场景 |
|---|---|---|
| 配置 | 修改后保存草稿、复核影响、发布新版本 | SLA从15分钟调整为12分钟 |
| 主数据 | 调整岗位、班次、责任区和经营授权 | Tyke当晚改为全店候补 |
| 任务 | 改派、接管、检查完成证据 | 服务员忙碌导致投诉升级 |
| 订单/KDS | 审批折扣赠送、安排补做、看出品瓶颈 | 错品需要补做并保留原单 |
| 库存 | 盘点、调整、损耗、存酒和预警审批 | 鸡尾酒基酒账实不符 |
| 支付 | 退款审批、对账和日结复核 | 物理POS已收但系统待对账 |
| 权益 | 审批赠送、发起召回、看通知失败 | 30天未到店会员召回 |
| 演出 | 复核排班和现场点歌异常 | 歌手临时无法履约需要退款 |

## 高峰调度案例

20:55，互动区同时出现3个呼叫，Jerry已有2个任务，Tyke空闲。

1. 在任务页确认优先级，投诉和身体不适优先于普通加水。
2. 将可替代任务交给Tyke，保留Jerry对原责任桌的主责关系。
3. 查看60秒接单和3分钟到桌目标是否恢复。
4. 超时原因记录为人员负荷，不把任务虚假完成。
5. 次日根据记录调整区域主责或候补规则。

## 审批边界

运营负责人可在系统配置额度内批准赠送、折扣、退款和库存调整；超出额度或涉及重大品牌、资金、合规风险时升级陈方宇。不得同一人发起并利用他人账号代为批准。
