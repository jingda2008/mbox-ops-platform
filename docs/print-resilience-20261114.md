# 打印桥诊断与有限自愈候选（2026-11-14）

## 状态与范围

基于 rc292 / 2b144c49 的隔离开发候选，分支 `feat/print-resilience-20261114`。未提交、推送、合并、部署、安装、配对、真实打印或发送外部消息。原1.0.12候选与用户本地修改不变。

新增诊断模块为 `1.0.13-candidate`，**不是可直接覆盖门店1.0.11的发布包**。仓库历史renderer与门店版本不同；正式包必须由已验证门店1.0.11基线窄移植，保留票据布局、RAW字节、配对、journal并做安装回滚测试。现行RELEASE-HOLD仍有效。supervisor仅为候选，不改WinSW服务模板、不自动启用。

## 实现

- 桥主动HTTPS上传允许字段事件，使用既有桥身份；不开放入站端口、任意命令或远程文件访问。
- 缓存以原子写入持久化，最多2000事件、7天；按事件ID逐批确认。丢回执保留相同ID，服务端幂等去重。溢出/过期/损坏通过diagnostic_gap显式报告；损坏文件仅保留一份本地隔离，不上传原始内容。gapCount上限100万，超过表示至少该数量。
- 诊断上传在打印循环失败后仍尝试；失败退避，不把原始异常/命令行/票据/凭据上报。
- 防重打journal独立于诊断缓存。无效journal不当空记录，阻止打印并上报任务不明故障。已提交结果先持久化，网络回报失败不改成可重打。
- `spool_accepted`仅代表提交成功，不证明物理出纸；结束调用失败、超时与未知结果不自动补打。现有明确未提交的有限重试边界保持。
- supervisor固定运行本地桥；120秒无有效进度才终止固定子进程树。10分钟最多两次恢复；预算持久化。耗尽、损坏、时钟回拨、无法确认终止或在途自然退出时闭锁。不清打印队列、不清journal、不重启电脑或Spooler。
- 进度在每个HTTPS步骤前和循环/退避边界更新，避免长但仍推进的循环被误杀。恢复状态本地记录，桥重启后上报；停止时无法即时上传，由后台失联检测兜底。
- schema315增加门店隔离事件与故障表。字段白名单、桥所属任务校验、冲突检测、未来时钟标记、30天分批清理。
- 既有worker持续检测active桥超过120秒未心跳（含从未心跳），只在存在待处理打印任务时建立故障。不是对所有休业设备无条件报警。
- 员工设备页显示持久故障，15秒可见页刷新；认领、人工核验、未出纸待补救。设备恢复不能代替有任务的实体纸票确认。1分钟未认领升级领班、3分钟升级管理员是后台等级，不等于已发微信/短信。
- 外发渠道未配置/未发送。页面关闭不能保证人员收到通知；需另确认管理员/服务员接收渠道与接收人并验证实际送达。本文不能当作外发已开通。
