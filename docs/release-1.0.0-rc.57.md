# M-BOX 1.0.0-rc.57 退款审批与AI资金权限修复

## 本次范围

- 修复验证环境已有退款申请无法显示审批动作的问题，使服务端支付模拟能力与前端保持一致。
- 退款申请人不能审批本人申请；只有具备退款审批权限、额度足够且不是申请人的员工可以处理。
- 待处理退款显示申请人、状态、候选审批人和具体交接说明；同一商品重复申请返回明确冲突，不再显示通用数量错误。
- 乌鸦等不具备收款权限的岗位不再加载收银结算、显示现金收款按钮或由AI生成必然失败的执行计划。
- “生成／创建现金收款单”等自然语言统一归为受保护的人工财务流程，AI只能说明权限和交接对象。
- 已接管的预约风险从当前警报和AI规划上下文移除，保留在交班记录中，不再持续重复提示。

## 验证要求

- 乌鸦输入“生成现金收款单”时，AI必须明确说明无权限，且不得出现执行计划或确认按钮。
- 李艳发起的退款必须由另一名具备审批权限且额度足够的员工处理，系统不得自动审批。
- 同一订单商品已有待处理退款时，再次申请必须返回`REFUND_ALREADY_PENDING`和具体申请人提示。
- 验证环境的模拟微信退款、物理POS退款和服务商退款必须按支付渠道显示对应人工动作。
- 预约被确认或接管后不得继续作为未处理风险进入AI提示，交班统计仍保留历史。
- 收银、退款、预约和AI页面在手机及桌面端不得出现无权限但可点击的控制。

## 发布边界

本版本只部署到阿里云验证环境。退款不会由AI或系统管理员自动批准；真实微信／星驿退款、物理POS退款、现金日结与对账仍需真实渠道和岗位验收。现有待处理退款在发布后继续保留原状态，由不同于申请人的有权员工人工审批。
