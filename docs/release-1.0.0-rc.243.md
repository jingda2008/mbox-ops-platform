# 1.0.0-rc.243 支付宝重复授权手机号入会

包含已合并的 PR #317（`dd0e73b25dc881ca900d6f5fd35173ba0e64fa61`）。生产 rc.242 上，支付宝小程序勾选协议后点「确定加入并授权手机号」，`POST /api/public/mini/membership/enroll-with-phone` 连续返回 500。支付宝手机号密文在固定密钥和零 IV 下对同一号码稳定，旧实现把该摘要写成全店唯一授权引用，再次授权或撞上其他顾客、已撤销、已处置记录时违反 `customer_verified_contact_actions_authorization_reference_uq`。

本版每次授权使用独立引用，并用 schema 251 的 `repeatable_proof_sha256` 认出同一个支付宝手机号。该列只可插入、不可更新，不是明文号码。同一顾客再次授权直接复用；已有 6 位会员并入原会员；未绑定的有效手机号改挂到当前顾客。一次性微信授权码仍然占用全店唯一引用，跨顾客重放返回 409。核验来源仍是 `wechat_phone_authorization`，已发布小程序不必为入会成功重新上传。新的中文错误文案要等支付宝小程序重新上传后才替换「登录暂时没有完成」。本标签不上传微信或支付宝小程序，也不向隐私政策已发布记录写入新行。

迁移 `251_alipay_repeatable_phone_proof.sql` 成功后 schema 版本为 251。最低可读 schema 251。服务端发布包只含员工网页、规范化服务和数据库，明确排除微信小程序。

回滚目标是应用版本 `v1.0.0-rc.242`（提交 `1a9c5851ffd4d5ade8e566e986a2eadc6e406adb`，schema 250）。schema 251 只增加可空列和列级授权，并替换联系方式版本保护函数；不要用覆盖数据库的方式回滚经营事实。旧程序不读取该列，应用回退后库可以留在 251。

经营 TC 登记仍按既有口径保持未执行/阻塞，不把本候选写成全部 P0/P1 已通过。标签 CI、不可变产物和生产切换另记；本文件建立时尚未部署。MEMBER-20260928-01 继续开放。
