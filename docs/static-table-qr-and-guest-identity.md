# 固定桌码、员工日验证与匿名顾客识别

## 固定桌面二维码

- 桌贴二维码是长期静态凭证，不包含桌次ID和到期时间，打印后无需每天更换。
- 客人扫码后，服务端根据当前已开桌次签发最长60分钟的短会话；页面轮询会续签短会话，但不会修改实体桌码。
- 结台、翻台、转桌、桌次冻结后，旧短会话立即不能访问新一桌的数据。
- 某一桌桌码遗失或被拍照滥用时，只提高该桌 `qrTokenVersion` 并重印该桌，其他桌码不受影响。
- 正式二维码默认输出目录固定为 `private/table-qrs/<storeCode>/permanent`，禁止按营业日重复生成。

## 员工每日验证

- 门店验证口令成功后，服务端签发“当日门店凭证”，有效至下一个北京时间零点。
- 同一设备切换员工时保留当日门店凭证，只要求新员工输入自己的PIN。
- 北京时间跨日后，门店凭证自动失效；员工下一次选择或登录时必须重新输入门店口令。
- 门店凭证不能代替员工PIN，也不能直接调用员工业务接口。

## 未注册顾客身份

- 首次打开顾客端时生成随机匿名ID，保存在该浏览器或微信WebView的第一方本地存储中。
- 不采集浏览器指纹，不使用人脸来推断身份，不把完整手机号、服务备注或自由文本写入行为分析属性。
- 每条行为记录同时带匿名ID、桌次ID、桌号、营业日、北京时间、来源和幂等键。
- 当前记录扫码入桌、页面功能、情绪、服务、服务反馈、菜单分类、商品增减、购物车、下单、付款、歌手资料和点歌。
- 服务员协助点单时生成稳定的“本次到店ID”，订单行为仍可按桌次分析。

## 微信与会员合并

- 小程序微信登录接口接受可选 `anonymousGuestId`。
- 微信认证成功后，匿名档案关联内部微信主体ID；以后绑定会员时再关联 `memberId`。
- 原始 `openid/unionid` 仍由现有加密身份库管理，行为库只保存内部主体ID。
- 同一个微信主体可关联多个设备匿名ID，分析时可以合并为同一顾客，但原始事件保持不变以便审计。

## 数据边界

- 完全没有扫码、微信登录、手机号或人工客户码时，只能识别“某桌某次到店”，不能可靠识别为跨次到店的同一个人。
- 当前验证环境保留原始事件且不自动删除；正式商业化前必须配置隐私告知、查询权限、导出脱敏、删除/撤回流程和原始事件保留期限。
