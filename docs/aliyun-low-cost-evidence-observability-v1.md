## 新增资源

仅允许新增或启用以下按量资源：

1. 复用私有 OSS Bucket `m-box` 的 `mbox/` 前缀。
2. 一个上海地域 SLS 项目，默认候选名 `mbox-validation-139224254060`。
3. 三个单分片 Logstore：`runtime-errors`、`payment-audit`、`release-audit`。
4. ECS 实例 RAM 角色，使用临时 STS 凭证。禁止长期 AccessKey。

不新增 ECS、RDS、ACR、SLB、Redis、CDN、WAF、ACK。

## OSS 目录与保留

| 目录 | 内容 | 保留 |

| `mbox/evidence/temp/` | 临时探针和测试证据 | 14 天 |

Bucket 必须为私有、阻断公共访问、启用版本控制和 SSE-OSS/AES256。当前阶段不启用 Bucket WORM。所有正式上传均逐文件回读，并校验字节数和 SHA256。

## SLS 采集边界

- `runtime-errors`，7 天：HTTP 5xx、数据库连接池等待或超时、容器启动/重启/OOM。
- `payment-audit`，90 天：支付、退款、回调异常。
- `release-audit`，90 天：部署、切流、回滚、权限拒绝和关键审计事件。

不采集图片、请求正文、响应正文、堆栈全文、Cookie、Token、支付密钥、身份证或完整手机号。关闭全文索引，只索引必要字段。宿主机定时器每 2 分钟触发一次，脱敏过滤复用应用容器内已有的 Node.js，每轮最多 500 条、512 KiB；发送失败保留队列，不进入客户或员工请求链路。

正式证据包只允许可检查的文本和结构化报告；截图、录屏、音频、PDF 与 `.env` 文件一律拒绝上传，避免二进制证据夹带客户隐私或凭证。Docker 镜像使用独立的受控镜像目录与摘要校验，不混入测试证据包。

## 发布门槛

正式流程固定为：准确提交的 CI 通过 → 构建证据包 → 敏感信息扫描 → 本地 SHA256 校验 → ECS 使用实例 RAM 角色上传 OSS → 从 OSS 回读并重新校验 → 上传可回滚镜像 → 创建并上传数据库备份 → 候选容器验证 → 切流 → 上传部署结果。

GitHub 制品只是短期转运：PR 成功证据 3 天、失败诊断 7 天、main 和标签转运 14 天。GitHub 上传失败不篡改测试结论；正式 OSS 上传或回读校验失败则禁止部署。

## 成本控制

- OSS 只保留规定前缀和期限，不保留无限历史镜像。
- SLS 各 Logstore 固定 1 个分片，不开全文索引，限制事件种类、频率和每轮体积。
- 验证阶段建议 OSS 与 SLS 合计月预算先设 30 元，50%、80%、100% 告警。预算管理需在费用与成本控制台首次免费开通并指定收件人，不能由 ECS 运行角色代替账户所有人完成。
- 阿里云费用告警是通知，不是硬性消费上限；账单数据存在延迟，仍需每周复核实际用量。

## 权限与风险

- 运行角色只允许访问 `m-box/mbox/*` 和三个指定 Logstore。
- Bootstrap 权限仅在首次配置时临时附加；完成后移除，保留运行权限。
- 新建 SLS 项目后最多等待 120 秒完成服务传播；新建 Logstore 最多等待 60 秒。超时立即停止，不继续写索引或发布。
- 已存在的 Logstore 必须逐一核对保留天数、分片数和自动分裂开关；与期望配置不一致时停止并人工确认，不静默覆盖既有数据策略。
- 最大风险是错误覆盖现有 Bucket 生命周期。脚本检测到非 M-BOX 生命周期规则会停止，不自动覆盖。
- SLS 项目名全局唯一，默认候选名必须经真实账户查询确认。
- 当前代码完成不代表云资源已完成；只有 bootstrap 报告、OSS 回读报告和 SLS 检索报告全部通过后，才能标记为已启用。

## 回滚

1. 应用失败：自动恢复上一个容器并重载 Caddy。
2. 数据库迁移异常：使用该提交部署前上传的 `mbox/backups/<date>/<sha>/` 备份人工恢复。
3. SLS 采集异常：停止 `mbox-sls-collector.timer`，不影响业务请求。
4. OSS/SLS 配置回退：先停采集器，保留审计证据；移除 ECS Bootstrap 权限，不删除仍在保留期内的发布证据。
