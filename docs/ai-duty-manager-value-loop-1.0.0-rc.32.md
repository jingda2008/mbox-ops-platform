# AI值班经理价值闭环 RC.32

## 目标

让AI值班经理不仅提示问题，还能把任务交给更合适的人，并用营业日数据回答“今天服务是否更快、更稳、SOP是否真正执行”。

## 本版能力

- 明确指定员工时优先执行配置；未指定时在桌台主服务员和候补中选择当前开放任务更少的人。
- 同负荷时保持主责优先；人员离线、暂停或达到岗位并发上限后，才进入其他匹配岗位和经理候补。
- 新建、重新派发、员工离线、客户反馈未解决和SLA升级都使用同一套负荷选择逻辑。
- 每次自动派单记录候选来源、派单前负荷、岗位容量和负荷比例，支持复盘与追责。
- AI值班经理展示首响中位数、按时响应率、服务闭环率、自动派单率、SOP闭环率和升级率。
- 当前营业日与前一营业日样本均达到3条后，系统给出改善、持平或下降趋势。
- 数据样本不足、按时响应偏低、升级率偏高或SOP阻塞时，显示对应的现场建议。

## 指标口径

| 指标 | 计算口径 |
| --- | --- |
| 首响中位 | 服务创建到员工接单的耗时中位数 |
| 按时响应 | 在首响SLA内接单的任务数 / 已接单或已超过首响截止时间的任务数；未到截止时间的不提前判失败 |
| 服务闭环 | 已完成服务任务数 / 当日服务任务数 |
| 自动派单 | 创建时已匹配责任人的任务数 / 当日服务任务数 |
| SOP闭环 | 已完成SOP执行数 / 当日SOP执行数 |
| 升级率 | 发生过SLA升级的任务数 / 当日服务任务数 |

所有指标按北京时间和早上6点营业日切换规则计算，历史营业日只用于比较和经营分析，不回流实时任务队列。

## 决策边界

- 大模型负责理解自然语言、解释数据和提出建议，不直接绕过权限执行操作。
- 派单、SLA、权限、营业日和指标计算由确定性规则执行，模型不可自行修改。
- AI不会根据少量样本自动改SOP；规则调整仍需有权人员确认、发布并保留版本。
- 自动派单仅选择在线、未暂停、岗位匹配、数据范围匹配且未达到并发上限的员工。

## 验收重点

1. 主服务员已有任务而候补空闲时，新服务派给候补；两人同负荷时回到主责。
2. 后台明确指定的合格员工仍优先，不被自动均衡覆盖。
3. 派单事件包含完整选择依据，SLA升级与离线重派使用同样口径。
4. 李艳在iPhone 14 Pro Max宽度打开AI值班经理，可直接看见今日成效且页面无横向溢出。
5. 指标严格按营业日计算，当日和前日各至少3条任务形成首响结果后才判断跨日趋势。

## 发布边界

RC.32通过后仍属于验证版本。真实支付、真实打印机、耳机、摄像头、门店网络和现场岗位验收不由代码测试替代；213条经营验收基线中的外部阻塞项清零前，PR继续保持草稿状态。
