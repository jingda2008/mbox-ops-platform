## 已发现并修复

1. **全店/活动到期额度不一致（19）**：未绑定券时间已过但后台过期任务尚未运行时，活动已释放承诺额度，全店仍占用，导致正常领券被拒。全店、活动延期/替换核验统一按有效时间统计；已绑定/已兑现仍占用，N/K发行历史不恢复。
2. **顾客预览与实际领取不一致（19）**：预览检查次数但没检查金额与全店额度；现增加只读核验，不扣券、不锁定额度，最终领取仍在事务内重检，预览不保证并发下仍有余量。
3. **配置合同/请求容量不一致（20）**：网页可以提交后端拒绝的短名称、超过100万全店次数；新增共享校验合同与输入约束。合法500个适用商品/500个计佣商品超过旧16KiB上限；只将批次接口放到512KiB，继续保留字段数量与超限请求拒绝。2000汉字跟进记录可超过原4KiB，跟进接口改为16KiB。
4. **跨账号草稿残留（21）**：切换账号只清优惠商品、未清计佣商品，且非受控表单保留旧值；现清计佣选择，并按会话重建表单。
5. **邀请码/合作跟进实际HTTP失败（22）**：缺少审计事件必要内容，整个命令回滚；真实HTTP跟进失败后定位到 `audit event requires beforeData, afterData, or reason`。两种同路径操作补充审计记录ID和操作类型，不将邀请码秘密写进审计；补HTTP原回执重放、邀请接受和所有跟进状态测试。

## 多优惠和金额口径（当前实现）

- 单个批次只能选一种优惠。同一推荐人、同一活动的多个批次/多张券，可在L范围内共同生效；不同来源或活动不能直接混绑。
- 两张八五折按各自原适用金额减15%后相加。100元各减15元，共付70元；不是85%×85%。两券各封顶20元时，之后再消费100元仅余各5元，总共再减10元。后台已增加说明，通常L=1便于控制。
- 两张80元金额券用于100元：先减80，再减20，应付0；第二张剩余60元可用于同客组后续符合条件的加单，不能凭空多退或负价。
- 折扣加赠品通过两张同来源同活动券组合，L至少2；赠品不会再作为折扣消费基数，重复出品保持同一原单。
- 渠道报价与会员券/会员卡价/积分价格选择互斥；新增小程序会员券/积分切换到渠道及再切回积分测试。
- 金额成本上限是发券承诺：折扣按每券最高减免、金额券按券额、赠品按档案总成本预占；不是只按当次已用金额，亦不是包含佣金、人工租金的全部营销开支。
- 承诺份数按券承诺计数，赠品实际件数另受库存控制；总发行数不会因正常到期恢复。已绑定有效承诺不因为停发或时钟到期而被抹除。
- 两个入口、二维码和优惠号码共享N/K；L随连续客组走，转桌/拆桌不重置。退款冲减净收与佣金，不恢复已兑现优惠。
