# M-BOX 高级SOP编排与AI值班经理 1.0.0-rc.19

## 本版目标

`rc.19`把复杂SOP从固定顺序升级为可配置的步骤图，并增加不依赖大模型判断的AI值班经理巡场简报。模型仍只负责理解和生成建议计划；任何实际操作继续经过员工身份、岗位权限、数据范围、实时页面状态、确认和审计链。

## 高级SOP编排

- 旧规则保持原顺序和计时语义，不要求重新配置。
- 每一步可选择前置步骤，支持“全部完成”或“任一步完成”后继续。
- 多个步骤可依赖同一步骤，从而并行派发酒水关怀、桌面整理等工作。
- 每一步可独立判断未点单、未付款、主服务员满负荷、出品未完成或未送达。
- 条件不满足时可选择跳过，或作为失败进入停止、继续、补偿流程。
- 失败补偿步骤平时休眠，只在指定源步骤失败后启动。
- 循环依赖、自依赖、无效引用和错误补偿目标在保存发布前被拒绝。
- 经理复核、桌码到桌验证、摄像头证据继续复用原SOP验证链。

## AI值班经理

- `GET /api/assistant/briefing`按当前员工数据范围返回确定性巡场简报。
- 风险来源包括营业日未切换、服务SLA、出品制作/取送SLA、占用桌台责任人、SOP阻塞、待复核/联调异常和今日未确认预约。
- 简报营业日始终按北京时间计算；数据库营业日滞后时必须显示紧急系统风险，不能把旧营业日静默当成今天。
- 风险按紧急、高风险、关注分级，并给出桌台、责任人、事实说明和建议入口。
- 对话上下文同步注入同一份风险事实；模型不能绕过权限直接写数据。
- 即使模型服务关闭，巡场简报仍可正常工作；员工仍可使用原快速命令。

## 回归验收

| 编号 | 场景 | 预期 |
|---|---|---|
| SOP19-01 | 旧顺序SOP执行 | 顺序、延时和停止条件不变 |
| SOP19-02 | 两步骤依赖同一前置 | 前置完成后两条分支同时派发 |
| SOP19-03 | 多前置全部完成 | 所有前置完成后才执行 |
| SOP19-04 | 多前置任一完成 | 第一条满足的分支完成后即可执行 |
| SOP19-05 | 步骤条件不符并跳过 | 不创建任务，后续可继续 |
| SOP19-06 | 步骤条件不符并阻塞 | 按本步骤失败策略处理 |
| SOP19-07 | 主步骤失败并补偿 | 补偿步骤被唤醒，原失败留痕 |
| SOP19-08 | 配置循环依赖 | 草稿校验失败，不允许发布 |
| SOP19-09 | 历史执行快照加载 | 缺少新字段时自动补默认值 |
| DUTY19-01 | 服务经理接管超时 | 简报显示紧急风险和桌台 |
| DUTY19-02 | 酒水制作或取送超时 | 简报按逾期时长分级 |
| DUTY19-03 | 模型接口关闭 | 巡场简报可用，对话明确降级 |
| DUTY19-04 | 服务员与店长查看简报 | 分别只看到授权数据范围 |
| DUTY19-05 | 点击风险请求处理 | 进入自然语言计划，执行前仍确认 |
| DUTY19-06 | 数据库营业日未切换 | 显示北京时间当前营业日并产生紧急系统风险 |

## 发布边界

本版继续使用支付验证模式。外部耳机、企业微信、摄像头和正式模型密钥是否可用，以运行参数和就绪检查为准；未配置时必须显示待联调或降级，不得伪报成功。213条经营TC仍是商业发布门禁，未执行或阻塞项不会因本次工程升级自动变成通过。
