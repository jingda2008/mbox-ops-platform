# M-BOX 员工原生 App

Android 当前正式签名候选为 **0.4.0-rc.3 / build 8**，默认进入真实员工登录，没有演练入口；身份和设备核验成功后读取生产门店业务。iOS仍沿用各自历史交付状态。本轮不改网页或后端合同。

当前 Android 商用修复、验证和交付边界见 [2026-10-05商用检查表](COMMERCIAL_READINESS_ANDROID_20261005.md)。现有核心营业模块已接入；正式签名构建与本地回归不等于多品牌真机、真实收退款、纸票及整班验收。供应商采购退货已由用户明确排除出本轮范围。

下方保留早期0.2工程预览到后续开发的历史记录，演练、版本号和“尚未部署”等描述只适用于记录当时，不作为当前Android安装说明。当前安装步骤以上述商用检查表为准。

## 使用

两台现有模拟器已安装名为「M-BOX 原生」的新应用，和旧设计样例使用不同包名。

- iOS：打开 `ios/MBOXStaff.xcodeproj`，选择 MBOXStaff 与 iPhone 模拟器。最低 iOS 17。
- Android：打开 `android/` Gradle 工程。最低 Android 8 / API 26，编译及目标 API 36。
- 首页先显示营业中桌台，已结清仍在座。A8、A9 初始为空桌；B2 为原款未知的阻断样例。
- 完整演练：开台 → 点单/选择规格 → 提交 → 记录现金 → 确认送达 → 结束用餐。
- 「更多」可模拟下一次回执中断，再使用「核对原操作结果」恢复；保留原请求编号，重复恢复不重复记账。
- 本机演练数据、草稿、请求日志在重启后保留。重置需要确认，存在未决请求时禁止重置。

## 实现约束

金额统一使用整数分，输入只接受最多两位小数；找零不计入已收。付款结果未知不能再次收款；结清与释放桌台分开。所有演练命令含桌次和请求编号，同一编号更换载荷被拒绝。草稿随桌次转台，不可跨桌次复用。

演练库存/套餐只是示例选项，不等同于服务器套餐组、库存占用和出品合同。真实查询缺少金额时显示「待核对」，不填成零。真实 PIN 和门店日口令不落盘。默认仅本次登录；用户勾选记住登录后，iOS Keychain / Android Keystore加密存储有期限的会话Cookie，重启必须由服务器重新校验身份与租约。网络不明保留安全记录，失效/撤权清除并保留原员工未决操作隔离。真机与真实账号验收仍开放。

真实商品、自选套餐、下单、线下收款与出品取餐已接入。订单指纹包含会话和租约：原publicId查询确认成功才清理草稿，同登录且同营业日才允许原请求重放；跨登录查无结果保留未知。取餐使用服务端原设备恢复接口。客户端金额规则不能代替真实账本。

## 桌号模糊搜索

支持桌号包含匹配（如 A、5、A5），忽略大小写和首尾空白，与营业中/空闲筛选同时生效。有关键词时完整命中优先，其余匹配结果保留已开台优先；清空关键词恢复首页排序。只搜索桌号，不匹配账单金额或商品信息。
