# M-BOX 1.0.0-rc.130

## Scope

This release candidate supersedes `1.0.0-rc.129` for the normalized staff web,
service and database bundle. It makes the production release evidence relay
more resilient without changing business, payment, inventory or customer data
behaviour.

The application host remains deliberately unable to write directly to OSS. The
release controller waits for the separately authorised relay to upload and
read-back deployment evidence, then records completion only after that second
evidence archive is verified and the new release has become canonical.

This release does not build, upload or replace the native WeChat mini-program
package.

## Acceptance boundary

The exact candidate must pass immutable CI quality, PostgreSQL transaction,
browser, performance and release-metadata gates. Production verification must
confirm the exact SHA, image digest, schema `138`, worker health, public
readiness, migration outcome and both verified evidence archives.

Local and CI checks do not claim a completed real provider payment, physical
POS, printer, hardware, staffed-field shift or native WeChat upload.

## Production route

The public origin is `https://mbox.shmbox.com`. Deployment uses the immutable
GitHub pre-release, the private application host `10.100.80.223:22` through
the configured relay `139.224.254.60:6122`, and the existing backup,
migration, candidate-health and rollback safeguards.

## Deployment evidence

Commit, CI run, release asset, image digest, backup and production verification
identities are generated by the immutable release and deployment workflows.
They must not be pre-filled before those workflows finish.
