# 2026-09-23 小程序加购后无法下单

## 已确认的现场证据

- 线上运行版本为 rc.225，提交 `3280275e450ffea48dce2eb70b01557ba1f5abbd`。本地修复基于主线 `b153a42c`，使用独立工作树。
- 现场访问日志中，C05、A01、B02、B03、A07 等桌加购返回 200，下单反复返回 409。近期最多 40000 条访问日志样本中，微信挑战接口 261 次返回 201，身份认证接口 259 次返回 503；这不是全日统计。
- 生产只读查询显示，最近两小时创建的 47 个桌台访客会话均没有直接关联的微信付款身份，且对应顾客没有合并到其他顾客。最近两小时订单样本只有员工代客单。桌次均使用购物车协议 2，未冻结购物车。
- 微信身份和付款配置存在、AppID 一致，旧身份密文可正常解密。使用独立无效诊断 code 的微信请求正常返回 code 无效，不能据此声称完成真实微信登录。
- 在真实生产运行账号下，仅对原身份保存 SQL 执行 `EXPLAIN`（没有执行写入），复现 PostgreSQL `42501: permission denied for table wechat_identities`。`principal_id` 不允许更新；原 SQL 的 `ON CONFLICT DO UPDATE` 却包含该列，即使新客首次插入也会先被权限检查拒绝。
- 隔离 PostgreSQL 按全部 242 条迁移建立权限，使用独立 `NOSUPERUSER NOBYPASSRLS` 运行账号，通过真实登录 API 复现 `503 IDENTITY_STORE_UNAVAILABLE` 及相同权限错误。微信上游在此测试中使用明确的测试替身。

## 修复

身份保存只更新原本允许更新的凭据字段，不再更新 `principal_id`。冲突更新必须匹配原主体及原外部身份 ID；不匹配则拒绝并回滚，避免把并发新身份误当成已保存成功。数据库授权、历史数据、小程序包和数据库 schema 均不需要调整。

## 本地验证

- 新客与老客完整登录接口、加密会话读取、顾客关联到微信付款身份、错误 AppID 拒绝、身份主体与外部 ID 冲突拒绝、跨门店写入拒绝、运行账号不能重绑定或删除身份：4 项受限 PostgreSQL 集成测试通过。
- 上述测试及微信适配器、身份服务、登录 API、顾客购物车/下单 API 回归共 98 项通过；修复前集成测试已复现失败。
- 服务端类型检查、生产构建、架构约束、商业化清单和差异格式检查通过。构建保留原有动态导入和大分包提示。

## 生效与现场恢复边界

首个修复已合并PR #285，但rc.226固定标签CI暴露付款身份查询依赖pgcrypto函数路径的兼容问题（2710通过、1失败），未部署。rc.227候选改用内建SHA256；固定pg_catalog路径后修复前失败、修复后相关98项回归通过，同时覆盖通知身份解析及越权拒绝。正式发布待完成。正式发布后，已进入匿名桌台会话的顾客需要重新扫码，以重新获取微信身份并绑定当前桌次；共享购物车不需要清空。真实微信登录、实际下单和渠道付款仍需在发布后逐层回读，不能用本地模拟替代。

现场可暂由员工代客点单，收款须沿现有流程核对实际到账，不因重复点击或支付尝试存在就视为收款。

本轮未修改生产业务数据或权限。仅创建了一个独立短期登录挑战并以无效诊断 code 验证认证链路，没有创建顾客身份、订单或付款。
