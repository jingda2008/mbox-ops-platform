# M-BOX 1.0.0-rc.61 员工点单锁桌与客户服务边界升级

## 员工协助点单

- 点击“全屏点单”后必须先选择并确认已开台桌号。
- 进入点单后桌号锁定，不提供切换控件，也不会在桌台状态变化时静默切换到其他桌。
- 更换桌号必须由当前登录员工输入本人PIN退出，再重新选择桌台。
- 验证退出后清空未提交购物车和原桌号，避免下一桌沿用上一桌数据。
- 从现场具体桌台进入点单时可以预填该桌，但仍需员工确认。

## 客户情绪与员工协作

- 客户点击情绪只写入当前桌次的行为记录和桌面状态，不再生成需要服务员接单、到桌、完成的服务任务。
- 需要上级或其他岗位配合的员工操作显示责任人、下一步和原因，并自动把页面移动到可执行提示位置。
- 保留客户行为数据用于服务复盘，同时避免低价值提醒挤占员工任务台。

## 测试与风险边界

- 新增客户操作、异常要求、模拟支付和复杂退单专项测试。
- 无理要求不能自动触发赠送、免单、改价、退款或越权操作。
- 退款继续执行人工审批、申请人与审批人分离、额度校验和渠道确认。
- 本次没有数据库结构迁移，不修改既有订单、支付、退款、库存、预约和历史桌次。
- 当前真实微信、星驿支付、退款、物理POS和日结仍未完成生产联调。
- 213条经营TC仍有66条发布阻塞项，本版本只批准阿里云验证环境使用，不代表正式商业生产验收完成。

## 发布与回滚

- 发布目标：阿里云验证环境。
- 发布镜像必须来自主分支成功CI的不可变镜像资产。
- 候选容器通过就绪、提交SHA、镜像摘要和数据库投影一致性验证后才能切流。
- 异常时回滚至上一已验证容器。
