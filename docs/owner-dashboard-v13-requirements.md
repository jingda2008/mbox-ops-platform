## 3. 已确定的共用规则

1. 沿用门店现有时区和营业日规则。当前门店为 Asia/Shanghai、06:00切日；实现读取现有配置，不为仪表盘另设切日。

3. 同名指标在同一范围、同一归属规则和同一截止时刻下保持一致；不同口径明确名称及差异，不能强行把金额改到相等。
4. 未录入、未知、查询失败、无权限、实际为零分别显示。
5. 没发现已知缺口不等于财务已经关账。不得仅凭系统状态显示“数据已完整核对”或“最终利润已确认”。
6. 服务员不新增财务录入、费用分摊、利润核对或手机二次送达工作。
7. 权限配置与入口一致；提交时仍须重新校验权限、订单状态、库存等最新事实。会话过期、权限撤销或并发变化导致拒绝时，说明原因和下一步，不取消必要校验。
8. 正常操作复用原页面和流程；异常复用原查询、恢复、售后和记录，不新建异常工单平台。

## 5. 仪表盘入口与时间范围

复用员工网页现有经营入口。老板普通登录默认进入经营仪表盘，首次默认显示当前营业日；按第14节C01保留业务直达、专用屏及原操作恢复优先级。保留常用业务入口和返回路径，当前工作中返回仪表盘恢复原查询范围。

| 选择 | 有效统计范围 |
|---|---|
| 今日 | 当前营业日截至本次查询时刻。 |
| 本月、本年 | 当前营业日所属月或年起点至当前营业日截至查询时刻。 |
| 指定日期 | 所选营业日；当前营业日显示“截至当前”。 |
| 指定月份、指定年份 | 已结束期间取完整期间；当前期间截至当前，清楚标注。 |

- 不将未来期间没有业务显示为零；首期不提供未来实际经营查询或预测。
- 成本按已确定的日分摊粒度处理，不新增按小时分摊。当前月、年不得因选择整月、整年而将未来日期的费用算进“截至当前”。
- 收入、成本、利润、订单、销售和趋势共用所选有效期间；当前待办单独标注“截至现在”，不受历史期间隐藏。
- 页面显示期间、营业日范围、业务覆盖范围及更新时间。历史资料不足说明起点和缺口。
- 日期快速切换以最后选择为准；旧请求不得覆盖新范围。加载时不混用新旧指标。
- 有明确刷新入口，首期不要求秒级刷新。不同模块更新不一致时显示各自时间，不能宣称整页同一时点已核对。
- 返回列表恢复选择和位置后先核对最新数据；记住位置不等于使用旧金额继续交易。查看历史期间时进入当前待办处理，返回后恢复原历史范围、筛选和位置并更新结果，不自动重置为今日。

## 6. 页面内容与信息层次

老板第一屏保留六项主指标；手机依次排列，不要求六项同时挤入一屏：

| 指标 | 展示要求 |
|---|---|
| 经营收入（按订单归属） | 按已确认C06使用原购买记录营业日归属，明示业务覆盖；不称“已履约收入”或完整会计收入。 |
| 总经营成本 | 同期商品成本、经营费用和独立损耗，仅各计一次。 |
| 经营盈亏 | 显示盈利、亏损或持平；有已识别缺口时为暂估。不能仅称税后净利润。 |
| 实际净收 | 本期已确认收款减本期成功退款，不等于银行到账或账户余额。 |
| 退款金额 | 本期成功退款；待审批、待执行、处理中另列。 |
| 本期待收款 | 所选期间产生、截至查询时仍未收回的有效应收。 |

下方为经营概况、收入与成本明细、当前待处理。经营概况保留有可靠来源的有效订单数、已支付订单数及已有销售指标，按真实订单或购买记录去重，不按支付尝试次数计订单；不同业务对象分别说明，不把套餐份数称为人数或订单数。月度显示每日收入与成本趋势，年度显示每月趋势；单日以汇总和明细为主。无依据的接待人数、人均、预估转化或利润预测不展示。

“本期待收款”与“目前全部未收款”分开；后者包括历史有效欠款。同一订单的多次支付尝试不等于多笔欠款，待支付状态也不自动等于有效应收。历史期间的“截至现在仍待收”会随后续收款变化，不冒充当时的关账余额。

“全部未收款”及待办总数必须来自授权范围内的完整汇总，不能把列表前100条或当前页相加称作全部。详情列表可分页，并显示其范围；统计查询失败或范围受限时明示，不冒充全量数字。

当前待办分清待审核、待执行、正在核对和明确失败，并按权限给出具体入口。查看历史经营期间时，当前待办仍显示，标题与日期范围明确区分。活动待收款、待复核、待退款数字可直接筛选对应活动记录，并能返回全部；不让活动数字错误过滤普通订单。

不同岗位继续使用不同布局：顾客看图片、价格及可买状态；门口看核销结果、本份号码；后厨看菜品、数量和备注；送餐看号码、菜品及本批数量；管理者保留筛选明细。统一按钮语义、字体层级、颜色含义和点击区域，不统一信息密度、不自动频繁改变菜单顺序。

## 7. 金额与归属口径

### 7.1 必须消除的原稿歧义

- 现有利润服务的收入以对账流水关联订单营业日汇总，并不根据实际核销、制作或取走确认收入。本期按C06沿用这一管理统计口径，严格履约确认不属于本期；活动付款不能从普通订单查询推定已覆盖，须补齐原购买记录的来源与营业日映射。
- 现有利润服务的部分净额包含手续费与其他调整，而其他经营汇总主要按收退款计算。新仪表盘“实际净收”明确为收款减成功退款，不能直接把含其他项目的旧字段换个标签。
- 财务费用总览是筛选命中记录的整笔有效金额；利润报表使用期间应分摊金额。两者通过“原费用总额、本期计入、归属期间”追溯核对，不强制原始总额与本期费用相等。

### 7.2 指标规则

| 指标 | 规则 |
|---|---|
| 实际收款 | 本期已确认收款；未付、处理中、未知不计入。 |
| 成功退款 | 本期已确认退款成功金额；审批通过不计作成功。 |
| 实际净收 | 实际收款－成功退款。手续费和其他调整单独解释。 |
| 经营收入（按订单归属） | 仅依据有效账证，按原订单或活动购买记录的营业日归属；后续成功退款仍回到原购买归属期间。不把未付订单金额直接作为收入。 |
| 商品成本 | 普通订单复用原冻结成本及有效调整，活动购买补齐对应成本来源；按原业务归属汇总，说明是现有成本统计口径，不冒充逐份实物实际耗用。未知历史成本不以当前价格回算。 |
| 毛利润 | 经营收入－商品成本。 |
| 总经营成本 | 商品成本＋经营费用＋独立库存损耗，重复来源排除。 |
| 经营利润 | 经营收入－总经营成本。 |
| 经营利润率 | 经营利润÷经营收入；收入为零或负数时显示“—”及原因。 |

- 支付手续费归入经营费用，只扣一次；若原收入净额已经扣手续费，先按同一来源拆分再展示收入和费用，不能重复扣。无法可靠拆分时标明具体缺口，保留原始流水，不凭差额补账。
- 其他调整按原业务性质处理，不全部当收入、费用或欠款。
- 负净收、负收入、亏损允许真实显示，不强制归零。
- 金额存算沿用原最小货币单位，展示元、两位小数。分摊余数沿既有确定规则分配，完整期间之和等于原额。
- 未来日期、更正后的金额和明细分页不得导致同口径合计失真。打印使用同一范围和明确的生成时间。
- “收款成功”不自动等于银行已结算到账；银行余额、第三方券待结算及现金收支差额不混作净收或利润。

### 7.3 特殊业务

| 情况 | 处理要求 |
|---|---|
| 活动提前收款、核销 | 收款按发生期计净收；经营收入按原活动购买营业日归属，并保留未履约状态说明。核销、打印、取走不再次产生收入；本期不新增递延或按履约确认引擎。 |
| 活动套餐、纯加餐、单点 | 分别覆盖并保留原单关联；套餐与组成菜品收入、成本不重复。 |
| 储值，如已有 | 充值不是消费收入，储值消费不是第二次现金收入。 |
| 积分、优惠、赠送 | 不冒充现金收款；赠送仍可能有实际成本，沿原规则。 |
| 第三方券 | 消费、应收结算与实际到账分别处理，未结算不冒充已收现金。 |
| 采购与销售成本 | 采购付款不与售出商品成本重复扣除；采购来源费用正确排除。 |
| 损耗、退款菜品 | 已包含的损耗不重复计；退款不等于食材退回，成本冲回有对应依据。 |
| 取消、未付、部分退款 | 不把取消未付计为成功经营；部分退款不误作整单取消。 |
| 跨期退款 | 净收按成功退款发生期反映；经营收入按C04归属原购买营业日。保留原账证，历史期间汇总可随之后成功退款更新，不将这种更新误作改写原交易。 |

开发前逐一核对已开展业务的收入、费用、商品成本及损耗覆盖。无法覆盖全部业务时明确显示范围和暂估原因，不能把局部利润标为全店完整利润，也不能以提示缺失代替完成原定覆盖要求。本期只补既定订单归属口径所需的来源映射和必要字段，不扩成新的履约收入确认或会计系统。

### 7.4 活动来源和冻结成本的必要补齐

- 普通订单沿用提交时冻结的商品成本及套餐成本归集规则。商品改价、配方变更或当前库存成本变化不回算旧订单；库存出库、补做、损耗用于核对及识别独立新增成本，同一来源不重复累加。
- 活动报名、独立加餐、单点分别关联各自原购买记录的资金与成本，不创建虚拟普通订单或桌次。各笔加购按自身购买营业日归属，不继承父套餐日期，不用活动举办日、核销日或取餐号日期替代。
- 新活动购买补齐购买营业日和提交时成本快照，复用现有营业日与商品成本计算能力；套餐与组成菜品仅选择一个成本归集层，收入也不重复累计。重试沿原购买记录，不能刷新归属日或冻结成本。
- 活动制作时记录的库存成本不能冒充购买时冻结成本。旧记录只使用可核实的原始证据，缺失明确列出；禁止用当前成本或售价补造历史成本。
- 来源核对包括普通订单、合并支付、旧活动报名周期、v3报名和加购。旧报名再次报名可能更新登记时间，历史付款与退款须对应当时的购买周期，不能被新周期日期覆盖。
- 退款返回对应原购买来源；成本是否冲回仍看真实取消、使用和成本调整依据，不随退款金额机械归零。

这部分是本期必要的数据接入工作，不以“已复用普通订单报表”替代，也不扩展成新的核算系统。

## 8. 财务数据、费用维护与更正

- 复用现有费用分类、成本中心、周期费用、单金额录入、查询和更正入口。财务已有录入不重填。
- 一次只录一个金额，不新增含税、不含税拆分或自动税务计算；历史记录不重新解释或重算。
- 实际付款日期与费用归属期间分开。房租、工资等按C03统一复用既有服务期按日分摊，期间和总额只维护一次；不重复建立分摊任务。
- 只对实际缺项请求相应财务人员补充，不因未知是否完整而笼统提示“所有费用未录入”。
- 保留原记录、更正原因、操作者、时间，更正填写替代后的完整金额，不是增减差额；合计仅使用更正链最后一条有效记录。更正移到其他期间时，原期间不得恢复累计被替代记录；跨期更正可解释报表变化。
- 不按名称或金额相同自动删去疑似重复费用；核对业务来源后按原更正流程处理。重做追加成本与损耗同样沿来源核对，避免漏计或重复计。
- 复用已有的关账及更正规则；本期不新建关账、锁期或重开账系统。
- 商品成本缺失显示缺失项数和明细入口；未知成本不当零。确有依据为零时正常显示零。
- 未发现已识别缺口时写“按已入账数据计算”；有缺口时说明具体缺口及相关指标暂估，不承诺未知费用已全部录入。

商品管理可记住列表搜索、筛选、展开和返回位置；费用或商品编辑对象按原专用规则保存或清理，不把上一笔交易草稿带入下一笔。

## 9. 活动、兴趣卡及现场流程沿用与补充

- 员工扫码放在“全部”，进入一次后连续使用；完成当前顾客并切换下一位时清理上一交易对象，结果未知时先恢复原操作。
- 每份套餐最多N人，顾客填写1～N；份数、预留名额、预计人数、实际到场按原稿分别处理。

- 餐饮核销后按实际菜品分派厨房、吧台打印任务；发牌、补打、制作、取走各按原事实处理。

- 新普通兴趣卡沿“后台简易建卡→会员一键申请→授权人员一键审批→有效持卡”流程；不新增关注、实体领卡、付卡费或二次激活门槛。旧联名卡、社交卡等其他卡类型保留各自原有条件。
- 普通、活动单点及兴趣卡指定商品的可见、可售和已购履约分开；隐藏或停售不取消既有有效订单。合法已发且尚未兑换的原券，仍按本人资格、原有效期、份次和原使用方式履约，不被新菜单时段误伤。

### 9.3 现场取餐核查，先不新增开发

已配置取餐屏不等于眼前设备匹配。现场负责人先在实际设备、原浏览器及当班账号上核查，再观察一次“制作完成→实际取走→一次确认→其他端同步”。

若是设备或岗位执行问题，沿原配置和培训处理；若复现入口或提示缺口，再做对应局部修复。不因零回执断言无人送餐，不为清空列表批量标记送达，不为本次调查补写生产回执。

## 10. 活动退款、审核与状态

顾客路径：小程序现有活动报名记录→本份详情→“申请本份整单退订”→查看进度。
员工路径统一为：**收银与退款 → 活动收银**。
审批路径：对应申请→核查→同意或拒绝→按原渠道与执行入口处理→查看实际结果。

保留顾客一键申请、原审核和原渠道退款；不新增自动审核政策或任意金额自助退款。员工代办由另一名有权限员工复核；顾客申请保留顾客申请人，不要求员工重新代办一遍。

顾客提交前看清本次可退对象、金额和条件；审批页保留实付、已退、申请金额、入场/核销/加购使用情况及申请原因。顾客、员工及审批端依据同一退款事实展示金额与进度，允许刷新时有明确的更新时间，不能同时给出互相矛盾的结果。

后台说明统一为：“顾客可在小程序申请符合条件的整份退订，申请统一进入本页审核。员工代办的退款须由另一名有权限的员工复核。”旧版报名仍保留“请联系门店办理”。

| 状态或条件 | 顾客及员工提示 |
|---|---|
| 符合整份退订条件 | 显示“申请本份整单退订”，不同时说只能联系门店。 |
| 已提交 | “等待门店审核”，展示原申请。 |
| 已批准尚待执行 | 明确已批准、待执行，不显示完成。 |
| 渠道处理中或结果待核对 | “退款处理中，尚未确认到账”或“正在核对原退款结果”，提供原结果查询。 |
| 已入场、已核销或有效关联加购 | “请联系门店核对已使用内容及退款安排”。 |
| 退款成功 | “退款已完成”；仅整份全退、相关权益结束且仍符合报名条件时显示重新报名。 |
| 拒绝 | 显示原因；同一申请明确终结且仍合格时允许重新申请。 |
| 明确失败 | 说明失败和授权处理路径；结果未知不冒充明确失败。 |
| 旧报名、不支持自助 | 沿原“请联系门店办理”，不显示无法执行的按钮。 |

- 审批通过后沿原渠道自动任务或授权人员原执行入口；不能把“系统执行”理解为所有渠道都新增自动退款。
- 同一申请、重试、重复通知只处理一次；审批与核销并发时重新核查最新事实。
- 部分退款、补偿退款、整份退订分开。补偿不自动结束履约，不自动释放已使用名额、恢复食材或允许重新报名。
- 退款成功前不计入成功退款，也不提前按退订完成释放名额或恢复可购资格；处理中沿原防重复和状态锁定规则。已经确认的渠道退款成功不能因后续权益处理异常改成失败。后续冲突保留原号、原记录，交原售后处理。
- 入场、制作、取走的历史事实保留；库存、名额、权益按实际退订范围处理。

## 11. 权限、历史查询与打印

- 核对重点账号及同类角色的有效授权、个人禁止项、菜单、接口和字段范围。工作模式或首页不能改变账号权限。
- 订单查看、金额汇总、历史日期范围、个人销售、全店经营、费用明细分别控制。没有对账权限不应使其他已授权订单功能消失。
- 修复老板历史查询，不顺带取消普通员工日期限制。汇总权限不自动暴露工资个人明细。
- 订单小票、扎账报表与老板经营报表分别校验权限。现有扎账报表不含完整经营成本与利润，且有打印、对账及历史范围权限要求；这些门槛保留，不因开放经营汇总而放宽。
- 本期提供一份简明经营汇总打印：所选期间的六项主指标、收入和成本分类小计、业务覆盖、暂估及缺项说明、生成时间。复用原打印通道、队列、设备及原结果查询，不另建打印系统。默认不展开逐笔订单、个人工资、趋势图或当前待办，避免年度查询打印成长流水。
- 经营汇总打印须同时具备对应经营数据查看、既有打印及适用历史范围权限；若复用的原通道另有权限门槛，继续遵守，不顺带授予对账、退款或费用修改权限。
- 页面无权时不提供可执行打印；权限变化时服务端仍可拒绝并提示。修复打印不附带退款、对账或其他授权。
- 打印带期间、范围、口径、生成时间；缺项和暂估说明随报表保留。同一时点、同一口径的金额与页面、明细一致。
- 报表打印与厨房制作单分开，不能把经营报表发到制作流程。实体出纸另验收，预览或打印回执不代替实物。

## 13. 实施顺序与范围控制

本节为已确认的开发执行顺序。实施和验证状态统一见本轮交付台账。原 v3 已实现事项复用并针对受影响链路回归，不重新建设全套功能。

1. **核对指标来源与实施映射**：按第14节已确定规则，逐项建立来源、归属日、已开展业务覆盖和重复扣减清单；六项不再重新确认。现有财务数据先核查后复用，活动及加购的遗漏来源列入本期补齐。
2. **现场核对取餐衔接**：由负责人核实真实设备、浏览器、账号及一次实物交接；只对复现缺口安排局部修改，可与第1项并行。
3. **修正明确冲突与权限**：净收名称与构成、完整性提示、至今期间、历史权限、退款展示和打印入口；补候选加餐、时段和弱网提示。
4. **完善老板仪表盘**：复用现有报表与费用能力，完成六指标、日月年选择、趋势、有效期间与明细联动。
5. **补少量便利操作**：活动待办直达筛选、商品列表记忆、兴趣卡真实去向、禁用原因和相关页面视觉一致性。
6. **逐项验证与审计**：按下表映射现有与新增检查，记录失败及修复。界面、金额、权限、并发和弱网分别验证；避免只验证正常画面。
7. **单独记录发布与现场结果**：本地、远端检查、后端部署、小程序上传/发布、真机、真实退款、实体打印及取餐现场分别留证；不互相替代。

不为了本期引入大规模埋点平台或新提醒系统。体验验证可选一个正常营业班次，少量观察找入口、求助、操作中断和原结果恢复，不能用后台请求量或轮询次数当员工点击量。

## 14. 已确认的六项经营规则

2026年10月23日用户已明确全部采用V1.2推荐方案。以下为实现和验收的确定基线，不再要求重复确认。

| 编号 | 已确定事项 | 实施规则 |
|---|---|---|
| C01 | 老板默认经营仪表盘 | 普通无目标登录进入经营仪表盘；保留常用入口，明确业务链接、制作/取餐专用屏及未知原操作恢复优先。根据有效权限决定，不按用户名特判。 |
| C02 | 首期展示经营利润 | 标明按已入账数据及覆盖业务计算；实际缺口标暂估。不称完整税后净利润或已关账结果。 |
| C03 | 跨期费用沿用按日分摊 | 复用服务期、总金额和原分摊规则，只维护一次；区分原费用整笔金额与所选期间计入金额，不重建费用台账。 |

| C06 | 经营收入沿用订单归属 | 首期按原订单及活动购买记录的营业日归属，明示“按订单归属”；补齐已开展业务来源。严格按核销/履约确认收入、递延收入引擎不纳入本期。 |

当前没有需要重新确认的功能或经营选择。账号授权、各业务实际数据来源、设备匹配、已录费用质量、上线版本及现场参数属于实施核查事项；核查不能变相扩权、改账或扩大本期范围。
