本轮是 PR #421 的增量修复，基线 `7b35a8f28a1677ea64e69a7d57c4ea1e8e4b4a41`。不合并、部署、发布小程序或改网站，不连接生产，不操作现场桌台、订单、员工账号。测试使用本机合成身份、浏览器和一次性 PostgreSQL 数据库。

## 方法与范围

- 沿调用链检查共享恢复器及其库存盘点/报损配置、存酒、经营费用、会员卡/礼赠/到店奖励、券日历、营销联系、活动、社交账号、商品售卖份数、桌次服务等调用者。共享基础实现测试覆盖不等于每个页面或每个接口均已实测。
- 状态序列故障注入：首次请求 → 响应丢失 → 后续明确拒绝 → 刷新 → 原键恢复；与首次明确拒绝的正常纠正对照。
- 存储故障：坏 JSON、空对象、null、数组、读取异常；检查请求计数及恢复日志未被覆盖。
- 回执变形：空结果、错误目标/配置、重复项、未应用、负数/小数/越界人数、无效时间；与五种配置、顺序重排、零受影响员工、无当前概览的合法回执对照。
- 并发探针：不同顾客服务请求交错，观察 Promise 结果和发送次数；回看真实页面同步防重保护，排除将底层合同缺陷直接描述为线上事故。
- 真实管理面板浏览器检查：旧记录、恢复拒绝/错误成功回执、重载、随后正确回执；核对只读参数、原键、提示和清理。
- 隔离真实数据库对照：只读恢复不存在的权限发布回执必须拒绝，配置版本、业务记录、审计、出站及幂等记录不变；正常首次发布及原键恢复保持可用。
