# 1.0.0-rc.275 员工本单放行与整桌低消调整

员工用本人账号协助点单，拥有本单低消放行权限时自动提交未达门槛的订单，无须额外勾选或填原因。系统记录员工、订单、时间、当时门槛、累计商品、本单商品与未达标金额。客人自助点单继续原拦截；赠送沿原赠送权限，本单放行不会免除付款或取消整桌最低消费。

负责人可查看当前门槛及操作记录，输入降低后的金额，或明确确认取消本桌剩余低消要求。两种开台模式共用此入口，必须填写原因；保存原开台金额与每次调整前后金额。并发修改需刷新核对，重复提交仅记录一次。已结清历史不能调整；物理释放桌位后仍待处理的旧桌次可继续处理，原账与新客人分别保留。

门店配置升至2026.10.31-v29：OWNER、OPS_LEAD、MANAGER、DEPUT_MANAGER、SERVER、CASHIER获得本单放行权限；前四个负责人角色另获整桌低消调整权限。原岗位付款、退款申请、异人复核、金额额度、渠道执行及查询权限不增加。旧预收减免接口保留兼容，但同时要求新的负责人权限，不能从旧入口绕过授权。

预收模式继续要求足额预收、付款人授权及足够可用余额。降低或取消低消只改变商品门槛，不修改订单应收、付款、原款分摊或退款记录，也不自动退款。取消门槛后余额不足仍须补款。优惠前商品累计、批准退菜、多人订单、转桌及往期待办按原桌次统一计算。差额收费固定关闭。

新增迁移295–296，原迁移不改写。数据库写入再次核验岗位权限，旧版本减免入口也不能绕过；员工姓名按当时快照保留。不可改写的本单放行记录与新减免前后快照独立保存；正常结台会检查放行后的整桌未达标，现有物理释放与自动截止继续保留旧桌次处理记录。

## 验证与发布

当前本地开发和专项测试中，尚未部署本候选。逐项检查覆盖权限与数据范围、自动放行、客人拦截、应付款、预收不足、双模式降低和取消、非法金额、并发、幂等冲突、审计、转桌、物理释放和新开台隔离。全量、浏览器、准确提交CI及生产回读结果完成后更新。本次员工Web和后台改动，不需要修改客人小程序代码；既有微信开发版、体验审核及正式发布状态单独记录。真实资金、真机和打印不以模拟渠道或浏览器测试代替。


专项证据：17项低消例外及17项原预收数据库回归通过；手机尺寸3项流程已验证普通服务员本人账号自动放行、负责人降低和取消、收银无权调整。常规2674项与构建通过；完整数据库首轮3616通过、1测试失败并有16项因测试配置跳过，缺口为新增权限目录数量和自动收工策略未启用，已修复并在34项专项中覆盖。全量复验、提交CI和部署仍在进行，不用专项替代最终门禁。
