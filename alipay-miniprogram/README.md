# M-BOX 支付宝小程序

原生支付宝小程序前端。页面、底部导航、静态资源、视觉标签结构和布局样式以同一提交中的 `../miniprogram` 微信小程序为基准；业务数据继续访问同一个 M-BOX 后端。

## 当前边界

本工程只新增支付宝前端，没有修改后端。由此产生一个不能回避的事实：共享业务后端不等于平台协议可以直接复用。

当前可复用：公开首页、品牌、菜单、演出和活动内容浏览，桌码和无需会员身份的桌边服务，以及基于匿名预约会话的新建、查看和管理本人预约。免费活动报名等会员写操作会随支付宝身份/手机号能力一起失败关闭；不能把“内容可浏览”写成“业务已可办理”。

当前失败关闭：

- 支付宝账号身份：后端尚无 `my.getAuthCode` 换取 M-BOX 客户身份的适配接口。
- 手机号入会/找回：后端尚无支付宝手机号响应的验签解密接口。
- 支付宝支付：后端只会生成其他平台的支付动作，尚不能返回支付宝 `tradeNO`；付费点单和收费活动在创建交易前停止。
- 支付宝消息：后端尚无支付宝消息模板、授权记录和发送适配。
- 企业微信客服：支付宝端保留电话和二维码入口，不伪装成可直接打开的原生客服会话。

当前已知风险：共享预约后端仍将预约来源固定记录为 `wechat`。这不阻止匿名预约流程，但会造成支付宝预约的平台归因和审计字段错误；须由后端增加可信的平台来源识别后，才能把支付宝预约归因视为验收通过。

上述能力在 `config/index.js` 的全部配置合并完成后仍强制为 `false`，本候选不能通过开发存储、扩展配置或发布配置绕开。只有后端适配、联调和真机证据齐全后才可修改代码开放。

## 导入开发工具

1. 安装并打开支付宝小程序开发者工具。
2. 选择“打开项目”，目录选本文件夹 `alipay-miniprogram`。
3. 在开放平台创建应用后填写真实支付宝小程序 AppID；仓库不保存占位或私密密钥。
4. 开发阶段可在调试存储的 `mbox.runtime.config` 中覆盖非秘密 API 地址和门店编号；体验版和正式版必须使用受控发布配置。

本项目使用 WebView 渲染，以最大程度保留微信端的 CSS Grid、gap、sticky、媒体查询等布局行为；`mini.project.json` 使用 format 2 和 `compileOptions.component2`，format 2 默认采用基础库 2.x。IDE 3.10.15 模拟器已读回基础库 2.10.15；无界面编译器仍报告 SDK 1.x，因此不能用无界面结果替代 IDE 或真机版本证据。不要擅自切换 Native 渲染后仍声称像素一致。

源码工具模块使用支付宝基础库 2.x 支持的 ESM 导出。仓库根目录本身是 ESM package scope，若继续写 `module.exports`，开发工具 3.10.15 在基础库 2.10.15 下会在启动阶段报错并只显示空白主体；自动门禁会阻止该写法回归。

## 自动监督

在仓库根目录运行：

```sh
npm run check:alipay-miniprogram
npm run compile:alipay-miniprogram
```

第一条门禁会核对 21 个页面、5 个底部入口、页面标签顺序、事件处理器、页面标题、下拉刷新、全局及页面布局样式、静态资源哈希、支付宝语法、包体积、业务接口来源、生产态安全默认，以及身份/手机号/消息/支付的最终强制关闭。仓库统一 `npm run check` 也会运行该门禁。第二条调用已安装或已挂载的支付宝官方开发者工具内置编译器，验证 21 页面产物完整，并反查产物中不得出现微信运行时、相册桌码重放或伪企业微信客服调用。

`AGENTS.md` 定义独立监督智能体的复核职责。静态与无界面编译通过仅表示候选源码和产物完整，不等于 IDE 交互预览、平台上传、体验版、真机或真实支付通过。

## 真机验收

至少分别核对 360、375、390px 宽度和 iOS/Android：页面布局、长文案、大字体、弹层、扫码、分享、弱网、桌次切换、预约、免费活动。身份、手机号、消息和支付必须在后端适配完成后单独验证；支付还要覆盖取消、超时、未知结果、查单、重复点击和到账回调。
