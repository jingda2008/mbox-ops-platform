# rc.218 native maintenance rehearsal

This branch-only workflow runs on a disposable GitHub-hosted x86_64 runner. It does not change the main branch, rc.218 business code, release tags, production credentials, or production services. Only synthetic records and locally generated secrets enter the nested LAB. No host socket or directory is mounted into the LAB; network is disabled after assets are copied, PostgreSQL shares only that LAB network namespace, and cleanup uses the exact created container IDs.

The official rc.216 image is the source. The first recovery target is built from the real reviewed 0de13804 commit; the final target is the official 51fc2fba rc.218 image. Neither source nor image revision is relabeled to pretend it is another commit. Formal deploy/activate/maintenance/backup/restore scripts remain byte-identical to each target's source. Synthetic transport adapters exercise actual copy/readback and corruption but do not prove real OSS/RAM or GitHub release approval. Those actual release artifacts and external services are verified separately.

Two scenarios run: an ordinary upgrade with a synthetic signed delayed callback, and backup readback failure followed by same-SHA reentry, real financial facts, epoch readback failure, and a different-SHA forward recovery. Six nonempty immutable financial tables and exact payment/admission/authorization bindings must match the baseline across recovery and duplicate callbacks. Positive cases are selected unchanged from existing command/API integration tests; their historical input is synthetic repository composition, not old-binary financial-history proof. No direct inserts create the six target fact tables. The verifier also checks journal/epoch, original backup origin, API/worker actual low LOGINs, retired high LOGIN, restart fencing, current callback drain and ready identity. Formal entry logs retain their own exit codes.

Temporary keys, password/service files, dumps and callback bodies are never uploaded. Exported logs have all generated environment/password values removed and pass the repository's sensitive-artifact scanner. Only fixture code, safe evidence and public immutable source identities are disclosed. This LAB does not prove live RDS, actual payment channels, production systemd219 behavior, public DNS, or physical store acceptance.
