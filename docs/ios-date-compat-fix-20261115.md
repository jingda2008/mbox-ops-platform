### 根因与同类遗漏

1. 推荐优惠页直接把 PostgreSQL 文本（如 `2026-11-16 10:15:35.489+00`）交给原生日期解析；部分页面也使用原始字符串解析，未覆盖空格分隔、短时区偏移与微秒精度。
2. 原通用 dateTime 取手机本地年月日时分，积分、会员等级及权益到期日还直接截取 UTC 日期；境外手机时区或北京时间午夜可能显示另一日期。
3. 隐私政策时间依赖 Intl；旧运行环境不能保证该接口存在。会员券无效截止字符串被转换为空，继而可能写成“无固定截止日期”。

## 统一规则

- PostgreSQL/ISO 有时区时间统一为 `YYYY-MM-DDTHH:mm:ss.SSS±HH:mm` 或 Z。支持 `+08`、`+0800`、`+08:00`、负偏移以及 1–9 位小数，截取到毫秒，不向后舍入延长有效期。
- 解析前验证日期、闰年、时分秒、时区范围。无时区时间、无效日期、空值均返回不可核对，不按设备时区猜测，也不把 null 当作 1970 年。
- 显示固定北京时间 UTC+8；生日/营业日等纯日历日期另用日历接口，不当作时间戳换算。
- 截止规则保持 `[开始, 截止)`：开始瞬间允许，到期瞬间禁止；授权仍由服务端决定。报价过期清理并要求重核，不修改计价、领取额度或服务端佣金规则。
- 只有业务字段明确 null 才按其原合同显示长期/无固定截止；无效、空串或缺失截止显示待核对。
- HTTP Cookie 的 Expires 保留标准 HTTP 日期解析，这与业务时间戳不是同一种输入格式。

## 修改覆盖

| 范围 | 处理 |
|---|---|
| 小程序通用 format | 严格日期规范化、parseInstant、北京时间日期/时刻；不依赖 Intl |
| 推荐优惠、已有券和券包 | 统一领取/使用窗口显示，原始 PG 字符串不再直接交给原生 Date |
| 积分、个人资料、会员中心、会员卡、会员身份 | 积分/等级/权益截止先转换北京时间；身份有效期保持开始含、截止不含；不扩大身份权限 |
| 首页、活动、预约、服务和状态 | 共享时间显示；活动结束/加餐截止/预约取消期限/刷新重试等采用统一解析 |
| 隐私、营销偏好、存酒 | 统一北京时间显示，隐私页面去除 Intl 依赖，存酒到期比较兼容 PG 时间 |
| 小程序报价、升级优惠、每日权益核销码 | 原截止比较全部经统一解析；已过期/无效时间继续阻断 |
| 登录和恢复记录 | 身份有效期、桌次连接缓存年龄、预约恢复记录及重复订单时间使用统一解析；异常记录仍保留核对流程 |
| 网页渠道绑定、购物车、顾客演出时间 | 规范化后显示或比较，无效时间不使绑定/演出页面渲染崩溃；报价校验保留 |
| 网页/服务端共享 venue-time | 共用严格 TS 解析，日期键保留既有语义；与小程序用同一输入矩阵校验一致性 |
