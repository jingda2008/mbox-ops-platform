# M-Box 全岗位语音命令架构

## 1. 产品原则

语音命令是现有岗位页面的另一种入口，不是第二套业务系统。语音和手工操作必须共用：

- 当前员工签名会话、岗位和兼职角色；
- 现有权限、数据范围、审批额度和离线限制；
- 现有订单、桌台、支付、库存、会员、演出 API；
- 幂等键、北京时间营业日、审计日志和事件中心。

任何 AI 模型只能生成结构化“命令建议”，不能直接修改数据库。

## 2. 双模式交互

员工登录后可随时切换：

1. **岗位页面：** 处理复杂信息、异常、批量配置和最终结果。
2. **语音命令：** 说自然语言、查看系统理解、确认后执行或跳转。

切换员工、会话失效或重新登录时自动回到岗位页面，避免共享设备把上一个员工的待确认命令带给下一个员工。

语音模式以覆盖层运行，原岗位页面不会卸载。确认后系统触发原页面同一个控件，因此继续复用已有 React 状态、接口、权限、审批、校验、幂等和审计逻辑，不维护第二份业务实现。

## 3. 统一命令链路

```text
设备麦克风/文字输入
  -> 多候选语音转写
  -> 门店动态词典（人员/岗位/桌台/商品/歌手/控件）
  -> 拼音、同音和别名纠错
  -> 意图和实体提取
  -> 确定性命令解析器
  -> 当前员工权限与数据范围校验
  -> 风险分级和参数完整性校验
  -> 人工确认/审批
  -> 现有业务 API
  -> 业务事件、审计和结果反馈
```

AI 输出必须经过结构化校验，例如：

```json
{
  "intent": "table.open",
  "entities": { "tableCode": "K2", "partySize": 4 },
  "missingFields": [],
  "confidence": 0.96
}
```

系统根据 `intent` 重新查找桌台、权限和实时状态，不能相信 AI 返回的权限结论或金额。

验证阶段不依赖模型接口。当前确定性规划器已经支持明确的单步命令、用“然后/接着/再/并且”连接的最多五步命令，以及“K2 四位客人开台并归属 Tom”这类受控口语模板。模型适配器只保留为正式商业版的可选理解兜底，模型关闭时全部基础能力仍可运行。

## 4. 风险分级

| 等级 | 示例 | 处理方式 |
| --- | --- | --- |
| L0 查询/导航 | 查看我的任务、今晚谁演出、打开库存 | 可直接展示结果或打开有权页面 |
| L1 低风险操作 | 接单、到桌、K2 开台、标记制作完成 | 显示对象与影响，一次确认后调用原 API |
| L2 经营/资金操作 | 转桌、结台、赠送、折扣、排班发布、退款 | 明确复述金额/对象/原因，二次确认；超限进入原审批链 |
| L3 安全配置 | 修改 PIN、权限、支付密钥、删除审计、批量改价 | PIN/密钥等敏感值禁止语音输入；其他配置只能在有权管理页面二次确认并复用原审计链 |

当前页面适配器对退款、支付、收款、结台、转桌、赠送、折扣、库存调整、保存、删除、发布、权限、授权和员工切换执行二次确认。导航、标签页和折叠展开不因模块名称中含“支付/权限”而被误判为资金操作。PIN、密码、密钥、Token、验证码和付款码等敏感值禁止语音填写。

## 5. 各岗位优先命令

| 岗位 | 第一批高频命令 |
| --- | --- |
| 老板/运营负责人 | 查看经营风险、待审批、异常账务、今晚经营摘要 |
| 系统管理员 | 查看健康状态、失败事件、配置版本、人员与权限 |
| 店长/副店长 | 开台、转桌、替补调度、投诉接管、排班与演出调整 |
| 服务员/门迎/传菜 | 开台、查看责任桌、接单、到桌、完成、暂未点单、协助点单 |
| 调酒师/厨房 | 查看待制作、开始制作、缺货、制作完成、呼叫取送 |
| 收银员 | 查看待收款、生成支付码、扫付款码、POS 报送、发起退款申请 |
| 舞台/灯光 | 查看当前和下一场、歌手到场、演出开始/结束、异常上报 |

兼职员工的命令能力取当班有效角色权限并集，但每条命令仍按数据范围和审批额度单独校验。

## 6. 防错规则

- 桌号、人名、金额或目标不唯一时必须追问，禁止猜测。
- 低置信度转写只显示文字，不生成可执行确认按钮。
- 确认卡必须显示命令对象、当前状态、执行影响和操作者。
- 确认卡超时或业务修订号变化后失效，执行前重新校验。
- 所有写命令使用幂等键，重复说、重复点击和网络重试不得重复执行。
- 离线时沿用现有限制：只开放已经支持离线队列的服务任务动作。
- 语音转写失败时保留文字输入；语音服务不可用不能影响岗位页面。
- 相似目标返回 2 至 6 个带上下文的可点击候选；点选候选只完成消歧，不等于执行确认。
- 动态词典只采集明确的业务名称，不写入 PIN、Token、付款码、输入值、顾客备注或其他敏感字段值。
- 浏览器支持上下文短语时注入热词，不支持时继续使用本地拼音、同音和别名匹配。
- 中文播报优先设备保存声线和自然/高级中文声线；员工可在语音面板切换，敏感内容不播报。
- 设备只申请使用期间的麦克风权限，系统不保存原始录音；如未来需要留存必须单独取得员工授权并配置留存期限。

## 7. 落地阶段

### 阶段 A：安全入口（已完成）

- 登录后双模式切换；
- 浏览器语音转写和文字兜底；
- 角色专属常用命令；
- 权限过滤、命令确认、返回原岗位页面；
- 桌面、平板和手机响应式布局。

### 阶段 B：全页面确定性控件适配（已完成）

- 自动发现当前员工已授权、当前页面可见的按钮、链接、输入框、下拉框、开关、单选项和折叠详情；
- 支持“点击立即开台”“搜索预约输入张三”“销售归属选择 Tom”“打开某开关”等确定性命令；
- 无名称控件、重复口令和禁用控件会明确提示，不静默猜测；
- 折叠区未展开时不暴露内部命令，展开后自动加入命令目录；
- 执行后读取原页面状态、提示和标题，返回成功、失败或仍在处理的反馈；
- 当前实现覆盖每一步页面操作，不把多步骤业务绕过为直接写库。

### 阶段 B.2：动态词典、自然播报与候选消歧（已完成）

- 按当前门店数据自动生成员工、岗位、桌台、区域、商品、服务类型、工作站、歌手、歌曲、页面控件和下拉选项词典；
- 支持无声调拼音、拼音首字母、中文同音、Tom/Jerry/Tyke 常见中文读法和桌号口语；
- 浏览器返回多个转写时，综合识别置信度和门店词典选择最可信文本；
- 找到多个相似目标时展示可点击候选，候选选择后仍进入原确认与高风险二次确认；
- 中文 TTS 自动选择更自然的普通话声线，并允许当前设备记住员工选择。

### 阶段 C.1：验证版连续命令助手（已完成）

- 一句话可生成最多五步的可视计划，并按原页面控件逐步执行；
- 每一步重新读取当前页面、权限、控件和风险，歧义或失败立即暂停；
- 高风险步骤必须单独二次确认；
- 该执行方式明确不是服务端事务，已经成功的页面步骤不会因后续失败自动撤回，适合验证流程价值，不作为商业版原子复合写入能力。

### 阶段 C.2：商业版服务端智能体执行器（待完成）

建立服务端 `CommandPlan`、计划哈希、有效期、确认令牌、整体幂等和命令审计。内部同一聚合的复合步骤在一个数据库事务执行；支付、退款、微信通知等外部副作用采用可暂停工作流和补偿状态。云端 ASR 和大模型只在确定性解析失败时生成结构化建议；系统仍逐项查实时对象、补齐缺失字段、展示影响并调用白名单业务链路，模型不负责权限、金额计算、状态判断和直接写库。

### 阶段 D：耳机与主动助手

事件中心把桌台超时、出品超时、投诉和替补调度转成耳机播报；员工可语音回应“收到”“我去”“转给 Tyke”。需要控制播报频次、安静时段和优先级，避免信息疲劳。

## 8. 商业化验收指标

- 命令理解正确率按岗位和意图分别统计，不使用单一平均值掩盖高风险错误；
- 高风险误执行为零，越权执行为零，重复写入为零；
- 高频操作从进入页面到完成的中位点击数不超过 2 次；
- 语音不可用时 5 秒内可切回岗位页面；
- 每条命令可追溯原话文本、解析结果、确认人、审批人、API 结果和业务事件；
- 300 人营业压力场景下，语音服务降级不得影响点单、KDS、支付和服务任务主链路。

## 9. 当前交付边界

- “全页面”指员工登录后、当前岗位有权访问并已渲染的页面；越权页面和控件不会出现在语音目录。
- 每次页面切换、弹窗打开、折叠展开或按钮状态变化后，语音目录自动刷新。
- 当前浏览器语音识别不可用时可输入同样的自然语言命令，岗位页面始终可切回。
- 当前连续计划属于验证版页面编排，不具备服务端事务原子性；正式商用复合写命令必须完成阶段 C.2。
- 云端 ASR、大模型口语兜底、耳机播报和主动事件对话仍属于后续阶段；模型接口不是验证阶段上线的前置条件。
