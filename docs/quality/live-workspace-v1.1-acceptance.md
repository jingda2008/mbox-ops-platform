# M-BOX 员工现场服务与同桌协作 V1.1

## 1. 目标

营业后使用一套固定、简单的工作方式，不设置“平时/忙时”切换。减少员工点击和盯屏时间，同时保留责任人、时间、异常、投诉和财务审计。

## 2. 信息分级

| 级别 | 信息 | 前台行为 | 留痕 |
|---|---|---|---|
| 桌台标签 | 客人情绪、画像、一般偏好 | 只在桌台显示小标记，不创建任务、不震动 | 行为事件和桌次历史 |
| 快速服务 | 呼叫服务员、个性化需求、普通SOP | 合并为一个待办，执行人一次点击完成 | 创建、完成、执行人和时间 |
| 强处理 | 投诉、安全、退款、取消出品、权限拒绝 | 置顶；按权限处理；投诉必须填写结果 | 完整审计和原因 |

## 3. 固定现场流程

### 3.1 服务

客人发起需求 -> 主责/候补/授权岗位看到 -> 员工完成现场服务 -> 点击“完成”。

- 不要求“接单、到桌、处理中”逐步点击。
- 同桌同类未完成请求合并，记录点击次数，不重复生成卡片。
- 默认设备每分钟最多5次、桌次每分钟最多20次，超过后友好提示。
- 投诉不能按普通服务快速关闭，值班经理必须记录至少4个字的处理结果。

### 3.2 出品与配送

收款或确认订单 -> 按商品出品站进入吧台/后厨 -> 制作岗位点击“制作完成” -> 自动进入待配送 -> 任何有配送权限的空闲员工可送达 -> 点击“已送达”。

- 调酒师只看允许吧台站的制作任务；后厨只看允许厨房站的制作任务。
- 服务员不看待制作任务，只看已完成待配送任务。
- 主责/候补桌的配送优先；未指派的成品也允许其他配送员工支援。
- 取消、失败、退款仍走异常流程，不能被一步完成绕过。

### 3.3 单一待办队列

员工只使用“待办、桌台”两个高频入口。待办最多展示8项，完成后自动补入：

1. 投诉和安全事件。
2. 已超时事项。
3. 本人主责/候补桌待配送。
4. 本人负责的服务。
5. 可支援的其他桌待配送。
6. 高优先级服务。
7. 普通服务。
8. 本岗位待制作。

页面可见时每5秒静默刷新。新投诉、紧急、超时或待配送事项只轻震一次；普通更新不打扰员工。

## 4. 同桌多人扫码

- 每台手机保留独立匿名客户ID和独立购物车。
- 未付款的客人自助订单只对下单本人显示。
- 已付款订单、员工协助点单和收银订单向本桌所有当前客人共享商品及出品状态。
- 不共享付款人、手机号、支付方式、金额明细和会员权益。
- 本桌最近10分钟出现同商品时，提交前提醒一次；客人再次确认仍可加单。
- 翻台以`table_session_id`隔离，新桌次不读取上一桌订单和需求。

## 5. 配置边界

- 岗位权限、出品站、主责/候补桌、服务SLA、菜单和高频入口继续由后台配置。
- 一步完成是固定高效流程，不增加“忙时模式”开关。
- 配置不能放宽支付、退款、赠送、取消出品和投诉审计。

## 7. 发布门禁

- 规范化单元测试、真实PostgreSQL测试、构建和静态检查全部通过。
- 手机视口完成客户订单共享、员工待办和桌台情绪标记的浏览器验收。
- 300人测试必须记录P95/P99、错误率、积压、重复执行和状态不一致。
- 现场员工仍需演练调酒师、后厨、服务员、店长四个账号；自动化不能代替真实设备和真实网络验收。
- 未取得现场证据前，只能标记“开发验证通过”，不能标记“商业上线通过”。
