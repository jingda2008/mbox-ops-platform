# 菜品可选剩余份数

用户确认：每道菜可设置剩余可售份数，包括兴趣卡限定菜品；手动补充，不自动每日重置。不填写就沿用原来的库存、状态和供应时段。

商品编辑中增加“可售数量”：留空不限制；0表示售罄；正整数表示当前还能接受的新订单份数。新商品先保存基本资料，再编辑份数，避免价格和商品创建失败时误报数量已保存。已有商品可直接设置。原料库存、售价、卡资格、指定时段和手动停用仍独立生效。相同商品ID各入口共用份数，不把不同编码的同名菜自动合并。

即时付款提交时预留，原支付/取消流程决定消费或释放，重复回执不重复扣。挂账订单提交即扣减并进入原出品流程；挂账已提交或已付款的订单，撤单和退款不自动补回，门店核实实际剩余后补充。这里只限制销售份数，不替代原料出入库、成本或活动报名名额；旧活动与旧卡不改。

后台显示的剩余份数不包含已预留份数。设置为10表示还可接10份新订单，原有效预留继续保留；若这些预留后来取消，相应份数再释放。保存需要当前版本，页面打开后有销售变动则提示重新读取。清空限制后再次启用视为新一轮计数，旧预留取消不能增加新一轮数量。不追扣旧的不限量订单。

## 门店最简操作

路径：**库存与酒水上架 → 商品与上架 → 编辑菜品 → 剩余可售份数 → 保存可售数量**。新菜品先保存基本资料，再编辑份数；计划限量的新品可先保存为“停用”，设好份数后再上架。

| 填写内容 | 含义 |
|---|---|
| 留空 | 不增加份数限制，继续使用原库存、销售状态、兴趣卡资格和供应时段 |
| 0 | 当前没有可新增销售的份数，按售罄处理 |
| 正整数 | 当前还能新增销售的份数；跨天保留，补货后手动修改 |

例如当前剩3份、又补10份，填写13，不是填写本次补货数10。首次启用时，应先扣除已经接下的订单，再填写还能接新单的份数；历史不限量订单不追扣。待付款已预留的份数单独显示，不包含在可售份数内，原取消流程释放后会补回。

普通菜品和兴趣卡限定菜品操作相同，同一商品各入口共用份数。临时停售仍用原销售状态。已提交出品或已经付款的订单，撤单退款不自动补回，核实实物后再补充。
