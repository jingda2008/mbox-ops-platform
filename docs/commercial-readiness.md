## 发布硬门槛

1. `npm run check`、全新数据库迁移和`npm run db:verify`全部通过。
2. Docker镜像以非root运行，预发布环境通过健康、静态页面、员工鉴权和签名桌码冒烟。
3. 支付只能由验签回调或服务端查单置为成功；退款和对账保留渠道证据。
4. 顾客端不得读取员工、会员、其他桌台、支付密钥或全店bootstrap数据。
5. 正式主数据必须通过预检、双人审批和一次性导入，禁止样例种子进入生产。
6. 完成50桌并发服务任务、断网恢复、支付未知结果、通知失败、员工缺岗和投诉升级演练。
7. 备份恢复到独立数据库并核对迁移、状态校验和与审计记录。
8. 门店负责人签署桌台、人员、权限、SLA、退款、权益、订金和应急联系人清单。

## 不得误报为完成

- 供应商接口代码完成不等于支付上线，必须有真实商户参数、签名向量、回调和对账PoC。
- 小程序代码完成不等于微信上线，必须通过域名、备案、隐私和真机审核。
- 通知进入Outbox不等于客户收到，必须保存服务商消息ID或明确失败原因。
- 摄像头能取图不等于可以做人脸识别，必须完成必要性、告知同意、保存期限和访问权限评审。
