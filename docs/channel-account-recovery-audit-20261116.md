# 账号切换、恢复权限及旧设备恢复网络

最新授权允许本轮部署后台及员工网页，微信/支付宝源码提交不代表平台发布，官网与打印桥不在范围。发布候选从origin/main建立，原目录未改动。

## 本轮修复

- StaffActionsApi已确认员工身份后发送 x-mbox-staff-employee-id；与原会话绑定共同校验。没有传入显式会话编号的页面也不会把旧请求作为新账号执行。
- 原核对/撤回正在等待时，先校验日志归属，再复用原Promise；另一账号不能借用等待中的原操作结果。
- 页面切换API身份后丢弃旧撤回的完成提示；原记录按员工归属保留，恢复权限只核对原编号。

## 模拟

1. 原移动断网，撤回在认证前延迟；切换账号后释放请求，服务端拒绝身份不符。
2. 撤回已提交但回执丢失期间切换账号；新账号不能核对/撤回原员工日志。
3. 回到原账号后撤销权限，原编号查询403且日志不丢；恢复权限后可查原回执，未找到仍保持未知，明确封存后才清除。
4. 旧设备携带原员工头、但Cookie属于另一员工时返回401；恢复原身份后连续重发原编号仍返回封存，不移动。新明确操作只移动一次，旧编号仍不能再执行。
5. 前端在途Promise跨员工隔离、无显式会话编号的身份请求头及迟到页面提示分别回归。

隔离Fastify路由与PostgreSQL使用合成身份，实际调用生产同一 assertStaffSessionBinding 校验函数；身份切换由测试认证上下文模拟，不是生产Cookie/真人登录实验。完整检查、数据库与浏览器结果见 release-1.0.0-rc.295.md；阶段日志 /Users/jingda/mbox/outputs/channel-account-release-20261116/。正式部署与真实设备验收分开记录。
