# 优惠券有效期、转桌与退款状态复查

本轮仅本地修复和隔离测试，未部署、未上传小程序、未修改生产数据。保留工作区既有购物车、日期兼容和权限改动。

## 已修复

| 情况 | 原表现 | 处理 |
|---|---|---|
| 领取未完成时退到后台再返回 | 提前读到空券包，后续领取成功也不刷新 | 同账号、可见页面在写操作结束后重新读取；不重发领取或核销 |
| 后台拒绝过期券或网络响应丢失 | 旧卡片仍可能显示待使用 | 读取最新状态，同时保留错误或结果待核对提示；原请求恢复记录继续保留 |
| 绑定过程中换桌，包括结果后的刷新阶段 | 旧桌成功提示可能留在新桌页面 | 核对桌码、扫码批次及已知桌次范围，抑制/清除旧提示；后台记录仍按原操作核对 |
| 推荐券、会员券页面停留跨过有效期 | 可用状态不会主动更新 | 到领取/使用起止时间重新查询；会员券也覆盖下次可用时间。隐藏页面清理定时器，返回重新读取 |
| 已兑现券发生退款 | 用户可能把已兑现历史误解为退款后可再用 | 明示退款不自动退券、不恢复已使用优惠；保留历史状态 |

时间只用于安排刷新，是否有效由后台判定。已绑定/已兑现渠道券不按原始截止时间在客户端直接作废；本次客组既有承诺继续由后台管理。读取失败不推断为可用或退款完成。

## 实际模拟与结果

- 前端真实页面函数：切后台/返回、换账号、重复点击、迟到回复、绑定后读取时换桌、过期拒绝、丢失响应后只读取不重复写、定时刷新及卸载清理。
- 独立 PostgreSQL + 受限运行账号：未运行过期任务前券包已正确显示过期；已绑定券过期后整桌转移仍复用原绑定；取消未使用绑定后保持过期，不恢复发行额度。
- 退款状态链：处理中冻结佣金；失败后解除退款冻结；部分退款按实退冲减；全退后佣金净额归零。重复核对不重复记账；券仍保留已兑现历史，已用额度不返还，不能换个新桌次再用。
- 原有完整渠道回归复跑：并发领取/核销、整桌转移/拆桌/合桌、共享封顶、过期报价、撤单释放条件、赠品库存、退款及对账结算，共 133 项通过。

本轮未发现需要更改后台业务规则的新缺陷；后台新增两项跨状态回归。前端新增 11 项回归。先保存了原页面 4 项失败及刷新期间换桌的失败证据，再修复。
