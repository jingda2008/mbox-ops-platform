# 退出重进、账号切换、拆桌恢复和退款回调复查

本轮仅本地开发与隔离测试，未部署、未上传小程序、未修改生产数据。保留已有改动。

## 修复的操作遗漏

原券包只给“待使用”券提供操作按钮。断网时后台已经领券/绑定，退出重进后显示领取达限或已绑定，原请求仍存在但页面没有恢复入口。

现在按当前账号及当前桌次读取本机待核对请求：

- 推广页显示“核对上次领取（不重复领券）”，即使领取已满也可核对原回执。
- 券包及推广已领券显示“核对上次绑定”。已绑定、已兑现、过期、撤销均能核对匹配的历史请求，不把这些状态改回可用。
- 恢复入口必须找到已有请求，沿用原编号并发送仅恢复原回执的标记。没有记录、换账号或换桌次时拒绝自动发起新操作。
- 恢复成功提示“原操作回执已核对，请以下方最新券状态为准”，不把历史成功回执表述成当前仍可使用。

## 实际操作边界

整桌转移保留原桌次/客组时，可以沿用原记录恢复。拆桌产生新桌次后，不能把旧请求的桌号改成新桌号重放；当前客户端也不会跨桌次自动生成新编号。应由服务员核对原回执及目标桌原券绑定。目标桌复用同一客组的原绑定，不新增领券/使用次数。

切换账号不会暴露或恢复上一账号的本机请求。员工网页的原请求也按登录会话及桌次隔离；读取新状态失败时保留原记录，不能先清除再重做。

## 前后端模拟

1. 真实小程序页面/API/恢复日志连接 Fastify 和隔离 PostgreSQL：后台成功后丢失响应或返回不完整回执；退出页面，重新创建客户端与页面，复用持久化存储。
2. 切换另一账号，恢复请求在客户端发送前被拒绝；返回原身份，页面显示核对入口，沿用原编号恢复。同时保留原有转桌、退款锁等待及旧报价并发提交验证。
3. 真实拆桌及整桌转移：原请求回执可按原内容核对；改成新桌号重放返回409；目标桌复用原绑定，券数不变。
4. 使用真实付款服务的退款回调处理与验后观察记录：先退款20元，同一回调四路并发；再用新回调编号重复通知；成功后通知失败、金额不一致均被拒绝。随后退款10元，再重复通知。
5. 最终断言：两笔成功退款共30元，退款账仅两笔共-30元；净计佣基数60元、佣金6元；并发重算不重复记账，已用10元优惠不返还，原券不复制。

账号身份、收款及验后回调观察由测试夹具提供；未访问真实微信或支付机构，未验外部平台真实签名投递。员工网页本轮验证恢复逻辑，未做浏览器录屏。
