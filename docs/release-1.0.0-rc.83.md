# M-BOX 1.0.0-rc.83 发布体系重构候选

## 目的

一次性消除多套部署入口、配置别名、分支遗漏、镜像身份不一致、数据库操作过早、深层地址漏验和失败证据不完整等重复发布问题。

## 核心变化

- 唯一阿里云发布入口、唯一根目录 Dockerfile、唯一规范化配置合同。
- 支付、AI、打印、耳机均使用明确模式：`disabled`、`test`、`uat`、`production`。
- 配置和外部依赖失败发生在备份、迁移和候选容器之前。
- 数据库迁移先做只读兼容检查，再备份，再执行写入。
- 候选必须按状态机经过完整验收，禁止跨阶段执行。
- 标签提交必须已进入 `main`；CI、OSS和服务器绑定同一SHA、镜像摘要和迁移清单。
- 首页、固定桌码、预约、员工入口及前端资源全部在切流前后复验。
- 正式OSS证据失败会阻止完成并恢复旧镜像；GitHub临时诊断制品失败不改变测试结论。
- 已知发布故障进入永久登记，每项必须绑定回归测试和自动阻断位置。

## 三类发布演练

1. 缺失或半配置候选在数据库写入前拒绝，线上版本保持不变。
2. 切流后复验失败，直接使用已存在旧镜像恢复，不重新构建。
3. 完整成功路径产生状态机、部署清单和SHA256证据。

## 边界

本版仍是开发验证候选。真实支付、退款、物理打印机和耳机未制造事故验证；对应模式关闭时不影响系统部署，启用前必须完成各自UAT与人工审批。
