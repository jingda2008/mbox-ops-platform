# 1.0.0-rc.218 跨迁移账号升级的权限版本修复

原生维护演练发现：旧迁移账号拥有的门店权限初始化函数，在升级后触发新权限版本计数器时，无法写入新维护账号创建的表。新增迁移241，把版本计数限定为权威配置表上的安全定义者触发器，固定查询路径并撤销公共及运行角色的直接执行权。旧账号仍禁止登录，旧函数归属与已有业务记录保持不变；001—240迁移及已发布rc.217产物不改写。

独立数据库升级回归先按不同账号执行001—224及225—240，准确复现原权限错误，再验证241修复、受限身份正常更新、跨门店拒绝和伪造临时触发来源拒绝。完整CI、原生正常升级及故障向前恢复、生产备份恢复和公开路由验收仍需各自记录，不能由单项回归替代。此次仅修正数据库触发器边界，继承rc.217其余业务变动与尚未关闭的商业验收事项。

生产首次切换继续采用计划维护：暂停写入，停写备份及隔离恢复、OSS读回通过后升级；失败保持维护并向前修复，禁止重启不兼容旧高权限应用。仅使用正式deploy/aliyun/deploy-release.sh入口。此说明不代表已部署，也不代表小程序上传、真实支付渠道或实体打印验收。
