# M-BOX 客户体验与活动平台 V1

状态：隔离工作树本地候选。未提交、未部署，不代表微信小程序或真实支付已经上线。

## 1. 当前完成范围

### 客户小程序

| 主入口 | 高频任务 | 低频任务与边界 |
|---|---|---|
| 首页 | 到店前预约/活动；到店后点单、桌账、点歌、经理协助 | 隐私说明放底部；现场呼叫只保留在点单页，避免重复入口 |
| 预约 | 查容量、选人数/时间/位置偏好、提交本人预约 | 具体桌位由门店安排；普通预约订金沿用独立门店预约规则 |
| 点单 | 先选场景和酒水偏好；组合优先；付款前一次升级选择；现场服务呼叫 | 升级只替换未付款购物车中的指定单杯，不做付款后返还或伪抵扣 |
| 超嗨 | 活动列表、同行人数、活动付款规则、报名 | 活动支付与普通到店预约分开；候补不收预付款 |
| 我的 | 入会、积分、酒水偏好、服务强度 | 只向本人返回允许展示的偏好字段，不显示内部消费能力判断 |

### 员工端

- 有`community.activity.manage`权限的员工可创建活动草稿。
- 有`community.activity.publish`权限的员工复核后发布，创建和发布权限分离。
- 活动费用、订金、计价方式、付款时限、客户可见规则和退款说明一起保存。
- 客户体验计划到时自动转成迎宾、服务、吧台、冷厨、舞台、经理或营销岗位任务。

## 2. 活动订金配置

每个活动独立配置，不使用一个全店开关覆盖所有活动。

| 模式 | 客户报名结果 | 名额处理 | 适用场景 |
|---|---|---|---|
| 无需预付 `none` | 提交后直接确认 | 立即占用名额 | 免费活动、低违约风险会员活动、到店结算 |
| 订金可选 `deposit_optional` | 客户可付订金，也可选择不预付 | 不预付也确认；付订金的报名等待支付后确认 | 仅在业务确实给予订金客户额外保障时使用，默认不推荐 |
| 必须订金 `deposit_required` | 必须选择订金 | 暂留名额，超时未付自动释放 | 容量有限、外部采购或高爽约风险活动 |
| 全额预付 `full_required` | 必须全额预付 | 暂留名额，超时未付自动释放 | 有明确票务属性、外部成本已发生的活动 |

推荐默认：普通会员活动选“无需预付”；限量且会产生外部成本的活动选“必须订金”。“订金可选”只有在付订金与不付订金确有不同权益时才启用，否则客户没有支付理由，反而增加解释和对账成本。

### 配置字段

1. 计价方式：每人或每次报名/每组。
2. 活动总费用：按计价方式计算。
3. 订金：仅订金模式填写，必须大于0且不高于活动总费用。
4. 付款时限：5至1440分钟。
5. 客户可见付款说明：提交前展示。
6. 退款与取消说明：报名时形成快照，后续修改不追溯覆盖已报名客户。

### 状态规则

```text
无需预付 -> confirmed
必须预付 -> payment_pending -> paid -> confirmed
必须预付 -> payment_pending -> 超时且无有效支付 -> cancelled
支付结果未知/金额不足/部分退款 -> 保留人工复核，不自动确认也不擅自释放
活动满员 -> waitlisted，候补阶段不收预付款
```

## 3. 真实支付边界

当前候选完成了规则、报名快照、名额暂留、异常支付判断和超时释放，但真实活动支付仍受正式商户配置阻塞。生产开放前必须同时完成：

- 活动报名生成权威支付订单并关联同一`payment_id`。
- 微信/星驿正式商户身份、签名和回调配置。
- 支付后服务端查单，不能相信客户端“支付成功”。
- 取消、退款、部分退款、重复回调和未知结果恢复。
- 活动报名、支付账单、银行/服务商账单和门店日结四方对账。
- iPhone和Android微信真机测试。

因此，当前页面遇到必付订金活动时只会诚实显示“等待付款”，不会伪造到账。真实渠道未开通前不得发布要求在线预付的正式活动。

## 4. 付款前单杯升级

- 只在创建支付前出现一次。
- 只匹配后台已启用的指定单杯和目标套餐。
- 服务端按当前标准价、人数、毛利下限和有效时间重新校验。
- 接受升级后，将购物车中的一杯指定单品替换为目标套餐，按目标套餐总价付款。
- 不使用“首杯免费”“付款后返88元”等表述，不允许重复抵扣、拆单共用或人工口头承诺。
- 功能默认关闭，正式菜单、BOM、成本和228/398等目标套餐确认后再配置规则。

## 5. 体验任务自动化

客户选择体验方案后，系统按计划时间生成岗位任务，而不是要求服务员背完整SOP：

| 节点 | 默认时间 | 责任岗位 |
|---|---:|---|
| 需求与边界确认 | 0分钟 | 迎宾 |
| 第一轮核心酒水 | 5分钟 | 吧台 |
| 第一轮低气味冷食 | 8分钟 | 冷厨 |
| 第一轮口味回访 | 18分钟 | 服务员 |
| 演出衔接提醒 | 30分钟 | 舞台运营 |
| 第二轮准备 | 42分钟 | 吧台 |
| 场景互动 | 50至58分钟 | 服务员/经理 |
| 延续体验选择 | 72分钟 | 服务员 |
| 离店收尾 | 105分钟 | 经理 |

桌次或体验计划已关闭时，未执行节点自动跳过；节点到时会生成对应岗位任务并保留Outbox事件。
