# M-BOX 1.0.0-rc.33 四项架构升级

## 本版完成

1. **服务端 AI 工具执行总线**：模型只能提出结构化工具调用；员工确认后由服务端重新校验岗位权限、桌台范围、实时状态和参数，再执行真实领域动作。首批替换开台、创建服务任务、接单、到桌、完成；每次执行带唯一编号、幂等重放、对象 ID、实际状态版本和不可删审计。
2. **规范化高频经营数据**：新增桌次、服务任务、订单、订单品项、支付意图、库存余额六组规范化表。兼容期内与整店聚合在同一 PostgreSQL 事务同步，启动自动回填，写入失败共同回滚；就绪检查要求投影版本、实体数量与权威状态一致。
3. **不可变发布闭环**：CI 通过后才允许构建；GitHub 通过 Workload Identity Federation 登录 Google Cloud；生产只部署 Artifact Registry 的 `sha256` 镜像摘要。数据库迁移后先发布 0% 流量候选，候选和正式地址分别验真；切流后失败自动回滚，发布证据绑定提交、摘要、revision 和就绪状态。
4. **AI 值班经理五维经营判断**：在服务质量之外，同时计算净实收、客单、支付转化、投诉闭环、未解决需求、在线人数、负荷、无人任务、赠送折扣、退款、库存差异和 POS 待对账，并据此改变现场处理优先级。

## 专项验收

| 编号 | 场景 | 通过标准 |
|---|---|---|
| AI-BUS-01 | 李艳说“L01 开台”，但没说人数 | AI 必须追问人数，不得猜 2 人，不产生桌次 |
| AI-BUS-02 | Tom 确认“L01 4人开台” | 服务端返回桌台对象 ID 和新 revision；刷新后 L01 为已开台 4 人；同执行编号重试不重复开台 |
| AI-BUS-03 | 无权限岗位伪造工具请求 | 服务端拒绝，不能依赖前端隐藏按钮 |
| DATA-01 | 任意订单、任务、支付或库存写入 | 聚合状态和规范化表在同一事务提交，checkpoint revision 等于 runtime revision |
| DATA-02 | 删除或归档原对象 | 规范化表同步删除/更新，不保留误导性的活动记录 |
| DATA-03 | 投影缺表、数量不一致或版本落后 | `/api/ready` 返回非就绪，候选 revision 不得切流 |
| REL-01 | 构建生产候选 | 镜像引用必须含 `@sha256:`，就绪信息中的 commit 和 digest 与发布输入一致 |
| REL-02 | 候选验证失败 | 0% 候选不得接收正式流量 |
| REL-03 | 切流后正式地址复验失败 | 自动把 100% 流量恢复到切流前 revision，并保留失败证据 |
| MGR-01 | 有实收但出现 POS 待对账 | AI 经理同时显示收入和待对账金额，并把交班对账作为优先建议 |
| MGR-02 | 服务员满负荷且有无人任务 | 显示在线人数、负荷率、超载人数、无人任务，并优先建议补候补而非继续派给忙人 |
| MGR-03 | 投诉已完成但翻台仍有未解决需求 | 投诉闭环与未解决归档分别计算，不能用“已完成任务数”掩盖体验缺口 |

## 发布边界

本版可以部署到员工验证环境，但不改变商业生产门禁。213 条经营 TC 当前仍为 147 条通过、50 条未执行、16 条阻塞，共 66 条发布阻断；真实支付、打印机、耳机、摄像头、门店网络与岗位签字仍需现场完成。
