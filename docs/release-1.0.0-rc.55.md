# M-BOX 1.0.0-rc.55 公众号预约与店长任务监督

## 本次范围

- 将 `/reserve` 升级为手机优先的三步预约流程：时间人数、直接预约或座位自选、联系信息确认。
- 座位自选使用正式61桌目录，并按舞台前、室内中区和室外区域聚焦展示。
- 同时显示桌位可预约、已预订和临时锁定状态，以及建议人数、定金和最低消费。
- 顾客提交自选桌位后形成待门店确认的预约申请；同一营业时段不能重复申请同一桌位，取消后自动释放。
- 店长可在任务工作台查看他人任务并选择协助完成、亲自接管或转派给符合岗位、区域和负荷条件的员工。
- 所有监督动作保留原任务编号、原责任记录、实际完成人和审计事件。

## 验证要求

- 公共预约令牌只能访问公共预约接口，不能取得员工权限。
- 直接预约不提前绑定桌位；座位自选必须引用正式桌位目录。
- 顾客手机、店长预约台和桌位状态完成跨客户端一致性验证。
- 同桌同时段重复预约必须由服务端拒绝，不能只依赖前端颜色。
- 取消预约后相同桌位应重新变为可预约。
- 390×844手机视口三步流程无横向溢出，区域切换不会暴露其他区域的可点击桌位。
- 店长监督动作必须通过岗位权限、候选员工和幂等校验。

## 发布边界

本版本只部署到阿里云验证环境。预约申请不会自动扣款；真实定金仍需门店确认金额和抵扣规则后，通过后续支付流程完成。正式公众号入口、ICP备案、微信业务域名、模板或订阅通知、真实支付和门店岗位验收仍是商业生产发布前置条件。
