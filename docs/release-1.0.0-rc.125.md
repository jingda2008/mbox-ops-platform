# M-BOX 1.0.0-rc.125

## Scope

This patch candidate supersedes `1.0.0-rc.124` and deploys the normalized staff
web and service bundle against the existing normalized schema `105`. It does not
build, upload or replace the native WeChat mini-program package.

## Staff workspace identity

- Cached staff bootstrap data is accepted only when its employee identity
  matches the authenticated employee.
- Staff workspaces and module pages are remounted by both session and employee,
  preventing a previous employee's entries and data from returning after a
  switch or after navigating back to the workbench.
- Session expiry, employee switching and a fresh login all clear the previous
  bootstrap and navigation state before the next workspace is shown.

## Permission-to-page closure

- Final effective permissions remain the only authority for navigation and
  direct routes. Role navigation still controls presentation only.
- Parent entries now cover the independently rendered activity, customer
  experience, loyalty, membership, privacy, inventory, catalog and performance
  controls that employees can actually use.
- Refund requesters and other authorized cashier roles can read the cashier
  workbench needed by their entry; payment initiation alone still does not
  create a false top-level cashier page.
- Inventory operations and barcode binding load the inventory dashboard without
  exposing cost fields unless `inventory.cost.view` is effective. Catalog-only
  management does not make an unauthorized inventory request.
- Activity managers and publishers can read activity, homepage and media data
  required by the publishing page. Mutations continue to require their exact
  manage or publish permission.
- Performance phase managers and schedule revisers can read the schedule data
  their panels require. Song and performer mutations retain exact song
  management authorization.

## Acceptance boundary

The exact candidate must pass deterministic, PostgreSQL, browser, load,
mini-program contract and release checks. Production verification must confirm
schema `105`, the exact release SHA, readiness and consistent employee identity
after navigating from a module back to the workbench. No real cash, provider
payment, physical POS, printer output or WeChat platform upload is claimed by
these automated checks.

identities are generated by the immutable release and deployment workflows.
They must not be pre-filled before those workflows finish.
