# 1.0.0-rc.286 — 转台、预收与跨日收款候选

本版本处于上线前准备阶段。新增 schema301—304；未部署，未上传或正式发布微信小程序。服务费转换排除。

## 变化和业务口径

员工转台后顾客继续沿原桌次点单，重新进入及页面刷新同步新桌号。目标桌低消生效，补款计入本桌可用额度。员工可自填实收金额，未结清应付继续可收；原款抵扣只新增分配，不再增加收款。顾客自行下单须满足当前低消与可用余额。未确认履约的跨日员工挂账须授权逐单确认，不从未付款推定欠款。

商品卡片不再把长供应说明放进固定高度底部。限时商品保持正常图片，以“可销售时间”加具体时间范围展示；日期、星期、持卡限制仍保留。可购条件仍由服务端判断，18:00前不能通过界面改动绕过下单校验。

实现与前轮证据见[开发记录](table-credit-transfer-development-20261108.md)。本轮追加顾客预收持久幂等、可销售时间展示及部署兼容性检查；此前测试不能替代本轮准确候选验证。

## 上线及恢复条件

schema301跨日核对、302目标桌低消、303员工原款分配、304购物车余额预留分别属于应用兼容性边界。标准入口检测300→304时必须使用维护升级链：排空旧写入方、停写后新备份及OSS验证、迁移、新候选零流量核验、正式切换。不能用准备阶段的旧备份替代切换前备份。

恢复写入后，禁止直接退回rc285/schema300程序或覆盖数据库旧备份。保持旧写入方停止，以理解schema304账务的新候选向前修复。维护期间尚未恢复写入时，也只能按标准恢复流程使用已验证的停写备份，不允许手工删新表或回写订单。

准备阶段只读检查当前生产版本、迁移前缀、营业状态与TLS。准备结果不是维护窗口准入；实际开始前重新采集开放桌次、在途收退款/打印/硬件与事务状态，不能为满足门禁擅自关桌、作废付款或终止顾客事务。

后台应先完成准确提交CI、合并及不可变镜像发布，部署成功并只读核对后，再上传对应微信候选供真机验收。开发版上传、体验版、审核与正式发布分别记录。不能把本地包、截图或CI当成真实到账和实物出纸。
