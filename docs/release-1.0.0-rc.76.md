# M-BOX 1.0.0-rc.76 验证库存边界与菜单反馈

## 本版目的

解决验证环境因尚未录入商品配方和期初库存而无法点单的问题，同时改善客户菜单中加购、数量调整和购物车核对的操作反馈。

## 库存边界

- 验证环境可显式使用`MBOX_INVENTORY_ENFORCEMENT_MODE=audit_only`。
- 缺少配方时仍可建立验证订单和KDS任务，但订单审计与Outbox必须记录未配置商品。
- 正式环境只能使用`strict`；显式配置`audit_only`会拒绝启动。
- 本次不虚构期初库存、原料数量或BOM。正式营业前仍须完成配方、库存和盘点录入。

## 客户菜单

- 心情压缩为单行状态条，桌边服务与推荐工具改为紧凑控件，让商品更早进入首屏。
- 客户与员工规范化页面统一使用中性柔和白和浅灰绿层次，减少纯白带来的生硬感。
- 商品加号使用稳定44px点击区、清晰边界、按压位移和轻触反馈。
- 已加入商品使用紧凑数量步进器，增加侧保持明确强调。
- 底部购物车改为浅色、低压力样式，入口文案由“核对订单”改为“查看已选”。
- 真正的支付提交只在购物车明细中使用微信绿，避免浏览动作与付款动作混淆。

## 验证范围

- 运行配置、库存仓储、订单事务、审计和Outbox单元测试。
- iPhone 14 Pro Max与桌面真实浏览器点单、备注、模拟支付和重复加单流程。
- 320、360、390、430px顾客点单、预约页面和员工高频工作区适配。
- 按钮点击尺寸、计算样式、横向溢出和视觉截图检查。
- 全新PostgreSQL从0执行40个规范化迁移，并验证两个发布任务并发初始化时不会因旧事务快照产生`40001`。

## 发布边界

- 阿里云仍是开发验证环境，继续使用模拟支付；本版不宣称真实支付、打印和硬件联调完成。
- 经营验收清单仍存在未执行与阻塞项，本版只能用于员工现场验证，不能标记为正式营业发布。
