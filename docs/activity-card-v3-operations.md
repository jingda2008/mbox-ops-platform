# v3.0 开场、现场办理与验收交接

本文件配合 `activity-card-v3-requirements.md` 与 `activity-card-v3-implementation.md` 使用。代码和本地测试不能替代真实支付、退款、打印、手机及现场验收。本轮没有变更生产配置。

## 开场前

| 负责人 | 必须落实 |
|---|---|
| 运营 | 活动及餐饮服务时段、加购截止、退订条件；套餐固定总价、每份人数上限、份数、菜品及少量自选项；明确纯加餐价格。 |
| 厨房、吧台 | 菜品对应岗位、实际材料与配方；核对固定份数不随参加人数倍增；按岗位真实试打一份。 |
| 领班 | 门口核销兼发牌、出餐统筹、送餐、异常接手岗位；固定收餐区域；正常队列与售后分流；备用网络及足够号码牌。 |
| 卡管理员 | 新普通兴趣卡名称、申请开关、长期或统一到期日、审核权限和值班；明确实际权益、指定菜品及价格。停止申请不等于撤销已持卡资格。 |
| 授权收银 | “收银与退款 → 活动收银”内的原支付查询、退款申请、独立复核、执行权限及值班；先核清真实资金结果，再处理差价或退款。 |

同一门店活动共用自然数字号；普通桌台明确标“桌”，活动制作单明确标“餐号”。号牌按系统号码交付，当日不得把已结束号码再次给另一份套餐。跨日尚未结束号码继续占用。6、9等号码使用明确方向标识；缺牌时交领班安排唯一替代牌，不能随意另编系统外号码。

## 正常流程

1. **顾客购买**：每份套餐单独选择人数和已配置的菜品选项，固定整份价格与菜量。一次购买形成一份独立记录，可继续购买下一份；付款未知时恢复原请求。新购套餐全额预付，旧订金承诺沿原流程。
2. **核销员查询**：在“全部 → 扫码与活动核销”进入一次，连续扫码。会员码只查询；套餐专用码可办理该份。核对付款、剩余入场、餐饮状态和当前顾客，不根据截图确认款项。
3. **登记、核销和发牌**：默认核对本批首次到场人数，可一次确认入场与餐饮，也可只入场。核销后按系统数字发牌，“下一位”同时记本次发牌完成并继续扫描。晚到只登记新增入场；重入查原凭证，不重复累计。纯活动票不出餐，首次单点付款后到服务点凭原票核销取得餐号。
4. **厨房、吧台制作**：原岗位页面和对应打印机收到同一来源的活动明细。按实际份数开做、放好；允许分批。号、菜、选项、备注和制作记录一致。纸票重打不会增加应做数量；迟票先查原任务余量。
5. **统筹取餐交接**：按一个餐号核对本批实际可取份数，一次“本批已取走”。未取部分继续显示。此记录说明岗位交接，不是顾客签收；不选员工姓名，不增加手机送达确认。
6. **服务员送餐**：按号码到约定收餐点核对号牌。一个号一个收餐点，顾客留人接餐；同号饮品和菜可以分次送。顾客分散时由其集中收餐，不要求员工拆送多人。
7. **加购、收牌**：有效持牌关系下已付款单点自动追加到原号，只制作新增内容。另购套餐在就近服务点核销领新号。同行会员经原套餐专用码授权关联配送，使用自己的权益和付款身份。结束用餐归还牌后关闭新即时加购；已付款未完成内容仍必须交接，不能随着收牌删除。

## 异常处理

| 现场情况 | 接手人及动作 |
|---|---|
| E01/E02：扫错、无效码、摄像头不可用 | 核销员重新扫描或在同页输入完整码查询；查询不核销。会员查询不代替套餐领取授权。已取消权益的退订旧码失效；补偿退款按明确保留的服务办理，不能只看“财务已退”拒绝顾客。 |
| E03：本次人数多于填写或超过额度 | 核销员按实际新增首次到场人数登记，不把重入再计一次；上限内可办理，超过剩余额度交领班另购新增资格，不能放大原套餐承诺。 |
| 确认后无响应、断网或登录失效 | 恢复网络/原员工登录，使用原操作恢复按钮。取餐需原员工及原物理设备；不能通过改数量或重新开单解决未知结果。完全无法核实则暂停新核销发号，已确认纸票由统筹保留并在恢复后核对。 |
| 已有号但未领牌 | 查原号码继续发牌，不重新核销或重复制作。丢牌、发错、跨日原号冲突由领班处理唯一收餐关系；不得同时发两块有效同号牌。预计缺牌时暂停受影响的新发号；错牌有歧义时暂停对应交付，查清后续办。 |
| 已核销但菜品/岗位任务缺失 | 领班在原套餐的明细中恢复应有制作任务；原号和已有任务保留。不让顾客重新付钱或重新核销。 |
| 打印失败、缺纸、结果不明 | 对应岗位先核对实物纸票、打印队列及原制作编号；沿原生成/打印恢复入口处理失败部分。备用打印机由领班统一交接，禁止两个岗位各自补一整单。暂停菜品等待恢复，不反复点击补打。 |
| 缺菜、无法满足特殊要求 | 领班暂停受影响菜，厨房核实。经顾客确认后停做未制作部分，记录替换或售后安排；需要退款走授权收银，新增菜品使用原可追溯购买/出库流程。不静默修改已售套餐，不口头承诺未核实的过敏条件。首期没有自动替换和差价计算引擎。 |
| 错做、洒漏、确需补做 | 管理者选择原菜、实际数量和损耗环节后补做。沿原号建立独立补做来源，另记材料；原已取记录不清零。材料不足先协调，不能把补打当补做。 |
| 误触已取走 | 只有实物仍在出餐口且原批次未继续变化时，撤回该原批次。已经交出的实物不能按误触撤回。 |
| 错送、找不到顾客、无人接收或退回 | 服务员退回指定异常位置并交统筹；管理者在原餐号菜品下记录交付异常和处理结果。可追回实物先处理，确实损耗再补做。记录异常本身不重复制作、不改变已取数量。 |
| 顾客移动 | 服务点更新原号收餐位置并通知统筹；不另发号或复制原餐。 |
| 退款与制作冲突 | 领班核对实际已用内容及关联加购。收银分别确认金额与剩余履约安排；停未做须先在原出品记录停妥，不能用财务退款抹掉实际制作或已用入场。正常队列继续。 |
| 主套餐需退款，但有已付关联单点 | 先处理关联履约归属或分别退款，保留时确保原号及核销途径仍有效；不自动迁到新报名或留下孤立加购。 |
| E16：已归还牌又要加购 | 服务点先在原服务窗口内核对并恢复唯一持牌关系，再新购买；跨日原号被占用交领班处理，不能擅自再发同号。已付款欠餐先交接，不能直接关掉。 |
| E18：菜单到时关闭、旧购物车或报价变化 | 服务点说明具体不可购条目，保留其他选择；重新显示有效价格并由顾客确认，不能静默涨价、删项或后台绕过。 |
| 付款晚回执、超时实收、改价或撤卡争议 | 授权收银查询原交易；截止内实际成功按原承诺履约，截止后实收保留资金事实并接售后，不再次收费。已发起请求恢复原价和原截止，新交易另按当前规则校验。 |
| 卡审批或发券不明 | 卡管理员查原申请、原卡及原赠礼任务；卡已生效只恢复失败发券，不重发卡或重置额度。顾客不被要求补关注或重复填资料。 |
| E20/E22/E25/E26：卡失效、停申请或变更规则 | 卡管理员区分停止新申请、停用资格和旧权益；查原卡/旧券/订单承诺，不能用当前菜单隐藏删除历史或重赠额度。新普通卡不得要求补关注；无权限审批必须拒绝。规则调整不能覆盖已购和已发承诺。 |
| E28：权益会员用错或同菜重复制作来源 | 付款前服务点纠正会员并重新报价让顾客确认；付款后由领班/收银查原权益会员、原付款和唯一来源，沿原售后纠正，不凭换餐号转移权益或再出一份。 |
| 积压、交班或结束活动 | 领班停止必要的新售卖，逐号交接未完成菜、未发牌、待退款和交付异常。按实际峰值测量再决定增援，不用测试总数承诺现场吞吐。活动临时取消时，领班逐项沟通已售内容履约安排，收银接手需退款的原交易，不直接删除订单和制作记录。 |

## 退订与补偿的实施口径

- 按用户已确认的首期方案，顾客一键提交本人未使用整份退订申请，原审核按公布条件复核后沿原渠道执行。页面显示“等待门店审核”，不把申请成功当作退款到账；首期不增加自动审核退款。正常核销员不承担退款审核，疑难交授权收银。
- 授权收银补偿退款明确金额、顾客确认及剩余安排；由独立复核人审核，再执行原渠道退款。保留履约与停止未做部分分别记录，已用入场、制作、取走事实不因财务全退消失。
- 原单已有成功或未决补偿时，后续退款继续明确服务安排，不能切换普通整份退订。退款被拒绝且没有其他有效补偿记录时，才可重新按原资格判定。已用的免费套餐或仍有有效关联加购的免费父套餐，也不能由旧取消入口直接撤掉。
- 停做、备注、补打、退款和补做分别表达不同事实，不能互相替代。普通现场流程不增加这些步骤，只由异常岗位处理。

## 兴趣卡和旧券的简便办理

- 卡管理员在卡项目内进入“配置入卡权益”，系统预选当前卡。需要发券时复用已有权益规则、独立审核和发布；仅设置指定商品可见/可买时不必配置赠券。会员申请和一次审批不增加步骤。
- 有效固定价券的指定商品即使被新增可见时段隐藏，顾客仍可从券包进入原购物车，按份选择套餐选项并核对用券报价。没有该券覆盖的份数不能绕过当前售卖规则；库存、原有效期和全局停用继续生效。
- 免费赠品由有权限的员工在会员查询内进入“办理赠品券”，选择本人当前桌台，暂留后核对并出品。只有套餐包含自选项时才逐份选款；普通单品不增加选款步骤。核销未知时恢复原操作，不重复占券或生成出品。
- 原券与桌台信息变化时刷新后核对；缺货或过期由原售后接手。未明确核销成功前不凭口头承诺制作。
