# 1.0.0-rc.225 重复支付尝试与历史审核发布

同一次收款在刷新页面或换窗口后使用新请求键，过去会建立新的支付ID；渠道动作的幂等保护只覆盖原ID。后端现在按既有锁序检查精确的订单分摊、金额、渠道、方式，复用未释放的线上尝试，且不重复发出payment.initiated事件。不同金额/方式保持独立，明确放开重试仍保留审计；不增加进程全局队列。

历史处置作为正式维护发布的显式计划字段historicalPaymentReview，包含原因、租户/门店/支付ID及资金指纹。控制器先验证原冻结预检身份、已关闭桌次、实际欠款为零、已收款及退款匹配账务流水、没有未消费渠道终态或正在外送的动作，再只追加不可变审计和停止自动查询。原支付、退款、账务流水和原发布基线保持不变。审核收据单独受root:0600及哈希日志保护；后续任何资金/动作变化、未关联新增尝试或终态未入账继续阻断。恢复运行后晚到回调沿原验签与幂等命令入账，多收继续进入财务提示。

财务核对页显示关联订单、当时欠款及正确收款，历史尝试保持待核，不伪造支付失败、平台关单或财务结案。已停用的旧付款不再提供二维码；人工查单结果不能重新启动自动重试。正确收退款不调整，顾客无需重付。

## 验证与范围
