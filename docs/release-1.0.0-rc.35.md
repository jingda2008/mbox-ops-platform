# M-BOX 1.0.0-rc.35 全端即时交互升级

## 本版完成

1. **统一按钮事务反馈**：客户、员工、预约、支付、库存、经营工具和硬件接口统一获得点击反馈、处理中进度、成功确认和失败提示；同一按钮处理中不接受重复点击。
2. **高频流程乐观更新**：服务任务、KDS出品、预约确认/到店和客户情绪先更新当前行，再异步提交；服务端返回后用权威对象校准。
3. **失败自动恢复**：每次乐观操作保留原快照，请求被拒绝或网络失败时恢复原状态；对象级版本隔离防止旧请求回滚新操作。
4. **局部忙碌代替整页锁定**：服务任务和KDS只锁定正在处理的单条记录，其他任务、桌台和页面入口继续可用。
5. **后台同步不阻塞反馈**：客户呼叫和点歌在服务端受理后立即呈现，整店刷新转入后台；预约成功提示不会被后台刷新提前清除。
6. **风险分级**：支付、退款、库存、配置、权限和关账继续等待服务端权威确认，只优化反馈速度，不伪造业务成功。

## 本次关闭的问题

| 问题 | 经营影响 | 修正 |
|---|---|---|
| 操作成功后还等待整店刷新 | 员工认为按钮没反应并重复点击 | 高频流程先局部更新，整店刷新后台执行 |
| 单条任务操作锁住整页 | 高峰期无法并行处理其他桌 | 改为任务ID/KDS ID级忙碌状态 |
| 失败后页面可能保留预测状态 | 员工看到与服务端不一致的假完成 | 自动恢复原快照并提示重试 |
| React重绘覆盖按钮进度样式 | 移动端处理中边框可能闪退 | 改为独立网络状态属性驱动，不受组件class重绘影响 |
| 预约后台刷新清掉成功提示 | 店长不知道确认是否完成 | 后台刷新保留本次操作提示 |

## 验收证据

- 静态、领域和构建检查：119个测试文件、826条测试全部通过，其中新增7条乐观事务、状态投影和请求分类测试。
- 浏览器：15条跨客户端、权限、KDS、移动端与无障碍流程通过；新增延迟网络即时反馈和失败恢复覆盖。
- 移动视觉：430×932视口无横向溢出、无按钮重叠，客户页面反馈不改变布局。
- 压力：300位客人、60并发、900次HTTP请求，失败率0，5xx为0，接口P95约25毫秒。
- 供应链：生产依赖高危漏洞0。

## 发布边界

本版让页面操作更快、更明确，但不改变资金、库存、权限和关账的服务端权威边界。真实微信支付、星驿生产参数、硬件回执和门店现场签字仍是商业生产发布前置条件。

213条经营TC仍为147条通过、50条未执行、16条阻塞，共66条P0/P1发布阻断；本版可以部署验证环境，不能改称正式商业生产版。
