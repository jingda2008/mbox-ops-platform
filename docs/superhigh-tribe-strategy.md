# M-Box × 超嗨部落长期经营架构

## 母子品牌分工

| 品牌 | 核心职责 | 主要页面 | 成功指标 |
| --- | --- | --- | --- |
| M-Box（场所品牌） | 到店、预约、点单、支付、演出与现场服务 | 客人桌码、员工端、收银、出品、预约 | 到店率、客单价、服务响应、出品时效 |
| 超嗨部落（母品牌） | 品牌文化、兴趣连接、活动体系与长期关系 | M-Box 各触点中的轻量背书、活动页、微信服务号/企微 | 活动参与、复购、召回、转介绍 |

原则：客人在所有交易和会员环节首先识别 M-Box；通过小手、爱心、彩色短线和“超嗨部落旗下空间”等微元素，逐渐理解 M-Box 的母品牌关系。会员身份仍是 M-Box 会员，不另造一套高强调的“部落会员”身份，也不在收银、KDS、员工任务正文增加装饰。

## 客群沉淀闭环

1. 客人通过预约、桌码点单、付费点歌、领取权益或呼叫服务形成可识别访问。
2. 在合规授权后绑定微信身份与会员账号，合并同一客人的到店、偏好和活动记录。
3. 系统只沉淀经营需要的标签，例如常来日期、音乐偏好、酒水偏好、生日月份、同行人数和活动参与，不使用人脸识别替代会员授权。
4. 离店后按真实行为分群，发送权益、下一场演出或主题活动邀请。
5. 活动报名、到场、核销、消费和满意度回写会员档案，形成下一次推荐依据。
6. 店长查看留存、复购、活动转化和投诉闭环，不以群发数量作为经营成果。

## 系统模块

### 当前版本

- 在运营配置中管理超嗨部落名称、英文标识、口号、图片、活动关键词和展示开关。
- 客人订单页只显示小型母品牌签名，不遮挡订单、出品和支付信息。
- 会员中心以 M-Box 会员身份为主，在品牌头部、头像和权益边线分散使用超嗨微元素。
- 配置沿用草稿、发布、审计和版本回滚机制。

### 第二阶段：活动经营

- 活动模板：主题、时间、容量、票价、会员等级、适合人群、权益包、取消规则。
- 报名与候补：会员报名、同行人数、订金、候补递补、到场二维码、退款。
- 现场联动：活动座位、桌台、点单、付费点歌、生日与互动任务进入同一经营事件流。
- 客群标签：只由明确行为生成，并记录来源、时间、有效期和人工修正。
- 活动复盘：曝光、报名、到场、消费、复购、投诉、转介绍和单场利润。

### 第三阶段：部落文化

- 兴趣小组：音乐风格、歌手、城市社交、企业活动等可配置主题。
- 成员成长：到场、活动参与、友好互动和邀请好友形成成长值；消费金额不能成为唯一依据。
- 共创机制：歌单投票、主题夜提案、生日共创、成员主理活动。
- 内容资产：活动照片、歌单、回顾和成员故事在获得授权后进入服务号内容库。
- AI 运营建议：基于活动与消费事实提出分群、召回和排期建议，任何群发、权益成本和敏感标签仍由授权人员确认。

## 视觉使用边界

- 使用品牌手册中的小手角色和高饱和色作为会员身份符号，彩色面积控制在页面的少量关键区域。
- M-Box 头部、商品、金额、支付状态和服务按钮始终保持最高信息优先级。
- 超嗨完整视觉主要用于独立主题活动详情、报名成功、现场互动和活动回顾；M-Box 常规页面仅使用微元素。
- 不把吉祥物放入员工任务、厨房、调酒、收银和异常告警页面。
- 当前系统资产 `/brand/superhigh-mark.png` 来源于现有品牌视觉手册，正式商业发布前应由品牌方确认数字端使用授权和标准源文件。

## 商业化验收指标

| 环节 | 首期指标 |
| --- | --- |
| 会员识别 | 可识别消费桌次占比、授权入会率、重复档案率 |
| 服务体验 | 呼叫响应时间、未解决率、现场投诉闭环率 |
| 活动 | 报名转化、到场率、候补递补率、单场利润 |
| 留存 | 30/60/90 日复购、活动后复购、沉睡会员召回 |
| 文化 | 非消费互动参与、成员共创、有效转介绍 |

所有指标按门店、活动、渠道和客群分层查看；不以单次消费高低直接定义成员价值。
