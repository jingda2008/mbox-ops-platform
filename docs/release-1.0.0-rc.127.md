# M-BOX 1.0.0-rc.127

## Scope

This release candidate supersedes `1.0.0-rc.126` and deploys the normalized
staff web, service and database bundle. The deployment preflight verifies the
current production schema and applies the contiguous candidate migration chain
through `138`; it does not assume a production baseline from a release note.
It does not build, upload or replace the native WeChat mini-program package.

## Operational closure

- Keeps shared-table ordering and payment state server-authoritative, including
  controlled cashier collection, refunds, one-time recollection and printable
  payment evidence.
- Adds activity packages with independently configured pricing, capacity and
  inventory reservation, plus activity cashier collection and fulfillment
  paths without manufacturing table orders.
- Extends member benefit, inventory, KDS remake and business-day workflows
  with server-side permission and transaction checks.
- Repairs the customer continuation flow and the staff reservation-intake
  query so a non-critical refresh cannot trap the customer and mixed
  reservation/waitlist intake can be sorted by the published priority rules.

## Acceptance boundary

The exact candidate must pass immutable CI quality, PostgreSQL transaction,
browser, performance and release-metadata gates. Production verification must
confirm the exact SHA, image digest, schema `138`, worker health, public
readiness and migration outcome. Local and CI checks do not claim a completed
real provider payment, physical POS, printer, hardware, staffed-field shift or
native WeChat upload.

## Production route

The public origin is `https://mbox.shmbox.com`. Deployment uses the immutable
GitHub pre-release, the private application host `10.100.80.223:22` through
the configured relay `139.224.254.60:6122`, and the existing backup,
migration, candidate-health and rollback safeguards.

## Deployment evidence

Commit, CI run, release asset, image digest, backup and production verification
identities are generated by the immutable release and deployment workflows.
They must not be pre-filled before those workflows finish.
