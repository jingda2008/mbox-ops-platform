# M-BOX 1.0.0-rc.80 同桌订单与支付接力候选

## 本版目的

员工协助点单、桌码多人查看和客人手机付款必须围绕同一桌次订单工作。员工可以选择让客人扫描平板二维码，或由员工扫描客人的付款码；客人也可以从自己的手机对同一笔待付订单发起支付，系统不得因此复制订单或重复收款。

## 本版变化

- 员工协助点单在提交后先同步到本桌，再进入“客人扫二维码”或“扫客人付款码”的收款选择。
- 同桌多个客人可查看相同的商品、轮次、履约与应付状态，并可从手机继续允许接力的待付款订单。
- 员工生成的二维码支付动作由同桌客人复用，服务端返回同一个付款记录，不重新创建应收。
- 员工扫描付款码时，桌码显示员工收款中并禁止重复发起；客人JSAPI支付参数不能被另一名同桌客人复用。
- 每笔付款只允许一个短时支付动作；渠道载荷加密保存，桌码响应不包含付款人身份、付款码、`openid`或渠道原始证据。
- 支付机构明确拒绝时保留已建立订单并允许重新发起；结果未知时禁止重复收款，必须先查单。

## 自动化验收

- 单元/API：支付角色隔离、方法锁定、加密动作复用、拒绝与未知状态恢复。
- PostgreSQL：全新数据库迁移、同桌访问、支付动作唯一性和订单共享查询。
- 移动浏览器：员工连续建立挂账、二维码、付款码和赠送订单；两名客人看到同一桌订单；客人手机复用员工二维码的同一`paymentId`；付款码订单不能从桌码重复付款。

## 验收边界

本版允许部署到开发验证环境，但自动化支付测试不等于真实资金联调。星驿真实小额支付、微信身份授权、支付回调、主动查单、退款和对账仍须在明确授权、测试商户配置完整且值班人员在场时单独验收。任何真实支付结果只能以验签回调或主动查单为准。

字段和安全边界见 [星驿支付联调字段映射](postar-payment-integration-1.0.0-rc.80.md)，验收状态见 [规范化候选验收用例登记](quality/normalized-core-v1-test-case-register.md)。
