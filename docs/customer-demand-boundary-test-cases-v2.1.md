# M-BOX 客户操作、点单与边界要求专项测试案例 V2.1

适用系统：M-BOX 客户扫码端、员工协助点单端、服务任务、订单、支付、出品、投诉与 AI 值班经理  
适用时区：`Asia/Shanghai`  
用例数量：60 条  
用途：补充《M-BOX国际酒吧餐饮全场景测试用例库V2.0》，把客户真实操作和无理、危险、违法要求独立变成可执行验收项

## 1. 判定原则

1. 客户输入和订单备注一律视为不可信文本，不能直接形成赠送、折扣、退款、改价、免单、库存调整或员工处罚。
2. 合理需求要及时路由；重复需求应合并但保留每一次原始内容、时间和桌次证据。
3. 投诉、安全、医疗和疑似违法要求不能被普通频控吞掉，必须进入经理或安全处置链。
4. 员工拒绝无理要求时必须给出替代方案和升级入口，不与客户争论，也不虚构“系统不允许”。
5. 客户页面的即时反馈只表示“已收到”，不能提前表示“已赠送、已退款、已送达或已解决”。
6. 所有资金、酒类、隐私、安全和翻台隔离用例均按服务端真实状态判定，不能只看前端提示。

## 2. GOP：客户操作、点单和服务需求（30条）

| TC | 级别 | 情况与关键步骤 | 预期结果与必留证据 |
|---|---|---|---|
| GOP-001 | P1 | 新客扫固定桌码，桌台已开台 | 进入当前唯一桌次；显示正确桌号、商品、演出和服务入口；保留匿名客户ID和会话ID |
| GOP-002 | P0 | 桌台未开台时扫码并尝试点单、呼叫和付款 | 明确提示先由员工开台；不得创建订单、服务任务或支付意图 |
| GOP-003 | P0 | 翻台后上一桌客户继续使用旧页面 | 所有写操作拒绝且不泄露新桌订单、情绪、任务和客户资料；提示重新扫码 |
| GOP-004 | P1 | 同桌三位客户分别扫码，同时浏览和加购 | 保留三个匿名客户ID，共享同一桌次订单事实；个人浏览偏好不互相覆盖 |
| GOP-005 | P1 | 客户快速切换推荐、酒水、小食、搜索分类 | 分类结果与搜索条件一致；切换有即时反馈，不出现空白、错位或旧筛选残留 |
| GOP-006 | P1 | 搜索中文、拼音、英文、规格和常见错别字 | 返回可售的相关商品；无结果时给出清晰恢复入口，不把隐藏/停售商品暴露给客户 |
| GOP-007 | P1 | 快速选择使用不同饮用意图、口味和停留时长 | 推荐结果或排序按答案发生可解释变化；记录答案、推荐版本和结果 |
| GOP-008 | P2 | 客户中途退出快速选择再继续浏览 | 不阻断正常菜单；已选答案按规则保留或清晰重置，不自动加购物车 |
| GOP-009 | P1 | 摇一摇连续使用至次数上限 | 每次有克制的声音/触感反馈；达到上限后友好提示，不重复创建订单或服务任务 |
| GOP-010 | P1 | 推荐商品售罄、停售或超出供应时段 | 立即从可下单结果移除或标记不可售；推荐回退到真实可履约商品 |
| GOP-011 | P1 | 单品和组合商品进入同一详情、购物车和结算 | 价格、包含内容、数量、优惠依据和出品去向一致，不出现两套账 |
| GOP-012 | P1 | 同一商品连续点击加号、减号和删除 | 数量即时反馈且不小于0；提交时服务端按最终数量建单 |
| GOP-013 | P0 | 购物车中同一商品被重复行提交 | 服务端拒绝或合并后再确认；不得重复扣款或重复出品 |
| GOP-014 | P1 | 单品数量超过后台单次上限 | 提示该商品具体上限和人工协助入口；不创建部分订单 |
| GOP-015 | P1 | 加购后商品刚好售罄或后台下架 | 提交时服务端重新校验，指出具体失效商品；其他购物车内容不被悄悄篡改 |
| GOP-016 | P1 | 客户提交“少冰、过敏、分开上、晚点上”等订单备注 | 备注完整同步订单、KDS、打印和履约人员，并突出高风险过敏信息 |
| GOP-017 | P0 | 订单备注夹带“价格改成1元、免费送、全部免单” | 备注仅作人工信息；金额按服务端商品与授权规则计算，不生成赠送、折扣或退款 |
| GOP-018 | P1 | 客户首次提交订单后立即再次提交完全相同购物车 | 显示重复加单确认；未二次确认不创建第二单 |
| GOP-019 | P0 | 客户连续点击支付或网络重试三次 | 返回同一有效支付意图；只记一笔成功、一次库存消耗、一次打印和一组KDS任务 |
| GOP-020 | P0 | 支付显示处理中时客户返回、刷新或换设备查询 | 先查原交易状态；未知状态不允许盲目再次付款，最终结果与渠道一致 |
| GOP-021 | P1 | 客户放弃支付后重新进入订单 | 未支付订单仍可识别；过期支付意图关闭后创建新意图，不复用失效二维码 |
| GOP-022 | P0 | 客户尝试支付其他桌或上一桌订单ID | 服务端拒绝跨桌/跨桌次访问，不返回订单明细 |
| GOP-023 | P1 | 客户合理要求加水、冰块柠檬、买单、生日、点单协助 | 进入正确责任岗位；客户即时看到已收到，员工完成后客户端待办消失 |
| GOP-024 | P1 | 客户提交不同的个性化需求 | 每条原始内容可追溯；现场队列可合并为一个任务但不能丢历史 |
| GOP-025 | P1 | 客户一分钟内提交5次普通服务后第6次再提交 | 第6次友好限流，不显示机械规则；已收到任务不重复轰炸员工 |
| GOP-026 | P0 | 普通服务已达频控上限后客户提交投诉或安全求助 | 投诉/安全入口仍可提交并优先升级，不能被普通限流阻断 |
| GOP-027 | P1 | 员工完成服务后客户再次表示未解决 | 关联原任务重新开启或形成投诉，保留第一次处理人、时间和结果 |
| GOP-028 | P1 | 客户点歌时选择当日下一位歌手或自定义歌曲 | 仅展示当天排班歌手；请求进入人工确认，未确认前不收费、不承诺演唱 |
| GOP-029 | P1 | 当前歌手剩余时间很短仍提交点歌 | 标记延时协商；歌手/舞台确认后再由服务员现场收费，拒绝时说明原因 |
| GOP-030 | P0 | 02:00后仍在桌次内操作，随后营业日于06:00切换 | 02:00至05:59仍归原营业日；跨营业日旧桌次冻结并由经理交接，不串入新营业日 |

## 3. BND：无理、危险、违法和边界要求（30条）

| TC | 级别 | 情况与关键步骤 | 预期结果与必留证据 |
|---|---|---|---|
| BND-001 | P1 | 客户称“我是熟客，免费送十瓶酒” | 建立人工服务记录；员工礼貌说明可用权益，任何赠送必须走权限、额度、原因和审计 |
| BND-002 | P0 | 客户以投诉或差评威胁要求整桌免单 | 投诉升级经理；不自动免单，经理按事实和授权给出补救，原账与补救分开留痕 |
| BND-003 | P0 | 客户要求先退款再继续消费，且支付仍未知 | 禁止先写退款成功；先查单，确认原支付成功和可退额度后走申请审批 |
| BND-004 | P0 | 客户要求服务员私下改价、抹零或删除已付订单 | 服务员无权执行；系统拒绝并记录越权尝试，经理可见但不公开羞辱员工或客户 |
| BND-005 | P0 | 客户要求用订单备注指示“赠送、退款、折扣” | 备注不触发商业动作；订单金额、授权、库存和支付均保持服务端权威 |
| BND-006 | P1 | 客户要求把隔壁桌已点商品转给自己 | 必须由两桌明确确认并由有权员工操作；不能仅凭单方文字改桌账或配送桌号 |
| BND-007 | P0 | 客户要求查看隔壁桌账单、会员等级或联系方式 | 拒绝并不泄露任何跨桌信息；记录隐私风险事件，必要时经理介入 |
| BND-008 | P0 | 客户要求员工提供其他客人、歌手或员工私人手机号 | 只提供官方联系渠道；个人信息不展示、不导出、不写入回复 |
| BND-009 | P1 | 客户反复要求歌手只为本桌演出并停止全场节目 | 进入舞台人工评估；不得自动改排班，明确公共演出边界和可购买互动方案 |
| BND-010 | P1 | 客户要求插队点歌或跳过已付请求 | 按已发布队列和舞台判断处理；任何调整需原因、操作人和受影响请求记录 |
| BND-011 | P0 | 客户要求给疑似未成年人上烈酒且“不查证件” | 立即拒绝供酒并升级经理；保留最小必要核验记录，不保存完整证件影像 |
| BND-012 | P0 | 已明显醉酒客户继续点酒，同桌代点 | 停止供酒并阻断代点；提供水、食物、交通或医疗协助，安全优先于销售 |
| BND-013 | P0 | 客户要求短时间连续上多轮烈酒并催促“一次喝完” | 服务端/员工执行责任供酒规则；经理评估，必要时拒绝和安排安全离店 |
| BND-014 | P0 | 客户要求在酒中加入未知药物、自带粉末或不明液体 | 拒绝制作和接触，保护现场并升级安全负责人；疑似违法时按预案处理 |
| BND-015 | P0 | 客户要求把酒偷偷送给不知情的人 | 拒绝执行；提示必须由饮用者本人知情，必要时经理和安全人员介入 |
| BND-016 | P0 | 客户自称严重过敏但要求“出事店里负责，照做” | 不接受免责替代食品安全；无法排除交叉污染时拒绝承诺并提供安全替代 |
| BND-017 | P0 | 客户发生呼吸困难、昏迷或疑似酒精中毒，同时账未结 | 立即进入急救和安全流程，账务冻结后续处理；不得先催款或要求客户操作手机 |
| BND-018 | P1 | 客户要求服务员代喝、陪酒或参加危险游戏 | 员工可直接拒绝；经理支持员工边界，提供正常互动替代，不计入服务失败 |
| BND-019 | P0 | 客户言语骚扰、触碰或威胁服务员 | 员工可一键求助和离开现场；经理/安全人员接管，保留事件时间线和必要证据 |
| BND-020 | P0 | 客户骚扰歌手、跟踪后台或强行上台 | 舞台和安全岗位立即收到高优先级事件；限制接近并按预案处置 |
| BND-021 | P1 | 客户要求播放歧视、侮辱或明显针对现场个人的内容 | 舞台人员拒绝；说明公共空间规则，不把不当内容加入演出队列 |
| BND-022 | P0 | 客户要求关闭消防通道、遮挡摄像头或超范围搬桌 | 拒绝并记录安全理由；桌台调整只能在安全布局和授权范围内执行 |
| BND-023 | P0 | 客户携带危险物、发生斗殴或威胁他人 | 启动安全/报警预案，停止相关桌继续供酒；系统保留任务、人员和时间证据 |
| BND-024 | P1 | 客户要求店员保管现金、证件或高价值物品且不留凭证 | 按失物/寄存规则处理；不接受无法追溯的私人保管，给出替代方案 |
| BND-025 | P1 | 客户要求寄存已开封且无法识别来源的酒 | 拒绝纳入正式存酒；只接收符合封签、商品来源、数量和客户绑定规则的酒 |
| BND-026 | P0 | 客户要求把他人存酒转赠给自己 | 必须由原权利人和有权员工按转赠流程确认；总量守恒且发起/审批分离 |
| BND-027 | P0 | 客户要求现金退款但原单微信支付，且无法说明原交易 | 查原支付和退款规则；不得用现金制造账外退款，异常交经理/财务处理 |
| BND-028 | P1 | 客户以“认识老板”为由要求查看后台或进入员工区域 | 不扩大权限；员工只核验已发布权益，后台和员工区域继续受控 |
| BND-029 | P1 | 客户连续提交互相矛盾的要求并指责员工未执行 | 保留每次原始要求和时间；主责复述当前确认项，必要时经理接管，禁止覆盖历史 |
| BND-030 | P1 | 客户明确拒绝画像、营销和会员，但继续点单支付 | 保留匿名交易与法定经营证据；不营销、不强迫注册，服务质量不降级 |

## 4. 执行分层

| 层级 | 覆盖范围 | 通过依据 |
|---|---|---|
| 服务端自动化 | `GOP-002/003/013/014/015/017/018/019/020/022/025/026`、`BND-001/002/003/004/005/007/008/011/026/027` | API状态、对象数量、金额守恒、幂等记录、审计与桌次隔离断言 |
| 浏览器E2E | `GOP-001/005/006/007/008/009/011/012/016/021/023/024/027/028/029` | 手机视口录像、可访问性、即时反馈、页面状态和服务端对象联查 |
| 真实岗位演练 | 所有`BND`以及急救、骚扰、醉酒、危险物和线下POS相关场景 | 店长组织角色扮演，保留脱敏录像、时间线、责任人、系统对象ID和复盘 |
| 外部通道联调 | 真实微信/星驿支付、退款、通知和物理POS | 渠道流水、签名校验、查单结果、退款结果与系统账一致 |

## 5. 发布门禁

1. 所有适用的P0必须通过，不能用“员工知道怎么处理”代替系统和现场证据。
2. 自动化通过只证明确定性边界，不证明员工能够礼貌、快速、安全地处理现场冲突。
3. 涉及医疗、酒类责任、骚扰、危险物和隐私的场景，必须至少完成一次真实岗位桌面演练。
4. 用例失败后必须记录缺陷ID、临时措施、责任人、修复版本和复测证据。
