# M-BOX 1.0.0-rc.79 网页入口发布门禁候选

## 本版目的

保留 `rc.78` 已完成的审计整改，在发布前后增加网页入口与静态资源验证，避免只检查 API 健康状态而遗漏固定桌码、预约或员工深层网址。部署后还必须由同一提交的 Playwright 执行 JavaScript 并确认页面真实渲染，不能用 HTTP 探测冒充真实浏览器测试。

## 本版变化

- 发布冒烟同时检查首页、`/guest?table=W01`、`/reserve` 和 `/staff/live`。
- 网页检查使用移动浏览器请求头，要求返回 200、HTML 类型、`#root` 挂载点，并验证页面引用的模块脚本真实存在且类型正确。
- 前端 HTML 写入构建提交号，必须与健康接口和候选提交一致；部署后真实浏览器还要检查页面错误、脚本和样式加载失败及空白根节点。
- 非网页接口请求仍返回结构化 404，不把未知 API 错误兜底成前端页面。
- 蓝绿切流前后的同一检查失败时自动停止发布或恢复上一版本；恢复后同时核对旧提交、镜像摘要、数据库版本、部署层级、网页入口和容器自动启动策略。
- 激活、验证、回滚及 OSS 辅助脚本全部写入发布清单并逐文件校验 SHA256，发布机只执行证据包内脚本。
- 中断信号使用明确退出码；恢复时读取容器的实际提交和镜像摘要，不依赖进度标记，避免切流中断被误报成功或留下错误容器。
- 探测参数有明确上限，四个入口并行检查；目标提交身份错误立即失败，网页或资产连续两次失败才终止，避免瞬时网络抖动误回滚。

## 验收边界

本版没有改变点单、预约、支付、退款、库存或岗位业务逻辑。真实支付、实体 POS、打印、通知、硬件和员工现场演练仍属于商业发布阻断项；本版只能作为阿里云开发验证版本。公网验收在候选实际切流并核对提交与镜像摘要后才允许标记通过。

详细业务整改沿用 [rc.78 审计复核](audit-report-reconciliation-1.0.0-rc.78.md)，本版新增门禁见 [rc.79 增量 TC](tc-release-route-gate-1.0.0-rc.79.md)。
