# M-BOX 1.0.0-rc.47 订单重点备注

## 本版完成

1. 客人扫码点单和员工协助点单均可在提交订单时填写选填备注，前端限制300字并在提交前保留内容。
2. 服务端统一校验备注长度、标准化空白并纳入幂等冲突判断，避免网络重试把不同备注误认为同一订单。
3. 备注在创建订单时形成快照，并同步到吧台/厨房KDS、出品取送任务、打印任务、收银桌账和客人订单记录。
4. 吧台、厨房、传菜、服务员、收银和管理页面使用一致的重点样式，不依赖口头二次转述。
5. 订单失败时保留备注供再次提交，订单成功后清空，避免备注错误带入下一单。

## 数据迁移

- 本版不新增数据库迁移。
- 备注属于订单聚合及其履约快照字段，现有PostgreSQL聚合持久化可向前兼容。
- 打印、KDS和送达任务均保存提交时的备注快照，后续界面文字变化不影响历史订单。

## 发布验证

- 完整静态检查、单元/集成测试、生产构建和小程序兼容检查。
- Playwright客户、员工、预约、打印、KDS、损益和移动端流程。
- 阿里云候选容器必须在独立端口通过就绪、数据库投影、真实员工登录及客人员工菜单备注显示后才能切流。
- 切流前创建PostgreSQL备份并保留`rc.46`容器与镜像用于应用回滚。

## 发布边界

本版仍为门店验证环境。线上支付保持模拟模式；微信/星驿真实资金、真实退款、双打印机和门店硬件尚未完成生产联调。订单重点备注自动链路可进入岗位验证，但真实打印和吧台、厨房、传菜、收银交接未签字前，`SYS-025`不得标记完成。
