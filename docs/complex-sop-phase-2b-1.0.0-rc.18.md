# M-BOX 复杂SOP第二阶段第二批 1.0.0-rc.18

## 本次范围

`rc.18`把SOP从系统内派单继续扩展到外部终端和独立验证节点。所有动作仍归属于原SOP执行、步骤、桌次和任务，使用幂等键、版本快照、重试租约和审计记录，不另建无法追责的提醒模块。

## 通知终端

- 系统内任务始终保留，不能配置成仅依赖外部终端。
- 每一步可同时选择耳机播报和企业微信员工通知。
- 耳机使用门店Webhook适配器；企业微信使用正式员工消息接口和员工账号映射。
- 外部终端缺少地址、密钥或员工映射时，记录为“未配置”或失败，不返回虚假送达。

## 完成验证

- 责任员工完成：沿用接单、到桌、完成闭环。
- 指定岗位完成：只有配置岗位可以结束任务。
- 经理独立复核：任务完成后生成复核待办，批准后SOP才继续；驳回后执行阻塞并留痕。
- 实体桌码验证：员工到桌后扫描固定桌码，校验门店、桌台和撤销版本；审计只存摘要，不保存二维码原文。
- 摄像头抽帧验证：向视觉适配器发送任务，必须返回任务编号和证据引用才算通过。

## 运行可靠性

- 外部动作使用独立派发队列、租约、指数重试和幂等键，避免多实例重复发送。
- 外部通知是辅助通道，发送失败不会抹掉系统内任务。
- 经理、桌码和摄像头验证是阻塞节点，后续步骤从验证完成时间开始计时。
- 转桌时，未完成的验证动作跟随原桌次转移到新桌台。
- 所有通过、驳回、未配置、失败和重试均进入审计日志。

## 商用参数

- `MBOX_SOP_HEADSET_WEBHOOK_URL`、`MBOX_SOP_HEADSET_WEBHOOK_TOKEN`
- `MBOX_SOP_WECOM_EMPLOYEE_USER_IDS_JSON`
- `MBOX_SOP_CAMERA_WEBHOOK_URL`、`MBOX_SOP_CAMERA_WEBHOOK_TOKEN`
- 企业微信仍需配置既有企业ID和应用凭据。

以上参数没有取得真实设备或生产账号前，云端验证版保持适配器未启用状态，不影响当前没有启用复杂SOP的门店流程。

## 后续范围

- 条件分支、并行步骤、失败补偿和更通用的人工审批编排。
- 耳机厂商、企业微信真实账号和摄像头边缘代理的现场联调及断网演练。
- 原生App扫码组件；当前网页验证支持扫码枪自动输入或粘贴完整桌码链接。
- 客户小程序/服务号通知需要完成桌次、临时访客ID和会员身份的可靠绑定后再接入。

支付继续保持验证模式；正式支付密钥、回调域名和商户生产验收不属于本版本。
