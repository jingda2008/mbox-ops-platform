# M-Box 生产值班与故障手册

## 每日开店前

1. 检查`/api/live`和`/api/ready`均为200，`/api/ready`显示PostgreSQL仓储和最新迁移。
2. 检查前一营业日支付账单、物理POS报送、退款、权益核销和点歌收款无未解释差异。
3. 确认当班人员在线、区域主责/候补/领班/经理齐全；缺岗时先调整责任链再开台。
4. 检查菜单、库存、低库存、歌手排班、预约、桌码和服务SLA使用当天已发布版本。
5. 由值班经理在PC、平板和手机各完成一次登录、呼叫服务、下单和KDS冒烟。

## 营业中告警分级

| 等级 | 例子 | 第一责任人 | 立即动作 |
|---|---|---|---|
| P0 | 重复扣款、跨桌数据、密钥泄露、数据库不可恢复 | 技术负责人+老板 | 停止相关写入口，保留日志与请求ID，禁止手工改账 |
| P1 | 支付结果未知、全店无法点单、任务大面积不派发 | 技术值班+店长 | 切物理POS/纸质应急单，记录桌台和流水，持续查单不重复支付 |
| P2 | 单设备离线、通知失败、KDS单档口异常 | 领班+技术值班 | 更换设备或人工传单，Outbox保留原幂等身份后重试 |
| P3 | 话术、排版、非关键配置问题 | 产品负责人 | 记录营业日期、桌台、人员和截图，次日配置或版本修复 |

## 支付未知结果

1. 客户端跳转、超时或员工口述不能把支付标记为成功。
2. 保留支付意图、订单、桌台、渠道请求号和请求ID，使用原幂等键服务端查单。
3. 渠道确认失败才允许重新发起；渠道成功则补录回调证据，不二次扣款。
4. 退款只针对原支付和原商品分摊，保留渠道退款号；人工POS退款进入待对账。

## 弱网与离线

1. 离线只允许服务任务接单、到桌和完成，动作按原始幂等键顺序同步。
2. 支付、退款、订单、预约、库存、会员、主数据和配置写入全部停用。
3. 出现同步冲突时由领班核对现场结果后移除冲突，不清空整个队列。
4. 共享平板切换员工前先检查待同步数量；仍有动作时必须完成人工交接并确认，切换会清除该设备的离线快照和剩余队列。
5. 清理IndexedDB失败时系统会保留原员工会话并阻止切换；不得通过开发者工具手工替换令牌，应更换设备并按P2上报。

## 备份与恢复

```bash
DATABASE_URL='postgresql://...' BACKUP_DIR='/secure/mbox-backups' ./scripts/backup-postgres.sh
DATABASE_URL='postgresql://...' MBOX_CONFIRM_RESTORE=RESTORE \
  ./scripts/restore-postgres.sh '/secure/mbox-backups/<file>.dump'
DATABASE_URL='postgresql://...' npm run db:verify
```

生产环境至少每日备份并启用PITR。每月恢复到独立数据库，核对迁移校验和、运行状态、审计和财务汇总；不得直接覆盖生产库进行演练。

## 版本发布与回滚

1. CI通过依赖审计、`npm run check`、全新数据库迁移、RLS验证和容器构建。
2. 先部署预发布，完成员工鉴权、签名桌码、订单、退款、预约、库存和通知失败冒烟。
3. 灰度时只切受控设备；保留上一镜像和数据库向前修复脚本。
4. 应用故障回滚到上一镜像；数据库不执行破坏性down migration，用经过测试的前向补丁。
5. 发布后记录版本、迁移、操作者、审批人、开始/结束时间和冒烟证据。

## 关店

值班经理关闭开放桌次，处理未完成KDS、服务任务、预约订金、存酒动作和权益锁定，完成支付/退款/POS日对账；未解决差异必须交班并指定负责人和截止时间。
