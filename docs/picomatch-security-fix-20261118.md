# picomatch 安全修补与兼容验证

目标：解除rc299的GHSA-fc5q-39xc-vjpf发布阻断，不改变业务代码和数据库。

## 方案和边界

官方4.0.7仍受影响且没有公布修复版本。使用显式私有安全分支
`@mbox/picomatch@4.0.7-mbox.2`，保留MIT许可、原作者及上游归属。
`vendor/picomatch/provenance.json`记录上游npm包SHA512、上游与修补源码SHA256；
仅`lib/parse.js`改变，包元数据单独标明私有分支。

安全边界：在生成正则前，对重复extglob中的星号、加号量词、嵌套组/花括号以及非前缀互斥的分支显式抛出`ERR_UNSAFE_EXTGLOB`；不能通过关闭旧递归限制绕过。
这有意收紧危险配置语法，不声称兼容所有历史正则表达式。普通glob、globstar、花括号、字符类、有限extglob、转义字面量、排除条件、scan和回调保持原接口。业务代码无需改动。
不把未登记私有包的npm audit零告警当成安全修复证明；实际漏洞复现、恶意变体、安装包来源与源码一致性测试是额外的强制门禁。

## 安装和构建

根devDependency引用仓库内tarball，override使用`$picomatch`统一Vite、Vitest、tinyglobby、fdir；锁文件记录包SHA512。Docker两个安装阶段都先复制该包，生产运行依赖不增加它。CI保持原moderate审计阈值，新增`test:glob-security`。安全包更新必须更换私有补丁版本、重新打包、更新锁文件并回归；不可覆盖旧版本冒充同一安装包。
