# M-BOX 独立质量监督门禁

本门禁用于约束代码修改、功能声明和发布结论。修改者不得自行把“代码已写”“页面可见”或“测试命令退出0”解释为商业完成。

## 角色分离

- **修改者**：定位问题、修改代码、补充测试和提供证据。
- **独立质量监督智能体**：只读审查差异、测试、页面、服务端状态和审计记录；可以驳回，不修改被审代码。
- **现场验收人**：使用真实账号、设备、网络、打印机和支付渠道执行门店TC。
- **发布批准人**：根据代码、现场和外部渠道证据决定是否切流。

## 不得冒充完成的情形

- 只看到按钮，没有验证服务端对象状态。
- 只通过单元测试，没有验证角色页面和跨端流程。
- 只用模拟支付，没有真实渠道流水、查单和退款证据。
- 只生成打印任务，没有真实打印机输出、断纸和补打证据。
- 本地通过但未形成提交SHA、不可变镜像、切流和回滚证据。
- AI返回“已执行”，但业务对象、审计事件或幂等记录没有变化。

## 强制证据

每个候选版本至少提供：

1. 基线提交、完整差异和候选版本号。
2. 新增或更新的TC及其风险等级。
3. 自动测试、浏览器流程、并发测试和构建结果。
4. 不同岗位页面的可见范围和可执行动作。
5. 操作前后业务对象、任务事件、审计记录和幂等结果。
6. 未执行、阻塞和外部依赖，不得隐藏在“全部通过”中。
7. 独立质量监督智能体的复审结论及退回整改记录。
8. 部署时补充提交SHA、镜像摘要、数据库备份、切流、线上观察和回滚证据。

## 判定口径

| 状态 | 含义 |
|---|---|
| 代码通过 | 本地代码、测试和构建满足候选要求，尚未部署 |
| 待现场 | 必须使用真实员工、设备或门店网络执行 |
| 外部阻塞 | 缺支付渠道、生产微信、物理设备或外部批准 |
| 已部署待观察 | 不可变版本已切流，但线上观察期未结束 |
| 商业完成 | 代码、现场、外部渠道、发布和回滚证据全部齐全 |

任何驳回项修正后，必须重新执行相关窄测试和完整发布门禁；不得只修改文案或手工更改TC状态。
