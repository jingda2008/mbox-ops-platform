# M-Box 岗位最短操作验收

目标：高频现场动作首屏完成，按钮名称直接表达结果；只有规则配置、资金凭证和异常原因进入独立面板。

| 岗位 | 高频场景 | 最短路径 | 点击数 | 首屏要求 |
|---|---|---|---:|---|
| 门迎 | 临客候补 | 预约台 -> 登记候补 -> 填写 -> 确认登记 | 2次按钮 | 手机首屏显示完整登记表和确认按钮，无区域下拉 |
| 门迎 | 有桌释放 | 通知并锁桌 -> 入座 | 2次 | 系统只给一个按顺序、人数和区域计算的推荐桌 |
| 门迎 | 预约准时到店 | 已到店 -> 安排入座 -> 桌号按钮 -> 确认 | 3次按钮 | 不需要进入经理配置 |
| 门迎/店长 | 预约迟到 | 迟到保留 -> 填预计时间/联系证据 -> 确认 | 2次按钮 | 保留分钟数由经理配置，现场不临时改规则 |
| 店长 | 营业中换桌 | 点原桌 -> 点目标桌 -> 确认转桌 | 3次 | 只显示可用且容量足够的目标；风险状态直接阻止 |
| 服务员 | 接单到桌 | 接单 -> 已到桌 -> 完成 | 每状态1次 | 首页只显示本人责任区任务；无转桌、收款和配置控件 |
| 调酒师/厨房 | 制作 | 开始制作 -> 完成制作 | 2次 | 只显示本档口队列；完成后自动生成取送责任 |
| 传菜员 | 出品送达 | 已取走 -> 已送达 | 2次 | 卡片直接显示桌号、商品和数量 |
| 收银员 | 物理POS报送 | 选桌 -> 报送POS -> 填流水 -> 确认 | 3次按钮 | 不允许把人工报送显示为渠道已对账 |
| 老板/管理员 | 配人配权 | 配置页按模块修改并发布 | 低频独立流程 | 不出现在当班高频首屏；保存形成新版本和审计 |

## 本轮实测

- 店长：桌面端`L01 -> L04 -> 确认转桌`成功；原桌释放、目标桌占用、账单桌次不变；容量不足桌不显示。
- 门迎：桌面与390x844手机均可在首屏完成候补登记；队列按钮直接显示推荐桌号。
- 服务员：仅看到本人区域和任务入口，页面无转桌控件；跨区域服务端仍返回403。
- 响应式：390px宽度无横向溢出；候补登记不需要横向滑动，确认按钮在首屏可见。

金额券核销、支付退款和真实微信/企微通知不纳入“少点击”优化来绕过风控。它们必须保留支付分摊、审批、渠道回执和审计证据。
