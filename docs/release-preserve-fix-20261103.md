# 发布保留现场配置修复

对应RELEASE-PRESERVE-20261103-01，用户要求解决定时发布前发现的阻塞。

## 原因与改动

门店provision原先先写入现场配置、员工及凭据，再校验配置版本；新应用SHA即使沿用同一配置也会重复初始化。菜单provision已有同版本只登记应用回执的处理。

门店现改为在既有全局/门店事务锁内先比较版本及内容摘要。同版本不同内容立即拒绝；相同内容只登记新应用SHA，不重写桌台、区域、权限、员工、口令或其他配置，重复SHA不重复登记，并发调用受原锁和唯一约束保护。回执绑定新SHA供发布核验，不能把保留现场配置误当成没有发布记录。

明确变更配置版本时，配置仍走原事务校验与应用；已有员工通过冲突不写入保持PIN、姓名、启停状态和角色历史，仅新员工初始化角色。门店口令仅无任何历史记录时初始化，撤销或过期都不会被当成缺失而重新发放。配置不再承担重置员工PIN、恢复在岗或轮换口令的职能，这些操作应走现有授权管理入口。无schema或发布脚本门禁变更，不修改不可变产物、不跳过标准provision。

## 保留边界

同版本已应用的现场变更必须保留；不能借重放配置恢复误删的员工或角色。如果需要恢复或变更现场数据，应通过授权管理与单独审计。新配置版本仍允许有意配置变更，必须独立复核；本次沿用现有配置版本和内容。部分拆并桌规则02不变；仅后台和员工Web，不发布小程序或原生应用。
