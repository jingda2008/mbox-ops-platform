# M-BOX AI值班经理闭环 1.0.0-rc.20

## 本版目标

`rc.20`把上一阶段的风险简报升级为可持续跟踪的值班事件。系统不再只提示“这里有问题”，而是记录风险从发现、接管、暂缓、复核到关闭的完整过程，并生成交接班数据。确定性规则负责发现和关闭风险，大模型只负责理解自然语言、解释现场和提出操作建议，不能越权写入业务数据。

## 事件闭环

- 服务、出品、人员、SOP、审批、预约和系统运行风险会生成稳定的事件编号。
- 相同风险持续存在时更新观察次数，不重复制造事件；风险消失后自动标记为已解决。
- 已解决风险再次出现时进入新周期，保留上一周期记录，不覆盖历史。
- 一线员工可以点击“我接管”，明确现场责任人并继续处理到源业务真正完成。
- 店长和管理员可以“稍后处理”，到期后风险自动重新进入待处理列表。
- 误报必须二次确认并填写现场复核原因，不能用误报代替正常完成。
- 同一操作携带幂等键，网络重试不会重复修改状态或重复写审计日志。

## 权限和审计

- 员工只能查看其岗位和桌台数据范围内的事件。
- 接管需要具备现场看板和服务、排班或审计相关权限。
- 暂缓和误报需要排班管理或审计权限，一线服务员不能改变风险判断。
- 系统级风险只能由管理岗位处理，避免普通员工隐藏营业日、配置或联调异常。
- 每次接管、暂缓和误报都记录员工、时间、风险编号、说明和幂等键。
- 对话助理收到同一份风险与交接事实，但最终执行仍经过原权限、确认和审计链。

## 交接班

`GET /api/assistant/handover`按北京时间营业日返回：

- 今日发现事件数和当前活跃数；未接管数由巡场简报实时给出。
- 已接管、暂缓、误报和自动解决数量。
- 平均接管耗时和当前最早未处理风险。
- 员工页面显示精简交接条，不占用主要操作区域。

## 接口

| 接口 | 用途 |
|---|---|
| `GET /api/assistant/briefing` | 巡场并返回当前员工可见风险 |
| `POST /api/assistant/duty-actions` | 接管、暂缓或误报复核 |
| `GET /api/assistant/handover` | 获取当前营业日交接统计 |

## 回归验收

| 编号 | 场景 | 预期 |
|---|---|---|
| DUTY20-01 | 同一风险连续巡场 | 仅更新同一事件观察次数 |
| DUTY20-02 | 服务需求完成 | 对应风险自动关闭并记录系统解决 |
| DUTY20-03 | 已关闭风险再次出现 | 新周期重新打开，历史仍保留 |
| DUTY20-04 | 服务员接管授权桌台 | 显示接管人并写审计 |
| DUTY20-05 | 服务员尝试暂缓 | 返回403，不改变事件 |
| DUTY20-06 | 店长暂缓10分钟 | 风险暂时隐藏，到期自动重新出现 |
| DUTY20-07 | 店长标记误报但未写原因 | 校验失败，不允许提交 |
| DUTY20-08 | 同一幂等键重复提交 | 第二次返回重放结果，不重复写入 |
| DUTY20-09 | 角色或桌台越权操作 | 返回403并保留原状态 |
| DUTY20-10 | 模型服务不可用 | 规则巡场、接管和交接仍可运行 |
