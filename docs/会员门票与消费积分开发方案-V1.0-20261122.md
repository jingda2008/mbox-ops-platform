# M-BOX 指定场次门票与购票赠分开发方案

**V1.0 开发与验收评审稿 · 2026年11月22日**

顾客按场次购买桌票。每张票对应指定桌型的一整张桌，票价按桌计算。以选用促销方案的中间区域桌票为例，票价500元，付款成功后每张赠550会员积分。门票只能用钱购买；积分可抵全店菜品、酒水和餐饮套餐。同一会员一次买多桌，所有赠分进入该购票会员账户，每张票独立记录票号、票款、赠分批次、桌型、分配的桌号及核销情况。顾客可在微信点菜时用分，也可让服务员代填、自己确认。退票从原订单正常退款入口发起，系统识别具体票号，按该票实际用分情况处理菜款和积分。

## 2. 场次上架、购票赠分、接待与入场

### 场次按演出日期和时间段设置

在门票上架页点「选择场次」。已有场次直接选，没有就点「新增场次」。在当前演出项目下，日常只填 **演出日期、开始时间、结束时间**，系统按上海时间生成场次标签。同一演出一天可排多场，一场可挂中间区、靠窗卡座、内场沙发区等多个票档，日期和时段只填一次。

例如，11月28日可设「19:30–21:30」和「22:30–次日01:00」两场。输入跨午夜时段时，结束栏明确标出「次日」及实际日期，保存前可核对。起止时刻相同则提示修正。菜单先带出最近有票的日期，顾客可直接比较该日各场次和桌型，也可切换日期。确认页、电子票、员工排桌和验票页都显示场次的完整起止时间，跨午夜仍归开演自然日。

**售卖与桌位。** 开售和停售时间沿用原售卖设置，可提前卖票。每张票绑定所选场次及票档版本；提前买晚场票也按晚场票档赠分，积分有效期从付款成功日起算。验票核对场次，同日早场票不能核销为晚场。桌位按实际接待时段与已有预约共用容量；如门店已有提前入场或清台安排，一并计入占用。上场结束时仍未清台，前台继续保留该桌占用。

**修改场次。** 草稿可直接改日期或时段。在售场次调整时先核对预订、已分桌及在途支付；新下单前展示新时间并重新核对余量。门店接待逐单主动联系已有购票人，记录沟通结果。购票人可在原单查看改期说明，可选择接受新场次或从原单办理售后。顾客接受改期后才衔接新时段的桌位，一次交接保留原票关联、原赠分和到期日。拒绝改期则走第4节和第7节的原票售后。

本地活动后台已支持录入开始、结束时间，服务端也会检查结束时刻晚于开始时刻。本方案在桌票上架页复用这些时间字段，增加场次选择和跨日展示。[现有活动时间表单](/Users/jingda/.codex/worktrees/store-operations-rc305/mbox-table-minimum-spend-20261031/src/normalized-ui/ActivityOperationsPanel.tsx:501) · [现有起止校验](/Users/jingda/.codex/worktrees/store-operations-rc305/mbox-table-minimum-spend-20261031/server/normalized/activity-operations-api.ts:231)

### 后台上架时可直接编辑产品名称、价格和赠分

沿用菜品后台的操作。运营进入场次，点「新增桌票」，选桌型后即可在同一张表单编辑以下三项，再点「保存并上架」或按原权限提交复核。可售桌数按本场余量带出，桌号范围沿用桌型设置。上架页不设每桌人数或每人限购张数字段。

| 表单字段 | 填写与生效规则 |
| --- | --- |
| 产品名称 | 可直接改成面向顾客的票名，例如「周五爵士夜 · 中间区桌票」。去掉首尾空格后必填。名称用于展示，实际安排仍由所选场次和桌型决定 |
| 每桌售价（元） | 可直接修改，一张票购一整桌。付费桌票须填大于0的金额，最多两位小数。确认页按张数计算总票款 |
| 每张赠送积分（分） | 可独立于售价修改，接受零或正整数。填0表示该票无赠分，留空可存草稿，发布前须填明。顾客买多张时展示合计，付款后按每张票分别入账 |

**上架核对一次，日常不重复填。** 场次维护举办及售票主体、适用的演出批准文件与授权、客服、演出地点时间、主要演员或团体、最低演出时长及适用的最低曲目数。校验核准人数、全场可售数量、各区票价和已售／待售区域，整桌票显示全场入场容量说明。对依法须批准的场次，取得批准后才可预售或开售。后台读取场次已核实的资料、退票规则和门店统一的积分说明，自动生成第7节的顾客说明；重要资料缺失可存草稿。门店资质、场次批文、真实票价依据和已发布的门店条款尚未在本次核验。[文化部关于规范营业性演出票务市场经营秩序的通知](https://zwgk.mct.gov.cn/zfxxgkml/zcfg/gfxwj/202012/t20201204_906318.html)

**点击后的结果。** 符合上架条件且当前人员有相应权限时，主按钮为「保存并上架」，保存后读回状态。场次尚在草稿或本次发布按原权限需要另一人复核时，主按钮显示「提交上架」，同一份数据进入现有发布复核，提交人无需再填表。未到开售时间显示“待开售”，窗口内有余票才显示“在售”；售罄、停售和下架各自显示原因。列表支持下架、恢复，在售旧票照原条款履约。

**默认规则放在后台。** 场地、全场容量、可见范围、安全及退票条款取所选场次。普通桌票无每人或每单限购；积分使用范围由系统统一展示，全部菜品、酒水和餐饮套餐均可使用积分，门票统一采用货币支付，运营免配商品名单。票款足额结清后逐票出票和核算赠分、周年到期、退票回收、已用分菜品补差及原单追溯均自动带出。运营无需再到会员中心建立同一奖励。若缺场次容量或有效条款，只提示具体缺项并定位场次设置；若赠分规则有冲突，由规则管理员处理一次。普通不赠分票不因缺少赠分规则被拦截。

**在售后编辑。** 在原票种点「编辑」仍可改这三项。按原发布权限生效后，列表、详情和新购票确认页展示新版。仍有效的待付订单保留已确认的票名、价格和赠分，已售电子票、发分、退款及冲正均读取原票快照。顾客仅选了票、尚未确认建单时，如版本有变，回到确认页明确标出改了哪一项，由本人确认新版后继续。编辑沿用原票种和同一桌型余量。

涉及已经公开承诺的限时赠分活动，按公示期限兑现原承诺。后台允许编辑草稿、安排后续促销版本，当前活动期间不得通过改版减少已承诺的赠分、缩短期限或追加使用限制。[市场监管总局《规范促销行为暂行规定》第六、七、十三、十四、二十二条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_cae53a080be2401e8f91c6d6291539f8.html)

**与原系统衔接。** 菜品后台已有售价权限校验和保存后读回。现有活动的套餐承诺发布后锁定，因此本次增加独立的票种版本，保留已发布套餐。原活动积分字段只允许0，会员中心已有活动付款促销。服务端按票种版本识别购票奖励，统一校验其发放及退款，独立促销沿用其已发布规则。

### 大分类、单张门票和单个菜品的对客可见时间

大分类（例如「演出门票」「酒水」）、单个场次票档和单个菜品都可独立设置 **「对客可见时间」**。建议在原分类编辑页和商品上架页共用同一个控件。大分类默认「上架后一直可见」，单品默认「跟随分类」。选择「指定时间」才展开开始和结束日期时间，可只设开始或只设结束。采用上海时间，到开始时刻显示，到结束时刻隐藏。售票人员无需为每个商品重复设置日期。

**父子时段取交集。** 大分类和单品都处在自己的可见时段，且原有上下架及对客权限允许时，顾客才能看到单品。例：门票大分类11月28日12:00至23:00可见，靠窗票档单独设18:00至22:00，则靠窗票只在18:00至22:00显示；没有单设的中间区票跟随分类。菜品同理。两段没有交集时，编辑页提示「本商品在所选时段不会对客显示」并允许存草稿。分类没有任何对客可见商品时，菜单不留空栏目。

赠分文案按所选票种和张数计算。明确赠0分的会员桌票也需要已验证号码安排接待，页面只展示实际票务权益。购票确认页可核对或按既有验证流程更正本人号码。本人拒绝授权且尚无已验证号码时，保留选票供继续浏览，本笔会员桌票暂不能提交付款。

**原页面需要调整的地方。** 本地活动详情目前将独立勾选设为手机号授权按钮和提交逻辑的前置条件，成功后重新加载活动详情。桌票入口在顾客点「立即购票」时呈现上述提示，用一个明确写有「同意并授权」的按钮承接协议确认和授权请求。复用现有服务校验微信授权凭证、核验协议版本并返回有效会员，再恢复原选票。普通点菜沿用原有结账入口。

1. **选票。** 顾客在微信菜单点某场某档桌票，在详情页选张数，或由员工在代售端选择。桌票独立结账，展示本次合计票款及总赠分。
2. **按已确认的会员建单。** 微信自购使用上一步识别的会员。员工代售可输入客户手机号查找，老客核验后沿用原号，新客由本人手机打开本次选票的确认入口，按同一路径完成入会，员工端接续原代售草稿。服务端在建单和发起支付时均校验有效会员及其已验证手机号，并绑定本单所用的已验证联系方式、会员内部ID、展示会员号和票档版本。代售与自购、现场与远程遵守同一规则。员工手输号码仅用于查找；缺少验证或身份不符时保留草稿，由客户本人核实。预约联系人、付款人、经办员工分别记录，购票赠分只发至订单绑定的会员。收款后若发生会员合并，按核实后的会员身份入账。归属异常时保留实收、原票和待发任务，按原单核查补发。
3. **收款。** 确认页列场次、张数、实付、赠分、入账会员、最后可用日和售后条件。购票页仅展示应付票款和本票赠分。微信自购及员工代售都通过原有收款方式收足票款。每张票关联订单的购票会员ID；另行记录实际支付人或支付凭证及代办员工。常规场次对单个购票人和单笔订单不限张数，可一次购买本场仍能交付的多桌。同单所有票的赠分全部进入购票会员账户。支付页面不提供逐张指定收分人；不同会员希望分别获赠时，须各以本人会员身份购票。下单占用本档可售名额，不锁具体桌号；仅待付款、顾客出示付款截图或员工点了“收款”，均不能触发发分。
4. **交付。** 确认票款足额实收后，按每张票交付电子门票并按票种发分，自动进入排桌队列；出票或发分失败按原票补齐，页面分别显示票、积分和桌号进度。取消前核对是否已有支付成功证据；原申请已关闭后收到迟到款项，核对并走退款或经顾客同意重办，不自动锁桌；无名额时进原单异常处理，不能超售发分。下架后已售票仍可查询、入场、消费或售后。
5. **核销与到期。** 对准场次、逐票核销一次。退票冻结中、已领桌或已作废的票不可重复开台。同行客人按原桌登记到场。入场不触发再次发分，消费用完积分不影响有效票入场。2026年11月22日付款，最后可用日为2027年11月22日，次日00:00失效；2028年2月29日付款，则至2029年2月28日。按上海自然日计算，与营业日06:00切日分别处理。补发、转正保留原周年；续买只新建批次。

**门口怎样验票。** 接待扫电子票码，员工端向服务端核对门店、场次、票号、桌型、有效状态及本票安排，当面确认领桌人和同行人数。扫码只显示核对结果，点「确认领桌」后才记核销与开台；重扫显示已领桌及经办记录。顾客手机无法出示时，有权限的前台可用票号或经本人核实的购票信息查原票，走同一核销记录。弱网时先查原票状态，避免两个入口各开一桌。

**散场时仍未到店。** 场次正常履行、顾客未到场的，场次结束后把接待结果记作「未到场」，保留当时票务状态和原售后入口；付款时已赠的积分照原周年使用。场次进行中，未接通或未到场不触发转售。若顾客到过但门店未能交付，记录为履约异常，按第7节办理。

### 与现有订桌共用容量和桌号

**现状核对。** 现有订桌按门店及重叠时段检查总接待人数；员工可以登记尚未指定物理桌的预约。已经指定桌号的有效临时锁和确认锁受数据库的同时段排斥约束。预约入座时会关联实际桌次并释放原预约桌锁。现有检查单独使用时看不到“已付靠窗桌票、尚待分配桌号”的承诺，因此本功能要同时接入售票、普通订桌和前台带位。

| 原来已有的记录 | 接入桌票后的处理 |
| --- | --- |
| 没有原预约 | 同场同时段、同档待付限时占量 → 已付待分桌 → 已关联桌号 → 实际开台，各阶段接续同一张票的占用。待付到已付不再扣第二次；排桌时在同一事务内退出未分配数量、取得桌号锁 |
| 同一批客人已有预约，但未指定桌号 | 顾客或员工明确选择「沿用这笔预约」，核验会员或经授权的预约凭证、门店、起止时间、人数和桌型。普通预约已经计入的人数只算一次；尚未保过指定桌型，因此仍须核实本档有整桌余量。姓名、同手机号或“偏好靠窗”只用于找候选，不自动合并 |
| 同一批客人原预约已经锁住匹配桌号 | 支付前可从该预约出发核验并关联所选桌票。确认原锁覆盖完整场次、匹配所购桌型且未被其他票使用后，原占用可以承接本次购票，即使该档对其他人已显示售罄。购票不提前代替门店确认；后台确认时关联原锁，不另建一把锁。未付失败，原独立预约及原订金按原规则保留 |
| 先买桌票，又打开订桌入口 | 对经验证的本次会员展示同场已购票，可直接查看排桌进度或选择沿用；如确为另一批客人或另订一桌，明确按新增需求重新检查容量。既有预约只认领经确认的具体桌和人数，余下预约或同行订单不自动合并 |
| 开台、换桌、迟到或取消预约 | 核销时关联已有桌次或开台一次，预约桌锁转为实际开台占用，中间不得出现可售空档。同档换桌原子地取得新桌、交还旧桌；跨档须顾客同意后核对价差和赠分。普通预约取消或到期，不得取消已购票；若原锁不能继续沿用，须同步转回该票的同档未分配权益或落实替代桌 |
| 退票 | 待审核、待补款及退款结果未知时均保留权益占用。退款成功：未分桌只释放该票档位名额；已分桌且仅为本票保留时才释放对应桌；尚有独立有效预约则保留该预约占用；已经入座则保留实际桌次直到清台。释放不等于重新开售，还须满足售卖窗口、票种及场次状态 |

**怎样计算可卖几桌。** 按门店、桌型和完整重叠时段核实可服务桌号，扣除有效预约锁、已开台或停用等物理占用（同一桌取并集），再扣尚无物理桌承接的待付与已售桌票。已关联有效原锁的票不再扣未分桌名额。同时保留原接待人数校验：同一批人按同一承诺去重；不同预约各自计入。还要确保未分桌的普通预约仍有可容纳其人数的安排。四人独享一张六人桌时，空出的两把椅子不另卖。桌型、容量不一时检查实际可行分配，两个重叠场次不能各用一份独立库存。

**开发约束。** 展示余量只作预览。购票占量、支付转已售、订桌创建/变更、候补转正、临时开台、排桌/调桌及自动释放都须在写入时串行校验同一批重叠时段的容量。保留原数据库桌号冲突约束；逻辑权益记录关联票号、预约号、桌号、桌次和占用来源。一个票号同时只可有一个生效安排，同一个桌号和时段只有一个物理占用；多人或多桌预约按具体明细关联。关联既有订金时先核对原资金流水，不默认抵扣票价或重复收取。普通预约旧的超时任务、票务退票任务和前台清台按实际权属释放，重复回调读回原结果。

**两张靠窗桌的核对例。** 某时段可用两桌，原普通预约已锁甲桌，乙桌空闲。另一名会员买靠窗票后尚未指定桌号，余量从1变0；前台把该票安排到乙桌后仍为0。若改为原预约本人买票并明确沿用甲桌，则其购票和排桌都不再占乙桌，余量一直为1。后一种情形退票且仍保留原预约，甲桌仍须保留，余量仍为1。

**整场可用与核准人数。** 即使每分钟都还有一张空桌，也要有同一张符合所购档位的桌覆盖完整接待时段。例如甲桌前半场有预约、乙桌后半场有预约，仅有甲乙两张同档桌时，不可再卖一张整场桌票。普通整桌票按桌售卖，页面不设每桌人数或个人购票张数上限。场次售票前按核准的观众总量、区域、有效普通预约及接待安排核定全场可售桌量。尚未联系到的已售桌也要给入场留余量，不能当作零人。接待可记录预计人数辅助安排，沿用原预约时去重；该数字不成为单桌票面限制。若客流情况使同一场次无法再履约，暂停新增销售并人工处理已有订单。一次买多桌时按本次全部所选桌数核验余量，数量不足提示修改，不自行少出票或按原数量收款。

桌票逐桌核销，实际观众逐人计数；同桌分批抵达只增加新到场人数。现场达到核准观众数量且仍有人等候时，应停止验票并按规定向演出所在地县级公安部门报告。已有订单若无法按约履行，由门店主动联系处理。商品页在购买前展示「整桌销售，每桌不设人数上限，入场按本场核准容量安排」。逐人实名或限购另有要求的特殊演出按第7节办理。[《营业性演出管理条例》第二十一条](https://xzfg.moj.gov.cn/front/law/detail?LawID=1538)

## 3. 微信自助与服务员代客用分

**微信原操作顺序。** 选菜 → 提交订单 → 核对商品与金额 → 直接支付，或选择积分、填分、核价后确认。积分输入框旁增加 **「填入本单最多可用的积分」**。余额550分、本单待付260元时填260；可改填200，核价后还需付60元。如果其中60元此前已结，剩余应付200元，则最多填200分。填数、改数、预览均不扣分。积分取整数，现金尾数保留。

**核价规则。** 微信端与员工端调用同一服务端报价，校验会员、余额、有效且可用的批次、门店权益开关、每份商品的真实应付及已结金额。账户暂停抵扣、存在原规则规定的待追收积分、门店暂停新增抵扣等情形要给出原因，历史交易仍可办理售后。涉及多个来源时先保证选定积分数能实际分配，再在可行分配中优先最早到期批次。同类同到期批次以固定顺序扣用。同单同档的票采用订单票明细顺序，异常补发不改变已经落账的分摊。报价、落账和售后都可查每个菜品份实际使用的票号、积分批次和抵扣金额。已结清的金额不能重复抵扣。对新售商品统一保存成交价及分摊，历史记录缺失的售后转人工核对。

**最大可用数的边界。** 餐饮订单最多可用积分取「账户有效可用整分」和「本单尚待支付金额按元向下取整」中的较小值。每1分抵1元，支持全额抵扣，零星不足1元按实付结清。微信和员工端使用同一报价返回值。餐饮商品种类、售价、时段及抵扣比例均不另设限制。上限为0时说明原因，保留原支付入口。

**门票与餐饮的支付规则。** 门票只能用钱购买，任何来源的积分均不能抵票款。顾客自购与员工代售的购票页只显示应付票款、赠分及收款方式。服务端按票务订单类型校验，报价、建单和支付均拒绝全积分或部分积分抵票款的请求。足额实收后，按售出时票档配置逐张赠分。

全部菜品、酒水和餐饮套餐均支持积分抵扣。点菜结账时按本人的有效余额和本单待付金额计算上限，也可由服务员代填、本人确认。退票按原票实付和条款核定退款，另按本票批次回收赠分；该批分已用于餐饮时，按第4节核算对应菜款。

**优惠与弱网。** 建议把积分作为结算方式，先按券或优惠本身的既有条款计算成交应付，再允许用分抵余额。若券自身明确约定互斥，应在切换前展示两种实付并让顾客选择。当前本地页面仅打开积分就会清除已选优惠，读取余额失败后再次点同一入口也未重新请求。建议浏览积分时保留仍有效的原选择，错误位置提供“重新读取积分”。改菜、换桌、改分或余额变化导致报价失效时，保留订单并重新核对。用到门票赠分时显示“个人原因退票并符合本场补款约定时，按点单时正常售价核对已消费差额。演出取消等情形可从原票申请售后”。

| 代客结账环节 | 员工与顾客操作 | 系统完成条件 |
| --- | --- | --- |
| 选单、找会员 | 员工在原桌单选本次结账的菜品及份数，经客户同意查会员。新会员入会后可查实际可用余额 | 同桌多人按消费明细分单；不能以桌主、点单人或服务员身份代定扣分账户 |
| 代填与确认 | 员工点最大值或输入客户要求的分数。顾客扫本单确认码，或从「本桌已点」打开原单，核对菜品、会员、积分、差额并确认 | 微信登录会员匹配，确认只对本单当前版本有效。知道手机号、扫入场码或代填数字均不能单独授权扣分 |
| 结算 | 普通桌全分结清直接下单；有差额时支付差额。预收款桌先显示本单积分后应付，再按原桌次规则计算可抵余额及是否需补款 | 查明原支付是否在途，防止按原全额付款码和新差额各收一次。已占用积分只在订单足额结清后转实扣。未知结果查原单 |
| 出品与凭证 | 顾客与员工看同一订单状态，小票列菜款、各类抵扣及实付 | 新单按结算方式出品一次。挂桌已出品、跨日挂账或部分结清的原单，只结符合条件的未清明细；不重出品、不重扣库存、不重复计算低消 |

**预收款举例。** 普通菜款260元，用200分后，本单应付60元。若预收款桌尚有100元已收且可用，同时无其他待结款、无额外首充要求，则分配原桌款60元，桌余额余40元，本次微信新增收款为0。餐饮场次仅列本次实际应付及有明细的原订单欠款，不按旧首充门槛追加金额。后续退菜按该笔消费实际使用的资金来源及可退分摊办理。

## 4. 从原订单退票、补收菜款与回收赠分

**已出票、尚未分桌的订单**也从原票发起正常退款，按原票条款核查已发和已用积分。受理时冻结分桌或换桌，保留该档占量；退款办结才释放对应权益，撤回则恢复原票。核对门店原因和顾客主动退票的不同条款。分桌与退票并发时锁定同一票号，按已提交结果继续办理。

**共同起点。** 顾客或员工从原订单发起正常退款，按现有权限提交原因。售后预览按选中的原项目及数量识别类型；提交时服务端重新识别。多张同价票逐行显示票号、场次、桌型、已分配桌号或「待安排」、核销及本票赠分状态。系统按所选票的原始扣分流水算补款；用餐桌号、账户总余额和同单各票平均数均不作为归属依据。既有活动页面在显示“整份退订”前就校验资格，新票种须同步改页面可见性、服务端资格判断、审批和执行入口，避免已用分但符合退票条款的客户在第一步就被挡住。

| 退款对象 | 判断依据 | 处理 |
| --- | --- | --- |
| 菜品，含用购票赠分消费的菜 | 消费订单、菜品份、成交分摊及实际履约 | 走原退菜、停单或补偿流程。已停菜、仅退款补偿、换菜或已送达的事实分别保留；不得仅因退款就自动退库存、停止整桌或作废门票 |
| 普通票、旧活动报名 | 原售票或历史报名的适用规则 | 保留原退订资格、已核销、关联加购、补偿与审批要求 |
| 本次新增的整桌票（含明确设置零赠分的桌票） | **售出时**的票种快照、原售票明细和选中的票号 | 先查顾客申请原因及法定权利，再处理桌台及入场权益；有赠分再查原票发分、占用、净已用、过期、冲正及关联菜品，决定是否补收。当前余额为0、尚未发分或错户已更正回购票会员，仍可正确识别 |
| 只有支付金额、无法对应原票或明细冲突 | 支付与票号、菜品服务记录无法勾稽 | 保留原申请，提示补选或交收银核对。后台、批量取消、人工退款和重试任务共用同一资金执行前检查 |

**退票办理顺序**

先区分退票原因。以下“先补菜款再执行退款”只用于顾客个人原因、已符合本场公布的自愿退票规则、补款依据有效且顾客确认明细的案件。演出取消、法定重大变更或门店不能提供约定桌型的，适用第7节的履约异常处理。审核员须能将应退票款与争议菜款分开流转，不能用售后审批或核销状态拖延应退票款。

1. **提交与冻结。** 预览不冻结。正式受理时建立一笔售后案，关联并冻结该票验票、该票批次新增用分及未完成的发分任务。相同请求返回原案；关联消费在途、退菜中或已有冲正时，先查原结果再重新报价。其他票和会员其他余额仍按原规则使用。
2. **原退款审核。** 审核员按原有权限、额度及不得自审的规则，核定退票资格、原票可退金额、菜款差额、退款路径和责任方。原支付的已退、在途及按原规则仍占额度的已批准失败退款一并计入。审核未通过，解除本案冻结并按原期限恢复；顾客可查原因。审核通过与钱已退回分别显示。
3. **收菜款差额。** 仅对本票积分抵扣过、仍实际消费的菜品，取下单时规格、数量和正常售价，减去已有效结清的款项、仍有效的其他抵扣及已核准的门店承担金额。仅纳入本次撤销抵扣产生的应补差额，其他挂账欠款仍由原收银流程处理。补款明细先以原成交分摊核定并和正常售价勾稽；两者不符时查明优惠与历史调整后再收，避免将无关欠款转嫁给退票人。正差额逐份列出，原付款和此前补款分别只计一次。补款走原餐饮收银，关联原菜品、原消费会员和售后案，按正常餐饮积分及成长值规则结算。按最终合资格实付重算与原已记奖励的差额，到账、冲回或重试均只记一次。补款不新增菜品份数或出品。差额为0直接进入退款执行。顾客个人原因且适用补差约定时，由本人核对并补付，未收到款保持“待补菜款”。经营方原因及依法应退的案件仍可独立执行应退票款。核定事实或金额变化时，旧确认失效，重新核对受影响条款。
4. **执行票款退款。** 审核通过并查明原交易后，顾客个人原因且补款约定有效的案件，按已确认的菜款结清情况执行。法定退票、经营方原因或其他依法应当退款的案件，在应退期限内原路退回应退票款。争议菜款另案留存，不自动收取，不阻塞票款。应退金额为0的合法处置须说明依据。拒绝退票则保持票的原资格。买两张票只退一张时，按该票实付分摊校验；同一原支付的金额占用与退款累计须在并发申请时统一校验。退完一张而仍有有效票时，订单显示「部分已退」，其余票继续可查、接待、核销和使用各自的剩余赠分。
5. **确认完成。** 渠道确认退款成功，或应退现金为0且已有明确的作废决定时，按案号作废原票，在同一内部事务中撤销原抵扣、回收恢复的积分和未用积分，记录到期、未发终止等去向。撤销的分数不会短暂变为可用。“全额回收”落实为该票最终无可用、占用或待发权益；已过期或根本未发的分数不再扣一次。保留已发生的验票历史。退票结案时检查该桌是否仍在用、有无独立有效预订，以及同场同档能否再售；桌台与场次名额各自只调整一次。

| 异常或交叉售后 | 处理及结案条件 |
| --- | --- |
| 补款或退款结果未知 | 保留原案、占用和冻结，查原交易。已收菜款但退款失败，重试原退款，不重复收菜款 |
| 撤回或最终终止 | 外部退款结果明确且允许撤销后，未收菜款直接解除冻结；已收菜款先按原交易退回，确认成功后解除冻结。冻结期间到期的批次按原期限处理 |
| 渠道已退、内部回收未完成 | 标记“票款已退，权益处理中”，按原案补记权益、票状态和报表。外部直接退款或拒付已形成资金事实时，拦截再次退款，另列待处置菜款及权益差异 |
| 先退菜、后退票 | 用原菜品售后结案事实重算，剔除已实际退掉的数量，只补剩余消费。服务补偿与真正退菜分别记录 |
| 先退票、后退菜 | 现金按该菜原实收和后续补款各自剩余可退金额办理，门店承担部分剔除。已退票积分回到关闭批次结清；同菜其他有效来源按原规则退回 |
| 两张票先后或同时退 | 逐票、逐份识别尚未结清的菜款。两案涉及同份菜时串行更新，同一差额只收一次 |
| 演出取消、改期、主要演员变更或已验票 | 先识别变更、履行程度及法定权利。核销只证明一次入场记录。整场取消逐票受理，门店不能履约时应退票款可独立执行，已消费菜款的承担或争议另行留据 |

## 5. 管理员按原票冲正

员工从原票提交差错原因及证据。核对该单已验证的购票会员和售出时应发分数。错户只纠正到该购票会员本人或经核实的合并后同一身份。多人希望拆分赠分、换付款人或换经办员工，均不能作为改发理由。后台展示原票应发、实发、可用、占用、已用、过期及售后状态。按既有权限由另一名有足额审批权限的人员复核；提交执行时重新核对批次、账户有效身份与并发售后。保留原记录、审批和反向流水。

| 情形 | 更正方法 |
| --- | --- |
| 漏发、重发、发错数量 | 先按支付和票种快照核对应发数。漏发走原发放任务；多发只冲原票差额。已退款或不具备发放资格的票终止误任务 |
| 本票误发给A，原单购票会员是B，尚未消费 | 一次事务收回A原批次、向经核实的B记同等分数并更新赠分归属，继承原到期日。原购票人、支付及入场记录保留 |
| A已使用200分，余350分 | 冻结可收回的350分，查200分对应消费。若实际是B授权消费，经复核把本票与该消费关联，B可用350分。若A实际消费且B应得完整550分，则先登记顾客确认的补款或经批准的门店承担，再结清A的使用、回收350分，并向B补足应得权益。涉及争议时保留案件，不自动扣其他余额或收款 |
| 到期、退款或会员号变更 | 按原有效期、原票状态及现行会员内部身份处理；已退票只更正历史及差错，已过期权益另行补偿须有独立审批。冲正与退票争用同一批赠分时，串行处理权益并重算未结差额；已确定应退的票款按原案办理 |

退票和收错钱按资金售后权限处理。积分冲正只更正权益，管理员在积分面板操作不会直接发起现金扣款或退款。

## 6. 开发分工、数据与对账

### 数据归属与操作权限

| 业务对象 | 必须能从原单找到的记录 | 允许改变状态的依据 |
| --- | --- | --- |
| 场次、票档和订单 | 门店、起止时刻、区域、场次核准容量、票种版本、票名、每桌售价、每张赠分、展示起止及分类、到期规则和售后条款 | 运营按现有权限发布。顾客确认建单时固定版本，发分按实际付款日期计算到期日 |

| 消费与积分 | 菜品份、点单时正常售价和有效优惠、会员确认、已付现金、预收款分摊、所用批次、到期日、占用与确认流水 | 自助由本人提交，代客由客户在本人微信确认。既有挂桌只结未清部分，出品记录沿用原订单 |
| 售后与冲正 | 案号、退款原因、责任方、冻结权益、应退票款、逐菜差额、实收补款、资金原路及结果、争议处理、冲正审批记录 | 申请与复核按原权限分离，实收或退款由支付结果确认。值班接待不能通过改电话、换桌或改备注调整收款和积分 |

分开记录三种进度，顾客可以同时处于「已付款、已出票」「550分已到账」「桌号待安排」。员工标记「已联系」只改接待进度。发生异常时，客服能分别看到支付、逐票权益和排桌结果。一单多票时，退一张只暂停该票的排桌或跟进，剩余有效票继续列在同一接待任务中；全部履约或已退后才可关闭整个任务。

### 实施顺序与交付责任

1. **票务后端与运营后台**先完成场次、票档版本、会员及手机号校验、逐票数据、容量及已有关联预约的匹配。以同档最后一桌、已有预约买票两个场景验收。
2. **支付、积分与接待端**接入确认订单结清后的出票、逐票核算赠分和接待任务。将已确认支付和待执行的交付记录可靠落库，再由同一原单完成交付及失败重试。日常效果为付款即交付；遇故障显示哪一步待补，工作台通知失败仍可从订单找回。实现微信菜单两种状态、员工主动致电／现场接待和核销。
3. **收银、售后与财务**接入最大可用分、代客确认、挂桌结算、逐份分摊、退票补收、门店原因退款、管理员冲正和日报。早期两步可在隔离环境联调，正式销售前须走通整票退款、菜品交叉售后和渠道结果不明的恢复流程。

| 工作包 | 复用与新增 | 可独立核验的交付 |
| --- | --- | --- |
| 上架与微信购买入口 | 上架表单增加三个可编辑字段及发布版本，大分类、单张门票和单个菜品支持对客定时展示。菜单页在到店前和桌边两种状态展示场次票档，接续详情、选票草稿、会员及手机号验证与购票确认页 | 运营在原表单完成上架或修改。新客授权后在原票继续付款，已识别有效会员且有已验证手机号时直接结账。可用匿名计数查看「点立即购票 → 到达确认页 → 付款成功」各步完成情况，并单列授权取消与售罄，用来判断购票流失 |

**必须保存的分摊。** 一份菜保存数量单位、规格、下单时正常价及有效优惠、原单实收、预收款分配、使用的每个积分批次、对应票号和该批抵扣金额。售后按成交快照回算；不取当天新菜单价。套餐按原有整套及拆项规则保留父子关系、当时的单品参考价和实际退回数量；父套餐与子菜不重复计价。所有商品都要在新单成交时保存价格和分摊。历史订单缺凭证时由售后人工核对，不依据当前菜单价自动补收。

**整数积分与金额尾差。** 货币按分保存，积分按整分记账。按本单各明细尚待支付的金额比例分配该批抵扣额，并保留来源，尾差按最大余数、相同余数按固定菜品份序分配。每份菜分摊不超过该份可抵额。部分退菜按同一原批次累计应退的抵扣金额折算整分，只记相对历史已退整分的新增量，零头保留到后续售后。例：一个积分抵扣两份菜各0.50元，分两次退菜，第一次累计0.50元、第二次累计1.00元，合计最多恢复1分。若中途退票，按剩余实际消费的金额核菜款，关闭该票批次时一并结清零头。过期、已退票与有效批次分别归还，不跨批次取整或借分。

**并发与恢复。** 单票赠分、消费确认、原菜品补款、票款退款、补款退回和管理员决定各用可追溯的唯一业务凭据。逐票发分按票号和购票奖励种类查重，不按整个支付单或会员号去重；恢复任务只补未成功的票，零赠分及已退票按各自状态结案。积分报价只试算，查看和填数均不占分。相同请求返回原结果，不同会员、金额或商品版本重新核价确认。同笔数据库事务维护票、批次、占用、分摊和流水的一致性。外部支付与退款采用已验证通知或主动查单，记录待补作业、重试和人工处理结果。先按原付款证据查重，再允许换支付方式。保留审批失败但原支付仍占额的退款，待原案终止或明确释放后才允许再申请。

**支付超时和撤回。** 已调起支付而结果未知时，查询原渠道单，恢复或关单按其权威结果执行。不能仅因本地计时到期就释放容量并让顾客重复付款。若渠道确认迟到成功且原名额已经释放，先保留该笔实收并处理原单异常；重新履约需有可兑现的余量并取得顾客同意。菜品退款、票款退款或补款撤销分别查对应原始交易。[既有活动关单前查款](/Users/jingda/.codex/worktrees/store-operations-rc305/mbox-table-minimum-spend-20261031/server/normalized/activity-payment-service.ts:185)

**交易归属与顾客凭证。** 票款退原购票支付，菜款补收由实际补款人明确确认。顾客放弃退票时，已收补款退到该笔补款的原路径，即使两笔钱来自不同的人。顾客可在原单查到退款原因、已批准票款、待补或已补菜款、回收积分及最终到账状态。凭证只展示与本人相关的会员和支付信息，后台保留完整审计关联。

**日终核对。**

- 票务按张核对预留、售出、已验、退票冻结、已退及名额释放。会员和门票页分别显示收款、出票和发分状态；已售未分桌进入排桌队列；已收未出票、应赠未发分分别进入异常待办。
- 积分按票验证：有效发放－净已用－已过期－已回收＝可用＋消费占用＋售后冻结。撤销原抵扣要从净已用扣除。错户转入转出全店抵销，未发终止不冒充已回收。
- 资金区分售票实收、票款退款、菜品原收款、桌上预收款分配、菜品补款、菜款退款及已退补款。消费按原订单营业日呈现，收退按各自入账营业日呈现。预收款使用是原款分配，不计第二笔现金；菜品补款不增加销量、低消额或库存消耗。正式收入确认口径由财务核定。
- 异常待办逐笔显示原单、金额、处理负责人和下一步。至少覆盖渠道已收但未入账、补款成功未退票、票款已退权益未结清、在途支付占分、已批准失败退款仍占额、错户使用及跨日差异。关店日结后以关联调整记录接续，保留原日结快照。

**上线与回退。** 先部署兼容旧订单的数据与读写能力，再联调两端消费和售后，最后按测试场次启售。原订单是否使用新规则取决于售出快照，不能用当前开关去推断。暂停新售时，已售票仍可入场、消费、退款和冲正；资金恢复任务继续运行。旧客户端若不能识别新票或新售后状态，显示原案及可用的升级或门店办理路径，不回落为整笔直接退款。

## 7. 经营边界、上架说明与门店待定事项

**经营前提（上海门店）。** 本次调整的目的是取消餐饮最低消费。商务部、国家发展改革委《餐饮业促进和经营管理办法》自2025年6月15日起施行，第二条按实际服务界定餐饮经营，第十六条禁止餐饮服务经营者设置最低消费。对提供餐饮服务的桌台，微信、员工端和现场均须取消起点金额、强制购买指定套餐、强制首充和不足补差。普通餐饮营业时段保留单点，可销售顾客自愿选择的套餐，按实际点单收费。只有真实举办、具备相应售票条件、能独立交付观演及所购区域桌位的指定场次，才采用本方案的整桌售票。购票后全桌餐饮消费为0元，门店也须照常让顾客入场、领桌、观演和离店。[商务部、国家发展改革委令2025年第3号，第二条、第十六条](https://www.mofcom.gov.cn/zcfb/blgg/bl/2025/art/2025/art_5eb7697fc9d44b07abc4032bd5b02656.html)

### 500元整桌票是否保留550分

**结论。** 门店已确认有实际演出，顾客买票后可以全程零酒水消费。这两项事实支持按指定场次售卖整桌观演权益，也降低了餐饮低消方面的风险。**产品可保留500元赠550分这一可选配置。** 本次核对的餐饮、促销和上海预付卡规则中，未见针对这种按票固定赠分设定“最高只能赠票价的某一比例”。有关促销规则要求如实公示可抵范围、折算方式、期限和限制，并履行承诺。具体场次能否采用550分还要看500元票价的依据和实际经营方式。[餐饮业促进和经营管理办法第十六条](https://www.mofcom.gov.cn/zcfb/blgg/bl/2025/art/2025/art_5eb7697fc9d44b07abc4032bd5b02656.html) · [规范促销行为暂行规定第六、十四、二十二条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_cae53a080be2401e8f91c6d6291539f8.html) · [上海市单用途预付消费卡管理规定第二条](https://jrj.sh.gov.cn/jcgk-dfxfg/20260105/20546800cebd4360a060ece9c3e28db4.html)

**仍需判断的是顾客实际买到了什么。** 每1分可抵1元餐饮消费，所有菜品、酒水和套餐均可抵。付500元即得550分，按足额使用算，餐饮最高可抵金额为票价的110%。即使顾客买票后没有到场，按现有设计，他也已拿到可在一年内分次使用的550分。如果长期每场如此、票档直接沿用原低消，或员工主要按“花500以后能抵550”推销，交易就可能同时具有预收餐饮款的特征。如果实际以预收资金供以后分次兑付，退款及余额处理需要适用相应预付规则，“赠送”和“不退现”两个字样不能决定法律性质。110%是这张票的计算结果，法律定性仍需结合实际履约。[上海市单用途预付消费卡管理规定第二条](https://jrj.sh.gov.cn/jcgk-dfxfg/20260105/20546800cebd4360a060ece9c3e28db4.html) · [最高法预付式消费司法解释第一条、第十八至二十一条](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=102568)

**促销成本怎么估。** 若售出100张500元、各赠550分的票，票款为50,000元，发出的55,000分最多可抵55,000元消费。按实际兑分比例和商品结构估算兑现成本，另列演出、场地、税费及被积分替代的原可售收入。未兑分仍可能在一年内使用，不能在散场当天把全部票款当作该场利润。

**经营复盘。** 按场记录售票数、实际入场桌数、零餐饮桌数、已兑积分和退票争议；用实际兑分商品成本评估促销是否划算。零餐饮顾客少也可能是正常消费偏好，应结合实际点单与清台流程判断。若出现主要买票攒分、很少入场的情况，复核后续场次配置。建议按场选择上述方案，顾客现有积分、有效期及已公布的赠分承诺继续按原版本履行。日常上架仍只需维护产品名称、每桌售价和每张赠分，不新增“合规比例”字段。

| 单位票价和促销预算 | 运营核实各档独立的观演定价依据，财务核算拟赠积分的兑现成本。常用价格和赠分可存为模板。各档具体赠分最迟在该档开售时填；1,500元、2,000元档均可按场定，不按500元档的比例推算 |
| 普通场退票条款 | 票务先选已有且适用的已审条款。若需新订，建议小型常规场先评估「开演前未核销可免退票手续费，开演后或已核销按履约情况受理」。这是一项待确认的经营建议；需结合临场空桌成本及适用规定核定，特殊演出可预先设置其他条款。每个时段和费用在付款前显示，售出后保存原版 |
| 接单、联系和排桌时限 | 店长指定当班接待与值班负责人。建议试行营业时段内远程订单30分钟内首次联系，临近开演的单优先；非营业时间购票在下次接待开始后跟进。具体桌号在约定入场前确认，临场购票现场确认。无人认领或逾期由值班负责人接手，未接通保留名额。30分钟是待试排班的内部目标 |
| 退款、补偿和冲正权限 | 店长和财务沿用既有审批人及额度，为门店承担、错户已用、到期补救和顾客撤回明确经办人。建议待补款案件进入每班交接，能从原案撤回；在途资金先查原结果，不因交班或联系超时自行作废。门店有新的授权额度时在权限管理统一调整 |
| 演出资料与发布权限 | 票务在演出项目中维护举办及售票主体、门店、客服和已核实资料。排不同场次时核对该场日期、演员、适用批文、核准人数及票价；变动由票务更新，日常门票表单自动引用。发布和复核沿用既有权限。首售前，现场实走一次无餐饮消费的验票、领桌及离店 |

#### 每场、每档实际要填什么

1. **选场次。** 已有场次直接选。新增常规场只填演出日期、开始时间、结束时间；同场三个档共用一次。若演出项目、演员或适用批准范围有变化，先由票务在场次资料中更新。
2. **选桌型，看三格。** 选中间区、靠窗卡座或内场沙发区，自动带出票名、每桌售价、每张赠分。三项均可编辑，模板正确时直接沿用。例如「周五晚场 · 中间区整桌票｜500元／桌｜赠550分」。未确定的赠分留空可存草稿，发布前填具体数或明确填0。
3. **预览并上架。** 同屏看本场时段、桌型、当前可售桌数、票价、赠分及退票条款摘要。点「保存并上架」，需要原权限复核时点「提交上架」。分类或单品需要定时展示时，点「对客可见时间」选择起止；平时沿用默认值。若本场要限售更少的桌数、改售卖窗口或使用其他已核定的退票条款，再打开「更多选项」。人工限售量只能收紧实际余量。

可售桌数由普通预约、桌票和实际桌况共同计算。后台自动生成周年有效期说明、购票会员提示、接待待办和退票提示；会员入会方式、具体桌号、积分到期日、客服电话和审批人都不占日常上架输入框。售出票价、赠分或条款按原单保存，之后修改用于后续订单，并履行已公示的促销承诺。

## 8. 验收与交付标准

**一笔完整业务。** 顾客付500元买中间区域桌票，立即出票并赠分，门店随后确认具体桌号。原单购票会员是B，管理员经复核将误发给A的550分更正到B，保留原到期日。服务员给B点260元的菜，B确认使用200分并付60元。原购票人在正常退款入口选择这张票；假设顾客个人原因、票款可全退、菜款补差约定有效且本人确认，经批准后补收200元菜款，再向原付款人退500元，收回未用350分及撤销抵扣后的200分。门店最终净收260元、出品一次；A和B名下该票可用积分均为0。购票人、用分人、代办员工和审批人均能从原案追到。

| 核对算例 | 预期结果 |
| --- | --- |
| 本票550分全部抵菜款550元，票款可全退500元 | 分别展示票款与实际菜款。若系统试算得出顾客还需净付50元，转人工核实交易性质及责任。符合预付式消费司法解释第二十条条件时排除超出部分，门店原因按第7节处理 |
| 同一道260元菜，A票抵150分、B票抵50分、原实付60元 | 先退A仅补150元，再退B只补50元。先退菜则相应积分按原批次结清，后续退票不得再追这份菜 |
| 预收款桌原余额100元、无其他欠款，260元菜用200分 | 积分200、预收款分配60、桌余额40、本次新增微信收款0。票款和菜品补收另按原交易入账 |
| 550分中已用200、剩余350在退票前过期 | 菜款仍按已用200分对应菜品核算；350列已过期、200列撤销后回收，其他会员余额不受影响 |

#### 菜单、会员、付款和接待

| 场景 | 通过标准 |

| 完整时段和全场容量分别核对 | 同档仅甲乙两桌，甲前半场有预约、乙后半场有预约，整场可售0桌。按全场容量仍可接待时，同桌增加同行者不触发固定单桌人数拦截；全场达到核准数量时停止验票，记录现场处理 |

#### 积分报价、代客结账与出品

| 场景 | 通过标准 |

### 同一会员买两桌，退不同票分别核对

会员同单支付1,000元，买A、B两张各500元的桌票，每张赠550分。会员账显示本单共赠1,100分，同时列出A、B两条550分入账记录。假设该会员原无其他积分，两张票均未入场、没有独立预约，菜品在演出前已实际消费。260元餐饮订单使用A票200分，并实付60元。以下两行分别从同一初始状态计算，假设个人原因可全额退票且补差条件成立。

| 只退哪张 | 退票款 | 本次补菜款 | 退后仍有效的票及其购票赠分 | 门店净实收 |
| --- | ---: | ---: | --- | ---: |
| B票，未动用其赠分 | 500元 | 0元 | A票有效、余350分。B的550分直接回收 | 560元 |
| A票，已抵菜款200元 | 500元 | 200元 | B票有效、余550分。A结清未用350分及撤销抵扣后的200分 | 760元 |

两种情形都只释放所退桌票占用，按原售卖窗口决定是否再售；保留同单另一张票的接待子项。普通消费奖励按餐饮规则另外入账，表中余额只列购票赠分。若A票已用完、B票只用50分，则退B时只按B的50分处理，A的消费流水仍归A。
