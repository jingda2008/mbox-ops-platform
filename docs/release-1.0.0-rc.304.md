# 1.0.0-rc.304 渠道赠品券消费核销与近期修复整合

用户于 11 月 21 日确认新券发放时不查库存，只有顾客实际消费用券时才查。自领或员工代发只登记领取，绑桌不预占库存。顾客实际核销赠品时核对条件及库存。缺货保留原券，可在补货后按原券重试。历史已预留的券保留原承诺。领取数量限制有效，活动和全店的成本预算用于预警。

在 rc303 的基础上整合，A10 付款回执和一次出单保护仍在。新增迁移 320，原库 318、319 的内容及编号均保留。320 是应用兼容边界，标准发布须在停写后备份，再迁移及切换。恢复营业后旧版不能承接新发券的写入。

11 月 14 日以来的本地与远端分支已核对。原始盘点覆盖 245 个登记工作树，其中 3 个历史临时目录已移除。现存工作树有 3 个保留本期未提交文件。旧桌台、会员及拆并桌工作区的实现已合入或被后续修复覆盖。独立渠道券工作区的 42 个改动文件已逐项纳入。另将此前只在独立分支的 Windows 打印桥 1.0.13 源码、构建器及原生测试纳入。现网打印桥最后一次心跳自报 1.0.13，实际纸票由门店验收。

审核与安装状态分别取证。正式后台以公开就绪接口、迁移和上线前后对照为准。微信最终候选包含渠道券及 A10 两项，支付宝此次修改点为原付款恢复；审核通过及上架以对应平台版本回执为准。
