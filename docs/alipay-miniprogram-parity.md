## 平台转换规则

- WXML/WXSS 转为 AXML/ACSS；`wx:` 转为 `a:`；绑定事件转为 `onTap`、`onInput`、`onChange` 等。
- 页面业务代码只调用 `utils/platform.js`，由其适配 `my.request`、存储、导航、弹窗、扫码、选图和 `my.tradePay`。
- 自定义组件使用支付宝 `props`。后端适配完成前，手机号按钮只展示明确阻断说明，绝不声明 `getAuthorize` 或触发个人信息授权。
- checkbox 使用支付宝公开的 `color` 属性和外层缩放；微信私有 `.wx-checkbox-input` 选择器不复制到支付宝端。
- 分享继续由各页面的 `onShareAppMessage` 返回公开白名单内容；不在 `onShow` 自动打开 `my.showSharePanel`。
- 预约是公共到店服务，不读取会员 bootstrap、不显示入会拦截；匿名预约会话仅允许顾客访问自己的预约。积分、优惠券和会员中心仍是会员能力。
- 默认使用 WebView 渲染。Native 渲染对现有 sticky、grid、gap、媒体查询等存在兼容风险，不作为当前像素一致方案。
- `mini.project.json` 使用 format 2 和 `compileOptions.component2`；format 2 默认采用基础库 2.x。IDE 3.10.15 模拟器已读回基础库 2.10.15。当前无界面编译命令仍报告 SDK 1.x，因此它只能证明 WebView 源码可编译，不能替代 IDE 或真机版本证据。
- 工具模块使用 ESM 导出。开发工具 3.10.15 在基础库 2.10.15 下已实证：仓库根目录 ESM package scope 中的 `module.exports` 会在启动阶段中断页面渲染；门禁现已明确禁止该写法。

## 尚未完成，不能写成“完全一样”

| 阻断 | 缺少的共享后端适配 | 开放条件 |
|---|---|---|
| 支付宝身份 | authCode 换取客户身份、退出和身份绑定 | 契约测试、隔离数据库、真机登录 |
| 支付宝手机号 | 授权响应验签解密、幂等入会/找回 | 隐私声明、真机授权、拒绝/取消 |
| 支付宝支付 | 服务端预下单返回 `tradeNO`、查单、通知、退款 | 真实小额资金、取消/超时/未知结果、对账 |
| 支付宝消息 | 模板策略、授权记录、发送和回执 | 平台模板、真机授权与送达 |
| 会话 Cookie | 支付宝真机是否可靠收发当前 HttpOnly 会话 | 开发者工具和双端真机网络证据；不可靠则改后端会话载体 |

## 发布状态口径

当前完成本地源码候选、独立监督智能体的源码/编译产物复核、静态门禁、运行时单测和支付宝开发者工具 3.10.15 内置编译器复核。IDE 模拟器已在基础库 2.10.15 启动并渲染完整首页内容；这次实测发现并修正了 ESM 导出不兼容导致的空白主体。编译产物还会反查微信运行时调用、相册桌码重放和伪客服能力。尚未完成 360/375/390px 截图量化对比、其余页面逐页交互、iOS/Android 真机、Cookie 兼容、支付宝身份/手机号/消息/支付后端适配、真实资金、上传和体验版验收。因此源码、官方编译和 IDE 首页渲染维度可通过，但“视觉完全一致/可真机交付”的整体验收仍不通过；后续任何报告必须逐项区分这些状态。
