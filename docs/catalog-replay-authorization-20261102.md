## 已确认并修复：RULE-AUDIT-20261102-03

分类创建、分类修改、商品创建、商品修改、独立标准售价修改的普通接口，原先只在写入 handler 内校验权限。通用命令执行器命中已完成幂等记录时不调用 handler，导致原操作者撤权后仍读到旧响应。原生分类/商品入口已有 beforeClaim 保护；不能把普通入口缺陷描述为所有原生接口都失守。

修复将这些入口统一通过 `catalogWriteExecutor`，在缓存读取或原生持久回执恢复前重新读取当前员工权限：分类/商品需要 `catalog.product.manage`，夹带售价需要 `catalog.price.manage`，显式成本输入需要 `inventory.cost.view`；独立调价只要求其既有调价权限，不额外要求商品管理权限。保留商品管理或调价权但失去成本查看权时，旧商品响应的 `costAmountMinor` 在返回前脱敏。

保留原 operationScope、请求指纹、幂等键与原生持久回执协议，没有迁移。身份由每次请求的上下文解析器提供，事务内再检查当前员工状态和权限；不在持有命令连接时嵌套解析身份。版本、分类结构、商品形态等可变业务检查仍在首次写入 handler 内，避免成功重试被后来发生的版本变化误拦。回执恢复不重复业务写入、审计和 outbox。

## 已检查的相邻保护与限度

- 菜品可售数量：已有 beforeClaim 授权与持久回执，本轮增加撤权/恢复回归通过。
- 群发草稿和排期：执行器调用前已有当前权限事务检查；不是只在 handler 中检查。静态核查，无生产发送。
- 会员卡员工操作：先调用 `staff(request, permission)`；会员号配置、首页弹窗也有入口权限检查。未将这些代码归为同一撤权重试缺陷。
- 会员通知发布：先调用 `authorized(..., 'loyalty.policy.publish')`；不能看到 execute 缺第三参数就判漏洞。
- 会员号/首页弹窗的原生再授权仍在命令事务内调用上下文解析器，存在连接池嵌套使用的审计线索；本轮未做压力复现，不作现场超时根因结论。

检查方法是逐条追踪“入口身份 → 当前基础权限 → 请求附加权限/数据范围 → 缓存/持久回执 → 响应字段”，并分别验证新请求与原请求。入口授权可以构成有效保护；beforeClaim 存在也不代表附加范围完整。此次覆盖不是全系统无缺陷证明，部分拆并桌的账号/人数业务语义问题仍保留原结论。
