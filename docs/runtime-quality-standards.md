# M-BOX 运行质量指标与发布门禁

更新时间：2026-08-09

## 判定原则

- 功能测试通过不代表高峰性能合格；性能结论必须包含样本量、分位数、错误率和测试环境。
- 样本不足时只能标记“待观察”，不能标记通过。
- 客户、员工点击可先给即时视觉反馈，但服务端失败必须恢复权威状态并明确告知原因。
- 真实支付、打印机、弱网和连续营业晚班不能用模拟测试替代。

## 核心SLO

| 指标 | 候选发布门禁 | 说明 |
|---|---:|---|
| 业务接口5xx率 | 0 | 发布观察窗口内不得出现应用5xx |
| 数据库连接池等待P95 | 不超过50ms | 同时监控waiting数量，不得持续大于0 |
| 变更队列深度 | 不超过100 | 达到容量前应限流，不得耗尽连接池 |
| Node事件循环延迟P95/P99 | 理想50ms；硬门禁75ms / 100ms | P95超过50ms必须记录性能告警；超过75ms或P99超过100ms阻断候选发布 |
| 员工心跳P95/P99 | 150ms / 300ms | 至少300个成功样本；不得改写整店revision |
| 已缓存员工启动P95/P99 | 150ms / 300ms | 返回304或轻量响应 |
| 首次员工启动P95/P99 | 500ms / 800ms | 返回完整工作区数据 |
| 客户会话P95/P99 | 500ms / 800ms | 至少300个成功样本且覆盖60并发；重复轮询不得重复写到访事件 |
| 服务任务创建P95/P99 | 800ms / 1500ms | 至少300个成功样本；忙时呼叫服务不得被整店写队列长期阻塞 |
| 协助下单创建P95/P99 | 1500ms / 2500ms | 至少300个成功样本；只计算服务端确认，不用前端乐观反馈替代 |
| 任务/KDS动作P95/P99 | 800ms / 1500ms | 各至少300个成功样本；以服务端确认时间计，不用乐观UI掩盖失败 |
| 前端投影CPU P95/最大值 | 50ms / 100ms | 不含网络和数据库时间 |

## 历史基线

`rc.64`历史运行日志显示，员工启动、心跳、KDS和任务动作均存在秒级长尾，并出现134次数据库连接池超时。`rc.67`错误信号显著减少，但心跳仅9个样本，不能据此判定高峰通过；客户会话和首次启动仍有超过目标的长尾。

## 候选发布要求

1. 使用不可变候选镜像执行迁移、健康检查和核心流程。
2. 采集带规范化路由标签的请求计数和延迟直方图，不记录令牌、桌码或业务对象ID。
3. 至少执行员工启动、心跳、客户会话、任务和KDS专项压力测试。
4. 使用`npm run logs:audit -- --input <日志文件>`生成结构化报告；缺少路由或样本不足必须保留为待观察。
5. 切流后持续观察并保留版本SHA、镜像摘要、数据库备份、指标报告和回滚证据。
6. 商业生产还需连续至少3个真实营业晚班达到SLA，并完成真实支付、退款、打印和弱网验收。
