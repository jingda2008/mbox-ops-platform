# 新商家优惠方案复用（2026-11-19，本地候选）

用户反馈属实：原来只能复制当前店长自己的历史，新商家第一次仍需重填全部优惠。商家基础资料本来已持久保存，不需要每日新建；本轮解决的是跨商家优惠配置复用和入口说明。

## 员工操作

1. 新商家只登记一次名称、店长和佣金结算主体；已有商家直接选“当前推荐店长”，不再登记。
2. 打开“新商家快速配置：沿用已有优惠方案”，选择已配好优惠的参考商家，点“沿用方案到当前商家”。新商家登记后该入口自动展开。
3. 优惠、适用商品、次数、佣金、条款及活动自动带入。填本次领取/使用时间，需要时改数量或优惠；核对标题、佣金及条款适用新店，勾选确认后生成。
4. 另一管理员审批，下载该新店专属图，发送后登记。后续给同一店发券继续用“复制这位店长上一批配置”。

全店第一套方案仍须配置一次。沿用原活动会共用其总额度，不会为新商家扩预算。账户、收款核实、联系人和权限各自配置一次，不复制其他商家的身份或收款资料。商家名称即使写在标题/条款里也不会擅自替换，需核对修改；生成前和审批页均展示新店主体及完整规则。

## 实现与保护

- 复用原有只读 `/api/staff/channel/batch-template/:promoterId`；权限仍为 `channel.manage`，租户/门店范围不变。无需数据库迁移，无小程序改动。
- 来源选择与当前推荐人分开；读取参考商家的最新批次，但生成时始终使用当前推荐人和当前商家的结算主体。
- 保留原来的日期清空、商品停用拒绝、活动缺失拒绝、账号切换取消旧响应、持久请求重试和独立审批机制。
- 跨商家沿用后必须核对条款；切换商家/账号清空来源和确认状态。优惠方案读取不发券、不占领取额度。
- 实际新批次由后端创建新优惠号码和公开令牌，审批和已领记录不复制，源批次不变。
