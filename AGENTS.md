# M-BOX repository working rules

## Commercialization checklist

- Read `docs/commercialization-pending-checklist.md` before changing commercial behavior, releases, payments, inventory, recommendations, permissions, hardware integration, or operating acceptance.
- When development, tests, integration, deployment, or on-site acceptance changes the actual status of an item, update the checklist in the same work turn.
- Add newly discovered commercial risks to the checklist with a unique ID, priority, owner, target version, completion criteria, and evidence requirement.
- Do not mark an item complete based only on a visible page, local demo, simulated payment, AI response, or verbal confirmation.
- Every checklist update must refresh the Beijing-time `最后更新` value and append one row to `变更记录`.
- Do not remove completed or superseded items. Preserve history and link replacement decisions.
