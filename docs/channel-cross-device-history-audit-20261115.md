# 关闭标签页、重新登录与换设备核对原拆并桌

> 后续修正：本文件为当时阶段记录。“未查到原回执”不能证明原请求未执行或不会迟到；新版保持待核对，并提供明确封存原编号的撤回入口。以 [迟到请求审计](channel-delayed-intent-audit-20261115.md) 为准。


时间：2026-11-15。范围：员工网页、服务端和隔离模拟；暂不部署。

## 员工操作

1. 使用**原员工账号**登录员工网页，进入桌台页面，点击 **“核对历史拆并桌（服务端）”**。不要求原标签页或本地恢复日志仍存在，也不要求原桌次仍营业。
2. 按北京时间、记录尾号、员工、原桌→目标桌、人数核对。界面区分“当时移动到哪桌”和“目标原桌次现在在哪桌/是否结束”，避免把历史成功回执当成当前桌位。
3. 如需更早记录，点击“更早的记录”。查询只读取服务端永久记录，不补执行、重放或复制原操作。
4. **未查到不代表未执行。** 请求可能尚未到达服务端；先核对现场和当前名单，再重新预检。不要凭本地日志消失或空列表认定未提交。
5. 源桌或目标桌已有移动记录时，网页要求先查询历史，再勾选“已核对服务端记录及现场名单，本次是新的拆并桌”，才能确认新操作。

查询只返回当前员工、有权访问门店内的已完成记录。不能用另一员工账号查询原员工记录；权限被撤销后也不能读取。需要跨员工核对时应使用现有主管审计流程，本轮没有扩张权限。

## 本轮实现与修复

- 新增服务端历史只读接口和独立网页入口，复用永久移动记录，包含整桌转桌、拆桌、并桌；每页20条，按事件时间和ID稳定分页，返回 `Cache-Control: no-store`。
- 不返回顾客身份、会员、优惠券、商品、金额、请求编号或原请求正文。换账号时立即隐藏旧列表，旧账号迟到结果不覆盖新账号。
- 新增网页快照 `movementRevision`，取源/目标桌次相关永久移动事件数。执行时在现有移动锁内重算；即使桌位、人数恢复原值，期间发生过移动也拒绝旧快照。新网页请求缺少此版本会明确拒绝，历史已完成原请求仍可按原回执恢复。
- 已有移动历史的新网页操作需要显式确认。读取失败、损坏历史或未确认时，不能直接从当前预检提交新操作。重新查询历史时立即取消上次确认，连点旧按钮也不能沿用旧确认。
- 查询先等待已进入移动事务的操作，再读取已提交历史。补测发现等待期间撤权仍可能返回记录，已修复为取得锁后再次检查权限。
- 不自动把“未查询到完成记录”转换成“未执行”，也不从历史页面提供重新执行按钮。

无数据库迁移；未修改优惠、库存、退款和佣金规则。此次新增历史界面及移动记录版本约束针对员工网页。原生员工App的既有协议和界面未改动，不能将本轮网页结果泛化为原生App已增加同样入口。

| 清空本地存储、重新登录、换一台设备 | 新API实例、空存储仍能读服务端已完成历史，无新的POST |

| 查询遇到正在执行的移动 | `pg_blocking_pids` 证明实际锁等待；等待结束后可看到刚提交的事件 |

| 断网、损坏历史响应、未确认新操作 | 不把读取失败当空列表，不直接放行新操作 |
