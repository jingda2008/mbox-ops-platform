# M-BOX 1.0.0-rc.34 规范化高频读取升级

## 本版完成

1. **高频页面改读规范化表**：员工端桌台、桌次、服务任务、订单、KDS、支付和库存数据由 PostgreSQL 独立实体表提供，不再以整店 JSON 中的历史数组作为现场权威来源。
2. **经营日隔离**：桌次、订单、KDS 和支付只读取当前营业日；旧数据继续用于分析和追责，不进入今天的现场操作列表。
3. **一致版本快照**：一次 SQL 读取全部高频实体，同时校验聚合 revision 与投影 checkpoint；版本不一致时刷新并重试，持续异常返回 503，不展示混合状态。
4. **低延迟复用**：同一门店、同一 revision 的规范化快照只查询一次，12 名员工的岗位视图复用数据后再分别执行权限裁剪。
5. **权限和发布门禁**：新增表全部强制 RLS，并向受限应用角色授予最小读写权限；CI 在真实 PostgreSQL 16 中验证 17 个迁移、84 张强制 RLS 表、启动回填、增量更新和未变化实体不丢失。

## 本次发现并关闭的问题

| 问题 | 经营影响 | 修正 |
|---|---|---|
| 规范化表缺少应用角色授权 | 非表所有者的生产连接会返回 503 | 迁移补齐九张投影/检查点表权限，并加入自动数据库门禁 |
| 只修改一个实体后其余实体从新 revision 查询中消失 | 修改 L01 后其他桌台可能暂时不见 | checkpoint 负责整店版本一致性，行版本只代表该实体最后变化版本 |
| 旧营业日订单继续参与现场数据组装 | 员工端变慢且容易误操作旧单 | 桌次关联数据按北京时间营业日过滤 |

## 验收证据

- 定向测试：21 条通过，覆盖投影、读取、版本冲突、缓存失败重试和 PostgreSQL 仓储。
- 实库验证：PostgreSQL 16，17 个迁移，84 张强制 RLS 表；单独更新 1 张桌后 12 张桌仍全部可见，投影 revision 与运行 revision 一致。
- 就绪接口新增 `operationalReadPath=normalized_tables` 和 `operationalReadEntityTypes=8`；员工启动接口返回 `x-mbox-operational-source=normalized_tables`。

## 发布边界

本版完成的是高频**读取路径**迁移和事务内增量投影。配置、权限和低频领域仍保留兼容聚合；写入仍使用整店事务锁确保订单、支付、库存和审计共同成功或共同回滚。行级领域写入要按命令边界逐步迁移，不能为了追求速度直接取消一致性锁。

213 条经营 TC 仍为 147 条通过、50 条未执行、16 条阻塞，共 66 条商业发布阻断；验证环境可部署，真实支付、硬件、门店网络和岗位签字未完成前不能改称正式商业生产版。
