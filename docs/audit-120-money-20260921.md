## 新增问题

### SIM120-01 / MONEY-01 / P1：数量售后之后仍有实际欠款，关桌却按状态当成结清

**确证场景A：**原套餐40元，组成5瓶水（原单点每瓶8元）及一份20元小食。已付40元后退2瓶水，按已确认的“打散套餐后保留品按原单点价”规则，有效应收为 `3×8+20=44元`。本次退款0元，仍欠4元。

实际结果：

| 位置 | 当前读回 |
|---|---|
| 原订单付款状态 | `paid`，未随增加应收同步 |
| 待收款列表 | 正确显示欠400分 |
| 结账汇总 | 应收4400、已收4000、待收400分、`partial` |
| 关桌检查与阻断明细 | 待收0、没有 `ORDER_UNSETTLED` |
| 保留品全部送达后 | `/table-sessions/:id/begin-closing` 和 `/close` 均200；桌次变 `closed`，结账汇总仍欠400分 |

**确证场景B：**40元普通订单先收16元，再按份退一件8元商品并完成8元退款。有效应收32元、净收8元、应收余额24元；订单状态正常为 `partially_refunded`。关桌检查仍报告欠款0，没有未结订单阻断。这个场景表明，仅增加套餐批准后的状态同步不足以修复问题。

根因定位：

- `server/normalized/table-session-closure-blockers.ts:128` 仅对 unpaid/pending/partially_paid 计算余额；`:133`—`:134` 将 paid/partially_refunded/refunded 一律当成结清。
- `server/normalized/business-day-blocker-facts.ts:66` 附近同样依赖付款状态和未减退款的累计收款，遗漏阻断详情。
- `server/normalized/item-after-sales-command-service.ts:221`—`:224` 结束原售后时只同步售后进度，没有同步增加应收后的付款状态。
- `server/normalized/normalized-operations-api.ts:531`—`:538` 使用上述关桌检查作为普通关桌门槛，故实际API也放行。

风险：高峰退套餐/分笔付款后退品，收银与店长看见不同欠款，正常关桌可掩盖未收款。这里证明的是隔离环境漏阻断，没有证据声称生产已经损失资金。

建议及关闭条件：建立统一的有效消费应收/已收/售后对应退款/补偿/重收授权口径；所有关桌、日结、转桌/并桌检查基于同一资金事实，状态只作展示。保留未授权重收保护。场景A和B在款项未清时均应阻断普通关桌，补齐准确金额与来源；合法客离例外应仍单独审计。

复现：`server/normalized/audit-120-money.test.ts:121`、`:159`。

### SIM120-02 / MONEY-02 / P2：已做数量退款后，再服务补偿会凭空恢复票据欠款

原40元订单已付，按份退8元后有效应收32元、净收32元，结清。再因等待过久补偿1元，实际净收31元；这1元是明确的 `service_compensation`，不是要求顾客再付。后台没有“重新收款”授权。

当前真实生成票据为“预结账单”，其“尚未收款”为100分；收款列表却为空。付款4000分、两笔退款合计900分、退款分录各一笔都正确。普通订单仅服务补偿1元的对照场景正确显示待收0，组合经过数量售后才出现差异。

根因：`server/normalized/order-collection-sql.ts:10`—`:11` 只要存在任意已批准的数量计价记录，就把本订单**全部**成功退款都从已收中减去，未区分原售后退款和额外补偿。`server/normalized/checkout-print-summary.ts:11`—`:14` 使用该判断生成待收；而 `server/normalized/commerce-kds-api.ts:443`—`:446` 仍要求成功退款后的有效重收授权，结果前后冲突。`server/normalized/print-ticket-source.ts:139`—`:151` 将错误待收写入真实票据快照。

风险：顾客要求单据时被错误显示欠款，收银却找不到待收入口，容易引发重复解释或不当补收。未发现自动重复扣款，不能把风险写成已经多扣款。

建议及关闭条件：按退款业务来源分别计算应收调整与补偿，打印状态与收款工作台一致；数量退款前/后发生补偿、金额调整、多收退回及其先后顺序均需覆盖，仍维持退款不自动授权再次扣款。

复现及对照：`server/normalized/audit-120-money.test.ts:101`、`:107`。

### SIM120-03 / MONEY-03 / P2：部分付款再退品，日结待收金额低于结账单

沿 MONEY-01 场景B：原40元、收16元、退品8元并实际退8元。保留商品应收32元，净收8元，剩余待收应为24元。

真实 `mbox.operating_day_summary` 的本订单待收增量却为16元；`readCheckoutPrintSummary` 正确为24元。**日报漏计800分待收。**用前后增量隔离同日其他测试订单，未把店总额误当单笔。

根因：`database/normalized-migrations/201_item_quantity_after_sales_foundation.sql:596`—`:601` 仅在存在 active 的重收授权时把已退款加回余额；数量退品后保留品的应收不是由该临时授权决定的。数据库schema 224中该函数仍采用该定义。

建议及关闭条件：日报的真实欠款独立于“当前是否允许发起重收”的授权状态；发起收款的额外授权可以保留。补齐授权创建、过期、消费前后，同一未结消费余额不应无业务原因跳变的断言，覆盖日结报表、打印和导出一致性。

复现：`server/normalized/audit-120-money.test.ts:159`—`:172`。与 MONEY-01 同一业务案例但属独立日报计算根因，单独登记便于防止只修关桌遗漏报表。
