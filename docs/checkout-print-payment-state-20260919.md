# 结账票收款状态与总合计修复

VIP3 的未收款整桌账单以固定“结账单”为标题，且没有传入整桌合计。现在新生成的整桌及单笔账单按已确认的收款事实确定标题：无成功收款、渠道待确认或仍有订单待收时为“预结账单”；已有成功收款且各订单无需继续收款时为“结账单”。部分付款明确标记尚未结清；无收款的零元单不伪装成实收。

整桌汇总全部订单，合计按现行应付金额计算，考虑退菜减额、套餐补差并排除取消订单；合付按原订单分摊统计，不能将同一笔合付重复算入。实收、实际退款、净收和尚未收款分别显示；单笔多收不能抵消另一笔订单待收。退款沿用现有收款资格规则，不把普通售后退款变成再次追款。

票尾增加应付总合计，使用已有大字加粗总额区域。HTML在80mm为26pt，58mm为21pt；已核验的PrintBridge 1.0.9包原生布局输出“合计：¥3144.00”，ESC/POS字号17（0x11，双倍宽高）且加粗。复用现有桥接能力，无需为本次修改重做驱动、中文编码、Logo或切纸程序。原网页预览已归档到 `artifacts/checkout-print/browser-reference/`；对外预览已替换为从原打印脚本输出的 RAW 字节解码的图片，保留打印指令中的换行、分列、字号、加粗、Logo 位图与切纸位置，不再另用网页 CSS 排版。中文字形使用本机字库，纸张及可打印点宽采用常见 58/80mm 配置；这两项仍需原打印机实测确认。

新快照增加可选checkoutState，序列化与分页保留它，最终总合计只出现一次。历史缺少该字段的快照保持原标题。已打印的预结账单不会因后来付款改变；付款后应重新生成账单，补打仍重放原快照。旧请求ID在账务变化后重试如发生内容冲突继续拒绝，不篡改旧票。
