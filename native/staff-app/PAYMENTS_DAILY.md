# 日常支付开发与验收台账

更新时间：2026-09-27。范围是前一批列出的 **20 项员工 App 日常支付业务**，不代表会员、预约、完整库存及门店管理等整套网页功能已经迁移。iOS / Android 为独立原生客户端；本轮没有修改网页界面，没有生产交易或部署。

**20 项均已有两端代码和入口；没有任何 A（营业验收）项。** C 表示本地规则/接口合同与构建通过，不表示已经连接生产完成业务。超时或没有确证的旧接口错误保留原请求，不能任意清除、换键或把未知款当失败。

## 新增入口

- 收银 → 商品售后 / 原订单 → 处理原商品。
- 收银 → 活动原报名 → 收款、退款及重收；每笔迟到旧款独立处理。
- 收银 → 团购券核销与原事项恢复；从原订单进入可关联原桌次。
- 收银 → 现金盘点与双人交接。
- 收银 → 票据与打印；原订单可打印该单和整个桌次。
- 收银 → 原线上付款 → 核对渠道并关闭；原单合付显示整笔金额和关联订单。

## 上线及现场验收仍是开放条件

1. 将增量整合到最新生产主线，不能用这个 rc.240 基线直接覆盖后续 rc.242。需要迁移 `251_native_voucher_operations.sql`、`252_native_cash_handover.sql`，并部署活动金额保护、真实关单、原请求关联和跨日兼容接口。没有部署本轮后台。
2. 两端真实账号逐页联调、双岗位复核、双设备并发、真机相机、锁屏/杀进程/安全存储不可读/空间故障、跨营业日与撤权测试尚未完成。当前模拟器证据只证明覆盖安装和本机演练首页启动。
3. 实际支付通道收退、迟到款、关闭竞态、平台团购核销、PrintBridge 真正出纸和补打，以及现金双人实点，需要门店独立验收。没有拿生产钱款或券进行破坏性测试。
4. 团购平台未知结果需查询平台原凭证再双人复核，人工凭证与自动回执分开留痕。平台结算、银行账单导入与财务调整不由核销按钮自动完成。不可把签名句柄、券码或付款码放普通日志。
5. 现金交接覆盖门店现金总额；不支持把同一门店拆成多个独立钱箱。实点期间需暂停现金收退；提交后已入账的新现金会要求重新盘点，确认后新流水衔接下次期初。现金差额不自动虚增收入或自动核销。
6. 原生票据中心处理现有打印策略生成的原账单/日报和补打；打印机安装、模板/路由策略管理仍使用现有设备管理。原生完整设备配置不在本轮支付补齐范围。
7. 正式签名、iPhone 分发渠道、Android 正式更新包和线上版本清单仍按原更新发布清单办理，模拟器覆盖安装不算线上发布。
