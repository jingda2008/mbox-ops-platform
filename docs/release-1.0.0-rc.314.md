# 1.0.0-rc.314 整桌门票与收银退票候选

门票按场次与桌区在菜单展示。顾客通过门店联系办理售后，收银从原单受理。顾客确认且原餐单实收补款后，后台按票生成独立退款复核待办。同一支付下的多张票分别核算。门店员工负责场次、票档及购票公示的真实性核实。

## 发布准备

- 营业基线为 rc.313，源提交 ca70380c，数据库 365。2026-11-24 只读就绪结果确认营业镜像摘要为 sha256:81c140bc78c8dfdd6eb1ef6d08fec50fb04f2cb81c8ad60e3770c7882b7a0702。正式切换前再次读取并记录当前版本。
- 366 新增场次及票档展示字段并默认关闭。367 新增原票核定金额、经办人、自动送审异常、两个待办索引及清款检查。升级前原案的核定金额为空，员工在原案核定后才能自动送审。切换前记录在办售后、实收待回执及未完结退款，核对旧案的后续岗位。
- 使用隔离历史快照从 365 升到 367、重跑迁移并恢复到另一个 365 库。17 张表的原字段指纹一致，含 153 张餐单、279 笔收款、220 笔退款。该快照的门票和退票案表为空。非空门票的双票独立复核、补款与冲回由票务专项验证。
- 构建及发布采用阿里云运行手册。正式发布包要能追溯到主线冻结提交、版本标签、镜像摘要和迁移校验值。切换前做营业数据库备份并确认可恢复，运行零流量候选；切换后核查就绪版本、收银待办、补款任务、门户和微信菜单。发现异常时记录在途收退款，按日志回切已验证的应用，逐笔对渠道；涉及数据库恢复须由财务及数据库负责人核对备份后新增业务。
- 微信上传前核对同一发布源、AppID、合法域名、隐私配置、设备和平台资料。上传后留版本与上传回执，再提交审核，留审核单号。平台批准及正式发布另行登记。

## 微信提审资料草稿

本次更新优化演出门票购买和售后进度。顾客在“点单”的“门票”分类查看票档、场次、桌区、赠分及使用和退票规则，通过微信支付购票；在“我的门票”查看单张票、联系门店办理退票，按原餐单查看并确认补款明细。

审核入口：进入门店小程序，打开“点单 → 门票 → 票档详情”。选择有展示权限且仍有效的场次。登录会员后可查看“我的门票”。审核用账号、审核所需材料和可见场次由发布人与门店在提审时核实并按微信平台要求提供。凭证和真实顾客资料走受控渠道保存。
