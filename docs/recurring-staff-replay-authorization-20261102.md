# 周期费用历史来源与员工旧概览回执审计（2026-11-02）

本轮属于 PR415 修复候选：未合并、未部署，未访问或修改现场桌台、订单或真实员工账号。动态验证仅使用本机一次性 PostgreSQL 数据库及受限 LOGIN（非超级用户、无 BYPASSRLS、继承 mbox_runtime），应用连接池上限为 1。

## 08：历史来源与当前规则必须分开

周期规则可在执行成功后改类或结束。旧修改回执的 previousRule 仍保存原来源和金额；生成回执可能只记录数量，无法仅从当前规则可靠推断当时检查过哪些来源。把整个写入 handler 再跑一次会误触版本/状态检查，甚至重复业务动作。

修复在首次真实执行的来源授权中收集实际需要的权限，随命令回执原子保存 `replayAuthorization: {version:1, sourcePermissions:[...]}`。它是服务器计算的“该回执需要什么权限”，不是历史账号授权凭证，也不采纳客户端提交的同名字段。

- 周期修改捕获改类前规则的来源/会计分类，状态变更捕获变更前来源，生成捕获所有实际检查的适用规则，包括新增数量为 0 的情况。
- 命令执行器增加可选回执授权钩子：校验命令指纹并锁定原回执后、解码和返回业务结果前，在同一事务中检查当前权限。拒绝不清空、不重写回执，不包装成“本次未提交”，不重跑 handler。
- 元数据放在现有 response_snapshot 的结果外层，不改变接口结果、指纹、命名空间或 TTL；未使用此功能的命令保持原存储格式，无 schema 迁移。
- 新普通费用回执记录空来源权限集合，后来规则变成工资/采购费用也不反向扩大旧回执权限。新建周期规则原本禁止工资/采购来源，无需新增回执来源检查。

### 旧回执兼容限制

发布前已存在的修改/状态/生成回执没有完整来源证据，不能猜测为普通费用。缺少元数据时，要求当前操作者同时具有工资管理及采购收货权限才可核对原回执；权限不足返回 403 并提示保留原请求、勿重复操作。**这会收紧部分历史普通费用回执的读取**，是避免从可变现状推断历史来源的保守边界，不代表要给普通费用人员默认增加权限。原记录保留，满足授权后仍能恢复同一结果；不通过换键、删除缓存或重跑生成来“修复”它。

旧创建回执不受这项保守限制。元数据格式损坏、未知版本或未知权限代码直接拒绝，不把它当作空集合放行。

## 09：员工创建/状态回执重新授权

普通员工创建和状态变更只在首次写入时检查管理员，旧回执会返回含员工及权限概览的结果。现在两条服务命令的 beforeClaim 都先获取员工权限配置锁，再检查当前 staff.access.configure。

原生适配层原有授权保留；两层在同一事务内取同一锁，不创建嵌套连接。员工停用、换操作者、换门店都不能取得旧概览；恢复授权后仍返回原回执，不重新创建员工或改变其状态。

权限交接是不同业务：仍在职原操作者可核对本人完全匹配的交接回执，撤权后 overview=null，不能继续新写入。本轮保留并回归这个例外，不将其机械改成拒绝。
