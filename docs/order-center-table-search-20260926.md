## 修复行为

- 综合搜索及高级桌号筛选先在当前租户/门店查完整编号，匹配时只取该桌台ID。A5不会再匹配其他桌订单号里的a5，W1不会混入W10/W12。
- 复用已批准的28组旧编号别名，W01可查到改名后的W1；若原编号在该门店确实是另一张桌，优先原编号，避免合并两个实际桌台。其他门店的同名桌不干扰解析。
- 没有完整桌号匹配时，保留订单号片段、桌号片段和金额查询。若存在纯数字桌号888，则888优先查该桌；888.00可明确查询金额。
- 分页与导出使用同一查询规则；保留原营业日、岗位权限、跨日未完事项、金额和桌次分组逻辑。全店资金汇总仍按既有说明独立于搜索条件。

## 全入口排查范围

| 入口 | 发现与处置 |
|---|---|
| 订单中心、订单导出 | 综合搜索会混入订单号片段；完整桌号解析为当前门店桌台ID，导出同规则 |
| 收银、退款工作台 | 同样会混入订单/付款/退款及渠道编号；完整桌号优先，活动付款不因编号片段混入桌单 |
| 现场桌台列表 | 编号/显示名/区域合并子串匹配；改为完整桌号优先，保留全部/我的/待收款范围 |
| 责任桌安排 | 前缀混桌，且搜索隐藏区域UUID可误命中；改为桌号优先，普通文本只搜可见区域名称 |
| 后厨和吧台制作板 | 待制作组、在制批次、批次定位均有桌号/订单号子串混查；统一逐桌匹配。整批制作和份数选择保持原规则，不把搜索自动变成制作授权 |
| 普通制作、取送队列 | 桌号与品名拼接匹配；完整桌号不再误中商品名称或相邻编号 |
| 会员礼遇/点心任务 | 桌号与会员号/核销码混查；完整桌号优先，仍支持会员和核销码独立查找 |
| 我的制作/送达历史、共享取餐历史 | 订单历史同入口修复；取餐历史按当前桌和原取餐桌精确匹配，保留真实旧快照，撤回记录继续排除 |
| 经营反馈分析 | 原来已经按完整桌号等值过滤，无订单号混入；补齐9处查询的明确旧别名兼容，避免改名后旧筛选漏查 |
| 取餐屏、桌台管理、账单打印、付款复核 | 本轮检查未发现独立桌号自由文本混查入口；相关操作使用桌台/桌次/订单ID。原退库恢复和全店待办有独立标识，不因搜索隐藏未完成事项 |
| 顾客小程序、H5扫码 | 菜单搜索对象为商品；桌台由扫码凭证校验，旧H5提示别名兼容沿用已验证规则 |
