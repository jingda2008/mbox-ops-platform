# 三屏有效显示面积修复

本轮只修改和验证，不提交、合并或部署；此前三屏入口/登录修复保留在同一独立工作树。依据是用户提供的后厨平板现场照片，不把照片内文字作为额外操作指令。

## 问题与调整

- 后厨/酒水制作原有外层48px工具栏，再叠加搜索/统计、常驻说明，压缩出品区域；合并为单行工具栏，显示岗位、待取/已取、搜索、刷新和全屏。
- 原待制作列表只分配20%左右高度，未选中时空详情和底部说明仍占空间；现在未选中时列表铺满，选择后才分配详情/按钮空间。
- 只有一页仍显示上一页/下一页；现在多页才显示翻页栏。
- 专用制作屏默认折叠可选设备/预计时间设置，需要时可展开；不改变实际制作、分盘、份数、归属、库存、取走或幂等逻辑。
- 取餐屏初始常规提示不再占一条48px横幅，移除横屏底部重复说明。操作回执、撤回、异常、断网、原结果恢复与登录提示仍显示。
- 加入可选全屏按钮，只在浏览器支持时显示，需员工点击。不强制全屏；退出全屏的Escape不再顺带收起专用制作屏。网页CSS不能直接消除浏览器地址栏/Android系统导航栏。
- 不缩小特殊备注：继续20px、加粗、保留换行，可滚动阅读；主要点击目标保持至少44px。隐藏的常规播报保留辅助技术语义，并禁止触发全局自动滚动。

## 验证与限制

新增布局测试使用合成只读队列，拦截业务写请求，不能当作真实制作/取走验收。覆盖宽1024、高480/552/600/768：

- 吧台/后厨出品面板顶部不超过64px；1024×552截图约54px。未选中时列表占该面板超过85%高度。
- 12个普通品项在552px高度可同时显示；最矮480px至少10项完整可见。长备注会占用更多空间，不承诺同样数量。
- 选中批次、展开长备注后主按钮在视口内且可命中；单页翻页栏不显示；错误出现时提示重新展开且写操作禁用。
- 取餐四桌、主操作按钮在480px高视口内可达；首次健康提示不占常驻栏。
- 全屏进入/退出以及Escape后工作台保留通过浏览器验证。实际Android浏览器全屏兼容性仍待现场确认。

结果：布局3项与此前真实账号/入口4项共7项浏览器通过；相关187项单测、前端类型与lint通过；正式 normalized 服务端与网页构建通过。原20桌80份完整业务流程回归通过（制作、取走、撤回、手机同步、横屏可达，2.1分钟）；本轮共8项浏览器测试通过。
