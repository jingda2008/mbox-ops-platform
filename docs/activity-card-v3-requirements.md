## 1. 目标与首期范围

目标：顾客提前选好并付款，门口连续核销和发牌，厨房按岗位单制作，服务员对牌送餐；运营提前设置菜品时段，系统自动控制入口与交易，异常由领班协调。普通兴趣卡由后台简易建立，顾客在小程序一键申请，后台一键审批成功即有效持卡，随后按卡享受关联权益、查看并购买适用商品。

| 需求 | 统一口径 |
|---|---|
| R1 扫码入口 | 放在员工“全部”内；进入一次后连续使用，不要求放到首屏。 |
| R2-A 退款后重报 | 全额退款成功、原相关权益结束后，满足报名条件可以重新报名；保留原记录。 |
| R2-B 报名后加购 | 支持活动套餐和单点菜品；新增套餐每份新号，单点关联明确号码。 |
| R3 套餐人数 | 每份设置最多 N 人，顾客填写 1～N 人；套餐份数、预留名额、预计人数、实际到场分别计算。 |
| R4 按菜品出单 | 餐饮核销成功后，按套餐实际菜品向对应厨房或吧台打印机出单。 |
| R5 每份套餐一号 | 使用简单自然数字；一份套餐一号、一块牌、一个收餐点，按号送餐。 |
| R6 菜品定时供应 | 普通菜品、活动单点加购及兴趣卡指定菜品支持指定时间可见、可售；复用既有兴趣卡菜单和权益规则。 |
| R7 兴趣卡简易申请审批 | 后台建立并开放普通兴趣卡 → 小程序一键申请 → 授权人员一键通过 → 有效持卡并取得关联权益资格。无需额外社交关注、付卡费、实体领卡或二次激活。 |

### 1.1 适度开发约束

- 复用现有订单、支付退款、库存、员工权限、菜品、兴趣卡专属菜单、打印与取餐流程；只补满足本稿所需的字段、判断和入口。
- 兴趣卡复用原卡项目、会员账户、申请、审核、持卡和商品关联；简化现有入口与前置条件，不新建另一套会员、审批引擎或发卡平台。新普通兴趣卡资格以第 4.6 节为准，不能笼统“沿用原条件”而重新带入社交关注门槛；其他卡类型不因此改规则。
- 时间设置共用一套判定方式；兴趣卡默认继承商品时段，确有差异时在现有专属菜单关联中设置本入口时段，不按持卡人建立个人排程。
- 正常员工操作限于必要的扫码、份数与到场核对、餐饮核销、发牌、实际制作及批次取走。系统自动带出订单和菜品信息，不要求逐单选择姓名或填写原因。
- 异常复用原查询、补打、撤回、售后与操作记录，不建设独立异常工单平台。
- 首期不增加：动态定价、复杂节假日规则引擎、每人一份独立行程、逐人实名、复杂转赠、定位地图、自动派送调度、离线核销账本、手机二次送达确认、按人数自动增减菜。
- 按时间开售、停售及隐藏不是厨房统一开餐调度；首期以餐饮核销后即可进入制作队列为主，不另建统一开餐调度系统。
- 下面的验收场景用于核对业务结果，不表示每个场景都需要新页面、新模块或一套独立自动化系统。

## 3. 权益、人数与状态必须分清

### 3.1 入场和餐饮是两项使用记录

- 同一扫码页可以同时办理入场登记和餐饮核销，但两者效果独立。正常顾客一次确认可同时完成；只入场时不生成餐号、不出制作单。
- 入场登记累计实际首次入场人数，晚到者只增加本批新到人数，再次入场不重复累计。
- 同一次入场登记只累计一次实际人数，超时查回原批次；多设备同时补到时合计不得超过该份剩余入场额度。一并办理入场和餐饮时分别恢复原操作的结果，只续办未完成部分，不因餐饮重试又增加一次入场人数。
- 餐饮按套餐份数核销，一份只有一次有效制作来源。先到者决定现在取用整份套餐时，整份开始制作；后到成员不会再次获得一套餐。
- 餐饮核销结果、原号码与应有制作明细必须能一致建立或可靠恢复。核销成功但制作任务缺失、仅部分岗位建立时，按原核销原号补齐缺失部分，已有任务不重复建立；页面显示待恢复的具体问题，不能要求顾客重新核销或无记录地漏餐。
- 含入场套餐即使餐饮尚未核销，只要已经有人使用入场权益，就不能走“整份未使用”的普通退订申请，应转原售后核定。
- 纯加餐不新增入场资格；其人数是该份用餐人数，不重复累计活动参加人数。

### 3.2 人数与容量

- 每份人数上限为正整数；顾客填写 1～N，N=1 时直接为 1，不接受空值、小数、负数或超限。
- 多份套餐分别记录人数，避免一个总数无法对应各份权益。
- 例如两份各最多 5 人的入场套餐分别填写 3 人、2 人：购买 2 份、预计 5 人、预留 10 个名额，餐饮核销后获得 2 个号；实际到场按真实批次登记。
- 预留名额、套餐可售份数、实际菜品库存分别控制；活动名额还要考虑同场其他业务，不因顾客少填人数超售入场承诺。
- 在已购入场额度内补到不临时加价或加菜；超额必须获得新的有效资格。
- 退款或取消只释放实际取消的未使用权益对应名额；补偿退款、已经入场或仍可再次入场的权益不能自动释放为可再次出售的名额。
- 上限预留减少门口协调，但会降低可售数量，这是确认方案的明确经营成本，不视为真实到场人数增加。

### 3.3 状态记录与员工操作

| 事实 | 记录要求 | 不增加的操作 |
|---|---|---|
| 支付、退款及其结果 | 沿用原交易与售后记录；结果不明先查询原交易 | 不靠付款截图认定成功，不重新收一遍解决不明状态 |
| 入场使用 | 已用、剩余额度及实际首次到场批次 | 不逐人填姓名，不把预计人数自动当已到场 |
| 餐饮核销 | 每份的核销结果、原号和有效制作来源 | 重试不重复核销 |
| 发牌 | 待发、已发、归还或异常 | 发完后“下一位”同时记录本次完成，不逐牌再确认 |
| 打印与制作 | 按岗位保留任务、出纸结果、实际完成数量 | 出纸不当作做完，补打不增加制作数量 |
| 取走及异常 | 按实际批次确认已取数量，异常退回另记 | 不增加手机送达确认，不把已取当成顾客签收证据 |
| 收餐关系 | 原号对应的有效持牌状态和收餐区域 | 暂时取完所有菜不自动结束后续加购 |

订单、菜品、号码、时间和可确认的操作者自动带出。公共屏无法确定个人时，追溯岗位与批次，不编造个人归属；正常服务不逐单选员工。

## 4. 菜品指定时间可见、可售（新增 R6）

### 4.1 三类时间不能混用

| 控制对象 | 时间控制的含义 | 到期后仍保留 |
|---|---|---|
| 新商品入口可见 | 顾客能否在菜单、活动加购、兴趣卡专属菜单中看到适用条目 | 已购订单、历史菜品明细、已领券、售后及员工履约查询 |
| 新购买可售 | 是否允许新下单、继续支付或按原权益规则新兑换下单 | 截止前已有效成立订单的制作、取走及售后 |
| 既有承诺履约 | 按订单、活动或券原有有效期、使用时段和内容履约 | 不被新菜单的隐藏、停售自动取消或缩短 |

套餐内承诺的菜品展示属于已购或待售套餐内容，不因单点菜单隐藏而被删掉。活动预售与活动履约安排独立于某道菜当前的单点供应时段。

### 4.2 首期配置方式

- 默认可见时段与可售时段相同，运营只需设置一次；需要提前展示时才开启“提前可见”，填写单独可见时段。可售时段必须包含在可见时段内。
- 时间能力限于指定日期范围、适用星期及一个每日连续时段，可跨午夜。日期、星期、时区等能力优先复用已有日历和商品供应时间；不扩展多层优先级或复杂节假日排程。
- 未设置新时间规则的商品沿用原可见、供应和权限规则；不能因新增字段将全部旧商品关闭。
- 普通菜品及活动单点默认使用商品时段。活动加购还必须满足活动加购起止时间和截止时间，两者取交集。
- 兴趣卡指定菜品默认继承商品时段；确需专属供应时段时，在现有卡项目的专属菜单关联中设置，仅影响该专属入口，不改普通入口的公开价格与时间。
- 商品基础供应时段是所有新交易入口共同遵守的上限。有效可售时间取基础供应时段、该入口可售时段、活动截止及其他适用限制的交集；例如商品 18:00～22:00、专属入口 21:00～23:00，实际只能在 21:00～22:00 新购。交集为空时提示无法售卖，不能误发布；首期不通过专属入口延长厨房供应时间。
- 公共可见开关只控制公共入口，不等于全渠道禁用；兴趣卡入口继续按其专属关联和资格判断。全局禁用、售罄或全局人工停售限制所有新交易，入口自身停售只作用于本入口，到点不自动解除适用的人工限制。
- 时间配置明确影响范围；已有批量编辑能力则复用，没有则先在现有商品或专属菜单编辑页设置，不为本次新增批量排程平台。
- 使用门店时区；本店按 Asia/Shanghai。开始时刻包含，结束时刻不包含，前台按分钟配置，以服务端时间为准。
- 跨午夜明确显示“次日结束”，日期范围与星期均按本次时段开始日判断，范围最后一天允许延续至已声明的次日结束；例如仅设置 10 月 22 日 22:00～次日 02:00，10 月 23 日 01:00 仍在窗口内，02:00 起关闭。活动或权益另有更早绝对截止时仍取交集；权益自然日或营业日计数继续按原规则，不因跨日供应另创计数口径。
- 开始等于结束不能隐含表示全天，全天需明确选择；结束早于开始但未声明跨日、结束日期早于开始日期、可售超出可见等错误配置应在保存前提示。

### 4.3 顾客看见什么、能做什么

- 可见时段外：新菜单入口不展示该适用条目；直接链接、搜索、收藏、再次购买、旧购物车及员工代客下单也不能绕过新交易限制。
- 可见但不可售：展示未开售、已结束或可购买时间，不能提交购买；首期默认同窗时不额外出现预告步骤。
- 已到可售时间：仍须满足上架状态、相应身份资格、价格、库存和原有次数/额度条件；时间到了不会自动解除人工停售、售罄或禁用。
- 顾客页面停留到时段切换、重新进入页面时应更新显示；最终提交与发起支付再次核对。手机时间、旧页面或缓存不能决定交易是否允许。
- 混合购物车里只有部分菜品过期或失去资格时，指出具体条目、保留其他选择，交顾客确认修改；不静默删菜、涨价或拆成多笔扣款。
- 管理端与获授权员工仍可查询隐藏菜品以处理存量订单，但不能用后台代客下单绕过新售卖限制。

### 4.4 兴趣卡指定菜品

- 复用已有兴趣卡专属菜单中的指定菜品、启用状态、专属价格；新普通兴趣卡的持卡资格按第 4.6 节的一次申请审批流程产生，不附加企微、公众号关注等隐藏条件。不是所有会员都能看见或购买专属项。
- 普通兴趣卡已审批生效、未到期、未被授权停用，且相应商品规则允许时，才可按专属入口新购买；停止接受新申请不等于停用已持卡资格，不能把“曾申请过”或待审批当成已经持卡。
- 有多张卡时，只在当前有效、适用时段内且满足条件的专属报价中沿用既有最低价规则；不能取已过时段或失效卡的最低价。
- 每笔使用兴趣卡权益的订单明确一个权益会员：本人下单默认本人，授权代客下单使用已确认顾客的既有会员身份。资格、卡价、额度扣减和退款恢复均归该会员；餐号只决定送到哪里，付款人、员工账号或餐号所属人不自动成为权益会员。不新增同行人实名、每单审批或多人权益拼用。
- 按已确定 D05，首期只对明确关联的单点商品使用既有卡价与原有优惠规则；活动套餐不自动享卡价，不根据套餐内某道菜的卡价打折整套，不新增优惠叠加机制；旧已售优惠承诺保留。
- 专属资格失效但菜品仍公开售卖时，可以展示公开入口及价格，由顾客重新确认；不能无提示按更高价格付款。
- 兴趣卡不自动等于免费、不自动发券、不新增每日领取次数、不代表不限量。免费商品券、固定兑换价、限次等只在既有对应权益明确提供时适用。
- 卡定向发券、已领券兑换与专属菜单购买是不同流程。已有券按原指定商品、价格、有效期、日历、次数及资格条件处理，不能把新专属菜单资格直接套在所有旧券上。
- 合法已发券不因停发、撤卡或新菜单隐藏而被删除；能否继续使用依原券条件，不承诺所有旧券退卡后均无条件有效。
- 时间窗口重新开放不会重新赠送次数，也不会恢复已用额度。领取失败、重复提交、退款或撤回，沿用原权益回退规则，不能额外返一次权益。
- 若已有券通过本次新增入口发起新的商品兑换订单，新订单受适用供应时段约束，前提是不追溯收紧原券承诺。无法兼容的规则调整应只用于新活动或新权益，不直接覆盖旧承诺。

### 4.5 截止时间与支付

- 新下单和支付发起均需在允许时段内；待付款截止取原订单支付期限、相关可售截止、活动截止及本次专属报价或必需资格的已知到期时间等适用上限的最早时间，页面明确倒计时。
- 超过截止的未付款订单不能继续发起支付；已发起但结果不明的交易先查询原渠道结果，不把页面超时直接当支付失败。
- 支付已经有效发起后，临时停售、撤卡或改价阻止后续新的支付发起，不追溯改写该次已确认的价格、资格和原支付截止。这里的“已发起”以后台记录的原支付请求为准，仅打开页面或提交过购物车不算；仍按渠道实际结果及原截止判断。确实无法履约时转原售后，不静默丢单、改价或再收费。
- 到期复用原关单机制，确认未付款并完成关单后，释放该单原库存和名额等预留一次；支付结果不明先核实，不盲目释放。重复到期处理、关单与回执并发不能重复释放、扣减或占用；无法确认的由收银接手，不新建另一套预留系统。
- 以支付渠道核实的实际成功时间判断是否按时支付。截止前成功、截止后回执到达，仍按有效订单履约，不能仅因菜单已隐藏而丢单。
- 若核实实际支付已超过允许期限而渠道仍实收，进入收银异常处理，默认不自动进入制作；通过原交易核查和既有售后流程明确履约或退款，不能无记录收钱或同时重收、退款。
- 零金额权益兑换以原系统确认接受兑换的时刻判断；保留同一次请求结果，失败不消耗有效权益，重试不重复扣次。
- 时段结束、人工停售或规则调整，不能自动取消已有效支付、已接受兑换或已建立的制作任务。
- 不新增“自动跨时段排队下单”，时段外顾客不能先付一笔不明确何时出餐的钱。

### 4.6 兴趣卡简易建立、申请、审批与使用（新增 R7）

适用范围：按已确定 D04，首期用于本次新建的普通兴趣卡，已有项目默认保持原规则。复用原有数据和权限；现有卡的历史记录、已发券、已购订单不批量改写。后续确需切换的旧项目须单列名单及原承诺后处理，不属于本次默认批量改造范围；其他联名卡、付费年卡等不因本项需求自动改变。

基础口径：是否接受新申请、某位会员的持卡资格是否有效、具体权益是否有效分别判断。长期表示没有预设到期日，不填任意远期日期代替。新建普通兴趣卡自动采用明确的简易流程规则，旧项目保留原规则，不靠创建日期或缺省字段猜测；不增加运营需要选择的复杂模式页面。

#### 4.6.1 后台简单建立

- 在现有兴趣卡管理页提供简洁的建立入口，卡名必填；介绍、封面可选并可用默认样式，不要求先设计卡面或填写复杂申请表。
- 按已确定 D01，新普通兴趣卡持卡资格默认长期，可选项目统一到期时间；具体权益仍按各自有效期和已公布规则。设置截止时必须晚于当前时间，不用新默认值延长或缩短旧卡承诺；长期持卡不等于永久固定价格、无限次数或永久免费。
- 持卡期限在审批成功时确定并向客户展示；之后修改项目的默认期限只作用于后续审批，不追溯改写已发卡期限。确需停用已有卡时使用原授权管理操作并记录原因，不能靠改默认值悄悄撤卡。
- 在同一管理流程选择已有权益、指定商品及相应价格，商品时间默认沿用第 4.2 节；权益关联在卡项目上配置一次，不在每次审批时重新选一遍。
- 可以先保存草稿再补权益。开放申请前清楚展示持卡能获得什么；未配置的权益不作承诺，不虚构免费、折扣或领取次数。卡介绍可公开说明“指定商品按时段开放”，但实际专属商品条目及报价仍同时满足可见时段和持卡资格才展示，不能借卡介绍绕过隐藏规则。
- 提供一次“保存并开放申请”操作；有相应权限的人员可完成建立并开放，不强制另找第二个人审核卡项目。申请人的审核仍由有审核权限的后台人员执行，可由同一运营人员兼任。
- 新普通兴趣卡的建立、开放申请、配置专属商品、提交申请、审核发卡和后续使用均不以绑定企微、配置服务号或客户关注为前置。
- 不新增付费开卡、充值、卡等级、积分升级或自动审批规则；商品购买是否收费仍按已配置价格。

#### 4.6.2 小程序一键申请

- 在现有“我的卡/兴趣卡”入口展示可申请卡及公开权益说明，不要求客户知道内部项目编号或找工作人员代申请。
- 按已确定 D02，全部已登录且具有正常会员身份的客户均可申请；点击一次“申请”即提交，自动关联本人已有会员资料，不重复填写姓名、手机号、理由或上传材料。是否通过由后台审核决定，不新增邀请码或分人群申请入口。
- 未登录或尚未完成基础入会确认时，仅复用必要的登录/入会授权，完成后回到同一次申请流程；不能跳多个配置页，也不能顺带勾选营销授权或强制关注。
- 申请成功显示“待审批”，原按钮不再重复提交。未审批期间只能看卡介绍和公开说明，不获得专属购买资格；公开商品仍按公开规则正常购买。
- 同一会员在同一卡项目下最多一张有效卡；待审时显示“审核中”，已有效持卡时显示“查看权益”，重复申请返回原结果。不同卡项目可以分别持有，不能因为有一张其他卡就阻止申请。
- 按已确定 D03，后台拒绝时展示简短原因；普通拒绝可在项目仍开放时重申，自然到期仅在项目仍开放且有新的有效期时重新审核，不自动续期。冻结恢复原卡，管理员撤销须先核查原原因，再沿用现有支持的恢复或重申路径；原流程不支持直接恢复撤销卡时，允许重申后再一次审核，不新增状态回滚能力。历史与已用额度保留，不能反复申请绕过处理。已有主动退出能力沿用原流程，不新增退出或申诉系统。

#### 4.6.3 后台一键审批即有效持卡

- 待审批列表直接显示申请会员、卡名、申请时间及现有必要信息；正常操作点击一次“通过”，无需强制备注、再次确认、另行发卡或再次激活。
- 一键申请不等于自动或立即通过。运营在现有待审列表安排审核人员与处理时段；顾客等待时可查待审状态，不要求门口核销员临时逐个审批，不新增催办、升级或消息通知系统。
- 同一次审核成功必须同时形成有效持卡记录、关联预先配置的权益资格，并返回原卡结果；不能出现“已通过，但还需要另点发卡才能使用”。
- 审批操作者、时间和结果自动留痕。无审核权限的账号不能审批；客户只能申请和查看本人的卡，不能提交自己已获批的状态。
- 审核失败或超时查回同一次结果；未确认成功前不显示有效持卡。若已成功则恢复原卡，不重复审批或发新卡。
- 必要的持卡资格关联失败时不能宣称审批和权益全部可用，应由后台恢复同一次申请；实际发券属于已配置权益的后续任务，发券失败按下文单独恢复，不与有效持卡结果混淆。
- 多名审核人同时处理、客户重复点击、网络重试，都只能产生同一份有效持卡结果，不多发卡、不重复发同一入卡奖励或增加额度。
- 审核时卡项目已过有效截止或存在明确停用原因，不得显示“通过并有效”；给审核人具体原因，保留申请供处理，不要求客户无记录地重来。
- 拒绝、停用或撤销使用现有入口并记录简短原因，不建设多级审批或独立工单；普通通过不强制输入原因。

#### 4.6.4 持卡后的权益与商品

- 审核成功即取得该卡资格，小程序申请页、卡包和菜单在返回前台或刷新后同步显示；不要求员工再手动绑商品、客户再领取实体卡或点击激活。
- 持卡后自动关联卡项目已配置的权益资格，按照原权益的次数、价格、有效期和使用方式享受；没有配置自动发券就不自动赠券或免费点菜。
- 如果已配置入卡发券，复用现有发券流程并保证同一奖励只处理一次。发券异常单独显示并恢复原任务，不撤销已成功持卡、不让客户重申或后台重审来补券。
- 同一奖励及已用额度以原会员、奖励规则和适用计数周期识别，不因新的申请或持卡记录重新起算；原规则允许的新周期权益仍可正常获得，不能把“防重复”误做成永远不再发放。
- 专属菜单和新下单按有效持卡、指定商品、可见/可售时段、库存、价格及既有权益限制共同判断。审批即持卡不代表所有商品全天展示、随时可售或必有库存。
- 已持卡但当前非供应时段时，卡包仍显示有效持卡，并给出当前不在供应时段等状态，不能让客户误以为审批失败。卡介绍不等于提前开放专属商品交易。
- 新普通兴趣卡不因未关注、取消关注、企微关系变化或社交同步失败而冻结、撤销或失去专属商品资格；这与另有明确社交任务条件的其他权益分开判断。
- 卡到期或被授权停用后，停止该卡支持的新专属购买；已有效发起的支付按第 4.5 节核查，原已付款订单及合法已发权益按第 4.4 节处理。是否可重申或恢复按 D03；不得通过换卡记录重置原周期已使用额度或重复领取同一奖励。
- “停止新申请”只关闭新的申请入口，已提交待审申请仍可按项目有效条件处理，已有有效卡不受影响；真正停用持卡权益须通过独立明确的原管理操作并说明影响。
- 审批结果以小程序页面可查询为准，不新增短信/消息通知系统，也不把消息送达当成持卡生效条件。

#### 4.6.5 正常流程与责任

| 环节 | 负责人 | 最少正常操作 | 完成结果 |
|---|---|---|---|
| 建立并开放 | 有卡管理权限的运营人员 | 填卡名，确认有效期和关联权益/商品，保存并开放 | 小程序有清楚的可申请入口 |
| 提交申请 | 顾客本人 | 已登录会员点一次“申请” | 本人有一条待审申请，无重复表单 |
| 审批 | 有卡审核权限的人员，可由同一运营人员兼任 | 点一次“通过” | 同时有效持卡，资格自动关联 |
| 享权益和购买 | 顾客本人 | 进入卡包/适用菜单，按原领取或下单方式使用 | 按资格、时段、库存和价格执行，无再次激活 |
| 异常处理 | 卡管理员；资金问题仍交收银 | 查询原申请、原卡或原权益任务，处理具体失败项 | 不通过重新发卡制造重复权益 |

## 5. 报名、加购与退款

### 5.1 报名与重新报名

- 购买时保存套餐份数、人数上限、固定菜品、价格、入场额度和有效使用规则；后改配置不静默改变已购内容。
- 新活动全额预付；旧活动、旧订金单和旧按人承诺按原约定兼容，不混入新套餐默认计算。
- 原报名全额退款成功且相关权益结束后，允许重新报名，重新检查活动开放、名额、库存、价格、限购和时间。
- 新旧报名、付款、退款及凭证可区分；不删历史，不把旧订单直接改回未报名。
- 退款中、部分退款不等同整单已退；原有效部分仍可使用。旧回执不能覆盖新报名结果。
- 旧已退款凭证不得兑换原权益；名额不足时如实提示，不承诺自动保留原名额。

### 5.2 加购与号码归属

- 顾客在活动详情、我的活动或原套餐中可继续购买允许的套餐和单点，提交前显示价格、时段和归属。
- 默认原参加者加餐；新增参加者通过独立入口使用剩余额度或购买新增资格。纯加餐套餐可以填写 1～N 用餐人数，不再次统计活动人数。
- 单点从某份套餐进入时自动关联；只有一份可直接默认，多份通用入口由顾客选择。未核销先关联套餐，核销后沿用生成的号。
- 核销前已付款的关联单点随本份餐饮核销一起进入制作；核销后对仍持有效牌的原号，已付款单点只出本次增补单。
- 新增套餐每份另行核销发新号，可在就近服务点完成。只有活动票者首次单点也在服务点办理餐饮核销并领独立号，后续单点沿用。
- “领牌前不主动出单”指尚未到服务点完成餐饮核销的首次单点或新套餐；餐饮核销成功后立即建任务并打印，随后发牌，不再追加开厨审批。
- 已核销却尚未实际拿到牌属于待发牌异常，保留原号、原任务，查回续办；不能再次核销或自动再做一份。
- 牌已归还、顾客离场或收餐关系关闭时，不直接接受以原号即时制作的新加购；在原服务窗口内先恢复该套餐原号持牌关系。恢复前核对原号仍唯一可用，跨日已被其他套餐使用的号码不能重新启用，有冲突交领班落实有效收餐安排。新套餐仍单独新号。
- 普通兴趣卡点餐沿用原桌台、订单或取餐归属；仅增加时间控制不自动让顾客报名活动，也不强制所有兴趣卡购买改成活动发牌流程。
- 兴趣卡单点若关联活动餐号，还必须同时符合活动允许加购的菜单与截止、商品供应及持卡条件；同一项只走一条制作流程，不能同时作为普通桌台单和活动增补单重复出餐。餐号不改变第 4.4 节的权益会员，也不凭卡补出活动入场资格。

### 5.3 退款和停止制作

- 商品所含权益均未使用时，顾客可一键提交整份退订申请；原审核按已公布退订条件复核，再沿原渠道执行。首期不增加自动审核退款；页面明确区分申请待审核、处理中与退款成功，不把申请提交当作退款到账。含入场套餐同时检查入场与餐饮，纯加餐只检查其餐饮权益；多份只退其中一份，其他有效内容不受影响。
- 退款前检查依赖该套餐核销或收餐的已付款未完成加购。有此关联时转现有售后，由顾客确认一并按规则退款，或保留并落实有效的核销、收餐安排；若同时退掉入场资格，保留餐单不代表仍能进入活动。不能把加购留成无法核销的孤立订单，也不能擅自退款、自动迁到重新报名的新套餐或重复制作。其他不依赖该份的有效订单不受影响，此异常不新建拆单或迁移平台。
- 已入场但未用餐、已制作或部分取走的情况，转领班与授权收银，按实际已用与可停止内容核定，不能一概拒退或一概全退。
- 退款处理中暂停对应取消范围的新使用；取消未成立或退款失败时先核对资金、权益和制作事实，再决定恢复，不自动重做。
- 厨房收到取消时反馈实际已做、未做和可停止范围；退款成功不代表厨房已经停做，补偿退款不代表全部入场和餐饮权益已取消。
- 菜品退款金额沿用已付款及原优惠分摊规则，普通服务员不现场拆算；不因此新建复杂退款定价系统。
- 重新报名、支付重试、退钱、释放名额及库存各有原记录，不因同一回执或重复操作执行两次。

### 5.4 退款状态展示与入口名称（补充确认）

后台说明区分新旧报名。新版显示“顾客可在小程序申请符合条件的整份退订，申请统一进入本页审核。员工代办的退款须由另一名有权限的员工复核。”旧版报名仍提示“请联系门店办理”。活动相关说明统一使用“收银与退款 → 活动收银”。

## 6. 岗位职责

岗位是责任划分，不要求每行新增一名员工；允许兼岗，开场时落实，交班时移交。

| 岗位 | 正常负责 | 异常负责与权限 |
|---|---|---|
| 运营/活动发布人 | 配套餐与价格、入场额度、菜单与时段、兴趣卡适用菜单、核销和退款规则 | 开售前修复配置冲突；不追溯削减已售权益 |
| 兴趣卡管理/审核，可由运营兼任 | 简易建卡并开放、维护关联权益和商品、按排班处理原待审列表，一次通过发卡 | 按权限处理重复/失败申请、拒绝和停用；不要求正常申请再加企微、关注或二次激活，不把正常审核转给门口队伍 |
| 门口核销兼发牌 | 连续扫码，核对本次权益、实际到场、核销份数，按号交牌 | 结果不明查原操作；争议转领班，不当场算退款 |
| 后厨/吧台 | 按本岗有效单制作，标明实际完成数量 | 报告缺菜、打印故障、可停止或需重做内容 |
| 出餐统筹 | 按号合并现成菜品、核对本批实物、一次确认取走 | 接退回餐、核对漏项重复、保留断网处理记录 |
| 送餐员 | 对照本批号码和菜品到固定点送餐 | 无人接收、错送、洒漏及时交回统筹；正常交餐不再点手机 |
| 值班领班 | 开场检查、责任分配、异常协调、增援、结束移交 | 接手发牌、位置、缺菜、积压和售后争议，决定暂停新销售 |
| 授权收银/售后 | 核查原支付、尾款、退款与差价 | 处理支付超时实收、退款冲突；按权限操作，不凭截图判断 |

异常至少有原订单/权益、号码、发生阶段、必要数量、已做动作和接手岗位。已有信息自动带入，现场只补缺失事实；普通员工不逐单填大表。

## 7. 统一正常流程

### 第 0 步：开场前配置与检查

主责：运营、值班领班；协作：各制作与核销岗位。

1. 核对活动名额、套餐份数与固定菜量、加餐价、库存、截止时间、退款和再次入场规则。
2. 配菜品可见/可售时间及兴趣卡适用范围；查看本次营业时段内哪些条目可见、可售，防止只到点可见却没有岗位能做。
3. 检查各菜品打印岗位与设备、号牌数量和数字范围、区域标识、备用网络、电源与纸张。
4. 明确同一任务以本岗有效单为制作依据，汇总票只核对，不作为第二份制作指令。
5. 落实核销与异常处理分流、出餐统筹、售后权限，以及兴趣卡审核负责人与处理时段。存在重要缺项先处理，不靠高峰时口头补规则。

完成条件：可出售的内容有人做、能正确出单，有足够唯一牌和明确收餐点。

### 第 1 步：顾客选择与付款

主责：顾客自助；配置支持：运营；异常：收银/领班。

1. 按适用时段与资格展示菜单、活动套餐或兴趣卡指定菜品。
2. 选择套餐份数、每份人数、固定自选项；单点确定归属，新增参加者明确入场额度。
3. 显示价格、支付截止和使用规则，顾客确认付款；卡权益自动归本次明确的权益会员，不从餐号或代客员工推断。
4. 时段、资格或库存变化时提示具体原因，保留其他选择；结果不明查询原付款。

完成条件：形成可查询的有效报名或购买；不能把仅建单当已付款。

### 第 2 步：门口连续扫码与核销

主责：门口核销员；异常：领班/授权收银。

1. 从“全部”进入一次，留在扫码页连续办理。
2. 扫码查询，核对活动、已购套餐、付款及可用权益；查询不触发使用。
3. 确认本次首次入场人数和要开始制作的套餐份数。多份不默认全核销；仅入场不出餐。
4. 正常一并办理时一次确认完成本次入场与餐饮核销，返回每份原号及任务状态；超时查回原批次与原号，入场人数也不重复累计。
5. 晚到者只补入场，重新入场只检查原入场凭证，不再次制作。

完成条件：实际入场、餐饮份数各自准确；结果不明的份数未被当作成功。

### 第 3 步：对号发牌

主责：核销兼发牌员；异常：领班。

1. 按成功结果逐份取牌、核对；两份套餐发两块不同牌。
2. 提醒明显摆牌、固定收餐点和保留至结束用餐。
3. 发完本次牌点“下一位”，同时记录发牌完成；转异常或中断时保留待发情况，不把跳过当已发。
4. 成功核销即有制作任务，不因发牌页停留再加一轮开厨确认。

完成条件：号、牌、套餐一致；未发到手的能查回续办。

### 第 4 步：分岗位打印与制作

主责：后厨/吧台；协调：出餐统筹。

1. 按菜品路由出票，醒目显示号码、套餐/来源、菜品数量、选项及必要备注；与普通桌号有清楚标识。
2. 每个岗位只做自己负责的菜，不把库存原料清单当菜品单，不把汇总票重复做。
3. 一份套餐按固定菜量制作，不乘以填写人数；同款两份分别对应两个号。含餐但无需制作的套餐不打空制作单；纯活动票仅办理入场，不凭空生成餐号。
4. 加购单只包含新增内容；各岗位交出本批实际完成菜品与数量。
5. 打印不再次扣库存；预留、消耗、重做沿用唯一业务来源，不叠加两套扣减。
6. 若核销已成功但任务尚未完整建立，恢复原核销应有的缺失明细，再沿用打印流程；不重新核销或重复已有岗位任务。

完成条件：实际菜品与有效任务一致，未做、停止和异常内容仍可追溯。

### 第 5 步：出餐汇总与取走

主责：出餐统筹；接收：送餐员。

1. 同号已完成菜品尽量合并，允许饮品先送，不等最慢菜。
2. 核对实物后一次确认本批实际取走数量；其他人只能领剩余未取数量。
3. 不选员工姓名、不增加手机确认；登录可确认的自动记录，公共屏追溯岗位批次。
4. 取走表示本批业务完成，不代表系统已有顾客签收证据。

完成条件：本批拿走什么、多少、哪个号清楚；剩余内容未被一起结清。

### 第 6 步：按号送餐

主责：送餐员；异常：出餐统筹/领班。

1. 按收餐区域找到实物牌，对照号码、菜品与本批数量交给接餐人。
2. 一号只送约定位置；同伴分散时由接餐人集中接收。
3. 正常交餐后不追加手机确认；找不到人、错送、洒漏则转明确异常处理。
4. 仍需后续菜品或加购时继续保留号牌，不能第一道菜送出就收牌。

完成条件：实物交给正确对象，或已交回有负责人接手的异常位置。

### 第 7 步：活动中加购

主责：顾客自助；新牌办理：就近服务点；制作和配送沿用第 4～6 步。

- 菜单按当前时间与资格展示；满足活动截止、供应时间、库存及付款条件才接受新单。
- 有效原号上的单点自动出新增单，员工不再批准一次。
- 新套餐及无套餐者首次单点，先在服务点餐饮核销领牌，再沿用同一出餐流程。
- 号码已关闭或无实际收餐关系，先恢复持牌关系，不让厨房向无人持牌的号盲目出餐。
- 普通兴趣卡顾客按原点餐流程；关联活动号时同时满足活动加购规则，只进入一次制作，不另向普通桌台重复出单。

完成条件：新增内容有明确有效收餐对象，原订单不会重复出餐。

### 第 8 步：收牌、交班与结束

主责：服务点、领班；协作：统筹和收银。

- 顾客结束用餐或离场归还牌时，关闭新的即时加购收餐关系；原号不分给其他套餐。
- 有已付款未完成内容时先处理或交接，不能用收牌自动取消。
- 交班移交未发牌、打印结果不明、未制作、已做未取、交付异常、退款冲突及断网期间已处理任务。
- 活动结束、跨日、设备重启或菜单停售不能清空这些任务。
- 顾客再次加购时按第 5.2 节核对服务窗口与号码唯一性，再恢复原套餐原号持牌关系，不重新生成一份原套餐；新增套餐另领新号。

完成条件：所有未结事项有下一步与接手人，号码没有被错误循环使用。

|---|---|---|---|
| E01 | 无效码、错活动、无资格、已退款 | 查询原因，不发号不出餐；核实真实有效权益后才办理 | 核销员 → 领班 |

| E20 | 兴趣卡失效、次数用尽、旧券或旧订单被隐藏规则影响 | 新购买按有效条件判断；旧权益按原承诺查回处理，不新赠次数、不删除合法历史 | 服务点 → 领班 |
| E21 | 制作/配送积压、活动临时取消 | 负责人暂停必要的新加购并沟通，安排已售内容履约或售后；不能删掉积压 | 领班 |
| E22 | 规则调整影响已购或已发权益 | 修改前提示影响，旧承诺不能直接覆盖；必要时新建后续活动或规则适用范围处理 | 运营/领班 |
| E23 | 兴趣卡重复申请、重复审批或多名审核人同时处理 | 查回同一申请/原卡，同会员同项目最多一张有效卡，不重复发同一奖励或加额度 | 卡审核人员 |
| E24 | 审批失败、超时、资格关联或入卡发券异常 | 查原结果；必要资格未建立不能显示全部成功，续办原申请。卡已有效但发券失败只恢复原发券任务，不重申、重审、重发卡 | 卡管理员 |
| E25 | 停新申请、项目到期、拒绝、卡到期或撤销 | 分清停止申请与停止持卡使用；停申请不影响原有效卡，过期项目不误发有效卡，拒绝及撤销原因可查，旧订单和权益按原承诺处理 | 卡管理员 |
| E26 | 新普通兴趣卡被关注条件拦住或无权限者尝试审批 | 前者属于不符合本稿要求，查原卡恢复正确资格，不要求客户补关注；后者拒绝操作并留原记录，不通过前台状态绕过审核权限 | 卡管理员 |
| E27 | 主套餐退款但关联加购尚未完成 | 退款前转原售后，顾客确认退款范围或保留的核销、收餐和入场安排；保留原记录，不擅自迁单、重复制作或留孤立订单 | 领班/授权收银 |
| E28 | 代客下单用错会员，或卡单同时进入桌台和活动流程 | 未付款先纠正身份及报价并让顾客确认；已付款查原权益会员和制作来源，按既有售后恢复实际应扣/应退内容，不因餐号换人转移权益，不重复出餐 | 服务点 → 领班/收银 |
| E29 | 入场确认超时、重复登记或多设备同时补到 | 查原入场批次，只续办尚未完成的操作，不重复累计；并发合计不能超剩余额度，争议由领班核对实际入场 | 核销员 → 领班 |
| E30 | 餐饮核销成功但制作任务缺失或部分建立 | 按原核销、原号和应有菜品恢复缺失任务，复用原恢复机制；已有任务不重建、不要求顾客再核销，领班接手无法自动恢复的异常 | 领班/出餐统筹 |

## 9. 验收标准

以下为开发后的验收标准，本轮未执行功能测试，不代表已实现。Q01～Q20 与 D01～D05 均按本稿确定规则验收。可以合并场景演练，避免为验收本身另建系统。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 从“全部”进入后连续办理多位顾客 | 只进入一次；核销、发牌、下一位在同页流程，结果不快速消失、不串人。 |
| A02 | 只查询会员、普通入场、无效码 | 不生成餐号或制作单；普通会员码不授权领取全部套餐。 |
| A03 | 扫码错误、摄像头坏、迟到响应 | 可手工查询或继续下一位；旧结果不能覆盖当前顾客，查询不误核销。 |
| A04 | 全额退款成功后重新报名 | 重新查名额、库存和价格，可形成新报名，旧历史和失效凭证保留。 |
| A05 | 部分退款、退款中/失败、旧回执晚到 | 原有效权益不误取消，不误判全退，旧回执不覆盖新报名。 |
| A06 | 重复购买、支付重试和重复退款请求 | 同一次操作不重复收费、退钱、扣库存或发权益。 |
| A07 | N=1、N=5，多份分别填人数 | 范围校验正确；两份各最多 5 人填 3、2，预计 5、预留 10、餐号 2，实际到场另记。 |
| A08 | 仅剩 4 个名额购买含最多 5 人套餐，填写 2 人 | 不因填写较少而超售入场承诺；纯加餐不误占名额。 |
| A09 | 在上限内修改、补到或超过上限 | 范围内不临时加价加菜；实际新增入场正确，超过额度需要新资格。 |
| A10 | 原顾客加餐及新增参加者 | 同人不重复计数，先使用剩余入场额度；新套餐仍独立发号。 |
| A11 | 新全额预付及旧订金订单 | 新单付款条件明确；旧约定不被覆盖，疑难补款分流。 |
| A12 | 先入场未用餐、同套餐分批到场、再次入场 | 入场与餐饮独立；晚到和重入不重复出餐，重入不重复累计人数。 |
| A13 | 已入场但餐饮未核销，及纯加餐申请整份自助退 | 前者不能走全未使用整份退订，转核定；纯加餐无入场权益，不因顾客已参加活动就拒绝其未使用餐饮退订申请。顾客一键申请，保留原审核与原渠道执行；申请成功不表示资金已退。 |
| A14 | 退款与制作冲突、补偿性退款 | 实际可停内容明确；不自动释放已用入场名额，不抹掉制作事实。 |
| A15 | 批量核销多份，部分成功或响应丢失 | 成功份数维持原号，只恢复未成功部分，无重复餐。 |
| A16 | 多设备同时核销同份套餐 | 仅一次有效核销、一份制作来源、一个原号。 |
| A17 | 多设备核销不同套餐 | 号码不同、牌不重复；数量 2 的同款套餐仍有两号。 |
| A18 | 套餐含后厨菜与吧台饮品 | 分别正确出纸，号码一致，固定菜量不乘人数，打印不重复扣库存。 |
| A19 | 含餐但无须制作的套餐，及纯活动票 | 前者按规则保留餐饮核销及号码，不打空制作单；纯活动票只办理入场，首次单点再按 A25 取得餐号。 |
| A20 | 部分打印失败、缺纸或离线 | 保留成功核销与原号，仅恢复失败部分，已成功部分不重复做。 |
| A21 | 回执丢失、恢复吐旧票、纸票与屏幕同单 | 可辨认同一制作任务，不因展示或出纸次数增加菜量。 |
| A22 | 补打、重做、备用打印机交接 | 副本与新增重做有区别，实物数量及消耗有来源，不重复处理。 |
| A23 | 原号有效，核销后单点加购 | 时间和付款符合条件后只打印新增明细，不需员工再批准，不重做原套餐。 |
| A24 | 活动中加购套餐 | 就近服务点核销并领新号，每份独立，不要求重新排门口队伍。 |
| A25 | 仅有活动票者首次单点 | 首次餐饮核销生成独立号及制作任务，随后对号发牌；未拿到牌时查原号续办，不重复核销或制作，后续单点沿用。 |
| A26 | 已核销未领牌与尚未核销新单 | 前者查原号续发、不重做；后者未完成餐饮核销时不擅自进入制作。 |
| A27 | 加购付款失败、结果不明 | 原报名正常可用，不按未明确成功的加购出餐，不重复收费。 |
| A28 | 归还牌、同时新增购买、已付款仍欠菜 | 新单不得向失效收餐关系盲目出餐；已有效付款的内容仍交接，不随收牌删除。 |
| A29 | 发错、丢失、无牌、6/9不清 | 有原号查询和唯一备用方案；不重核销，不出现两块有效同号牌交给不同顾客。 |
| A30 | 并行活动、普通餐饮、跨营业日及恢复旧收餐关系 | 同一现场无无法区分的重号；未结号码不因重启或换日被占用；已结束的旧号若跨日被其他套餐使用，不能再恢复为两份有效关系，转领班处理。 |
| A31 | 饮品先送、分批制作和取走 | 只交并结本批实际数量，显示仍欠内容；不选姓名、不加手机二次确认。 |
| A32 | 未送到、退回、错送、误触撤回 | 异常可追溯；已取不冒充实际签收，已交出不能伪造未交接。 |
| A33 | 缺菜替换、自选和特殊要求 | 下单选项到制作单一致，替换经确认并留记录，不静默改菜。 |
| A34 | 顾客分散或移动 | 一号一个收餐点，明确摆牌；找不到人转统筹，不长期无记录巡场。 |
| A35 | 全断网及恢复 | 停新增核销发号；已确认任务处理记录与恢复队列核对，无离线重复账。 |
| A36 | 付款、退款或资格争议 | 有接手人及原记录，正常队伍继续，普通服务员无需计算退款。 |
| A37 | 收牌、交班、停售或活动结束 | 未结任务逐项移交，不自动清空；原号再领不再生成原餐。 |
| A38 | 普通及兴趣卡条目在可见窗口外 | 适用新菜单隐藏，专属商品及价格不通过卡介绍泄露给无资格顾客；可显示通用权益说明，历史订单和权益仍可查。 |
| A39 | 提前可见但未到可售时间 | 仅展示信息和时段，不能新下单；默认同窗不增加额外步骤。 |
| A40 | 开始前、开始时、结束时及跨午夜 | 开始包含、结束不包含；仅设置 10 月 22 日 22:00～次日 02:00 时，23 日 01:00 有效、02:00 关闭，日期范围和星期均按开始日判断，另有绝对截止则取交集。 |
| A41 | 旧页面、搜索、直接链接、购物车、再次购买、员工代客 | 在实际提交和支付发起时再次校验，不能绕过时间、资格或库存。 |
| A42 | 截止前实际支付，截止后回执 | 原单正常确认履约，不因隐藏菜单取消、不重复收款。 |
| A43 | 截止后支付、超时实收、关单与回执并发 | 截止后不再发起支付；超时实收查原交易处理，不自动出餐。确认未支付并关单后只释放原预留一次，结果不明不盲目释放，重复回执不重复占用或退还。 |
| A44 | 混合购物车部分商品过时、资格或价格变化 | 具体提示并保留其他选择，经顾客确认再付，不静默删菜涨价。 |
| A45 | 到点但人工停售、禁用、售罄 | 不自动恢复销售；跨入口共用真实库存，不超卖。 |
| A46 | 隐藏/停售后处理已购、已兑及历史记录 | 原订单、券包、菜品明细、查询与售后保留，既有履约不被清空。 |
| A47 | 活动预售或已购套餐包含当前单点停售的菜 | 按活动承诺展示和履约，不删除套餐内容；开售前核对真实制作能力。 |
| A48 | 活动单点时段与活动加购截止不同 | 两者均满足才可新购，不因某一个开放而越过另一个截止。 |
| A49 | 有资格兴趣卡用户购买指定菜品 | 沿用原专属菜单和价格，满足时段才可新购；不自动免费或赠券。 |
| A50 | 无卡、待审批、到期或被停用的卡 | 不能用该卡专属入口及专属价；公开商品仍按公开规则展示。仅停止新申请不使原卡失效，新普通兴趣卡不因未关注或社交关系变化而失效。 |
| A51 | 多张卡且有效时段不同 | 只从当前有效且适用报价中按既有规则取最低价，不使用过期低价。 |
| A52 | 专属与基础时段交叉、只调卡入口或改用公开购买 | 基础 18:00～22:00、卡入口 21:00～23:00 时仅 21:00～22:00 可新购，交集为空不误发布；公共可见关闭不等于专属入口全局禁用；仅调卡入口不改公共规则，改付公开价须重新确认。 |
| A53 | 窗口关闭再开放、跨日和重复兑换 | 不额外赠次或重置额度，按原会员、奖励规则、日历及计数周期判定，换卡不重新起算；原规则允许的新周期仍可正常取得权益，失败重试不重复扣次。 |
| A54 | 旧券遇到停发、撤卡或新增隐藏 | 历史保留，依原条件核验，不追溯新增持卡或时段限制，也不无条件放行已过期券。 |
| A55 | 修改时段、套餐内容或专属规则 | 新配置影响范围明确，不能静默取消已成立订单或缩短已发权益承诺。 |
| A56 | 错误时段配置 | 日期、跨日、全天和可售包含关系校验清楚，保存前能发现错误。 |
| A57 | 客户手机改时间、切时区、页面停留 | 由门店时区和服务端决定；页面到时更新，旧缓存不能继续有效交易。 |
| A58 | 未配置新时段的存量商品与旧活动 | 既有正常入口、价款和有效权益保持原规则，不被批量关闭。 |
| A59 | 实际手机、门店网络、打印机、灯光与动线整链演练 | 报名/退款重报、加购、兴趣卡时段、核销发牌、各岗出纸、分批取走及按号送餐一致；不能用静态检查代替。 |
| A60 | 按预计集中到客量演练 | 测量门口、制作、取走、找人及异常耗时，依据瓶颈安排兼岗和增援；不预先声称几人或几分钟足够。 |
| A61 | 后台简易建立普通兴趣卡 | 用现有页填写必要内容，可保存并开放，不强制卡面、企微、公众号或另一个人开放；持卡默认长期、可选统一到期，审批后期限明确，改默认期限不追溯改已发卡；草稿和未配权益如实展示。 |
| A62 | 已登录会员及未完成登录/基础入会的客户申请 | 按 D02，全部正常已登录会员可一次点击提交、不重复填资料；未完成基础授权者完成后回到原申请，不强制营销、关注、邀请码或复杂表单。 |
| A63 | 未申请、待审、已持卡的入口与权限 | 分别显示申请、审核中、查看权益；待审只能看介绍和公开说明，不提前获得专属资格。 |
| A64 | 后台正常审批通过 | 一次通过即形成有效卡并关联预配权益资格，不再点发卡/激活或要求实体领卡、付开卡费；正常通过无需填写备注。 |
| A65 | 未加企微、未关注，或持卡后取消关注/关系同步失败 | 新普通兴趣卡仍可申请、审批并有效使用；没有额外社交步骤，也不被自动冻结或撤销。 |
| A66 | 重复申请、并发审批和网络重试 | 同会员同项目只有一张有效卡，恢复原结果，不重复奖励或加额度；不同项目仍可各自持卡。 |
| A67 | 审批超时、必要资格关联失败、审批成功后页面未刷新 | 查原操作并恢复；未完成不得假报有效可用，已成功不得重发；小程序返回前台或刷新后能查到真实卡状态。 |
| A68 | 入卡权益资格、已配置发券与发券失败 | 不需后台逐人再绑权益；只有原配置允许才发券，异常恢复同一任务，已有效持卡不因补券被要求重申重审。 |
| A69 | 拒绝后再申请、到期/冻结/撤销后恢复或重申请 | 按 D03 保留原申请及原因；普通拒绝可在开放期重申，到期须有后续有效期再审，冻结恢复原卡，撤销先核查；不通过换卡记录重置原周期权益或重复发同一奖励。 |
| A70 | 停止新申请与真正停用权益 | 前者只关闭新入口，待审仍可按有效条件处理，原卡正常；过有效截止不误批有效卡，真正停用有权限及记录。 |
| A71 | 越权审批、替他人伪造申请或篡改前台持卡状态 | 均不能获得资格；申请关联本人，审批按后台权限决定，操作者及结果可追溯。 |
| A72 | 审批后尚未到供应时间、售罄或没有配置免费权益 | 卡包仍显示有效卡及正确状态，商品遵守可见/可售与库存，不能因此承诺全天可买或自动免费；按时开放后可按卡资格正常下单。 |
| A73 | 本人、员工代客及同号不同购买人使用卡权益 | 每单权益会员明确，资格、卡价、次数与退款恢复均一致；号码只定配送，不能借员工卡或餐号转移权益，不增加逐人登记。 |

| A75 | 未核销主套餐申请退款，仍有已付款关联单点 | 提前发现关联并转售后；退款或保留安排经顾客确认，保留时仍有有效核销和收餐途径，入场资格另核查，不自动迁新报名、不重做。 |

| 审批通过但仍要手动发卡、绑权益或再次激活 | 有效持卡及必要资格同时完成；预配置权益自动关联，实际发券依原配置，失败恢复原任务。 |
| 停止新申请就让既有持卡人失去权益 | 申请入口与持卡有效状态分开，停申请不撤卡；旧券、旧订单继续按原约定。 |

| 新增建议未定、正文与验收仍写待选 | D01～D05 已获用户明确确认，正文、流程及验收同步采用确定口径；运营具体值单列，原 20 项不重新打开。 |

| 通过换卡重复领奖，或把所有后续周期误当重复 | 用原会员、奖励规则和计数周期识别重复，保留已用额度，也允许原规则内的新周期权益。 |
