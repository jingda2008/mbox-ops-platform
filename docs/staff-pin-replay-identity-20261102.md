# 普通员工创建 PIN 与回执一致性审计（2026-11-02）

对应 RULE-AUDIT-20261102-10、PR #415。本轮只开发、测试、提交和审查，不合并部署；所有写入验证均使用本机临时数据库，没有操作现场桌台或订单。

## 根因与修复

普通创建接口原指纹仅含 `pinConfigured:true`，未绑定 PIN 的值。同一请求键改 PIN 会得到原来的 200/replayed，实际仍只有原 PIN 能验证。这是关键请求字段丢失导致的假成功，不是新 PIN 已覆盖旧 PIN，也不等于权限撤销失效。

现为普通创建加入 HMAC-SHA256 PIN 绑定，使用现有服务端配置密钥，域包含版本、租户、门店、操作人、请求键、PIN。其余公开输入继续参与原指纹。数据库只保存完整指纹的摘要；回执、审计和响应不保存明文 PIN、无密钥的 PIN 摘要或此绑定。随机盐 scrypt 仍仅用于实际登录密码存储，不作为重试等值依据。

同键同内容恢复原结果；同键变更 PIN 返回 409；当前员工授权仍在认领回执之前检查。创建后另行重置员工 PIN，不影响原创建回执身份，也不会使重置后的 PIN 被误认作原创建输入。原生创建/PIN重置/日口令的现有 HMAC、命名空间、持久回执和版本守卫未改动。

## 兼容边界

旧普通创建回执没有原 PIN 的安全等值证据。不能用员工当前 PIN 哈希推断历史输入（可能已重置），也不能补写未知指纹或重新创建。对仍保存且未过期的旧回执，升级后无论提交旧 PIN 或新 PIN 都返回 409，保留原回执和业务事实；管理员需读取已有账号核对结果，确需改密走明确重置流程。现有普通回执 TTL/清理行为未改动，过期后仍按原业务重复账号约束处理。

服务端配置密钥应在实例间保持一致；密钥轮换会令此前绑定不匹配并返回冲突，不会修改已创建账号。原生入口已有相同运维约束。API 注册拒绝少于32字符的配置密钥，不提供固定或空密钥降级。

## 回归与复核

新增10项真实受限LOGIN数据库回归：普通/原生改PIN冲突、同PIN恢复、撤权、后续重置仍恢复原请求、两个历史PIN输入的保守冲突、同PIN/异PIN并发。检查原PIN/新PIN实际scrypt验证、账号唯一性，以及员工、角色、审计、发件箱、回执等表逐行不变。并发HTTP请求使用单连接池串行入库，验证排队重试与不重复账号，不冒充多连接竞争压力测试。

新增7项API单测：PIN、操作人、租户、门店、请求键、密钥的绑定隔离及短密钥拒绝；相同请求指纹稳定。既有明文检查改为结构断言，避免随机十六进制摘要偶然含四位数字造成误报。

旧接口对新增10项：5失败、5通过（其余63未选择）；修后扩展7文件172项通过，API17项通过。旧码失败覆盖普通改PIN、重置后错认、两个无绑定历史输入和异PIN排队。完整check、全数据库及最终提交CI结果在PR415记录；各层有重叠，不累加为独立测试总数。

## 相邻入口检查

- 原生创建、PIN重置、日口令轮换：秘密值均由服务端HMAC参与完整指纹；扩大回归中的员工生命周期测试实际验证改PIN/改口令409、原值回放成功、会话撤销和新会话不被重试误撤销。
- 普通员工状态：目标员工、状态、原因、操作人都在指纹内；回执前仍检查当前管理员授权。
- 权限发布交接：有意保留原操作者恢复本人回执且overview=null，不能新增写入。既有回归继续验证。
- 门店设备验证、员工登录与切换：直接验证当前口令/PIN，不经过创建命令成功回执缓存；不能仅因也处理PIN就推断有同类漏洞。
- 生产可达的PIN重置/口令配置只从原生管理包装器调用，包装器提供当前授权和秘密绑定；内部服务接收调用者指纹这一事实本身不是新增暴露接口。

本轮秘密指纹范围未发现另一项绕过；另发现下述未知结果恢复问题，不代表全系统已检查完毕。审查为作者代码复核，不代替独立外部批准；未进行生产读回或现场验收。


## 追加发现 RULE-AUDIT-20261102-11（待修复）

普通员工创建与状态表单每次点击用 `crypto.randomUUID()` 生成请求键；catch直接显示“员工账号没有建立成功”或“员工账号未能停用/恢复”。客户端网络错误不能证明服务端未提交。若响应丢失，新点击不能恢复原回执，创建报“账号已存在”，状态变更报“状态没有变化”。这不造成重复建号或重复状态修改，但提示与真实结果不一致。

2项本机受限LOGIN探针把真实 `NormalizedApiClient` 接到实际管理API，在事务提交成功后丢弃第一次响应并抛网络异常，随后按表单当前行为换键。两项均观察到：首次客户端网络失败、换键业务拒绝、原键恢复replayed=true，员工/角色/审计/outbox/回执等全行快照不变。表单提示和每次换键来自源码复核，未声称已做浏览器渲染、真实断网或现场设备验证。证据保存于本地 `outputs/staff-pin-replay-fix-20261102/recovery.log`、`staff-recovery-audit.probe.ts.txt`。
