- 本地确认：正式代码已有加密公众号账号配置、签名/加密回调校验、UnionID 关系绑定、一次性订阅通知以及模板消息发送适配。已有接入基础不证明生产账号具备积分模板权限。

若账号仅有一次性订阅通知，不能承诺每次积分变动均自动触达。本候选接的是公众号业务模板消息；可用模板及用途仍须账号实际审核证据。若平台不授予此权限，需要据实际可用能力调整接收方案，不能绕过授权次数。

## 逐条覆盖

主记录来自 `loyalty_point_ledger` 插入事务：业务回滚则通知同时回滚；每条流水一个唯一通知。旧流水不批量回灌。补充不新增积分流水的状态变化如下。

| 业务场景 | 依据/入口 | 本轮处理与验证 |
|---|---|---|
| 消费得分 | LoyaltyAccrualRepository / earn | 逐笔到账通知；积分入账、退款等现有测试回归 |
| 活动/促销/回访奖励 | PromotionalLoyaltyWorker / earn | 活动奖励独立标题；促销数据库联验通过 |
| 结账积分占用 | CheckoutPointsRepository / redeem | 标为“结账积分占用”，与结清区分 |
| 全积分及混合付款结清 | checkout_point_holds held→consumed | 追加“抵扣确认”事件，变动为0，不再次扣分 |
| 商品/权益积分兑换 | LoyaltyRedemptionRepository / redeem | 兑换扣减通知；兑换相关回归通过 |
| 取消、支付失败恢复、兑换释放 | restore 流水及既有恢复工作器 | 返回多少可用积分就记录多少；取消重复调用不再产生流水/通知 |
| 退款返还抵扣积分 | CheckoutPointsRepository / restore | 分次退款逐笔通知；同一退款重放不重复 |
| 已过期积分返还 | checkout_point_restorations | 即使实际返还可用0分，也解释超过原有效期；混合返还余额快照已校正 |
| 退款冲回消费或促销赠分 | reverse 流水 | 记录冲回及当时可用余额，不发送假负余额 |
| 退款时积分不足 | loyalty_accounts.pending_recovery_points | 待回收积分变化单独通知，区别于可用积分变化 |
| 新获得积分抵回欠分 | reverse / recovery-debt及待回收变化 | 独立“抵回退款欠积分”与待回收变化，不误称新的退款 |
| 漏积分补发 | supplement | 补发通知；原审批/退款一致性回归 |
| 人工加减/服务补偿 | adjust | 经原业务授权和审批后才随流水生成通知；人工积分联验 |
| 积分实际到期扣减 | expire | 到期扣减通知，和提前到期提醒分开 |
| 普通退款后再次补收恢复积分 | LoyaltyRecollectionRepository / restore、expire | 原政策恢复、已过期贡献及待回收调整均有记录；真实数据库补收联验 |
| 提前到期预告 | 现有小程序loyalty_points_expiring | 保留现有授权流程；它不是已发生的积分扣减，不伪装成变动 |

已检查所有正式 `loyalty_accounts` / `customer_memberships` 积分写入入口：消费、兑换、结账、促销、补收、到期、人工调整；会员展示读取不新增通知。今后新增流水类型也会生成待处理记录，不依赖开发者记住在每个业务分支单独调用发送函数。

## 发送、授权和可靠性

- 仅使用所选公众号中已验证且唯一的关注关系；不把小程序 OpenID 当成公众号 OpenID。企业微信内部员工通知接口不用于客户积分通知。
- 顾客在微信小程序“我的→消息提醒→公众号积分变动提醒”明确开关；关注公众号、小程序订阅授权、会员权益均不等同于这个选择。关闭不影响点单与积分权益。
- 精确保留数据库时间，拒绝将开启之前的变动在后来开启时补发。配置未就绪、未关注/未绑定、未选择接收等有单独状态和原因。
- 每次实际发送前检查公众号当前模板列表及字段、关注状态；提交发送前再次核对配置、会员状态、接收选择和紧急停用开关。
- 同一会员按事件顺序提交，两个工作器不能重复领取同一通知。数据库提交领取后才请求微信。
- 平台明确受理为 `accepted`；只有经过既有认证回调入口的成功事件才记 `delivered`。这仍不是已读，也不替代手机截图或本人确认。
- 保存提前到达的回执，随后合并接口结果。网络超时、进程中断或回执缺失为 `unknown`，不自动重发；明确拒绝/平台发送失败单列。
- 公众号已启用且该会员已选择接收时，新的到账/冲回通知不再重复加入原小程序订阅通道。保留小程序积分完整明细和原提前到期提醒。
- 通知数据包含有符号变动、变动后可用余额、原因和北京时间，按真实模板字段映射；运行时有正式小程序 AppID 时链接到积分明细。人工内部备注不直接发送给顾客。
- 后台沿用公众号管理权限；敏感配置和密钥不回显；租户/门店隔离、原积分数据与通知来源不可修改、已处理通知不可重新排队均有数据库保护。
